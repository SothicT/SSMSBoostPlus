## 2. 产品概述

### 2.1 业务背景与问题陈述

SSMSBoostPlus 提供基于本地对象缓存的 SQL 智能补全。当前引擎在以下场景中识别能力不足：

1. **FROM 在后写法无别名提示**：SELECT 列清单在前、FROM/JOIN 定义在后，输入 `A.` 时别名映射为空（根因：`ResolveAliasMap` 仅扫描光标前文本）。
2. **无别名时无字段提示**：`FROM [Table] WITH(NOLOCK) WHERE` 后输入字段名，当前仅在点号触发，不给提示。
3. **上下文不分层**：不论光标在 `FROM` 后、`WHERE` 后、`SET` 后，提示内容相同（关键词+模板混在一起），未按语法位置区分表名/字段/SP。
4. **跨库补全不支持逐层引导**：输入 `DBNAME.` 后不能逐层提示 Schema→Table。
5. **快捷键缺失**：关键词查询仅右键菜单。
6. **INSERT 字段未自动展开**。

### 2.2 核心分析：语句级上下文感知扫描方案（方法 D）

> 不扫全文，不扫前半段，不扫后半段——而是**找到当前光标所在的唯一一条完整 SQL 语句**，以该语句为单位解析语法结构，再根据光标在语句中的精确语法位置决定提示内容。

#### 2.2.1 语句断句（定位当前语句）

以 SQL 起始关键词为语句边界（不依赖分号，因为 SSMS 中分号不强制）：

| 起始关键词 | 类型 | 语句结束条件 |
|-----------|------|-------------|
| `SELECT` | 查询语句 | 遇到下一个顶层 `SELECT`/`UPDATE`/`DELETE`/`INSERT`/`MERGE`/`GO` 或缓冲区末尾 |
| `UPDATE` | DML | 同上 |
| `DELETE`/`DELETE FROM` | DML | 同上 |
| `INSERT INTO` | DML | 同上 |
| `MERGE INTO` | DML | 同上 |
| `CREATE` / `ALTER` / `DROP` | DDL | 遇到下一个顶层起始关键词或 `GO` |
| `EXEC` / `EXECUTE` | 过程调用 | 同上 |
| `WITH`（CTE） | 复杂查询 | 解析到后续的 `SELECT`/`UPDATE`/`DELETE` 作为 CTE 主体，整体为一条语句 |

**断句算法**：
1. 从光标位置向前回溯到最近的语句起始关键词，确定当前属于哪条语句。
2. 从该起始关键词向后快速扫描，找到语句结束位置（下一个同层起始关键词或末尾）。
3. 以该完整语句为范围做语法解析。

#### 2.2.2 简单语句 vs 复杂语句的分类处理

**简单语句**：无嵌套子查询、无 CTE、语法结构扁平。直接以模板化规则判断各位置应提示的内容。

判断规则示例（以 `SELECT` 为例）：

```
SELECT  ← 已输入关键词，后续应提示关键词+模板（如 TOP/DISTINCT/*/列名）
  *     ← 在 * 前输入，应提示关键词+表字段+模板
  col   ← 在列区域输入（FROM 之后不是列区域），应提示表字段
FROM   ← FROM 后应提示表名（含跨库逐层引导）
  T    ← 表名后空格，应提示别名或不提示（若为 JOIN 则提示 ON）
WHERE  ← WHERE 后应提示字段
  col  ← WHERE 条件区域，应提示当前 FROM 表的字段
  AND  ← 已输入 AND，应继续提示字段
  ORD  ← 输入 ORD，应提示 SQL 关键词（ORDER BY）和模板
  完   ← 完整语句后继续输入，应提示 SQL 关键词+模板（新语句开始）
```

> **关键原则**：每一步根据**当前已输入的关键词**和**光标位于子句的位置**，决定提示类型。

**复杂语句**：含嵌套子查询、CTE、多层结构。需要分析层级关系，不同层级提示不同内容。

```
SELECT TAB.* FROM (                     ← 外层 SELECT
    SELECT TOP 100 *                    ← 内层 SELECT（子查询）
    FROM [dbo].[BD_WorkOrder] A
    WITH(NOLOCK)
) TAB                                   ← 子查询别名 TAB
WHERE TAB.col                           ← 外层 WHERE
```

规则：
- **外层 SELECT 列区**输入 `TAB.` → 应弹出子查询 `(SELECT ... )` 的字段（需推导子查询输出列）。
- **内层 SELECT 列区**输入 `A.` → 弹出 `BD_WorkOrder` 字段（当前逻辑已支持，但要确保 FROM 在前在后都行）。
- **外层 WHERE** 输入 `TAB.` → 同上，弹出子查询输出列。

```
WITH cte AS (
    SELECT ID, Name FROM dbo.Users
)
SELECT c. FROM cte c WHERE c.
```

- 输入 `c.` → 应弹出 `cte` 的输出列（`ID`, `Name`）。
- CTE 字段推导方式：解析 CTE 内部的 SELECT 列表。

#### 2.2.3 标准 T-SQL 语法树（完整语句结构参考）

基于 Microsoft Learn 官方语法文档与 T-SQL BNF，以下是五种核心 DML 语句的完整语法树，作为上下文感知补全的 **标准化基础**。

**SELECT 语句语法树**（逻辑处理顺序=物理输入顺序参考）：

```
WITH CTE (...)                                    ← CTE 定义
SELECT [ALL | DISTINCT] [TOP n [PERCENT] [WITH TIES]]
    <select_list> ::=                             ← 列选择区
        { * | 别名.* | 表达式 [AS 列别名] } [, ...]
[INTO 新表名]                                     ← INTO 目标表
FROM                                              ← 数据源区
    <table_source> ::=
        表名 [AS] 别名 [WITH(表提示)]
      | [INNER|LEFT|RIGHT|FULL|CROSS] JOIN 表名 [AS] 别名 [WITH(表提示)] ON 条件
      | (子查询) [AS] 子查询别名
      | 表值函数(...) [AS] 别名
      | OPENQUERY/OPENROWSET
[WHERE <search_condition>]                        ← 行过滤区
[GROUP BY <group_list> [ALL]]                     ← 分组区
[HAVING <search_condition>]                       ← 组过滤区
[ORDER BY <order_list> [ASC|DESC]]                ← 排序区
[OFFSET n ROWS [FETCH NEXT n ROWS ONLY]]          ← 分页区
[FOR XML|JSON|BROWSE]                             ← 输出格式区
[OPTION (<query_hint> [, ...])]                   ← 查询提示区
[UNION [ALL] | EXCEPT | INTERSECT <query_expr>]   ← 集合运算
[;]                                               ← 可选分号
```

**INSERT 语句语法树**：

```
INSERT [INTO] <表名> [WITH(表提示)]
    [(<列名列表>)]                                ← 可选列清单
    VALUES (值列表) [, ...]                        ← 值列表模式
  | <SELECT 语句>                                  ← 子查询模式
  | EXEC <SP 调用>                                  ← 执行模式
  | DEFAULT VALUES                                  ← 默认值模式
```

**UPDATE 语句语法树**：

```
UPDATE [TOP n [PERCENT]]
    <表名> [AS] 别名 [WITH(表提示)]
    | OPENQUERY/OPENROWSET 函数
SET                                             ← SET 赋值区
    <列名> = 表达式 | .WRITE(表达式, @Offset, @Length)
    | @变量 = 表达式
    [, ...]
[FROM <table_source> [, ...]]                   ← 附加数据源
[WHERE <search_condition>]                       ← 行过滤区
[OPTION (<query_hint> [, ...])]
```

**DELETE 语句语法树**：

```
DELETE [TOP n [PERCENT]]
    [FROM] <表名> [AS] 别名 [WITH(表提示)]
    | 视图名 | 表值函数
[FROM <table_source> [, ...]]                    ← 附加数据源
[WHERE <search_condition>
    | WHERE CURRENT OF [GLOBAL] 游标名]           ← 行过滤/游标
[OPTION (<query_hint> [, ...])]
```

**EXEC 语句语法树**：

```
EXEC[UTE] ({存储过程名 | 函数名} [@参数名 =] 值 [, ...])
    [WITH RECOMPILE]
```

#### 2.2.4 语法节点→补全内容完整映射表（基于标准语法）

此表定义了每个语法节点处，编辑器应当提示的内容类型。是上下文感知引擎的 **唯一决策依据**。

**第一类：通用语法节点（跨语句类型）**

| 语法节点 | 所属语句 | 应提示内容 | 说明 |
|---------|---------|-----------|------|
| **语句起始** | 全部 | SQL 关键词 + SQL 模板 | 刚进入新语句，不知道要写什么 |
| **`<表名>`位置** | SELECT-FROM/JOIN<br>INSERT INTO<br>UPDATE<br>DELETE [FROM]<br>MERGE INTO | **表名/视图名** + 跨库逐层引导 | 见跨库规则 |
| **`<列别名>`位置** | SELECT 列区 | 不含 AS 则按当前输入片段匹配表字段；含 AS 则提示别名 | 列别名 = `表达式 [AS] 别名` |
| **`<search_condition>`** | WHERE / HAVING / ON | 当前上下文表的**字段 + 关键词**(AND/OR/IN/BETWEEN等) | 详细见下 |
| **`[WITH(表提示)]`** | FROM/JOIN/UPDATE/DELETE | 表提示关键词(NOLOCK/ROWLOCK/TABLOCK等) | 括号内提示 |
| **`[OPTION(...)]`** | SELECT/UPDATE/DELETE | 查询提示(RECOMPILE/FAST N等) | 括号内提示 |
| **`<表达式>`位置** | 通用 | 字段 + 函数 + 变量 + 关键词 | 优先级：字段 > 函数 > 变量 |
| **注释/字符串内** | 全部 | **不提示** | 防误触发 |

**第二类：SELECT 语句特有语法节点**

| 语法节点 | 位置判定规则 | 应提示内容 | 示例 |
|---------|------------|-----------|------|
| `SELECT` 后、`<select_list>` 开始前 | 光标在 `SELECT` 之后、第一个列表达式之前 | 关键词(TOP/DISTINCT/ALL) + 字段 + 模板 | `SELECT █` — 提示 TOP、DISTINCT、表字段 |
| `TOP (n)` 括号内 | 光标在 `TOP (` 之后 | 数字 + @@ROWCOUNT 等变量 | `SELECT TOP █` — 不提示，等待数字 |
| `TOP n` 后, `<select_list>` 前 | `TOP n` 已完成 | 关键词(PERCENT/WITH TIES) + 字段 | `SELECT TOP 100 █` — 提示 PERCENT、WITH TIES |
| **SELECT 列区域**（列表达式位置） | `SELECT` 与 `FROM` 之间，每个逗号分隔项 | **当前 FROM 表的字段** + 关键词(DISTINCT/AS/CASE等) + 模板 | 无别名单表→直出字段；多表→带 `别名.[字段]` |
| `别名.*` 模式 | 列区域输入 `别名.` 后 | 该别名的字段（点号触发，不标注来源） | `A.█` → A 表全部字段 |
| `SELECT...INTO` 后 | `INTO` 空格后 | 新表名候选（或当前库表名） | 用于 `SELECT * INTO █ FROM ...` |
| `FROM` 后 | `FROM` 空格后 | **表名/视图/子查询/表值函数** + 跨库引导 | 空→当前库表；`DB.`→Schema；`DB.Schema.`→Table |
| `JOIN` 后（任意 JOIN 类型） | `JOIN` 空格后 | **表名/视图等**（同 FROM） | `INNER JOIN █` → 提示表名 |
| `JOIN ... ON` 后 | `ON` 空格后 | JOIN 两侧表的**字段 + 关键词**(AND/OR/IN等) | `A JOIN B ON █` → 提示 A.字段 和 B.字段 |
| `WHERE` 后 | `WHERE` 空格后 | 当前 FROM 表的**字段 + 关键词**(AND/OR/IN/BETWEEN/NOT等) | `WHERE █` → 提示字段和 AND/OR 关键词 |
| `AND` / `OR` 后（条件链） | `AND`/`OR` 空格后 | 同 WHERE：**字段 + 关键词** | `WHERE a=1 AND █` → 提示字段和关键词 |
| `GROUP BY` 后 | `GROUP BY` 空格后 | 当前 SELECT 列的别名 + 字段 | 按可分组对象提示 |
| `HAVING` 后 | `HAVING` 空格后 | 聚合字段 + 关键词(AND/OR/IN等) | `HAVING SUM(█)` — 聚合字段 |
| `ORDER BY` 后 | `ORDER BY` 空格后 | SELECT 列别名 + 字段 + 关键词(ASC/DESC) | `ORDER BY █` → 提示列别名 |
| `ORDER BY x` 后 | `ORDER BY x` 空格后 | 关键词 ASC/DESC + 逗号 | 继续下一排序项 |
| `OFFSET n ROWS` 后 | `OFFSET` 完成后 | 关键词 FETCH NEXT | 分页提示 |
| `FETCH NEXT n ROWS` 后 | `FETCH NEXT` 完成后 | 关键词 ONLY | 分页提示 |
| `FOR XML/JSON` 后 | `FOR...` 空格后 | XML/JSON 模式关键词(RAW/AUTO/PATH/ROOT等) | 输出格式提示 |
| `UNION` / `EXCEPT` / `INTERSECT` 后 | 集合运算后 | 新的 SELECT/INSERT/UPDATE 语句起始 | 新子语句开始 |

**第三类：INSERT 语句特有语法节点**

| 语法节点 | 位置判定规则 | 应提示内容 | 示例 |
|---------|------------|-----------|------|
| `INSERT` 后 | `INSERT` 空格后 | 关键词 `INTO` | `INSERT █` → 提示 INTO |
| `INSERT INTO` 后 | `INTO` 空格后 | **表名**（同 FROM 跨库逐层规则） | `INSERT INTO █` → 提示表名 |
| 表名后、`VALUES` 前 | 表名确认后、未输入 `VALUES` | 自动展开字段 **([col],[col],...) VALUES (...)** | AC3.1 所述 |
| `(列名列表)` 括号内 | `(` 后 | 当前 INSERT 表的字段 | `INSERT T (█` → T 的字段（逗号分隔） |
| `VALUES` 后 | `VALUES` 括号内 | 当前列的`DEFAULT`/表达式/子查询 | 按列类型提示 |
| `VALUES` 下一列 | 逗号后 | 下一列的值 | 同前 |

**第四类：UPDATE 语句特有语法节点**

| 语法节点 | 位置判定规则 | 应提示内容 | 示例 |
|---------|------------|-----------|------|
| `UPDATE` 后 | `UPDATE` 空格后 | 关键词 TOP + **表名** | `UPDATE █` → 提示表名和 TOP |
| `UPDATE [TOP n]` 后 | TOP 子句完成后 | **表名** | `UPDATE TOP 100 █` → 提示表名 |

| 语法节点 | 位置判定规则 | 应提示内容 | 示例 |
|---------|------------|-----------|------|

**第七类：跨库逐层引导规则（适用于所有"表名"位置）**

| 输入状态 | 应提示 | 补全行为 |
|---------|--------|---------|

| 已输入 `[DBName]..`（双点省略 Schema） | 直接提示默认 Schema 的 Table | — |
| 输入了 `[服务器].[DBName]...` | 链接服务器跨服务逐层 | 多一层服务器级（链接服务器场景） |

## 3. 用户故事与验收条件

### 需求 1：SQL 补全上下文识别强化

#### 用户故事 1.1 — 语句级别名解析（兼容 FROM 在后 + 多行 + 跨库）

> 作为 DBA，我希望在任意复杂 SQL 中输入 `别名.` 时都能获得字段提示，无论别名定义在光标之前还是之后。

**验收条件**：

- **AC1.1**：Given 用户示例 SQL（SELECT 列清单在前、FROM 在后），
  When 在任意 `A.` 或 `B.` 位置输入，Then 弹出对应表字段列表（`A` → `BD_ERP_SO_LINE`，`B` → `BD_ERP_SO_HEADER`）。
- **AC1.2**：Given 跨库表 `[MESDATA].dbo.HONEY_832_MM_HEADER H`，When 输入 `H.`，Then 弹出 `HONEY_832_MM_HEADER` 字段。
- **AC1.3**：Given 方括号表名 `[dbo].[BD_ERP_SO_LINE] AL`（无 `AS`），When 输入 `AL.`，Then 弹出 `BD_ERP_SO_LINE` 字段。
- **AC1.4**：Given 多行换行别名定义，When 输入 `别名.`，Then 正确解析别名映射（不受换行影响）。

**优先级**：P0

#### 用户故事 1.2 — 根据语法的上下文感知提示

> 作为开发，我希望在不同语法位置输入时，系统自动区分并提示恰当的内容。

**验收条件**：

- **AC1.10（表名位置）**：Given 光标在 `FROM` / `JOIN` / `UPDATE` / `DELETE FROM` / `INSERT INTO` 空格后，
  When 输入字符，Then 弹出表名 + 视图候选（含跨库逐层引导）。
- **AC1.11（SP 位置）**：Given 光标在 `EXEC` 空格后，When 输入字符，Then 弹出存储过程 + 函数候选。
- **AC1.12（字段位置）**：Given 光标在 `WHERE` / `AND` / `OR` / `SET` / `ON` 后（非点号），
  When 输入字段片段，Then 弹出当前上下文 FROM 表的字段候选（单表/多表规则见 AC1.8）。
- **AC1.12.1**：Given `UPDATE A SET co FROM TABLE`（`A` 是 `TABLE` 的别名），
  When 在 `co` 处输入，Then 弹出 `TABLE` 的字段候选，选中后自动补全 `A.字段名`。
- **AC1.13（关键词位置）**：Given 光标在语句起始、完整语句末尾、或在 `SELECT` 后 `*` 前，
  When 输入字符，Then 提示 SQL 关键词 + SQL 模板。
- **AC1.13.1**：Given 已输入 `SELECT * FROM T WHERE col=1` 完整语句后继续输入，
  When 输入字符，Then 提示 SQL 关键词 + 模板（新语句的起始）。
- **AC1.13.2**：Given 在 `WHERE` 后已输入 `AND`，
  When 继续输入字段片段，Then 弹出字段候选（从"关键词"切换回"字段"上下文）。
- **AC1.14（非 SQL 区域）**：Given 光标在注释或字符串字面量内，When 输入，Then 不触发任何提示。

**优先级**：P0

#### 用户故事 1.3 — 字段提示显示来源表 + 带前缀自动补全

> 作为开发，我希望在多表上下文中清晰看到各字段来自哪张表，选中后自动补全 `别名.字段名`。

**验收条件**：

- **AC1.8**：Given 多表 `FROM`，当在 `WHERE` 中输入字段片段时，Then 提示在多表字段集合中去重合并；歧义字段展示 `别名.[字段]` 消歧。
- **AC1.8.1（展示规则）**：Given 多表上下文（有别名或裸表），When 字段提示弹窗弹出，Then 每个候选的 DisplayText 标注来源表：
  - 有别名时：`a.[FieldName]` / `b.[FieldName]`
  - 无别名时：`表名.[FieldName]`
  - 单表无别名：仅显示字段名（简洁）。
- **AC1.8.2（选中行为）**：Given 多表上下文，
  When 用户选中某个候选，Then 插入文本为 **`别名.字段名`**（而非仅字段名）。
  - 例：选中 `a.[ACTUAL_ADD]`，插入 `A.ACTUAL_ADD`
  - 例：选中 `b.[ACTIVE_FLAG]`，插入 `B.ACTIVE_FLAG`
- **AC1.8.3**：Given 用户示例 `SELECT TOP 100 ac* FROM [dbo].[BD_WorkOrder] a WITH(NOLOCK), [dbo].[LIST_WOReRun_Bak] b WITH(NOLOCK) WHERE...`，

- **AC1.8.4（点号触发行为不变）**：Given 已输入 `A.`，When 字段提示弹出，Then DisplayText 仅显示字段名（无需重复标注来源），选中插入仅字段名（用户已明确表来源）。
- **AC1.9**：Given 表在缓存中不存在，When 触发字段提示，Then 不弹窗，不残留旧弹窗。

**字段排序规则**：
- 按来源表分组显示（同一表的字段聚在一起）
- 同组内按字段名字母序
- 有 `prefix` 输入时，前缀匹配 > 子串匹配 > 其他

**优先级**：P0

## 4. 功能规格说明

### 4.1 模块：语法位置定位引擎（核心重构）

**设计原则**：基于 2.2.3 节的完整 T-SQL 语法树，从光标位置反向推导当前所处的语法节点。

**输入**：当前文本缓冲区 + 光标位置。
**输出**：`(SyntaxNode, Depth, StatementType)` — 光标所处的语法节点、嵌套深度、所属语句类型。

**核心算法**：

```
1. 语句断句（同2.2.1）：找到光标所在的完整SQL语句文本

2. 语法节点定位：
   a. 从光标位置反向扫描，识别最近的语法关键词
   b. 跳过：字符串字面量、注释、括号内内容（用括号栈）
   c. 关键词匹配优先级：
      第一梯队：SELECT / FROM / WHERE / SET / VALUES / ON / ORDER BY
      第二梯队：JOIN / GROUP BY / HAVING / INTO / EXEC / UNION
      第三梯队：AND / OR / AS / TOP / FOR / OPTION / OFFSET / FETCH
   d. 结合关键词在语句中的顺序位置，判定具体节点
      例：在 SELECT 与 FROM 之间 → SelectColumnArea
      例：在 FROM 与 WHERE 之间且有 JOIN → FromOrJoinArea
      例：在 WHERE 之后 → WhereConditionArea

3. 嵌套层级处理（关键）：
   - 遇到 '(' 入栈，')' 出栈
   - 栈深度 = 当前嵌套层级
   - 层级 0 = 主语句，层级 1+ = 子查询/函数参数
   - 不同层级的上下文各自独立（内层 SELECT 的别名不泄漏到外层）

4. 查询主语句的别名/表源映射（复用4.4解析器），作为字段提示的来源
```

**语法节点枚举**（完整，按 T-SQL 标准分类）：

```csharp
enum SyntaxNode
{
    // 通用节点
    StatementStart,                 // 语句起始 / 语句后新语句
    TableNamePosition,              // 表名位置（FROM/JOIN/INSERT INTO/UPDATE/DELETE）
    SearchConditionPosition,        // 条件表达式位置（WHERE/HAVING/ON）
    ExpressionPosition,             // 通用表达式位置
    AfterDotNotation,               // 点号后（表名. 或 别名.）
    CrossDbContextPrompt,           // 跨库逐层引导
    InCommentOrString,              // 注释/字符串内 → 不提示
    TableHintPosition,              // WITH(表提示) 括号内
    QueryOptionPosition,            // OPTION(查询提示) 括号内

    // SELECT 特有
    AfterSelectKeyword,             // SELECT 后、列区前
    SelectColumnArea,               // SELECT 列区域（FROM 之前）
    SelectAliasColumnAfterDot,      // 别名.* 点号后
    IntoNewTablePosition,           // INTO 后
    AfterFromKeyword,               // FROM 后
    AfterJoinKeyword,               // JOIN 后
    AfterJoinOnKeyword,             // ON 后
    AfterWhereKeyword,              // WHERE 后
    AfterAndOrKeyword,              // AND/OR 后（条件链）
    AfterGroupByKeyword,            // GROUP BY 后
    AfterHavingKeyword,             // HAVING 后
    AfterOrderByKeyword,            // ORDER BY 后（含 ASC/DESC 提示）
    AfterOffsetFetchKeyword,        // OFFSET/FETCH 位置
    ForOutputFormatPosition,        // FOR XML/JSON 位置
    AfterSetOperationKeyword,       // UNION/EXCEPT/INTERSECT 后
    AfterTopKeyword,                // TOP (n) 括号内

    // INSERT 特有
    InsertIntoTablePosition,        // INSERT INTO 后（表名）
    InsertColumnListPosition,       // INSERT (列名列表) 括号内
    InsertValuesPosition,           // VALUES 括号内
    InsertTableAfterInsertInto,     // INSERT INTO 表名确认后（触发展开）

    // UPDATE 特有
    UpdateTablePosition,            // UPDATE 后
    UpdateSetPosition,              // SET 后（被更新表的字段）
    UpdateSetColumnAssignment,      // SET 列 = 后
    UpdateFromTablePosition,        // UPDATE FROM 后（附加数据源）

    // DELETE 特有
    DeleteTablePosition,            // DELETE [FROM] 后
    DeleteFromTablePosition,        // DELETE FROM 附加数据源

    // EXEC 特有
    ExecPosition,                   // EXEC 后（SP/函数名）
    ExecParameterPosition,          // EXEC 参数位置
}
```

### 4.2 模块：分发引擎（语法节点 → 补全内容）

核心逻辑：一个 `switch(SyntaxNode)` 根据 4.1 的定位结果，决定展示哪类补全候选。

```csharp
switch (node)
{
    /* ===== 通用 ===== */
    case StatementStart:            → SQL 关键词 + SQL 模板
    case TableNamePosition:         → 表名/视图 + 跨库逐层引导（见 4.5）
    case SearchConditionPosition:   → 当前上下文字段 + 条件关键词(AND/OR/IN/BETWEEN/NOT/LIKE)
    case ExpressionPosition:        → 字段 + 函数 + 变量 + 关键词
    case AfterDotNotation:          → 表名/别名对应表的字段（点号触发，展示仅字段名，插入仅字段名）
    case CrossDbContextPrompt:      → 按层级提示 DB→Schema→Table→字段
    case InCommentOrString:         → 不提示（HidePopup）
    case TableHintPosition:         → 表提示关键词(NOLOCK/ROWLOCK/TABLOCK/TABLOCKX/READUNCOMMITTED等)
    case QueryOptionPosition:       → 查询提示(RECOMPILE/FAST n/MAXDOP n等)

    /* ===== SELECT ===== */
    case AfterSelectKeyword:        → 关键词(TOP/DISTINCT/ALL) + 表字段 + SQL 模板
    case SelectColumnArea:          → 当前 FROM 表的字段（单表直出，多表带别名前缀见4.6）+ 关键词(AS/CASE) + 模板
    case SelectAliasColumnAfterDot: → 该别名对应表的字段（点号触发，仅字段名）
    case IntoNewTablePosition:      → 新表名候选
    case AfterFromKeyword:
    case AfterJoinKeyword:          → 表名/视图 + 跨库引导（同 TableNamePosition）
    case AfterJoinOnKeyword:        → JOIN 两侧表的字段 + 条件关键词
    case AfterWhereKeyword:
    case AfterAndOrKeyword:         → 当前 FROM 表的字段 + 条件关键词(AND/OR/IN等)
    case AfterGroupByKeyword:       → SELECT 列别名 + 字段
    case AfterHavingKeyword:        → 聚合字段 + 条件关键词
    case AfterOrderByKeyword:       → SELECT 列别名 + 字段 + 关键词(ASC/DESC)
    case AfterSetOperationKeyword:  → SQL 关键词(新子查询起始)

    /* ===== INSERT ===== */
    case InsertIntoTablePosition:   → 表名 + 跨库引导（同 TableNamePosition）
    case InsertColumnListPosition:  → 当前 INSERT 表的字段（逗号分隔列清单提示）
    case InsertValuesPosition:      → 表达式/DEFAULT/NULL（按列类型）
    case InsertTableAfterInsertInto:→ 自动展开字段（AC3.1）

    /* ===== UPDATE ===== */
    case UpdateTablePosition:       → 表名 + 关键词(TOP)
    case UpdateSetPosition:         → 被 UPDATE 表的字段（带别名前缀规则见4.6）
    case UpdateSetColumnAssignment: → 表达式/子查询/DEFAULT
    case UpdateFromTablePosition:   → 表名（附加数据源）

    /* ===== DELETE ===== */
    case DeleteTablePosition:       → 表名 + 关键词(TOP)
    case DeleteFromTablePosition:   → 表名（附加数据源）

    /* ===== EXEC ===== */
    case ExecPosition:              → 存储过程 + 函数（含跨库引导）
    case ExecParameterPosition:     → @参数名 或 值
}
```

### 4.3 模块：语句解析器（别名映射 + 表源集合 + 字段查询）

**解析策略**：对 4.1 步骤 2 断出的当前语句全文进行语法扫描，不依赖光标位置。

| 解析项 | 实现方式 |
|--------|---------|
| 别名映射 | 增强正则，扫描语句全文 `FROM/JOIN + 表名 + 空格 + 别名` 模式 |
| 裸表集合 | 扫描语句全文中所有 FROM/JOIN 后的裸表（无别名） |
| 字段查询 | 基于映射解析出的物理表名，调用 `GetTableColumns(表名, prefix)` |
| CTE 推导 | 解析 WITH 定义中的 SELECT 列别名（后续迭代，本期旁路） |
| 子查询推导 | 解析子查询 SELECT 列表（后续迭代，本期旁路） |
| 缓存策略 | 输入防抖 200ms，文本变化后惰性重建语句解析结果 |

### 4.4 模块：跨库逐层引导

```
光标在 FROM 后且当前字符为空或部分DB名
  → 弹出数据库候选列表（来自 DbCache.GetDatabaseCandidates()）
  → 选中后自动补全 [DBName].

光标在 [DBName]. 后
  → 弹出该库下的 Schema 候选列表
  → 选中后自动补全 [DBName].[Schema].

光标在 [DBName].[Schema]. 后
  → 弹出该库该 Schema 下的 Table/View/Function 候选
  → 选中后自动补全 [DBName].[Schema].[ObjectName]

光标在完整 [DBName].[Schema].[ObjectName]. 后
  → 按照别名/表名触发字段提示规则处理
```

### 4.5 模块：字段提示候选展示与插入规则

| 上下文 | DisplayText 展示 | 选中插入文本 |
|--------|-----------------|-------------|
| 点号触发 `A.` | `FieldName`（不加前缀，来源已明确） | `FieldName` |
| 无别名+单表 | `FieldName` | `FieldName` |
| 无别名+多表 | `a.[FieldName]` / `b.[FieldName]` | **`a.FieldName`** / `b.FieldName` |
| 多表无别名 | `Table.[FieldName]` | **`Table.FieldName`** |

**关键行为变更（AC1.8.2）**：
- 多表上下文、无点号前缀时，选中候选不仅展示 `别名.[字段]`，插入时也自动补全 **`别名.字段`**（用户无需手动敲前缀）。
- 点号前缀上下文（已输入 `A.`），插入仅字段名（已有前缀无需重复）。

## 7. 风险

| 风险 | 等级 | 说明 | 缓解 |
|------|------|------|------|
| 断句不准 | 中 | 不含分号的 SQL 边界判断有歧义（如 SELECT 在注释中） | 过滤注释/字符串；以 GO 为硬边界 |
| 性能 | 低 | 当前语句范围远小于全文，解析成本在 μs 级 | 仅在文本变化时惰性解析 |
| 字段插入前缀误判 | 中 | 用户可能在单表中也希望带前缀 | 提供配置开关（默认按 PRD 规则） |
| 子查询推导 | 中 | `SELECT *` 形态需展开为表列，成本较高 | 本期不做，标注后续迭代 |

## 8. 方案对比总结

| 维度 | 原方案（三种方法） | 现方案（方法 D：语句级语法感知） |
|------|-------------------|--------------------------------|
| 扫描范围 | 全文 / 缓存 / 向后 | **当前光标所在的一条完整 SQL 语句** |
| 上下文判断 | 关键词匹配（粗糙） | **语法位置定位（精确到子句层级）** |
