问题链：dialog 关闭 → WPF 归还焦点到 ToolWindow → `OnWindowActivated` 触发 `DebouncedRefreshAsync` → `ConnectionFacade` 执行 DTE 操作 → DTE 操作间接触发窗口事件 → 最终焦点被 ToolWindow 再次抢走。

## 两个根本原因

### 原因一：WPF Dispatcher 时序问题

`ShowDialog()` 返回后，WPF 在内部 Dispatcher 队列中仍有待处理的焦点恢复操作。我们在 `ShowDialog()` 之后同步调用的 `ActiveDocument.Activate()` 可能先于 WPF 的焦点恢复执行，或在两者之间形成竞争，最终 WPF 的焦点恢复覆盖了我们的激活。

### 原因二：NewFile 模板错误

`dte.ItemOperations.NewFile("General\\Text File", ...)` 创建的是**纯文本编辑器**而非 SQL 编辑器。在 SSMS 中，纯文本编辑器可能不完全支持 Backspace/Enter 等键的预期行为（SSMS 为 SQL 编辑器专门配置了键盘绑定）。

## 修复方案

两处修改：

### 修改一：LocalHistoryDiffDialog.xaml.cs — 修正 NewFile 模板 + 移除 dialog 内 doc.Activate()

将 `OpenInEditorButton_Click` 中的：
```csharp
dte.ItemOperations.NewFile("General\\Text File", "VersionScript.sql");
...
success = true;
doc.Activate();
```

改为：
```csharp
dte.ItemOperations.NewFile("SQL Files\\SQL Query", "VersionScript.sql");
...
success = true;
// 不再在 dialog 内调用 doc.Activate()——WPF 模态 dialog 会立即抢回焦点，无效
```

理由：SQL Query 模板创建的是 SSMS SQL 编辑器，拥有完整的键盘绑定（Backspace、Enter 等）。移除 dialog 内的 `doc.Activate()` 因为它发生在 WPF 模态循环中，WPF 会立即抢回焦点。

### 修改二：LocalHistoryToolWindowControl.xaml.cs — Dispatcher 延迟焦点恢复

将 post-ShowDialog 的焦点恢复改为通过 `Dispatcher.BeginInvoke(Background)` 延迟执行，确保在 WPF 所有焦点操作完成后才激活文档：

```csharp
diffDialog.ShowDialog();

if (diffDialog.DialogResult == true)
{
    // 使用 Background 优先级延迟执行，确保 WPF 的焦点恢复操作先完成
    this.Dispatcher.BeginInvoke(new Action(() =>
    {
        try
        {
            var dte = Package.GetGlobalService(typeof(EnvDTE.DTE)) as EnvDTE.DTE;
            dte?.ActiveDocument?.Activate();
        }
        catch { }
    }), System.Windows.Threading.DispatcherPriority.Background);
}
```

`DispatcherPriority.Background` 在所有 Input/Loaded/Render 操作之后执行，确保 WPF 的模态 dialog 焦点恢复已完成。

## 边缘情况

- "关闭"按钮（非"在编辑器中打开"）：`DialogResult != true`，不触发延迟激活
- SQL Query 模板可能需要数据库连接：在已连接 SSMS 的上下文中，SQL 编辑器应正常初始化
- Dispatcher 延迟可能因窗口关闭而取消：try-catch 保护

## 结论

三个并发因素导致键盘持续失效：(1) NewFile 创建纯文本编辑器而非 SQL 编辑器；(2) WPF 模态循环中的 doc.Activate() 被 WPF 抢回焦点；(3) 同步的 ActiveDocument.Activate() 与 WPF 焦点恢复竞争。通过切换模板 + Dispatcher 延迟执行，从根源解决所有三个问题。
