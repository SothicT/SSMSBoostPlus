## 概述

本文档总结了 SSMSBoostPlus 项目在 SSMS 22 中新增主菜单命令并完整部署的全链路技术方案。
涵盖了从 VSCT 定义到部署验证的所有环节，以及在此过程中遇到的所有坑点和解决方案。

## 技术栈

| 组件 | 版本/说明 |
|------|-----------|
| SSMS | 22（基于 VS 18.0 Shell） |
| .NET SDK | 10.0 |
| VSSDK BuildTools | 17.14.2142 |
| 目标框架 | net472（WPF） |
| 编译工具 | VSCT.exe（手动调用） |

## 架构总览

```
SSMSBoostPlus.vsct (XML 命令表定义)
        ↓ VSCT.exe 编译
SSMSBoostPlus.cto (二进制命令表)
        ↓ 复制/重命名
Menus.ctmenu (SSMS 运行时加载的菜单资源)
        ↓ 嵌入 DLL（EmbeddedResource）
SSMSBoostPlus.SSMS.dll (含 Menus.ctmenu 嵌入资源)
        ↓ CreatePkgDef.exe
SSMSBoostPlus.SSMS.pkgdef (包注册信息)
        ↓ 部署到 SSMS Extensions 目录
SSMS 启动时加载 → privateregistry.bin 缓存 → 菜单显示
```

## 新增菜单完整流程

### 第 1 步：VSCT 定义命令

文件：`src/SSMS/SSMSBoostPlus.vsct`

需要修改三处：

#### 1.1 IDSymbol 定义

在 `<Symbols>` → `<GuidSymbol name="guidSSMSBoostPlusCmdSet">` 中添加：

```xml
<!-- Configuration group (0x0300-0x030F) -->
<IDSymbol name="cmdidMyNewCommand" value="0x0304"/>
```

**ID 分配规则**：

| 分组 | ID 范围 | 已用 ID |
|------|---------|---------|
| Version Guard | 0x0100-0x010F | 0x0100, 0x0101, 0x0102 |
| CODE WITH AI | 0x0200-0x020F | 0x0200-0x0206 |
| Configuration | 0x0300-0x030F | 0x0300, 0x0301, 0x0302, 0x0303 |
| Menu IDs | 0x1000+ | 0x1000, 0x1003, 0x1004, 0x1008 |
| Group IDs | 0x2000+ | 0x2000-0x2009 |

#### 1.2 Button 定义

在 `<Commands>` → `<Buttons>` 中添加：

```xml
<Button guid="guidSSMSBoostPlusCmdSet" id="cmdidMyNewCommand" priority="0x0260" type="Button">
  <Parent guid="guidSSMSBoostPlusCmdSet" id="Group_Config"/>
  <Strings>
    <ButtonText>📋 我的命令...</ButtonText>
    <CommandName>MyNewCommand</CommandName>
  </Strings>
</Button>
```

**Parent 分组选择**：

| 分组 | 说明 | 菜单位置 |
|------|------|----------|
| `Group_CodeWithAI` | AI 代码助手 | SSMSBoost++ 上半部分 |
| `Group_VersionGuard` | 版本守护 | SSMSBoost++ 中间部分 |
| `Group_Config` | 配置类 | SSMSBoost++ 底部（设置、检查更新等） |

#### 1.3 可选：KeyBinding

```xml
<KeyBinding guid="guidSSMSBoostPlusCmdSet" id="cmdidMyNewCommand"
            editor="guidVSStd97" key1="M" mod1="Control Shift"/>
```

### 第 2 步：创建 Command 类

文件：`src/SSMS/Commands/MyNewCommand.cs`

```csharp
public sealed class MyNewCommand : BaseCommand<MyNewCommand>
{
    private ILoggerService _logger = new ConsoleLoggerService();

    private MyNewCommand(AsyncPackage package, OleMenuCommandService commandService)
        : base(package, commandService, 0x0304)  // 必须与 VSCT IDSymbol value 一致
    {
    }

    public static async Task InitializeAsync(
        AsyncPackage package, ILoggerService logger)
    {
        await ThreadHelper.JoinableTaskFactory.SwitchToMainThreadAsync();
        var commandService = (OleMenuCommandService?)await package
            .GetServiceAsync(typeof(IMenuCommandService));
        Instance = new MyNewCommand(package, commandService!)
        {
            _logger = logger
        };
    }

    protected override void Execute(object sender, EventArgs e)
    {
        ThreadHelper.ThrowIfNotOnUIThread();
        // 命令逻辑
    }
}
```

**BaseCommand 基类核心机制**：

```csharp
// BaseCommand<T> 自动完成：

// 2. 创建 OleMenuCommand 并注册到 OleMenuCommandService

    new("c3d4e5f6-a7b8-9012-cdef-234567890123");  // 必须与 VSCT guidSSMSBoostPlusCmdSet 一致
```

### 第 4 步：编译（两次编译法）

#### 为什么需要两次编译？

| 编译阶段 | .cto 状态 | DLL 嵌入资源 |
|----------|-----------|-------------|
| 第一次编译 | 不存在 → VSCT.exe 生成 | ❌ 没有 Menus.ctmenu |
| 第二次编译 | 已存在（第一次生成的） | ✅ 有 Menus.ctmenu |

**根因**：csproj 中的静态 `<ItemGroup Condition="Exists(...)">` 在 MSBuild **评估阶段**（编译前）读取 .cto 文件。但 .cto 是在 `ManualVSCTCompile` target（编译阶段）才生成的。因此第一次编译时条件不满足，第二次编译时 .cto 已存在才能嵌入。

#### 编译命令

```powershell
# 第一次编译（生成 .cto）
dotnet build SSMSBoostPlus.slnx -c Release

# 第二次编译（嵌入 .cto 到 DLL）
dotnet build SSMSBoostPlus.slnx -c Release
```

#### 验证

```powershell
# 验证 DLL 嵌入资源
[System.Reflection.Assembly]::LoadFile('src\SSMS\bin\Release\net472\SSMSBoostPlus.SSMS.dll').GetManifestResourceNames()
# 期望输出包含: Menus.ctmenu

# 验证 .cto 文件
Get-Item 'src\SSMS\obj\Release\net472\SSMSBoostPlus.cto' | Select-Object Name, Length, LastWriteTime
```

#### csproj 关键配置

```xml
<!-- 1. VSCT 编译为 .cto（手动调用 VSCT.exe，替代 VSSDK 失败的 Pipeline） -->
<Target Name="ManualVSCTCompile" BeforeTargets="CoreCompile">
  <Exec Command="$(VSCTExe) %(VSCTCompile.FullPath) $(IntermediateOutputPath)%(VSCTCompile.FileName).cto" />
  <Copy SourceFiles="$(IntermediateOutputPath)SSMSBoostPlus.cto"
        DestinationFiles="$(OutDir)Menus.ctmenu" />
</Target>

<!-- 2. 静态嵌入 .cto 为 Menus.ctmenu 资源（需两次编译才生效） -->
<ItemGroup Condition="Exists('$(IntermediateOutputPath)SSMSBoostPlus.cto')">
  <EmbeddedResource Include="$(IntermediateOutputPath)SSMSBoostPlus.cto">
    <LogicalName>Menus.ctmenu</LogicalName>
    <Visible>false</Visible>
  </EmbeddedResource>
</ItemGroup>

<!-- 3. PkgDef 生成（手动调用 CreatePkgDef.exe） -->
<Target Name="ManualPkgDef" AfterTargets="Build">
  <Exec Command="$(CreatePkgDefExe) /out=$(IntermediateOutputPath)$(TargetName).pkgdef /codebase $(TargetPath)" />
  <Copy SourceFiles="$(IntermediateOutputPath)$(TargetName).pkgdef"
        DestinationFiles="$(OutDir)$(TargetName).pkgdef" />
</Target>

<!-- 4. 禁用 VSSDK 失败的 targets -->
<Target Name="GeneratePkgDef" />
<Target Name="CreateMenuPkgDef" />
<Target Name="GenerateTemplatesManifest" />
```

#### 为什么 VSSDK 原生 Pipeline 失败？

| VSSDK Target | 失败原因 |
|--------------|----------|
| `GeneratePkgDef` | 任务程序集(.17.0.dll) 在 .NET SDK 10 下报 VSSDK1032 |
| `MergeCtoResource` | `PrepareResourcesDependsOn` 被 SDK 覆盖，target 不被调度 |
| `CreateMenuPkgDef` | path 为空字符串导致崩溃 |
| `PrepareForRunDependsOn` | 被 .NET SDK 10 覆盖 |

### 第 5 步：部署

#### 部署清单

| 类别 | 文件 | 源目录 | 说明 |
|------|------|--------|------|
| 核心 DLL | SSMSBoostPlus.SSMS.dll | bin\Release\net472 | 含嵌入的 Menus.ctmenu |
| 核心 DLL | Core.dll, AI.dll, Shared.dll | bin\Release\net472 | 依赖层 |
| 调试符号 | *.pdb | bin\Release\net472 | 4个 PDB |
| 菜单资源 | Menus.ctmenu | obj\Release\net472 | .cto 重命名复制 |
| 包注册 | SSMSBoostPlus.SSMS.pkgdef | obj\Release\net472 | 包注册信息 |
| 第三方依赖 | 14+ DLL | bin\Release\net472 | NuGet 依赖 |

**部署目标目录**：
```
D:\Program Files\Microsoft SQL Server Management Studio 22\Release\Common7\IDE\Extensions\SSMSBoostPlus
```

#### SSMS 缓存清除（关键！）

| 缓存 | 路径 | 说明 |
|------|------|------|
| **privateregistry.bin** | `%LocalAppData%\Microsoft\VisualStudio\18.0_f46ef89a\` | **最关键！** 存储合并后的 pkgdef，SSMS 从此读取菜单定义 |
| ComponentModelCache | `%LocalAppData%\Microsoft\VisualStudio\18.0_f46ef89a\ComponentModelCache\` | MEF 组件缓存 |

```powershell
# 查找 SSMS 缓存目录（后缀可能不同）
$vsBase = "C:\Users\$env:USERNAME\AppData\Local\Microsoft\VisualStudio"
$cacheDir = Get-ChildItem $vsBase -Directory | Where-Object { $_.Name -like "18.0_*" } | Select-Object -First 1

# 备份并删除 privateregistry.bin
Copy-Item "$($cacheDir.FullName)\privateregistry.bin" "$($cacheDir.FullName)\privateregistry.bin.bak" -Force
Remove-Item "$($cacheDir.FullName)\privateregistry.bin" -Force

# 清除 ComponentModelCache
Remove-Item "$($cacheDir.FullName)\ComponentModelCache\*" -Recurse -Force -ErrorAction SilentlyContinue
```

#### 为什么必须清除 privateregistry.bin？

SSMS 启动流程：

```
SSMS.exe 启动
    ↓
读取 privateregistry.bin（缓存的合并 pkgdef）
    ↓ 如果缓存存在且有效
直接使用缓存的菜单定义 → 旧菜单（不含新命令！）
    ↓ 如果缓存不存在
扫描 Extensions 目录的所有 .pkgdef → 合并 → 重建 privateregistry.bin
    ↓
读取 DLL 嵌入的 Menus.ctmenu → 显示新菜单 ✅
```

**因此**：仅部署文件而不清除缓存，SSMS 仍会使用旧的缓存菜单定义。

## 完整部署脚本

使用 `deploy-current.bat`（管理员权限）或以下 PowerShell 脚本：

```powershell
# 完整部署脚本（保存为 deploy-temp.ps1 运行）
$SRC = "d:\172.31.1.44\AI\SSMSBoostPlus\src\SSMS\bin\Release\net472"
$OBJ = "d:\172.31.1.44\AI\SSMSBoostPlus\src\SSMS\obj\Release\net472"
$DST = "D:\Program Files\Microsoft SQL Server Management Studio 22\Release\Common7\IDE\Extensions\SSMSBoostPlus"

# 1. 检查 SSMS
if (Get-Process ssms -ErrorAction SilentlyContinue) { throw "SSMS 正在运行" }

# 2. 复制核心 DLL + PDB
@("SSMSBoostPlus.SSMS","SSMSBoostPlus.Core","SSMSBoostPlus.AI","SSMSBoostPlus.Shared") | % {
    Copy-Item "$SRC\$_.dll" "$DST\" -Force
    Copy-Item "$SRC\$_.pdb" "$DST\" -Force -ErrorAction SilentlyContinue
}

# 3. 复制 pkgdef + ctmenu（关键：cto → Menus.ctmenu 重命名）
Copy-Item "$OBJ\SSMSBoostPlus.SSMS.pkgdef" "$DST\" -Force
Copy-Item "$OBJ\SSMSBoostPlus.cto" "$DST\Menus.ctmenu" -Force

# 4. 复制第三方依赖
@("DiffPlex","Serilog","Serilog.Sinks.File","Serilog.Enrichers.Environment",
  "Microsoft.Data.SqlClient","Newtonsoft.Json","Microsoft.Bcl.AsyncInterfaces",
  "Microsoft.Extensions.Configuration","Microsoft.Extensions.Configuration.Json",
  "Microsoft.Extensions.Configuration.Binder","Microsoft.SqlServer.TransactSql.ScriptDom",
  "System.Net.Http","Markdig","Markdown.Xaml") | % {
    Copy-Item "$SRC\$_.dll" "$DST\" -Force -ErrorAction SilentlyContinue
}

# 5. WebView2 依赖
$wv2 = "$env:USERPROFILE\.nuget\packages\microsoft.web.webview2\1.0.2903.40"
@("lib\net462\Microsoft.Web.WebView2.Core.dll","lib\net462\Microsoft.Web.WebView2.Wpf.dll",
  "runtimes\win-x64\native\WebView2Loader.dll") | % {
    Copy-Item "$wv2\$_" "$DST\" -Force -ErrorAction SilentlyContinue
}

# 6. 清除 SSMS 缓存
$cacheDir = (Get-ChildItem "C:\Users\$env:USERNAME\AppData\Local\Microsoft\VisualStudio" -Directory |
    Where-Object { $_.Name -like "18.0_*" } | Select-Object -First 1).FullName
Copy-Item "$cacheDir\privateregistry.bin" "$cacheDir\privateregistry.bin.bak" -Force -ErrorAction SilentlyContinue
Remove-Item "$cacheDir\privateregistry.bin" -Force -ErrorAction SilentlyContinue
Remove-Item "$cacheDir\ComponentModelCache\*" -Recurse -Force -ErrorAction SilentlyContinue

# 7. 刷新配置标记
Set-Content "D:\Program Files\Microsoft SQL Server Management Studio 22\Release\Common7\IDE\Extensions\extensions.configurationchanged" "$(Get-Date)"

# 8. 验证
$asm = [System.Reflection.Assembly]::LoadFile("$DST\SSMSBoostPlus.SSMS.dll")
$res = $asm.GetManifestResourceNames()
Write-Host "DLL 嵌入资源: $($res -join ', ')"
Write-Host "Menus.ctmenu 文件: $(Get-Item "$DST\Menus.ctmenu").Length bytes"
Write-Host "请启动 SSMS 22 验证"
```

## 坑点总结

### 坑 1：VSSDK Pipeline 在 .NET SDK 10 下全面失败

| 失败的 VSSDK Target | 手动替代方案 |
|---------------------|-------------|
| `GeneratePkgDef` | `ManualPkgDef` target 调用 `CreatePkgDef.exe` CLI |
| `MergeCtoResource` | 静态 `ItemGroup` + 两次编译 |
| `CreateMenuPkgDef` | 禁用（仅用于强制刷新菜单缓存，不影响核心功能） |
| `PrepareForRunDependsOn` | 被 .NET SDK 10 覆盖，通过 AfterTargets 绕过 |

### 坑 2：Menus.ctmenu 嵌入资源时序问题

```
MSBuild 评估阶段 → 检查 ItemGroup Condition="Exists('.cto')" → .cto 不存在 → 跳过
              ↓
编译阶段 → ManualVSCTCompile → VSCT.exe 生成 .cto → 但 ItemGroup 已评估完毕
              ↓
结果：DLL 不含 Menus.ctmenu
```

**解决方案**：两次编译（第一次生成 .cto，第二次嵌入）

### 坑 3：privateregistry.bin 缓存

```
部署新 DLL + Menus.ctmenu → SSMS 启动 → 读取旧的 privateregistry.bin → 旧菜单
```

**解决方案**：每次部署后删除 `privateregistry.bin`

### 坑 4：.cto → Menus.ctmenu 重命名

部署脚本中必须将 `.cto` 文件**重命名**为 `Menus.ctmenu`：

```batch
copy /Y "%OBJ_DIR%\SSMSBoostPlus.cto" "%SSMS_EXT_DIR%\Menus.ctmenu"
```

文件名 `Menus.ctmenu` 必须与 `[ProvideMenuResource("Menus.ctmenu", 1)]` 特性匹配。
