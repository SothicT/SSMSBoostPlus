# SSMSBoostPlus — 基于 AI 大模型的 SSMS 智能增强扩展

> 本文档为四段式项目案例文案（背景 / 挑战 / 关键行动 / 结果），适用于对外宣传、售前展示或项目总结场景。

## 【背景】

SSMSBoostPlus 是面向 SQL Server 开发人员与 DBA 的 SSMS 22 扩展插件（VSIX），由 CodeBuddy AI Agent 全程驱动开发。项目以**版本管控**为核心抓手，内置「版本历史（Local History）」与「版本守卫」两大模块，把 DBA 原本只能从 DDL Trigger 散落记录中翻找的数据库对象变更，转变为可浏览、可对比、可恢复的完整时间线；同时规划 AI 增强能力，将数据库上下文（Schema、索引、执行计划）注入大模型，提升 SQL 审查与诊断效率。当前支持 SSMS 18 / 19 / 20 / 22，配套 103 个单元测试保障交付质量。

## 【挑战】

1. **数据库对象变更难以追溯**：生产环境虽有 DDL Trigger 持续记录每一次对象变更，但数据散落在历史表中，DBA 无法直观看到"谁在何时改了什么、改了哪几行、能否回滚"。
2. **已有数据未被工具化消费**：DDL Trigger 已长期运行并产生大量版本数据，却缺乏前端消费层，宝贵的数据资产沦为孤岛，价值未释放。
3. **多人协作缺乏版本冲突防护**：同一数据库对象被多人先后修改时，执行前无法感知"他人已改动"，极易引发覆盖事故。
4. **SQL 审查与格式化依赖人工**：安全审查、注释生成、代码格式化等重复性工作挤占核心开发精力，且质量因人而异。
5. **新版构建链路存在兼容性陷阱**：.NET SDK 10 与 VSSDK 17.14 的覆盖 Bug 导致原生 PkgDef 生成失效，扩展无法注册。

## 【关键行动】

1. **版本历史（Local History）模块 —— 零侵入消费已有数据**
   转变思路：从"造基础设施"变为"消费已有数据"。直接读取生产环境已运行的 DDL Trigger 记录（`MESBASE.dbo.DBTrigger_Object_Version_Table`），只读查询、零侵入，无需再建表建触发器。
   - **可停靠 ToolWindow 面板**：借鉴 IDE Local History（IntelliJ / VS Code）体验，打开面板即可看到所有对象的完整变更历史。
   - **脚本感知自动推断**：基于当前编辑窗口的 DDL 语句自动识别目标对象，并复用当前连接推导 MESBASE 连接串，无需用户配置。
   - **版本时间线**：DataGrid 按时间倒序展示，变更类型以彩色标签区分（CREATE 绿 / ALTER 橙 / DROP 红），并标注操作人与版本号。
   - **差异对比与一键恢复**：支持"与服务器当前定义对比"和"两个历史版本间对比"两种模式，生成回退脚本覆盖 ALTER / DROP / CREATE 三种场景，一键在编辑器打开审阅执行。
   - **窗口切换自动跟随**：监听 DTE 窗口激活事件实时刷新，支持钉住固定；数据库维度支持白名单隔离。
   - **与版本守卫联动**：版本守卫检测到外部修改时，一键跳转查看该对象的版本历史。

2. **版本守卫防冲突**：在执行 SQL 前（F5 自动拦截或手动触发）比对对象 `modify_date`，发现被他人修改即弹窗告警，支持强制审查与一键重载最新定义。

3. **AI 增强能力（开发中）**：规划 AI 智能建议、注释生成、代码格式化、性能分析与对话面板五大功能，将 Schema / 索引 / 执行计划注入提示词，结合差异预览与流式渲染给出精准 SQL 建议；当前仍在持续落地中。

4. **分层单向依赖架构**：Shared → Core → AI → SSMS 单向依赖链，严禁逆流与循环依赖，新增功能优先接口化以保证可测试性。

5. **绕过构建陷阱**：以 ManualPkgDef 机制作为永久方案绕过 VSSDK 覆盖 Bug，确保扩展稳定注册。

6. **质量门禁闭环**：以 xUnit + Moq + FluentAssertions 构建 103 个单元测试，提交前强制通过编译与测试门禁。

## 【结果】

1. **变更可追溯、可回滚**：版本历史模块已落地，所有数据库对象的 CREATE / ALTER / DROP 全程可视化，支持秒级差异对比与一键恢复，DBA 从"翻历史表"升级为"看时间线"。
2. **协作安全可控**：版本守卫在 F5 执行前自动拦截冲突，强制审查 + 一键重载降低多人协作覆盖事故风险。
3. **AI 能力稳步推进**：五大 AI 功能按规划逐步落地，数据库上下文注入机制已就绪，后续将持续增强 SQL 审查与诊断能力。
4. **工程质量达标**：103 个单元测试用例全部通过，编译与测试门禁 100% 覆盖，保障多版本交付稳定性。
5. **架构可持续**：单向分层 + 接口化设计使模块职责清晰，版本历史与 AI 层解耦，后续扩展无须重构核心链路。
