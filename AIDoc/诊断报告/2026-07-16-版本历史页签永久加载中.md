## 问题摘要

打开"版本历史"工具窗口后，面板永远停留在构造函数设置的占位文本 `正在加载版本历史...`，真正的版本历史控件 `_control` 从未被创建。根因不是异步初始化死锁，而是一个 **XAML 样式类型不匹配**：UI 里的 `ToggleButton`（钉住按钮 `PinButton`）引用了 `TargetType="Button"` 的样式 `ToolbarButton`，WPF 在 `InitializeComponent()` 加载 XAML 时直接抛出 `XamlParseException`，导致 `LocalHistoryToolWindowControl` 构造函数失败 → `EnsureControl()` 失败 → `_control` 永不创建 → 占位文本永久残留，且全程无错误提示。

## 根因分析

### 1. 触发异常的 XAML（核心缺陷）

`src/SSMS/UI/VersionHistory/LocalHistoryToolWindowControl.xaml:260-264`：

```xml
<ToggleButton x:Name="PinButton" Grid.Column="2"
              Content="📌"
              Style="{StaticResource ToolbarButton}"   <!-- ⚠️ 错：ToolbarButton 的 TargetType 是 Button -->
              ToolTip="钉住当前数据库（钉住后不受窗口切换影响）"
              Click="PinButton_Click"/>
```

而同文件 `ToolbarButton` 样式定义（第 43 行）为：

```xml
<Style x:Key="ToolbarButton" TargetType="Button"> ... </Style>
```

WPF 要求被设置 `Style` 的元素的类型必须 **是** `Style.TargetType` 或其派生类。`ToggleButton` 继承自 `ButtonBase`（→ `ContentControl`），**并不是** `Button` 的子类，因此 `CheckTargetType` 校验失败，抛出：

```
InvalidOperationException: “Button”TargetType 与元素“ToggleButton”的类型不匹配。
```

### 2. 异常在构造函数抛出，真控件永不创建

`LocalHistoryToolWindowControl.xaml.cs:52` 的 `InitializeComponent()` 解析上述 XAML 即抛异常，构造函数未执行完，`_control` 自然为 `null`。调用链 `LocalHistoryToolWindow.EnsureControl()`（行 212）依此失败，`InitializeContentAsync`（行 190）捕获异常仅记日志，占位文本不被替换 → 永久显示"正在加载版本历史..."。

### 3. 该错误是编译期不可见的运行时错误

`TargetType` 与元素类型不匹配只在 XAML **加载期**校验，MSBuild 的 XAML 编译（GenerateTemporaryTargetAssembly / MarkupCompilePass）对此不会报错，所以本地 `dotnet build` 能通过，但运行时必崩。这正是它"逃逸"到生产环境的原因。

### 4. 同类模式排查（无其它隐患）

- `LocalHistoryDiffDialog.xaml:151` 的 `SyncScrollButton` 也是 `ToggleButton`，但它**未引用任何 Button 样式**（用内联属性 `Background`/`BorderBrush`/`BorderThickness`），因此安全。
- 全项目搜索仅此一处 `ToggleButton` 引用了 `Button` 的 `StaticResource` 样式。

## 修复方案

### 方案一（推荐，最小化改动）：为 ToggleButton 增加匹配样式

保持 `PinButton` 的 `ToggleButton` 语义，新增一个 `TargetType="ToggleButton"` 的样式（视觉与 `ToolbarButton` 一致，并额外用 `IsChecked` 触发器提供选中态反馈），把 `PinButton` 的 `Style` 指向它。

```xml
<!-- 在 UserControl.Resources 的 ResourceDictionary 内，ToolbarButton 之后新增 -->
<Style x:Key="ToolbarToggleButton" TargetType="ToggleButton">
    <Setter Property="Height" Value="24"/>
    <Setter Property="FontSize" Value="11"/>
    <Setter Property="Background" Value="#F5F5F5"/>
    <Setter Property="BorderBrush" Value="#D0D0D0"/>
    <Setter Property="BorderThickness" Value="1"/>
    <Setter Property="Padding" Value="8,2"/>
    <Setter Property="Cursor" Value="Hand"/>
    <Setter Property="Template">
        <Setter.Value>
            <ControlTemplate TargetType="ToggleButton">
                <Border Background="{TemplateBinding Background}"
                        BorderBrush="{TemplateBinding BorderBrush}"
                        BorderThickness="{TemplateBinding BorderThickness}"
                        CornerRadius="3"
                        Padding="{TemplateBinding Padding}"
                        SnapsToDevicePixels="True">
                    <ContentPresenter HorizontalAlignment="Center" VerticalAlignment="Center"/>
                </Border>
                <ControlTemplate.Triggers>
                    <Trigger Property="IsMouseOver" Value="True">
                        <Setter Property="Background" Value="#E8E8E8"/>
                    </Trigger>
                    <Trigger Property="IsChecked" Value="True">
                        <Setter Property="Background" Value="#E67E22"/>
                        <Setter Property="Foreground" Value="White"/>
                    </Trigger>
                </ControlTemplate.Triggers>
            </ControlTemplate>
        </Setter.Value>
    </Setter>
</Style>
```

并将 `PinButton` 改为：

```xml
<ToggleButton x:Name="PinButton" Grid.Column="2"
              Content="📌"
              Style="{StaticResource ToolbarToggleButton}"
              ToolTip="钉住当前数据库（钉住后不受窗口切换影响）"
              Click="PinButton_Click"/>
```

仅 2 处小改动，修复类型不匹配，真控件即可正常创建，占位文本问题随之消失。

### 方案二（备选，改动更小但语义略变）：把 PinButton 改为 Button

`PinButton_Click` 不依赖 `IsChecked`，可直接把 `ToggleButton` 改为 `Button`（保留 `Style="{StaticResource ToolbarButton}"`）。改动仅 1 行，但会丢失"可按下"的视觉语义，不如方案一严谨。

## 边缘情况与异常处理

- `PinButton` 选中态：`IsChecked=True` 时由新增样式的 `Trigger` 高亮（橙底白字），与 `PinButton_Click` 里手动设 `PinButton.Background` 的橙底逻辑一致，无冲突。
- 若将来新增其它 `ToggleButton` 复用 `ToolbarButton` 样式：须引用新的 `ToolbarToggleButton`，避免复发同类 XAML 加载崩溃。
- 编译期无法捕获此类 `TargetType` 不匹配，建议在 Code Review / 构建脚本中增加"XAML 加载冒烟测试"（启动后实际打开一次 ToolWindow）以提前暴露。
