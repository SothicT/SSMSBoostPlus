## 1. 需求概述

### 1.1 业务背景

SQL Server 开发人员和 DBA 在日常工作中面临四大核心痛点：

1. **SQL 编写效率低下**：手动编写注释、格式化代码、分析性能问题耗费大量时间，且容易遗漏关键优化点。
2. **AI 工具与数据库上下文脱节**：通用 AI 编程助手（Copilot、ChatGPT）不理解当前数据库的 Schema、索引结构和执行计划，建议脱离实际，需大量人工修正。
3. **多人协作中的版本冲突风险**：多开发人员可能同时修改同一数据库对象，脚本引用的对象可能在编辑期间已被他人修改，导致上线后出现预期外行为。
4. **SSMS 原生能力不足**：SSMS 自带的 IntelliSense 和查询分析能力有限，缺乏智能化的 SQL 审查、优化建议和上下文感知的 AI 辅助。

**核心价值主张**：将数据库元数据（Schema、索引、执行计划）深度注入 AI 上下文，让 AI 真正"理解"数据库，提供精准、可落地的 SQL 分析和优化建议。

### 1.2 核心目标

| 目标维度 | 目标描述 | 可量化标准 |
|----------|----------|-----------|
| **效率提升** | 减少 SQL 编写与优化时间 | 用户平均 SQL 编写时间减少 30% 以上 |
| **质量提升** | 降低 SQL 性能问题与逻辑错误 | AI 建议采纳率 ≥ 60% |
| **协作安全** | 消除版本冲突导致的上线事故 | 版本冲突检出率 ≥ 95%，误报率 ≤ 5% |
| **用户满意度** | 成为 SQL Server 开发者的首选 AI 辅助工具 | NPS ≥ 40，月活跃用户留存率 ≥ 70% |
| **市场覆盖** | 在 SSMS 扩展生态中建立影响力 | VS Marketplace 安装量进入 SSMS 扩展前 10 |

### 1.3 适用角色

| 角色 | 技能水平 | 主要场景 | 使用频率 |
|------|----------|----------|----------|
| **SQL Server 开发人员**（主要用户） | 中级-高级 | 编写存储过程/函数/视图、优化慢查询、维护数据脚本 | 每天 10-50 次 AI 调用 |
| **数据库管理员 DBA** | 高级 | 监控数据库性能、审查 SQL、追踪对象变更、版本历史追溯 | 每天 5-20 次 AI 调用 + 5-10 次版本历史查询 |
| **数据分析人员**（次要用户） | 初级-中级 | 编写报表查询、数据提取脚本 | 每周 5-15 次 AI 调用 |

### 1.4 关联模块

| 模块 | 关系 | 说明 |
|------|------|------|
| `Shared` | 基础层 | 公共类型、工具、接口定义，被所有上层模块引用 |
| `Core` | 业务层 | 核心业务逻辑、数据库操作、SQL 解析、Diff 引擎、版本历史服务 |
| `AI` | 服务层 | AI 服务封装、Prompt 模板管理、Bridge 桥接 |
| `SSMS` | 表现层 | SSMS 集成、菜单命令、WPF UI、对话面板 |
| `Installer` | 部署层 | 独立命令行安装器 |

**依赖方向**：`Shared → Core → AI → SSMS`（单向，禁止逆流）

### 2.2 业务流转链路

```
用户操作 SSMS 编辑器
        │
        ├── 选中/未选中 SQL 代码
        │       │
        │       ├── 快捷键触发 AI 功能
        │       │       │
        │       │       ├── Ctrl+Shift+A → 收集数据库上下文 → 组装 Prompt → 调用 AI 后端 → 流式渲染建议 → Diff 对比 → 用户接受/拒绝
        │       │       ├── Ctrl+Shift+C → 组装 Prompt（comment 模板）→ 调用 AI 后端 → Diff 对比 → 用户接受/拒绝
        │       │       ├── Ctrl+Shift+F → 组装 Prompt（format 模板）→ 调用 AI 后端 → Diff 对比 → 用户接受/拒绝
        │       │       └── Ctrl+Shift+P → 获取执行计划 → 收集上下文 → 组装 Prompt → 调用 AI 后端 → 性能分析报告
        │       │
        │       └── Ctrl+Shift+K → 打开对话面板 → 加载 Schema 上下文 → 用户输入问题 → AI 流式回答
        │
        └── Ctrl+Shift+V / F5
                │
                ├── 解析脚本引用的数据库对象
                ├── 获取服务器上最新定义
                ├── DiffPlex 行级对比
                ├── 有差异 → 强制审查 → 二次校验 → 放行/阻止
                └── 无差异 → 直接放行

版本历史（菜单触发）
        │
        ├── 自动推断当前编辑器对象
        ├── 从 MESBASE.dbo.DBTrigger_Object_Version_Table 查询变更历史
        ├── 展示变更记录列表（序号、时间、变更类型、操作人、版本号）
        ├── 单击版本行 → 对比该版本与服务器当前定义
        ├── Ctrl+多选双击 → 对比两个历史版本间差异
        ├── 右键/按钮 → 版本回退（生成恢复脚本）
        └── 版本守卫联动 → VersionWarningDialog 一键跳转
```

```
SSMS 编辑器 ←→ SSMS 扩展层 ←→ Core 业务层 ←→ AI 服务层 ←→ AI 后端（CodeBuddy CLI / HTTP API）

     │                              │
     └── SQL 文本                    └── 数据库元数据（Schema、索引、统计信息、执行计划）
```

## 3. 详细功能需求（按模块拆分）

### 3.1 AI 智能建议（Ctrl+Shift+A）

#### 3.1.1 功能名称
AI 智能 SQL 优化建议

#### 3.1.2 功能描述
基于数据库上下文（Schema、索引、统计信息），对用户选中的 SQL 代码或全文进行智能分析，提出优化建议。是核心差异化功能，区别于通用 AI 工具的关键在于将数据库元数据深度注入 AI 上下文。

#### 3.1.3 触发条件
- 用户在 SSMS 查询编辑器中选中 SQL 代码或光标位于编辑器中
- 当前已连接数据库
- 按下 `Ctrl+Shift+A` 或通过右键菜单/工具栏触发

#### 3.1.4 前置条件
- 当前 SSMS 已连接 SQL Server 数据库
- AI 后端服务可用（CodeBuddy CLI 或 HTTP API）
- 数据库上下文已加载（首次使用自动加载）
- 需要数据库 VIEW DEFINITION 权限（获取 Schema）
- 需要数据库 VIEW DATABASE STATE 权限（获取统计信息）

#### 3.1.5 核心业务规则

**上下文收集规则**：
- 解析 SQL 中引用的表名、视图名、函数名
- 从数据库获取这些对象的 Schema（列名、数据类型、约束）
- 获取相关索引信息（名称、列、类型）
- 获取统计信息（如可用）
- 上下文大小控制在 AI 模型 Token 限制的 60% 以内，预留空间给 SQL 文本和 AI 回复
- 对于引用超过 20 个表的 SQL，仅注入最相关的 20 个表的 Schema（按 SQL 中出现的顺序优先）

**选中/未选中处理规则**：
- 有选中代码：仅分析选中部分
- 无选中代码：分析编辑器全文

**流式渲染规则**：
- 生成过程超过 5 秒时，以流式 Markdown 渲染方式逐步展示
- 展示进度指示器（状态栏"AI 分析中..."）
- 支持取消操作

**Diff 展示规则**：
- 建议中包含修改后 SQL 代码时，展示 Diff 对比视图
- 左侧原始代码，右侧 AI 建议代码
- 差异行高亮标注
- 操作按钮：「接受全部」「拒绝」「复制建议」

#### 3.1.6 页面/接口细则

**触发方式**：
- 快捷键：`Ctrl+Shift+A`
- 右键菜单：SQL 编辑器右键菜单项
- 工具栏：工具栏按钮

**结果展示**：
- 在 SSMS 内以停靠面板或弹出窗口展示
- 支持调整窗口大小
- 流式 Markdown 渲染（Markdig + Markdown.Xaml）

**Prompt 模板**：使用 `analyze` 模板，注入数据库上下文信息

#### 3.1.7 数据校验规则

| 校验项 | 规则 | 异常处理 |
|--------|------|----------|
| 数据库连接状态 | 必须已连接 | 提示"请先连接数据库"，阻止操作 |
| 编辑器内容 | 编辑器不能为空 | 提示"请输入 SQL 代码后再进行分析" |
| SQL 语法 | 语法严重错误时 | 提示"SQL 语法可能有误，AI 分析可能不准确，是否继续？" |
| Token 限制 | 上下文 + SQL 不超过 Token 限制 | 提示"SQL 过长，超出 AI 分析限制，请缩小选中范围" |
| 表数量 | 超过 20 个表时仅注入 Top 20 | 静默处理，注入最相关表 |
| 上下文加载 | 加载失败时降级 | 提示"无法获取数据库上下文，将以无上下文模式分析" |

#### 3.1.8 异常处理机制

| 异常场景 | 严重程度 | 处理方式 | 用户操作 |
|----------|----------|----------|----------|
| 数据库未连接 | 阻断 | 提示"请先连接数据库"，阻止操作 | 连接数据库后重试 |
| 数据库上下文加载失败 | 降级 | 提示并降级为无上下文模式分析 | 继续分析或重试 |
| SQL 解析失败（语法错误） | 警告 | 提示可能不准确，询问是否继续 | 确认继续或取消 |
| AI 后端不可用 | 阻断 | 提示"AI 服务不可用，请检查 CodeBuddy 配置"，显示错误详情 | 检查配置后重试 |
| AI 请求超时（60s） | 阻断 | 提示"AI 分析超时，请重试或简化 SQL"，提供重试按钮 | 重试或简化 SQL |
| AI 返回空响应 | 阻断 | 提示"AI 未返回有效建议，请重试" | 重试 |
| Token 超出限制 | 阻断 | 提示缩小选中范围 | 缩小选中范围后重试 |
| 选中内容为空且编辑器为空 | 阻断 | 提示"请输入 SQL 代码后再进行分析" | 输入 SQL 后重试 |

### 3.2 AI 添加注释（Ctrl+Shift+C）

#### 3.2.1 功能名称
AI 自动添加注释

#### 3.2.2 功能描述
自动分析 SQL 逻辑，生成中文注释，包括步骤说明、复杂逻辑解释、业务含义推断。支持保留已有注释，仅补充缺失部分。

#### 3.2.3 触发条件
- 用户在 SSMS 查询编辑器中选中 SQL 代码或光标位于编辑器中
- 按下 `Ctrl+Shift+C` 或通过右键菜单触发

#### 3.2.4 前置条件
- 编辑器中有 SQL 代码
- AI 后端服务可用

#### 3.2.5 核心业务规则

**注释生成规则**：
- 注释语言：中文
- 注释位置：关键步骤前、复杂逻辑处、存储过程/函数头部
- 注释风格：行内注释（`-- 注释内容`）或块注释（`/* 注释内容 */`）
- 不注释的内容：显而易见的简单语句（如 `SET NOCOUNT ON`）

**已有注释处理规则**：
- AI 应保留已有注释，仅补充缺失部分
- 如注释已较完整，提示"代码注释已较完整，无需补充"

**存储过程/函数注释规则**：
- 必须包含参数说明、返回值说明、主要逻辑步骤

**选中/未选中处理规则**：
- 有选中代码：仅注释选中部分
- 无选中代码：注释全文

#### 3.2.6 页面/接口细则

**结果展示**：
- Diff 对比视图，左侧原始代码，右侧带注释代码
- 操作按钮：「接受全部」「拒绝」「复制」

**Prompt 模板**：使用 `comment` 模板

#### 3.2.7 数据校验规则

| 校验项 | 规则 | 异常处理 |
|--------|------|----------|
| 编辑器内容 | 不能为空 | 提示"请输入 SQL 代码后再添加注释" |
| 注释完整性 | 已有注释较完整时 | 提示"代码注释已较完整，无需补充" |
| SQL 长度 | 极短 SQL（如单行 SELECT） | 正常生成注释，但提示"简单查询可能无需注释" |

#### 3.2.8 异常处理机制

| 异常场景 | 处理方式 |
|----------|----------|
| 编辑器为空 | 提示"请输入 SQL 代码后再添加注释" |
| AI 后端不可用 | 提示"AI 服务不可用，请检查配置" |
| 已有注释的 SQL | AI 保留已有注释，仅补充缺失部分；如注释已完整，提示无需补充 |
| SQL 极短 | 正常生成注释，但提示"简单查询可能无需注释" |

### 3.3 AI 格式化代码（Ctrl+Shift+F）

#### 3.3.1 功能名称
AI 智能格式化代码

#### 3.3.2 功能描述
智能格式化 SQL 语句，统一代码风格，包括关键字大小写、缩进、换行等。格式化不改变 SQL 语义。

#### 3.3.3 触发条件
- 用户在 SSMS 查询编辑器中选中 SQL 代码或光标位于编辑器中
- 按下 `Ctrl+Shift+F` 或通过右键菜单触发

#### 3.3.4 前置条件
- 编辑器中有 SQL 代码
- AI 后端服务可用

#### 3.3.5 核心业务规则

**默认格式化规则**：
- 关键字：大写（UPPER）
- 缩进：4 空格
- SELECT 列：每列一行
- JOIN：独立一行，缩进对齐
- WHERE 条件：每个 AND/OR 换行
- 嵌套子查询：每层缩进 2 或 4 个空格（可配置）
- CTE 的每个子句应独立成行并正确缩进

**语义不变规则**：
- 格式化不应改变 SQL 语义
- 字符串字面量内的内容保持不变
- 方括号引用 `[object]` 保持不变

**无变化规则**：
- 格式化后无变化时，提示"代码已符合格式规范，无需调整"

#### 3.3.6 页面/接口细则

**结果展示**：
- Diff 对比视图，左侧原始代码，右侧格式化后代码
- 操作按钮：「接受全部」「拒绝」

**Prompt 模板**：使用 `format` 模板

#### 3.3.7 数据校验规则

| 校验项 | 规则 | 异常处理 |
|--------|------|----------|
| 编辑器内容 | 不能为空 | 提示"请输入 SQL 代码后再格式化" |
| SQL 语法 | 语法错误时 | 提示"SQL 语法可能有误，格式化结果可能不准确" |
| 格式化结果 | 无变化时 | 提示"代码已符合格式规范，无需调整" |

#### 3.3.8 异常处理机制

| 异常场景 | 处理方式 |
|----------|----------|
| 编辑器为空 | 提示"请输入 SQL 代码后再格式化" |
| SQL 语法错误 | 提示"SQL 语法可能有误，格式化结果可能不准确" |
| 格式化后无变化 | 提示"代码已符合格式规范，无需调整" |

### 3.4 AI 性能分析（Ctrl+Shift+P）

#### 3.4.1 功能名称
AI 性能分析（结合执行计划）

#### 3.4.2 功能描述
结合 SQL 执行计划（Actual/Estimated Execution Plan），分析性能瓶颈并给出优化方案。分析报告包含瓶颈定位、影响程度评估、具体优化建议（含可执行的 DDL 语句）、预估优化效果。

#### 3.4.3 触发条件
- 用户在编辑器中选中 SQL 代码
- 已获取该 SQL 的执行计划
- 按下 `Ctrl+Shift+P`

#### 3.4.4 前置条件
- 当前 SSMS 已连接 SQL Server 数据库
- 已执行查询并包含实际执行计划（或已获取预估执行计划）
- 执行计划 XML 可获取

#### 3.4.5 核心业务规则

**执行计划处理规则**：
- 优先使用实际执行计划（Actual Execution Plan）
- 如仅获取预估执行计划，标注"基于预估执行计划分析，实际执行计划可能不同"
- 执行计划 XML 过大（>5MB）时，自动裁剪非关键信息（如极低成本的子操作），保留 Top 20 高成本操作
- 多语句 SQL 时，对每个语句的执行计划分别分析

**分析报告结构规则**：
- 瓶颈总览 → 逐项分析 → 优化建议（含 DDL） → 预估效果
- 瓶颈标注：严重（红色）、警告（橙色）、提示（蓝色）
- 按成本从高到低排序，逐一分析每个瓶颈

**优化建议规则**：
- 包含可直接执行的 DDL 语句（如 CREATE INDEX）
- 指明具体瓶颈类型（全表扫描、Key Lookup、排序溢出等）

#### 3.4.6 页面/接口细则

**结果展示**：
- 流式 Markdown 渲染分析报告
- 分析报告结构：瓶颈总览 → 逐项分析 → 优化建议 → 预估效果

**Prompt 模板**：使用 `analyze` 模板，重点注入执行计划信息

#### 3.4.7 数据校验规则

| 校验项 | 规则 | 异常处理 |
|--------|------|----------|

### 3.6 版本守卫（Ctrl+Shift+V）

#### 3.6.1 功能名称
版本守卫

#### 3.6.2 功能描述
检测脚本引用的数据库对象自编辑后是否已被他人修改，防止版本冲突。包含差异检测、强制审查、二次校验三个子功能。

#### 3.6.3 触发条件
- 用户在编辑器中打开 SQL 脚本
- 按下 `Ctrl+Shift+V`（手动触发）
- 或按 `F5` 执行前自动拦截触发

#### 3.6.4 前置条件
- 当前 SSMS 已连接 SQL Server 数据库
- 脚本中引用了数据库对象（表、视图、存储过程、函数等）

#### 3.6.5 核心业务规则

**差异检测规则**：
- 解析脚本，提取引用的数据库对象
- 对每个对象，获取服务器上的当前定义
- 使用 DiffPlex 引擎进行行级差异对比
- 分类为：一致 / 新增 / 删减 / 有冲突 / 对象不存在
- 无差异时显示"所有对象均为最新版本"

**强制审查规则**：
- 检测到差异时，拦截脚本执行
- 弹出差异审查窗口，用户必须确认已审查所有差异后才能继续执行
- 审查日志记录：审查时间、审查人、差异摘要
- 支持取消执行，返回编辑器修改脚本

**二次校验规则**：
- 用户审查差异后确认执行前，自动进行二次校验
- 确认对象定义在审查期间未发生变化
- 如发现新变更，重新展示差异并要求用户再次审查
- 如未发现新变更，直接放行执行，不额外打断用户

**跳过令牌规则**：
- 脚本中添加 `--version-guard-skip` 注释可跳过检查
- 可在 `appsettings.json` 中配置跳过令牌列表

**对象数量处理规则**：
- 引用 10 个以上对象时，以列表形式展示，差异对象优先排列
- 超过 50 个对象时，分批检查，显示进度条

#### 3.6.6 页面/接口细则

**差异展示**：
- 列表视图，每个对象一行，差异对象高亮
- 差异详情：点击对象展开 DiffPlex 对比视图

**操作按钮**：
- 「标记已审查」
- 「继续执行」
- 「取消执行」
- 「重载对象定义」

**配置项**（`appsettings.json`）：

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `VersionGuard.Enabled` | bool | true | 是否启用版本守卫 |
| `VersionGuard.SkipTokens` | string[] | ["--version-guard-skip"] | 跳过检查的标记列表 |
| `VersionGuard.ExcludedDatabases` | string[] | [] | 排除检查的数据库列表 |
| `VersionGuard.ExcludedObjects` | string[] | [] | 排除检查的对象列表 |
| `VersionGuard.BypassOnNoDiff` | bool | true | 无差异时是否自动跳过 |

#### 3.6.7 数据校验规则

| 校验项 | 规则 | 异常处理 |
|--------|------|----------|
| 数据库连接 | 必须已连接 | 提示"请先连接数据库" |
| 脚本对象引用 | 必须引用数据库对象 | 提示"未检测到数据库对象引用" |
| 对象存在性 | 对象已被删除 | 标注"对象已不存在"，红色警告 |
| 对象数量 | >50 时 | 分批检查，显示进度条 |
| 跳过令牌 | 脚本含 `--version-guard-skip` | 跳过检查 |

#### 3.6.8 异常处理机制

| 异常场景 | 处理方式 |
|----------|----------|
| 数据库未连接 | 提示"请先连接数据库" |
| 对象已被删除 | 标注"对象已不存在"，红色警告 |
| 脚本中无数据库对象引用 | 提示"未检测到数据库对象引用" |
| 对象数量过多（>50） | 分批检查，显示进度条 |
| 二次校验发现新变更 | 重新展示差异，要求再次审查 |

### 3.7 版本历史（菜单触发）

#### 3.7.1 功能名称
版本历史管控

#### 3.7.2 功能描述
版本历史（LocalHistory）是 SSMSBoostPlus 的代码管控功能，通过查询 DDL Trigger 自动记录的数据库对象变更历史表，提供变更记录浏览、差异比对、版本回退、以及与版本守卫联动等功能。帮助 DBA 和开发人员追溯数据库对象的完整变更轨迹，了解"谁、何时、改了什么"。

#### 3.7.3 触发条件
- 用户点击菜单"版本历史"或使用快捷键
- 版本守卫警告窗口（VersionWarningDialog）中点击"查看版本历史"按钮
- 首次打开时自动推断当前 SSMS 编辑器的数据库对象

#### 3.7.4 前置条件
- 当前 SSMS 已连接 SQL Server 数据库
- 数据库中存在版本历史表（`MESBASE.dbo.DBTrigger_Object_Version_Table`），由 DDL Trigger 自动填充
- 版本历史服务可用（`IVersionHistoryService`）
- 需要 `MESBASE` 数据库的查询权限
- 需要目标数据库的 VIEW DEFINITION 权限（获取服务器当前定义）

#### 3.7.5 核心业务规则

**变更记录浏览规则**：

- **自动推断**：打开面板时，系统自动从 SSMS 活动窗口获取连接信息，替换数据库为 `MESBASE`，并解析当前编辑器 SQL 提取 CREATE/ALTER 定义的对象名
- **搜索过滤**：用户在搜索框（可编辑 ComboBox）中输入关键字，300ms 防抖后从数据库模糊搜索匹配的对象，显示 Top 100 结果，含对象类型标签和版本数量
- **窗口切换跟随**：用户切换 SSMS 文档窗口时，300ms 防抖后版本历史面板自动跟随切换，刷新到新窗口的对象历史
- **钉住**：用户点击"钉住"按钮后，面板不再跟随窗口切换，保持当前对象的历史记录不变
- **列表展示**：DataGrid 展示每条记录，列包括：数据库名、序号、时间、变更类型（彩色标签：CREATE=绿/ALTER=蓝/DROP=红）、操作人、版本号
- **数据库过滤**：通过数据库下拉框过滤版本记录，数据库列表缓存 5 分钟，避免频繁查询 `sys.databases`
- **状态栏**：显示服务器名称（悬浮提示：服务器地址+连接用户）、数据库下拉框、钉住按钮、同步连接按钮、连接状态标签、刷新按钮

**差异比对规则**：

- **历史版本 vs 服务器当前定义**：用户单击版本列表中的某一行，系统自动对比该历史版本与服务器当前定义，展示并排差异视图
- **两个历史版本间对比**：用户 Ctrl+多选两行后双击，系统对比两个历史版本之间的差异，展示并排差异视图
- **DiffPlex 引擎渲染**：左右并排 RichTextBox，差异行高亮标注（新增=绿色、删除=红色、修改=黄色），支持子词级高亮
- **同步滚动**：左右面板默认同步滚动，用户可切换为独立滚动模式
- **服务器定义加载失败**：左侧面板显示错误遮罩和重试按钮

**版本回退规则**：

- **在编辑器中打开**：点击"在编辑器中打开"按钮，将历史脚本写入新的 SSMS 编辑器窗口，用户可审查后手动执行
- **ALTER 恢复**：当前记录的变更类型为 ALTER 时，直接返回该历史版本的 ALTER 语句
- **CREATE 恢复**：当前记录的变更类型为 CREATE 时，将 CREATE 语句转换为 ALTER 语句
- **DROP 恢复**：当前记录的变更类型为 DROP 时，查找上一条非 DROP 记录，将其 ALTER 转换为 CREATE 语句以重建对象

**与版本守卫联动规则**：

- 版本守卫（F5 执行时）实时比对 `sys.objects.modify_date`，检测"是否有人改了"
- 版本历史查询历史版本表，展示"谁、何时、改了什么"
- 版本守卫检测到过时对象时弹出 VersionWarningDialog，其中有"查看版本历史"按钮
- 点击该按钮，系统自动打开版本历史面板，传入对象名和数据库过滤，面板搜索框自动填入对象名，数据库下拉框过滤到对应数据库

**配置管理规则**：

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `LocalHistoryConfig.Enabled` | bool | true | 是否启用版本历史功能 |
| `LocalHistoryConfig.TableName` | string | DBTrigger_Object_Version_Table | 版本历史表名 |
| `LocalHistoryConfig.DatabaseName` | string | MESBASE | 版本历史表所在数据库 |
| `LocalHistoryConfig.MaxVersionsToLoad` | int | 100 | 最大加载版本数 |
| `LocalHistoryConfig.AutoOpenOnExternalChange` | bool | false | 外部变更时是否自动打开 |
| `LocalHistoryConfig.AutoFollowEnabled` | bool | true | 是否自动跟随窗口切换 |
| `LocalHistoryConfig.DebounceMs` | int | 300 | 搜索/窗口切换防抖毫秒数 |
| `LocalHistoryConfig.AllowedDatabases` | string[] | [] | 允许查看历史的数据库白名单，空=全部允许 |
| `LocalHistoryConfig.DatabaseListCacheMinutes` | int | 5 | 数据库列表缓存时间（分钟） |

#### 3.7.6 页面/接口细则

**面板布局**：
- 搜索框 + 数据库下拉框 + DataGrid（版本列表） + 状态栏
- 搜索框：可编辑 ComboBox，支持模糊搜索 + 300ms 防抖，下拉列表显示对象类型标签和版本数量

#### 3.7.7 数据校验规则

| 校验项 | 规则 | 异常处理 |

| AI 性能分析 | VIEW DEFINITION + VIEW DATABASE STATE | 仅分析执行计划，无 Schema 上下文 |
| AI 对话面板 | VIEW DEFINITION | 可进行通用问答，无 Schema 上下文 |
| 版本守卫 | VIEW DEFINITION | 无法获取对象定义，提示权限不足 |
| 版本历史 | MESBASE 查询权限 + VIEW DEFINITION | 无法查询版本历史表，提示"版本历史表未配置"或"权限不足" |

### 4.3 无权限交互规则

- 权限不足时，不阻断功能使用，而是降级提供有限服务
- 明确告知用户当前权限缺失及其影响范围
- 提供权限申请指引（如"请联系 DBA 授予 VIEW DEFINITION 权限"）

## 7. 研发注意事项与风险提示

### 7.1 易错逻辑

| 编号 | 易错点 | 说明 | 建议 |
|------|--------|------|------|
| R-001 | 上下文注入 Token 计算 | 注入的 Schema 信息可能远超 Token 限制，导致 AI 请求失败 | 严格控制在 Token 限制的 60% 以内，超过 20 表时仅注入 Top 20 |
| R-002 | 执行计划 XML 大小 | 复杂查询的执行计划 XML 可能超过 5MB，需裁剪处理 | 实现自动裁剪逻辑，保留 Top 20 高成本操作 |
| R-003 | 版本守卫二次校验竞态 | 审查到执行之间存在时间窗口，可能被其他用户修改 | 必须实现二次校验机制，已记录在 `2026-07-02-VersionWarningDialog二次校验竞态条件优化方案.md` |
| R-004 | Diff 视图滚动同步 | 双栏 Diff 视图的滚动不同步，用户体验差 | 已修复（UP-009），需确保新代码不回归此问题 |
| R-005 | 窗口切换时数据库上下文 | 窗口切换时数据库未跟随切换，导致上下文不一致 | 已修复（UP-011），需确保事件绑定正确 |
| R-006 | PkgDef 生成机制 | .NET SDK 10 与 VSSDK 17.14 的兼容性问题，需手动生成 PkgDef | 使用 ManualPkgDef Target，不要尝试"修复"回 VSSDK 原生方式 |
| R-007 | SSMS 内部 DLL 引用 | SSMS 内部 DLL 在不同版本间可能变化，需动态加载 | 使用 SmartAssemblyLoader 动态加载，编译时仅引用稳定 API |
| R-008 | 版本历史连接串推导 | 从 SSMS 活动窗口推导连接信息并替换数据库为 MESBASE 时，连接串可能格式不兼容 | 实现健壮的连接串解析器，覆盖多种连接串格式，失败时回退到手动输入 |
| R-009 | 版本历史 DROP 回退边界 | DROP 回退时查找上一条非 DROP 记录，如果该对象只有一条 DROP 记录（无历史）则无法回退 | 必须检查非 DROP 记录是否存在，不存在时提示"无法回退：未找到可恢复的历史版本" |
| R-010 | 版本历史窗口切换竞态 | 快速切换窗口时，前一个异步加载请求可能在后一个请求完成之后返回，导致显示错误数据 | 使用 CancellationToken 取消前一个请求，或使用版本号/时间戳校验结果有效性 |

### 7.2 易遗漏场景

| 编号 | 遗漏场景 | 影响 | 检查点 |
|------|----------|------|--------|
