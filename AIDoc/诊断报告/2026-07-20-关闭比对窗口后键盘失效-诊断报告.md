## 现象

比对窗口可以正常打开了，但关闭比对窗口后，SSMS SQL 编辑器中的 Backspace 和 Enter 键等部分键盘按键失效。

## 复现路径

双击历史版本行 → 比对弹窗弹出（正常）→ 点击"关闭"或"在编辑器中打开"关闭弹窗 → 焦点回到 SSMS SQL 编辑器后，Backspace、Enter 等键无响应。

## 日志证据

日志文件：`ssmsboostplus-2026072019.log`

```
19:05:23.807 [INF] [LocalHistory] 历史版本脚本已在编辑器中打开
19:05:23.876 [DBG] [LocalHistory] WindowActivated: gotFocus.Kind=Tool, lostFocus.Kind=Document
19:05:23.876 [DBG] [LocalHistory] WindowActivated: 非文档窗口 (Kind=Tool)，跳过刷新
```

时间线：用户点击"在编辑器中打开"（19:05:23.807）→ diff 对话框关闭 → 焦点回到 LocalHistory ToolWindow（19:05:23.876，Kind=Tool），而非 SSMS SQL 编辑器（Kind=Document）。键盘事件被发送到了 ToolWindow 而非 SQL 编辑器，导致编辑器内的 Backspace/Enter 失效。

## 根因分析

### 直接原因

`LocalHistoryDiffDialog` 的 `Owner` 为 `null`，导致 `ShowDialog()` 关闭后键盘焦点无法正确返回 SSMS SQL 编辑器。

关键代码（`LocalHistoryToolWindowControl.xaml.cs` 行 790-791）：

```csharp
diffDialog.Owner = System.Windows.Window.GetWindow(this);
diffDialog.ShowDialog();
```

`this` 是 `LocalHistoryToolWindowControl`（WPF UserControl），它被宿主在 `LocalHistoryToolWindow`（VS SDK ToolWindowPane）中，而 ToolWindowPane 又内嵌于 SSMS Win32 主窗口。UserControl → ToolWindowPane → Win32 Shell 这条链路上根本没有 WPF `Window` 对象，因此 `Window.GetWindow(this)` 返回 `null`。

### 机制解释

WPF `ShowDialog()` 的行为取决于 `Owner`：

- **Owner 非 null**（标准 WPF 应用）：WPF 将对话框模态化到指定 Owner 上。对话框关闭后，WPF 自动将焦点恢复到 Owner 窗口。
- **Owner = null**（当前情况）：WPF 创建一个隐藏的临时窗口作为 Owner，对话框模态化到这个临时窗口。对话框关闭时，临时窗口被销毁，但焦点恢复逻辑缺乏明确目标，导致焦点回到上一个处于活动状态的窗口——本例中为 LocalHistory ToolWindow（因为用户在打开 Dialog 之前最后操作的就是 ToolWindow 中的双击）。

在 SSMS 这类 Win32 原生 + WPF 混搭的环境中，Win32 的键盘消息路由与 WPF 模态机制之间存在间隙。焦点虽然看似回到了 SSMS 窗口，但实际键盘事件被 WPF 的 ToolWindow 吞掉了（ToolWindow 中没有处理 Backspace/Enter 的逻辑），SQL 编辑器收不到这些按键。

### 为什么之前没发现

之前（7/17 和本轮修复前），比对弹窗根本打不开，所以不会触发关闭后的键盘问题。这个 Bug 是前两个弹窗构造 Bug 的"下游连锁问题"——每个修复揭露下一层问题。

## 修复方案

修改 `LocalHistoryToolWindowControl.xaml.cs` 的 `OpenDiffDialogAsync` 方法（约行 790-791），在 `ShowDialog()` 之后显式将焦点恢复到 SSMS SQL 编辑器。

具体改动：

**行 790-791，将**：
```csharp
diffDialog.Owner = System.Windows.Window.GetWindow(this);
diffDialog.ShowDialog();
```

**改为**：
```csharp
diffDialog.Owner = System.Windows.Window.GetWindow(this);
diffDialog.ShowDialog();

// 修复：ShowDialog 关闭后，SSMS Win32/WPF 混搭环境下 Owner=null 时焦点不会自动回到
// SQL 编辑器。通过 DTE 显式激活 SSMS 主窗口，确保键盘事件正确路由到 SQL 编辑器。
try
{
    var dte = Microsoft.VisualStudio.Shell.Package.GetGlobalService(typeof(EnvDTE.DTE)) as EnvDTE.DTE;
    dte?.MainWindow?.Activate();
}
catch
{
    // 激活主窗口失败非致命错误，不做额外处理
}
```

仅此一处修改，无 XAML 变更。

## 边缘情况与异常处理

- DTE 为 null（极端情况）：`?.` 安全导航，不抛异常
- MainWindow.Activate() 失败（COM 异常）：catch 静默吞掉，不影响已有功能
- "关闭"按钮 vs "在编辑器中打开"按钮：两种关闭方式都会经过 `ShowDialog()` 返回点，统一修复
- ToolWindow 仍保持功能正常：焦点被显式拉回 SSMS 主窗口后，ToolWindow 的数据刷新等通过 DTE 事件驱动，不受影响

## 结论

这是 WPF-Win32 混合环境下的经典焦点问题。SSMS 的 ToolWindow 不是标准 WPF Window，`Window.GetWindow` 返回 null，导致 `ShowDialog()` 关闭后无法正确恢复键盘焦点到 SQL 编辑器。通过在 `ShowDialog()` 返回后调用 DTE `MainWindow.Activate()` 显式恢复焦点，即可解决问题。
