# 版本差异页显示与性能优化 竞品分析（显示与性能）

## 1. 分析目的与范围

针对「长文本差异对比的显示策略（换行/横滚）」与「大数据量性能处理」两项能力，对标主流 SQL / 文本对比工具，提炼最佳实践，为本需求的方案取舍提供依据。时间范围：2026 年。

## 2. 竞品筛选

- 直接竞品（SQL 对比）：Redgate SQL Compare、ApexSQL Diff、dbForge Schema Compare for SQL Server
- 间接竞品（通用文本/代码对比）：VS Code、Beyond Compare、WinMerge
- 替代品：Git 命令行 diff、GitHub / GitLab Web Diff

## 3. 功能矩阵对比

| 竞品 | 自动换行 | 横向滚动 | 大文件虚拟化/流式 | 行内差异着色 |
|------|----------|----------|------------------|--------------|
| Redgate SQL Compare | 支持（脚本视图） | 支持 | 是 | 是 |
| ApexSQL Diff | 支持 | 支持 | 是 | 是 |
| dbForge Schema Compare | 支持 | 支持 | 是 | 是 |
| VS Code | 可配（wordWrap） | 支持 | 是（虚拟滚动） | 是 |
| Beyond Compare | 支持（视图-换行） | 支持 | 流式加载 | 是 |
| WinMerge | 支持 | 支持 | 是 | 是 |
| Git 命令行 diff | 默认不换行 | 支持（终端横滚） | 流式 | 否（纯文本） |

## 4. 核心功能深度对比

### 4.1 显示策略（换行 vs 横滚）

- VS Code：通过 `editor.wordWrap`（off / on）配置，默认不换行但横向滚动流畅；大文件虚拟滚动，切换无卡顿。
- Beyond Compare：文本对比支持「View > Wrap」一键切换换行，大文件流式加载。
- Redgate / ApexSQL / dbForge：脚本视图均提供换行与横向滚动切换，作为 SQL 差异展示的标配。
- 共性结论：**「换行/横滚可切换」是主流差异对比工具的基准体验**，默认策略各产品不同（代码类默认不换行+横滚，文本类倾向可换行）。

### 4.2 性能处理手段

- VS Code / WinMerge / Beyond Compare：采用 UI 虚拟化（仅布局与渲染可见区域行），流式或分块加载，大文件（数万行）滚动流畅、打开快。
- 共性结论：**不一次性构建全量文档对象、按需布局**是大文件流畅的关键；一次性全量构建（如本产品当前 FlowDocument 逐行 Paragraph）是性能瓶颈典型成因。

## 5. 用户体验对比

- 共同点：换行/横滚切换是标配；大文件流畅是用户预期底线。
- 差异点：专业 SQL 工具额外提供「对象级」对比视图，文本/脚本对比作为补充；本产品聚焦脚本级 diff，需在脚本视图达到近似体验即可。

## 6. 商业模式对比

- Redgate / ApexSQL / dbForge：商业授权（按席位/年）。
- VS Code：免费开源；Beyond Compare / WinMerge：免费或一次性买断。
- 对本产品的启示：作为 SSMS 免费增强插件，应以「补齐主流标配体验」为目标，而非功能堆砌。

## 7. SWOT 分析（针对我们当前差距）

- 优势：已具备行内逐字符 diff 着色、差异点导航、同步滚动，基础能力完整。
- 劣势：当前 FlowDocument 无 UI 虚拟化、无横滚/换行切换，大数据量卡顿。
- 机会：通过「换行切换 + 虚拟化/异步渲染」即可接近主流体验，投入可控。
- 威胁：若性能选型不当（引入重型依赖）会加大包体积与 net472 兼容风险。

## 8. 差异化策略建议

- 必做：提供「换行/横滚」切换开关，对齐主流标配（默认自动换行，符合用户决策）。
- 性能：采用 UI 虚拟化或异步 + 增量渲染，避免一次性构建全量文档（对齐 VS Code 等做法）。
- 约束优先：优先不引入重型第三方编辑器依赖，控制包体积与 net472 兼容性；若评估必要，再考虑轻量控件（如 AvalonEdit）并验证依赖成本。

## 9. 结论与行动建议

- 结论：本需求是「补齐主流差异对比标配体验」，技术风险集中在性能实现选型，显示部分低成本可达成。
- 行动建议：
  1. 显示：换行/横滚切换开关，默认自动换行（已与用户确认）。
  2. 性能：以「5000 行 < 1 秒」为硬指标，由 Architect 评估「FlowDocument 优化 vs 轻量虚拟化控件」方案。
  3. 验收：以 PRD 的 AC-1~AC-7 为验收清单。
