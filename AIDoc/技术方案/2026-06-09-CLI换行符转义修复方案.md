# CLI Prompt 换行符转义修复方案

**创建日期**: 2026-06-09
**状态**: ✅ 已完成
**优先级**: 高

---

## 1. 问题描述

### 问题现象
通过 CodeBuddy CLI 方式与 AI 交互时，如果 SQL 代码包含多行换行符，可能导致 Prompt 被截断，AI 收到的提示词不完整。

### 根本原因
`StringExtensions.EscapeForCli()` 方法仅转义了双引号，未处理换行符：
```csharp
// 当前实现
return input.Replace("\"", "\\\"");
```

当 Prompt 包含换行符 `\n` 时，在命令行参数中被当作空白分隔符处理，导致后续内容丢失或格式错乱。

---

## 2. 修复方案

### 方案选择：增强转义方法（推荐）

**理由**：
- 改动最小，不影响现有调用方式
- 解决核心问题：换行符和特殊字符的 CLI 传递
- 保持向后兼容

### 具体修改

#### 2.1 修改文件：`src/Shared/Extensions/StringExtensions.cs`

**修改前**：
```csharp
public static string EscapeForCli(this string input)
{
    if (string.IsNullOrEmpty(input))
        return input;

    return input.Replace("\"", "\\\"");
}
```

**修改后**：
```csharp
public static string EscapeForCli(this string input)
{
    if (string.IsNullOrEmpty(input))
        return input;

    // 转义顺序很重要：先处理反斜杠，再处理换行符，最后处理双引号
    // 1. 反斜杠必须最先转义（避免二次转义）
    // 2. 换行符 → \n（Windows 兼容 CRLF 和 LF）
    // 3. 制表符 → \t
    // 4. 双引号 → \"
    var escaped = input
        .Replace("\\", "\\\\")      // 反斜杠转义（必须最先）
        .Replace("\r\n", "\\n")    // Windows CRLF → \n
        .Replace("\n", "\\n")       // Linux LF → \n
        .Replace("\r", "\\n")      // 旧版 Mac CR → \n
        .Replace("\t", "\\t")      // 制表符
        .Replace("\"", "\\\"");    // 双引号

    return escaped;
}
```

### 备选方案（仅当增强转义不够时）

#### 方案 B：通过 stdin 传递 Prompt

```csharp
// CodebuddyCliBridge.cs 修改
private static string BuildArguments(string prompt, string systemPrompt, bool streamJson)
{
    var outputFormat = streamJson ? "stream-json" : "json";

    // 不再通过命令行参数传递 Prompt
    return $"--output-format {outputFormat} "
           + $"--permission-mode bypassPermissions "
           + $"--append-system-prompt \"{systemPrompt.EscapeForCli()}\"";
}

// 添加 stdin 写入方法
private async Task WriteToStdInAsync(Process process, string prompt)
{
    await process.StandardInput.WriteLineAsync(prompt);
    process.StandardInput.Close();
}
```

**缺点**：需要修改 `RunProcessAsync` 方法，复杂度较高。

## 7. 边缘情况处理

1. **空字符串**：返回原值 ✅
2. **仅空白字符**：正常转义
3. **超长字符串**：不受影响，方法本身无长度限制
4. **二进制数据**：不适用，预期输入为文本
5. **已有转义字符**：正确处理，避免二次转义
