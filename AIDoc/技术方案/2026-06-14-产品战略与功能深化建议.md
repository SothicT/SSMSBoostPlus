# SSMSBoostPlus 产品战略与功能深化建议

> 上一份文档（`功能性增强方案-2026-06-14.md`）聚焦于竞品对标和功能清单。
> 本文档从**产品战略**和**AI 原生思维**出发，探讨如何建立差异化护城河。

---

## 一、核心观点：不要做"另一个 SQL Prompt"

SQL Prompt 用了 18 年积累补全引擎和元数据缓存，直接对标的胜算很低。
但 SQL Prompt 的 AI 能力是后加的（v11.0），而 SSMSBoostPlus 是 **AI-first** 起步。

**战略选择**：把 AI 作为产品的核心引擎，而非附加功能。

---

## 二、AI 原生功能——只有 AI 才能做到的事

### 2.1 智能错误诊断与修复（AI Error Doctor）

**用户痛点**：执行 SQL 报错后，错误信息晦涩，需要反复搜索解决方案。

**方案**：拦截 SSMS 错误输出，AI 自动诊断 + 建议修复。

```
用户执行 SQL → 报错（如 Msg 208, Invalid object name）
  → AI Error Doctor 自动触发
  → 分析：错误码 + SQL 上下文 + 当前数据库 schema
  → 对话面板显示：
     "❌ 错误原因：表 'Users' 在当前数据库中不存在
      💡 可能原因：
        1. 表名拼写错误（是否存在 dbo.User？）
        2. 需要切换数据库（MyApp.dbo.Users？）
      📋 点击应用修复建议"
```

**技术可行性**：
- 已有 `ExecutionInterceptor` 拦截机制，可扩展监听错误事件
- 已有 `SsmsEditorService` 获取编辑器上下文
- 已有 AI Bridge 通信链路
- **实现难度**：中

**差异化价值**：SQL Prompt 无此功能。这是 AI-first 的杀手级场景。

---

### 2.2 Schema 感知的 AI 补全（AI-Assisted Completion）

**与 SQL Prompt 的区别**：
- SQL Prompt：基于静态元数据 + 规则引擎补全
- SSMSBoostPlus：**基于 AI 语义理解补全**

**方案**：在用户输入自然语言描述时，AI 生成 SQL 片段。

```
用户输入注释：-- 查询最近30天下单超过3次的VIP客户
  → AI 自动识别意图
  → 生成完整 SQL：
     SELECT c.CustomerId, c.Name, COUNT(o.OrderId) AS OrderCount
     FROM Customers c
     JOIN Orders o ON c.CustomerId = o.CustomerId
     WHERE o.OrderDate >= DATEADD(DAY, -30, GETDATE())
       AND c.IsVIP = 1
     GROUP BY c.CustomerId, c.Name
     HAVING COUNT(o.OrderId) > 3
```

**技术可行性**：
- 已有 `CodeAnalysisService` + Bridge 通信
- 需要监听编辑器输入 + 意图识别触发
- 需要轻量级 Schema 注入（表名、列名列表，非全量 DDL）
- **实现难度**：中高（触发时机和性能是关键）

**差异化价值**：不是"补全"，而是"理解意图后生成"，这是传统补全做不到的。

---

### 2.3 SQL 变更影响分析（AI Impact Analysis）

**用户痛点**：修改表结构或存储过程前，不确定影响范围。

**方案**：修改前 AI 自动分析影响。

```
用户右键表 → "分析变更影响"
  → AI 分析：
     - 该表被哪些视图/存储过程/函数引用
     - 修改列类型可能导致的隐式转换问题
     - 建议的安全变更顺序
```

**技术可行性**：
- 可利用 `sys.sql_expression_dependencies` 查询依赖关系
- AI 负责语义分析和变更建议
- **实现难度**：中

**差异化价值**：SQL Prompt 的 Smart Rename 只做重命名，不做语义影响分析。

## 三、用户体验深化——降低摩擦力

### 3.1 首次运行引导（First-Run Experience）

**现状**：安装后无引导，用户可能不知道如何配置 AI。

**建议**：

```
首次启动 SSMS（检测到扩展新安装）
  → 弹出欢迎面板：
     Step 1: AI 配置向导（CLI 路径 / API Key）
     Step 2: 功能演示（3 个典型场景动画）
     Step 3: 快捷键速查卡
  → 完成后不再弹出
```

**价值**：降低新用户流失率。很多插件安装后因为"不会用"而被卸载。

---

### 3.2 右键上下文菜单增强

**现状**：AI 功能仅在顶部菜单栏。

**建议**：在编辑器右键菜单中添加 AI 入口，降低操作路径。

```
右键选中 SQL 文本 → 上下文菜单：
  ├── ✂️ 剪切 / 📋 复制
  ├── ────────────────
  ├── 🤖 AI 建议
  ├── 🤖 AI 添加注释
  ├── 🤖 AI 格式化
  ├── 🤖 AI 性能分析
  └── 💬 AI 对话面板
```

**技术可行性**：
- 通过 VS Shell `IVsMenuService` 或 `.vsct` 的 `IDM_VS_CTXT_CODEWIN` 组实现
- **实现难度**：低

---

### 3.3 状态栏集成

**现状**：AI 状态不可见。

**建议**：在 SSMS 状态栏显示 AI 连接状态。

```
状态栏右侧：
  🟢 AI 就绪 · CLI       ← CodebuddyCliBridge 可用
  🟡 AI 就绪 · API       ← AIApiClientBridge 兜底
  🔴 AI 未配置            ← 点击打开配置
```

**价值**：用户一眼知道 AI 是否可用，避免"点了没反应"的困惑。

---

## 四、Version Guard 深化——强化独创优势

Version Guard 是 SSMSBoostPlus 的独创功能，应持续深化：

### 4.1 变更审计日志

**建议**：记录所有被拦截/放行的版本变更事件。

```
Version Guard 审计日志（本地存储）：
  - 时间 / 用户 / 数据库 / 对象 / 操作 / 结果（放行/拦截/重载）
  - 可导出 CSV/Excel
```

**价值**：企业合规场景刚需，SQL Prompt 无此功能。

---

### 4.2 团队版本策略同步

**建议**：支持共享版本策略配置文件。

```
项目根目录放置 .ssmsboostplus-guard.json：
{
  "enabled": true,
  "askToken": "--ask",
  "skipToken": "--skip",
  "excludedSchemas": ["temp", "staging"],
  "strictMode": false
}
```

**价值**：团队统一规范，Git 可追踪策略变更。

---

## 五、性能与可靠性——用户信任的基础

### 5.1 AI 请求超时与降级策略

| 场景 | 当前行为 | 建议改进 |
|------|----------|----------|
| AI 请求超时 | 显示错误 | 显示进度 + "跳过"按钮 + 自动降级 |
| CLI 进程崩溃 | 报错 | 自动重启 + 重试（最多 3 次） |
| 无网络连接 | 报错 | 离线模式提示 + 仅使用本地功能 |

### 5.2 大 SQL 文件优化

| 场景 | 风险 | 建议 |
|------|------|------|
| 超长 SQL（>5000行） | AI Token 超限 | 自动截断 + 仅发送选中部分 |
| 超大执行计划 XML | 解析卡顿 | 限制 XML 大小 + 异步解析 |

## 七、核心结论

### 产品定位

> **SSMSBoostPlus = AI-first 的 SQL 开发助手**
> 
> 不是"SQL Prompt 的免费替代品"，而是"用 AI 重新定义 SQL 开发体验"。

### 三大护城河

| 护城河 | 说明 |
|--------|------|
| **AI 原生** | 每个功能都从 AI 出发设计，而非给传统功能加 AI |
| **Version Guard** | 独创功能，竞品无对标 |
| **中文优先** | 国内 SSMS 用户群体的刚需，SQL Prompt/dbForge 均无中文支持 |

### 一句话策略

> **先做 SQL Prompt 做不到的事（AI 原生），再做 SQL Prompt 做得到的事（传统功能），最后做 SQL Prompt 做不好的事（中文/本地化）。**
