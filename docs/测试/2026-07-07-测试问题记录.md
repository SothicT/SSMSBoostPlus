# Local History（历史版本管控）功能测试问题记录

## 问题一：对象标识符解析携带架构限定符导致历史版本检索失败

- **现象（Symptom）**：在 Local History（历史版本）工具窗口中，通过 DTE `WindowActivated` 事件触发活动文档自动刷新时，系统无法正确加载编辑器当前脚本所对应的历史版本，版本列表返回空集（无数据展示）。
- **根因（Root Cause）**：自动刷新流程 `LocalHistoryToolWindowControl.RefreshForActiveWindowAsync` 调用 `SQLParser.Object.Extractor` 从编辑器缓冲区（Editor Buffer / 活动文档）的 DDL 脚本中提取首个对象定义（`IsDefinition`），并以 `{Schema}.{Name}` 拼接出**带架构前缀的完全限定标识符（schema-qualified identifier，如 `dbo.ProcName`）**，以其作为查询键调用 `LoadVersionsAsync → GetObjectHistoryAsync`。而版本历史索引表（`DBTrigger_Object_Version_Table`）以**无架构限定的对象名（schema-unqualified object name）**作为 `ObjectName` 匹配主键。命名空间（schema）不一致导致按 `ObjectName` 的精确匹配失败，查询返回空结果集。
- **影响范围（Impact）**：所有在编辑器中以 `schema.Object` 形式（如 `dbo.` 前缀）标识的存储过程 / 视图 / 函数 / 表，其自动关联的历史版本快照均无法正确展示。
- **涉及模块**：`src/SSMS/UI/VersionHistory/LocalHistoryToolWindowControl.xaml.cs`（`RefreshForActiveWindowAsync`、`LoadVersionsAsync`）、`src/Core/SQLParser/Object/Extractor`。

## 问题二：版本序号与时间线错位（未按时间戳排序派生）

- **现象（Symptom）**：Local History 工具窗口版本列表中展示的版本序号（Revision / Sequence Number）与真实变更时间序不一致，版本号显示不正确。
- **根因（Root Cause）**：加载流程 `LoadVersionsAsync` 在获取快照集合后，以结果集数组下标倒序方式推导显示序号（`RowNumber = 记录总数 - i`）。该推导**隐含了"结果集已按 `PostTime` 降序排列"的前置假设**。若底层查询 `GetObjectHistoryAsync` 的返回顺序未以 `PostTime`（快照写入时间戳 / 版本入库时间）为唯一排序键保证稳定有序，则推导出的 `RowNumber` / 版本号将与真实时间线错位，造成版本序号展示错误。
- **修复建议（Recommendation）**：统一以 `PostTime` 时间戳作为版本列表的**唯一排序维度（chronological ordering）**，先对快照集合做稳定排序，再在其有序基础上重新派生连续版本序号，确保版本号与时间线严格一一对应。
- **涉及模块**：`src/SSMS/UI/VersionHistory/LocalHistoryToolWindowControl.xaml.cs`（`LoadVersionsAsync`）、`src/Core/VersionHistory/VersionHistoryService.cs`（`GetObjectHistoryAsync`）、`src/Core/VersionHistory/Models/VersionHistoryModels.cs`（`VersionRecord.RowNumber` / `PostTime`）。
