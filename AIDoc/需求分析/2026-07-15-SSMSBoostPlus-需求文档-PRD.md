## 2. 产品概述

### 2.1 业务背景与问题陈述

SQL Server 开发人员和 DBA 在日常工作中面临以下核心痛点：

1. **SQL 编写效率低下**：手动编写注释、格式化代码、分析性能问题耗费大量时间，且容易遗漏关键优化点。
2. **AI 工具与数据库上下文脱节**：通用 AI 编程助手（如 Copilot、ChatGPT）不理解当前数据库的 Schema、索引结构和执行计划，给出的建议往往脱离实际，需要大量人工修正。
3. **多人协作中的版本冲突风险**：在团队协作环境中，多个开发人员可能同时修改同一数据库对象，脚本引用的对象可能在编辑期间已被他人修改，导致上线后出现预期外的行为。
4. **SSMS 原生能力不足**：SSMS 自带的 IntelliSense 和查询分析能力有限，缺乏智能化的 SQL 审查、优化建议和上下文感知的 AI 辅助。

**SSMSBoostPlus 的核心价值主张**：将数据库元数据（Schema、索引、执行计划）深度注入 AI 上下文，让 AI 真正"理解"你的数据库，提供精准、可落地的 SQL 分析和优化建议。

### 2.2 产品目标与成功标准

| 目标维度 | 目标描述 | 成功标准（可量化指标） |
|----------|----------|------------------------|
| **效率提升** | 减少 SQL 编写与优化时间 | 用户平均 SQL 编写时间减少 30% 以上 |
| **质量提升** | 降低 SQL 性能问题与逻辑错误 | AI 建议采纳率 ≥ 60% |
| **协作安全** | 消除版本冲突导致的上线事故 | 版本冲突检出率 ≥ 95%，误报率 ≤ 5% |
| **用户满意度** | 成为 SQL Server 开发者的首选 AI 辅助工具 | NPS ≥ 40，插件月活跃用户留存率 ≥ 70% |
| **市场覆盖** | 在 SSMS 扩展生态中建立影响力 | VS Marketplace 安装量进入 SSMS 扩展前 10 |

## 3. 用户故事与验收条件

### P0（核心功能，必须完整可用）

#### US-001：AI 智能 SQL 优化建议

**用户故事**：作为 SQL Server 开发人员，我希望选中一段 SQL 代码后，AI 能基于当前数据库的 Schema、索引和执行计划，给出具体的优化建议，以便我快速发现并修复性能问题。

**验收条件**：

- **AC-001-1**：Given 用户在 SSMS 查询编辑器中选中一段 SQL 代码，When 按下 `Ctrl+Shift+A`，Then 系统将数据库元数据（涉及表的 Schema、索引、统计信息）与选中 SQL 一同发送给 AI 后端，并在 30 秒内返回优化建议。
- **AC-001-2**：Given 用户未选中任何代码，When 按下 `Ctrl+Shift+A`，Then 系统将当前编辑器的全部 SQL 文本发送给 AI 后端进行分析。
- **AC-001-3**：Given AI 返回优化建议，When 建议中包含修改后的 SQL 代码，Then 系统展示 Diff 对比视图，高亮原始代码与优化代码的差异。
- **AC-001-4**：Given AI 正在生成建议，When 生成过程超过 5 秒，Then 系统以流式 Markdown 渲染方式逐步展示建议内容，用户可实时阅读。
- **AC-001-5**：Given 数据库连接不可用，When 用户触发 AI 建议，Then 系统提示"无法获取数据库上下文，将以无上下文模式分析"，并降级为纯 SQL 分析。
- **AC-001-6**：Given AI 后端返回错误或超时（60 秒），Then 系统显示友好的错误提示并建议用户重试。
- **AC-001-7**：Given 选中的 SQL 语法严重错误，When AI 分析，Then 系统应在建议中明确指出语法问题，而非仅给出优化建议。

**优先级**：P0

---

#### US-002：AI 自动添加注释

**用户故事**：作为 SQL Server 开发人员，我希望 AI 能自动为我的 SQL 脚本生成中文注释，以便提高代码可读性和可维护性，减少手动编写注释的时间。

**验收条件**：

- **AC-002-1**：Given 用户在编辑器中选中一段 SQL 代码，When 按下 `Ctrl+Shift+C`，Then AI 分析 SQL 逻辑并生成中文注释，包括：每个关键步骤的说明、复杂逻辑的解释、业务含义的推断。
- **AC-002-2**：Given 用户未选中代码，When 按下 `Ctrl+Shift+C`，Then 对全文进行注释。
- **AC-002-3**：Given AI 生成注释，When 注释完成，Then 系统展示 Diff 对比视图，左侧为原始代码，右侧为添加注释后的代码，用户可选择接受、拒绝或逐行调整。
- **AC-002-4**：Given SQL 包含存储过程/函数定义，When AI 添加注释，Then 注释应包括参数说明、返回值说明、主要逻辑步骤。
- **AC-002-5**：Given 原始 SQL 已有部分注释，When AI 添加注释，Then AI 应保留已有注释，仅补充缺失的注释，不重复已有内容。

**优先级**：P0

---

#### US-003：AI 智能格式化代码

**用户故事**：作为 SQL Server 开发人员，我希望一键格式化 SQL 代码，使其符合统一的代码风格规范，以便提高代码的可读性和团队协作效率。

**验收条件**：

- **AC-003-1**：Given 用户在编辑器中选中一段 SQL，When 按下 `Ctrl+Shift+F`，Then 系统按照预设的格式化规则（关键字大写、缩进对齐、换行规范）格式化代码。
- **AC-003-2**：Given 用户未选中代码，When 按下 `Ctrl+Shift+F`，Then 对全文进行格式化。
- **AC-003-3**：Given 格式化完成，When 展示结果，Then 系统展示 Diff 对比视图，用户可预览变更并选择接受或拒绝。
- **AC-003-4**：Given SQL 包含嵌套子查询，When 格式化，Then 嵌套层级应有清晰的缩进，每层缩进 2 或 4 个空格（可配置）。
- **AC-003-5**：Given SQL 包含 CTE（公用表表达式），When 格式化，Then CTE 的每个子句应独立成行并正确缩进。

**优先级**：P0

---

#### US-004：AI 性能分析（结合执行计划）

**用户故事**：作为 DBA 或 SQL 开发人员，我希望 AI 能结合 SQL 的实际执行计划，分析性能瓶颈并给出具体优化方案，以便快速定位和解决慢查询问题。

**验收条件**：

- **AC-004-1**：Given 用户在编辑器中选中一段 SQL 并已获取其执行计划，When 按下 `Ctrl+Shift+P`，Then 系统将 SQL 文本、执行计划 XML、数据库 Schema 和索引信息一同发送给 AI 后端。
- **AC-004-2**：Given AI 分析完成，When 展示结果，Then 分析报告应包含：瓶颈定位（如全表扫描、Key Lookup、排序溢出）、影响程度评估、具体优化建议（如建议创建索引的 DDL 语句）、预估优化效果。
- **AC-004-3**：Given 用户未获取执行计划，When 按下 `Ctrl+Shift+P`，Then 系统提示"请先执行查询并包含实际执行计划"，引导用户先获取执行计划。
- **AC-004-4**：Given 执行计划中包含多个高成本操作，When AI 分析，Then 应按成本从高到低排序，逐一分析每个瓶颈。
- **AC-004-5**：Given 执行计划 XML 过大（> 5MB），When 发送给 AI，Then 系统应自动裁剪非关键信息（如极低成本的子操作），确保不超出 AI 上下文限制。

**优先级**：P0

---

#### US-005：AI 对话面板

**用户故事**：作为 SQL Server 开发人员，我希望有一个基于当前数据库 Schema 的 AI 对话面板，能自然语言提问关于数据库结构、SQL 编写、性能优化等问题，以便获得即时的上下文感知的 AI 辅助。

**验收条件**：

- **AC-005-1**：Given 用户按下 `Ctrl+Shift+K`，When 面板打开，Then 系统在 SSMS 内显示一个可停靠的 WPF 对话面板，AI 自动加载当前数据库的 Schema 上下文。
- **AC-005-2**：Given 用户在对话面板中输入问题，When 发送，Then AI 基于数据库 Schema 回答问题，回答以流式 Markdown 渲染展示。
- **AC-005-3**：Given 对话面板打开，When 用户切换数据库连接，Then 对话面板自动更新 Schema 上下文，并提示用户"数据库上下文已切换至 [数据库名]"。
- **AC-005-4**：Given 对话历史超过 50 轮，When 用户继续对话，Then 系统自动压缩早期对话摘要以控制 Token 消耗。
- **AC-005-5**：Given 用户关闭对话面板，When 再次打开，Then 对话历史保留（会话级别），直到用户手动清除或关闭 SSMS。
- **AC-005-6**：Given 用户在对话面板中引用编辑器中的 SQL 代码，When 提问，Then 用户可通过 "@选中代码" 方式将当前编辑器选中内容注入对话上下文。

**优先级**：P0

### P1（重要功能，影响用户体验）

#### US-006：版本守卫 - 差异检测

**用户故事**：作为 DBA 或开发人员，在多人协作环境中，我希望在保存或执行脚本前，能检测脚本引用的数据库对象自上次编辑以来是否已被他人修改，以避免因版本冲突导致的问题。

**验收条件**：

- **AC-006-1**：Given 用户按下 `Ctrl+Shift+V`，When 执行版本守卫，Then 系统通过 DiffPlex 引擎对比当前脚本引用的数据库对象定义与服务器上的最新定义，如有差异则高亮展示。
- **AC-006-2**：Given 检测到差异，When 展示结果，Then 系统显示差异对比视图，标注变更类型（新增/修改/删除）和变更时间。
- **AC-006-3**：Given 未检测到差异，When 检查完成，Then 系统显示"所有引用的对象均为最新版本"。
- **AC-006-4**：Given 脚本引用了 10 个以上的数据库对象，When 执行版本守卫，Then 所有对象的检查结果以列表形式展示，差异对象优先排列。

**优先级**：P1

---

#### US-007：版本守卫 - 强制审查

**用户故事**：作为 DBA，当检测到脚本引用的对象已被他人修改时，我希望系统能强制要求我审查差异后再执行脚本，以防止因疏忽导致上线事故。

**验收条件**：

- **AC-007-1**：Given 版本守卫检测到差异，When 用户尝试执行脚本，Then 系统拦截执行并弹出差异审查窗口，用户必须确认已审查所有差异后才能继续执行。
- **AC-007-2**：Given 用户已审查差异，When 确认继续执行，Then 系统记录审查日志（审查时间、审查人、差异摘要），然后放行执行。
- **AC-007-3**：Given 用户审查差异后发现需要更新脚本，When 取消执行，Then 系统返回编辑器，用户可修改脚本以适配最新对象定义。

**优先级**：P1

---

#### US-008：版本守卫 - 二次校验

**用户故事**：作为 DBA，在审查差异到实际执行之间可能存在时间窗口，我希望系统在执行前进行二次校验，确保在审查期间没有新的变更发生。

**验收条件**：

- **AC-008-1**：Given 用户审查差异后确认执行，When 实际执行前，Then 系统自动进行二次校验，确认对象定义在审查期间未发生变化。
- **AC-008-2**：Given 二次校验发现新的变更，When 检测到新差异，Then 系统阻止执行，重新展示差异并要求用户再次审查。
- **AC-008-3**：Given 二次校验未发现新变更，When 校验通过，Then 系统直接放行执行，不额外打断用户。

**优先级**：P1

---

#### US-009：版本历史 - 变更记录浏览

**用户故事**：作为 DBA 或开发人员，我希望查看数据库对象的完整变更历史，包括谁在何时做了何种修改，以便追溯问题、审计变更、了解代码演进过程。

**验收条件**：

- **AC-009-1**：Given 用户打开版本历史面板，When 面板初始化，Then 系统自动从 SSMS 当前活动窗口推断连接信息和当前编辑的数据库对象，加载该对象的版本历史列表。
- **AC-009-2**：Given 版本历史列表展示，When 用户查看，Then 每条记录显示：数据库名、序号、时间、变更类型（CREATE/ALTER/DROP，彩色标签）、操作人、版本号。
- **AC-009-3**：Given 用户在搜索框中输入关键字，When 输入时（300ms 防抖），Then 系统从数据库模糊搜索匹配的对象，显示 Top 100 结果，含对象类型标签和版本数量。
- **AC-009-4**：Given 用户切换 SSMS 文档窗口，When 窗口切换（300ms 防抖），Then 版本历史面板自动跟随切换，刷新到新窗口的对象历史。
- **AC-009-5**：Given 用户点击"钉住"按钮，When 面板钉住，Then 面板不再跟随窗口切换，保持当前对象的历史记录不变。

**优先级**：P1

---

#### US-010：版本历史 - 差异比对

**用户故事**：作为 DBA 或开发人员，我希望对比不同版本之间的差异，或对比历史版本与当前服务器定义的差异，以便了解具体变更内容和影响范围。

**验收条件**：

- **AC-010-1**：Given 用户单击版本列表中的某一行，When 选中，Then 系统自动对比该历史版本与服务器当前定义，展示并排差异视图。
- **AC-010-2**：Given 用户 Ctrl+多选两行后双击，When 触发对比，Then 系统对比两个历史版本之间的差异，展示并排差异视图。
- **AC-010-3**：Given 差异视图展示，When 用户查看，Then 差异行高亮标注（新增=绿色、删除=红色、修改=黄色），支持子词级高亮。
- **AC-010-4**：Given 差异视图展示，When 用户滚动，Then 左右面板默认同步滚动，可切换为独立滚动。
- **AC-010-5**：Given 服务器定义加载失败，When 展示差异，Then 左侧面板显示错误遮罩和重试按钮。

**优先级**：P1

#### US-011：版本历史 - 版本回退

**用户故事**：作为 DBA 或开发人员，当发现某个历史版本是正确的，我希望生成回退脚本，以便快速恢复到该版本。

## 4. 功能规格说明

### 4.1 AI 智能建议（Ctrl+Shift+A）

#### 功能概述
基于数据库上下文（Schema、索引、统计信息），对用户选中的 SQL 代码或全文进行智能分析，提出优化建议。

#### 触发条件
- 用户在 SSMS 查询编辑器中选中 SQL 代码或光标位于编辑器中
- 当前已连接数据库
- 按下 `Ctrl+Shift+A` 或通过菜单/工具栏触发

#### 前置条件
- 当前 SSMS 已连接 SQL Server 数据库
- AI 后端服务可用（CodeBuddy CLI 或 HTTP API）
- 数据库上下文已加载（首次使用自动加载）

#### 正常流程

```
1. 用户选中 SQL 代码（或光标在编辑器中，无选中）
2. 用户按下 Ctrl+Shift+A
3. 系统收集上下文：
   a. 解析 SQL 中引用的表名、视图名、函数名
   b. 从数据库获取这些对象的 Schema（列名、数据类型、约束）
   c. 获取相关索引信息
   d. 获取统计信息（如可用）
4. 系统组装 Prompt（使用 analyze 模板），将上下文注入
5. 系统调用 AI 后端，发送请求
6. AI 后端返回流式响应
7. 系统以 Markdown 渲染方式逐步展示建议
8. 如有代码修改建议，展示 Diff 对比视图
9. 用户选择：接受全部 / 拒绝 / 部分接受
10. 如接受，修改后的代码替换编辑器中的原始代码
```

#### 异常流程

| 异常场景 | 处理方式 |
|----------|----------|
| 数据库未连接 | 提示"请先连接数据库"，阻止操作 |
| 数据库上下文加载失败 | 提示"无法获取数据库上下文，将以无上下文模式分析"，降级为纯 SQL 分析 |
| SQL 解析失败（语法错误） | 提示"SQL 语法可能有误，AI 分析可能不准确，是否继续？" |
| AI 后端不可用 | 提示"AI 服务不可用，请检查 CodeBuddy 配置"，显示错误详情 |
| AI 请求超时（60s） | 提示"AI 分析超时，请重试或简化 SQL"，提供重试按钮 |
| AI 返回空响应 | 提示"AI 未返回有效建议，请重试" |
| Token 超出限制 | 提示"SQL 过长，超出 AI 分析限制，请缩小选中范围" |
| 选中内容为空且编辑器为空 | 提示"请输入 SQL 代码后再进行分析" |

#### 交互说明

- **触发方式**：快捷键 `Ctrl+Shift+A`、右键菜单、工具栏按钮
- **加载状态**：触发后显示进度指示器（如状态栏"AI 分析中..."），支持取消操作
- **结果展示**：在 SSMS 内以停靠面板或弹出窗口展示，支持调整大小
- **Diff 视图**：左右分栏，左侧原始代码，右侧 AI 建议代码，差异行高亮
- **操作按钮**：「接受全部」「拒绝」「复制建议」

#### 数据规则

- 上下文注入的 Schema 信息应包含：表名、列名、数据类型、是否可为空、主键、外键、索引（名称、列、类型）
- 上下文大小应控制在 AI 模型 Token 限制的 60% 以内，预留空间给 SQL 文本和 AI 回复
- 对于引用超过 20 个表的 SQL，仅注入最相关的 20 个表的 Schema（按 SQL 中出现的顺序优先）

#### 权限要求
- 需要数据库的 VIEW DEFINITION 权限（获取 Schema）
- 需要数据库的 VIEW DATABASE STATE 权限（获取统计信息）

### 4.2 AI 添加注释（Ctrl+Shift+C）

#### 功能概述
自动分析 SQL 逻辑，生成中文注释，包括步骤说明、复杂逻辑解释、业务含义推断。

#### 触发条件
- 用户在 SSMS 查询编辑器中选中 SQL 代码或光标位于编辑器中
- 按下 `Ctrl+Shift+C`

#### 前置条件
- 编辑器中有 SQL 代码
- AI 后端服务可用

#### 正常流程

```
1. 用户选中 SQL 代码（或全文）
2. 用户按下 Ctrl+Shift+C
3. 系统收集上下文（可选：数据库 Schema 用于理解表结构）
4. 系统组装 Prompt（使用 comment 模板）
5. 系统调用 AI 后端
6. AI 返回带注释的 SQL 代码
7. 系统展示 Diff 对比视图
8. 用户选择：接受全部 / 拒绝 / 逐行调整
```

#### 异常流程

| 异常场景 | 处理方式 |
|----------|----------|
| 编辑器为空 | 提示"请输入 SQL 代码后再添加注释" |
| AI 后端不可用 | 提示"AI 服务不可用，请检查配置" |
| 已有注释的 SQL | AI 应保留已有注释，仅补充缺失部分；如注释已完整，提示"代码注释已较完整，无需补充" |
| SQL 极短（如单行 SELECT） | 正常生成注释，但提示"简单查询可能无需注释" |

#### 交互说明

- **结果展示**：Diff 对比视图，左侧原始代码，右侧带注释代码
- **注释风格**：中文行内注释（`-- 注释内容`）或块注释（`/* 注释内容 */`）
- **操作按钮**：「接受全部」「拒绝」「复制」

#### 数据规则

- 注释语言：中文
- 注释位置：关键步骤前、复杂逻辑处、存储过程/函数头部
- 不注释的内容：显而易见的简单语句（如 `SET NOCOUNT ON`）

```
5. 返回格式化后的 SQL 代码

```

| 异常场景 | 处理方式 |
|----------|----------|
| 编辑器为空 | 提示"请输入 SQL 代码后再格式化" |

#### 数据规则

- 格式化不应改变 SQL 语义
- 字符串字面量内的内容保持不变
- 方括号引用 `[object]` 保持不变

### 4.4 AI 性能分析（Ctrl+Shift+P）

#### 功能概述
结合 SQL 执行计划（Actual/Estimated Execution Plan），分析性能瓶颈并给出优化方案。

#### 触发条件
- 用户在编辑器中选中 SQL 代码
- 已获取该 SQL 的执行计划
- 按下 `Ctrl+Shift+P`

#### 前置条件
- 当前 SSMS 已连接 SQL Server 数据库
- 已执行查询并包含实际执行计划（或已获取预估执行计划）
- 执行计划 XML 可获取

#### 正常流程

```
1. 用户选中 SQL 代码
2. 用户按下 Ctrl+Shift+P
3. 系统检测执行计划是否可用：
   a. 可用：获取执行计划 XML
   b. 不可用：提示用户先获取执行计划
4. 系统收集上下文：
   a. 数据库 Schema（涉及的表）
   b. 索引信息
   c. 统计信息
5. 系统组装 Prompt（使用 analyze 模板，重点注入执行计划信息）
6. 系统调用 AI 后端
7. AI 返回性能分析报告（流式 Markdown）
8. 用户阅读报告，按建议操作
```

#### 异常流程

| 异常场景 | 处理方式 |
|----------|----------|
| 执行计划不可用 | 提示"请先执行查询并包含实际执行计划（Ctrl+M），然后重试" |
| 执行计划 XML 过大（>5MB） | 自动裁剪低成本的子操作，保留 Top 20 高成本操作 |
| 执行计划为预估计划 | 标注"基于预估执行计划分析，实际执行计划可能不同" |
| SQL 涉及多语句 | 对每个语句的执行计划分别分析 |

#### 交互说明

- **分析报告结构**：瓶颈总览 → 逐项分析 → 优化建议（含 DDL） → 预估效果
- **瓶颈标注**：严重（红色）、警告（橙色）、提示（蓝色）
- **优化建议**：包含可直接执行的 DDL 语句（如 CREATE INDEX）

### 4.6 版本历史（菜单触发）

#### 功能概述
查询数据库对象的完整变更历史记录，支持差异比对、版本回退、搜索过滤、窗口切换跟随，以及与版本守卫的联动。

#### 触发条件
- 用户点击菜单"版本历史"或使用快捷键
- 版本守卫警告窗口中的"查看版本历史"按钮
- 首次打开时自动推断当前编辑器的数据库对象

#### 前置条件
- 当前 SSMS 已连接 SQL Server 数据库
- 数据库中存在版本历史表（`DBTrigger_Object_Version_Table`），由 DDL Trigger 自动填充
- 版本历史服务可用（`IVersionHistoryService`）

#### 正常流程

```
1. 用户打开版本历史面板
2. 系统初始化（自动推断 3 步）：
   a. 连接串推导：从 SSMS 活动窗口获取连接信息，替换数据库为 MESBASE
   b. 对象推断：解析当前编辑器 SQL，提取 CREATE/ALTER 定义的对象名
   c. 数据库过滤：按当前数据库过滤版本记录
3. 系统加载该对象的版本历史列表到 DataGrid
4. 用户可：
   - 单击版本行：对比该版本与服务器当前定义的差异
   - Ctrl+双击两行：对比两个历史版本间的差异
   - 右键：复制 SQL 到剪贴板
   - 点击"在编辑器中打开"：将历史脚本写入新编辑器窗口
   - 搜索框：输入关键字搜索其他对象
   - 数据库下拉框：切换数据库过滤
   - 钉住按钮：锁定当前对象，不跟随窗口切换
```

#### 异常流程

| 异常场景 | 处理方式 |
|----------|----------|
| 数据库未连接 | 显示"未连接数据库"状态，面板功能受限 |
| 版本历史表不存在 | 显示"版本历史表未配置，请检查 DDL Trigger" |
| 当前编辑器无 SQL 或无法解析对象 | 显示"未检测到数据库对象，请在搜索框中搜索" |
| 搜索无结果 | 显示"未找到匹配的对象" |
| 服务器定义加载失败 | 差异面板显示错误遮罩 + 重试按钮 |
| 数据库不在白名单中 | 显示"受限"状态，不允许查看历史 |
| 窗口切换时连接信息无法获取 | 保持当前状态，显示"未识别"标签 |

#### 交互说明

- **面板布局**：搜索框 + 数据库下拉框 + DataGrid（版本列表） + 状态栏
- **搜索框**：可编辑 ComboBox，支持模糊搜索 + 300ms 防抖，下拉列表显示对象类型标签和版本数量
- **DataGrid 列**：数据库名、序号、时间、变更类型（彩色标签：CREATE=绿/ALTER=蓝/DROP=红）、操作人、版本号
- **状态栏**：服务器名称（悬浮提示：服务器地址+连接用户）、数据库下拉框、钉住按钮、同步连接按钮、连接状态标签、刷新按钮
- **差异视图**：左右并排 RichTextBox，DiffPlex 引擎渲染，支持同步滚动/独立滚动切换
- **图例**：新增(绿)、删除(红)、修改(黄)

#### 数据规则

- 数据来源：`MESBASE.dbo.DBTrigger_Object_Version_Table`（DDL Trigger 自动填充）
- 搜索限制：Top 100 结果，按类型优先级排序（SP > FN > TBL > VW > TR > TYP > OBJ）
- 数据库列表缓存：5 分钟，避免频繁查询 `sys.databases`
- 窗口切换防抖：300ms
- 权限控制：`AllowedDatabases` 白名单

#### 版本回退策略

| 当前变更类型 | 恢复策略 | 生成的脚本 |
|-------------|---------|-----------|
| ALTER | 直接返回历史 ALTER 语句 | `ALTER PROCEDURE ...` |
| CREATE | 将 CREATE 转为 ALTER | `ALTER PROCEDURE ...` |
| DROP | 找上一条非 DROP 记录，将 ALTER 转 CREATE 重建 | `CREATE PROCEDURE ...` |

#### 与版本守卫的联动

```
版本守卫 (F5) → 检测到过时对象 → VersionWarningDialog → 点击"查看版本历史" → 打开版本历史面板
```

联动时传入对象名和数据库过滤，版本历史面板自动定位到该对象。

### 4.7 版本守卫（Ctrl+Shift+V）

#### 功能概述
检测脚本引用的数据库对象自编辑后是否已被他人修改，防止版本冲突。

#### 触发条件
- 用户在编辑器中打开 SQL 脚本
- 按下 `Ctrl+Shift+V`

#### 前置条件
- 当前 SSMS 已连接 SQL Server 数据库
- 脚本中引用了数据库对象（表、视图、存储过程、函数等）

#### 正常流程

```
1. 用户按下 Ctrl+Shift+V
2. 系统解析脚本，提取引用的数据库对象
3. 对每个对象，获取服务器上的当前定义
4. 使用 DiffPlex 引擎对比：
   a. 本地脚本中引用的对象定义
   b. 服务器上的最新对象定义
5. 展示对比结果：
   a. 无差异：显示"所有对象均为最新版本"
   b. 有差异：高亮展示差异，列出变更对象
6. 如有差异，用户审查
7. 用户确认后继续或取消执行
```

#### 异常流程

| 异常场景 | 处理方式 |
|----------|----------|
| 数据库未连接 | 提示"请先连接数据库" |
| 对象已被删除 | 标注"对象已不存在"，红色警告 |
| 脚本中无数据库对象引用 | 提示"未检测到数据库对象引用" |
| 对象数量过多（>50） | 分批检查，显示进度条 |
| 二次校验发现新变更 | 重新展示差异，要求再次审查 |

#### 交互说明

- **差异展示**：列表视图，每个对象一行，差异对象高亮
- **差异详情**：点击对象展开 DiffPlex 对比视图
- **操作按钮**：「标记已审查」「继续执行」「取消执行」「重载对象定义」
- **跳过令牌**：脚本中添加 `--version-guard-skip` 注释可跳过检查

#### 数据规则

- 对比基准：脚本中引用的对象定义快照（编辑时获取）vs 服务器当前定义
- 对比粒度：DDL 级别（存储过程/函数/视图的完整定义文本）
- 审查日志保留：记录每次审查的时间、对象、差异摘要、审查结果
