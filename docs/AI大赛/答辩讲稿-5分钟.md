## 开场（约 20 秒）

各位评委好，我们是「数据炼金小分队」。今天我带来的作品是 **SSMSBoostPlus**——一款基于 AI 大模型的 SSMS 智能增强扩展插件，**全程由 CodeBuddy AI Agent 驱动开发**。

---

## 一、作品概述（约 50 秒）

先说一下我们解决了什么问题。SQL Server 开发人员每天在 SSMS 里写存储过程、改表结构，但有四个长期痛点一直没人解决：

第一，**数据库对象的变更历史无法追溯**。生产环境虽然有 DDL Trigger 在记录，但数据散落在历史表里，开发人员 想查"谁在什么时候改了什么"只能翻表拼凑。

第二，**多人协作时版本冲突频发**。你正在改一个存储过程，同事已经先你一步提交了，你一执行就覆盖了别人的修改，而且执行前完全不知道。

第三，**SQL 审查全靠人工**。安全审查、加注释、格式化代码、性能分析——这些重复劳动挤占了 开发人员 大量时间，质量还因人而异。

第四，VSIX 扩展的构建链路本身就是一个坑，.NET SDK 10 和 VSSDK 有兼容 Bug，不处理好连部署都跑不通。

我们的方案是：版本历史面板 + 版本守卫 + AI 五大能力，六合一插件。项目最终交付了 **199 个 C# 源文件、103 个单元测试、122 次提交**，两个月内完成。

## 二、提效价值与痛点解决（约 55 秒）

那么 AI Coding 到底帮我们省了多少人力？我们和团队历史经验做了对比。

一个同类 VSIX 扩展插件，传统开发需要 **40 到 62 人天**。引入 AI 之后，实际只用了 **15 人天**，综合提效约 **68%**。

拆开来看：架构设计提效 75%，AI 功能层提效 72%，Core 层业务逻辑提效 70%，测试和文档都提效近 70%。

但最大的提效不是数字，而是模式的改变。传统开发是串行的——需求做完写方案，方案写完写代码，代码写完写测试——任何一个环节卡住，后面全堵。我们的 Agent Team 把串行变成并行了：BA 做需求分析的同时，Architect 已经在推演技术方案，Developer 同步编码，Tester 同步生成测试用例。全链路打破瓶颈。

另一个关键提效点是 **问题诊断**——传统 Debug 一个 Bug 要 2 到 4 小时，引入 error-diagnosis Skill 后，从日志解析到源码定位到修复方案输出，**缩短到 15 分钟**。

## 三、AI 全链路与人机协同（约 100 秒）

下面说说我们是怎么和 AI 协作的。核心是四个字：**规范先行**。

项目启动第一件事不是写代码，而是让 AI Agent 定义了 **7 个 Rules 文件**，覆盖架构、构建、编码、部署、文档、测试、协作七个维度。这些 Rules 以文件形式沉淀在项目里，每次 AI 会话自动加载，确保所有 Agent 产出的代码都在统一约束之下——不会偏离项目标准，Code Review 零沟通成本。

在 Rules 之上，我们定义了 **五角色 Agent Team**：产品经理 PM、需求分析师 BA、架构师 Architect、开发工程师 Developer、测试工程师 Tester，外加两个专项 Agent——小Q 负责问题诊断，小H 负责发布部署。

整个流程是：PM 出产品方向和竞品分析 → BA 拆解成需求规格 → Architect 设计技术方案 → Developer 按 TDD 编码实现 → Tester 独立验证 → 小H 编译部署。每两个阶段之间有道门控，必须人类审核通过才能进入下一阶段。人在关键决策点介入，其余全由 AI 自动化。

举一个真实例子说明人机协同闭环。我们有一次打开版本历史页签，面板始终显示"正在加载"，功能完全不可用。传统的排查流程要在日志、源码、搜索引擎之间来回切，预计 30 到 60 分钟。我们直接用 error-diagnosis Skill，Agent 自动读取 Serilog 日志，5 分钟内定位到根因：一个 ToggleButton 控件引用了 Button 类型的样式，WPF 在运行时类型校验失败导致崩溃。Agent 还做了全项目排查，确认没有其他同类隐患，然后输出两套修复方案让我们选。整个人工只需要 2 次介入——反馈问题、确认方案，其余全由 AI 完成。

关于 AI 生成占比，我们的 C# 业务代码约 75% 由 AI 生成，XAML UI 代码约 85%，单元测试约 90%，项目文档约 95%。

关于 SDD 规范驱动开发，我们沉淀了 4 个 Python 脚本，覆盖规范追踪、一致性校验、门控检查、验收条件自动转测试，形成了"定义→追踪→校验→生成→修正"的闭环。

## 四、方法论沉淀（约 45 秒）

这套方法论最核心的价值是**可复用**。我们沉淀了四类资产：

**7 个 Rules 文件**——架构约束、构建命令、代码风格、部署流程、文档规范、测试门禁、协作规则。任何 C# 项目拿过去就能用。

**8 个 Skills 技能包**——其中 6 个是通用型的，像 error-diagnosis 自动诊断、issue-tracker 问题追踪、build-and-deploy 编译部署，这些任何项目都能直接复用。

**8 个 SubAgent 角色**——五角色 Agent Team 是通用框架，小Q 问题分析、小H 发布部署的模式可以直接复制。

**4 个 SDD 工具脚本**——规范追踪、一致性校验、门控检查、测试生成，100% 通用。

整体通用性超过 70%。而且我们还沉淀了 93 篇结构化 AIDoc 文档，从需求分析到诊断报告，全部可追溯。

---

## 五、总结（约 20 秒）

最后总结一下我们的方法论公式，就四步：

**定义规范 → 角色分工 → 门控把关 → 沉淀资产。**

先定义 7 个 Rules 建立约束，再用五角色 Agent Team 并行推进，五道门控确保人在关键时刻介入，最后把经验沉淀为可复用的 Skills 和工具。

这套模式已经在 SSMSBoostPlus 项目里验证有效，可以直接迁移到后续任何软件项目。
