# 04 - 代码分析与建议

## 一、功能概述

SQL Prompt 内置**静态代码分析**引擎，在编码时实时检测 SQL 代码中的问题，涵盖代码风格、性能隐患、安全漏洞、弃用语法等多个维度，并支持部分规则的**自动修复**。

---

## 二、功能细节

### 2.1 分析规则分类

| 类别 | 说明 | 典型规则 |
|------|------|---------|
| **代码风格** | 不符合最佳实践的写法 | ST001: 旧式 JOIN 语法（`*=` 和 `=*`），应使用 ANSI 标准 |
| **性能问题** | 可能导致查询缓慢的写法 | ST003: 潜在性能隐患 |
| **安全漏洞** | 可能导致 SQL 注入或其他安全问题 | 检测动态 SQL 拼接中的风险 |
| **弃用语法** | SQL Server 已弃用的 T-SQL 语法 | 如旧的数据类型、系统存储过程 |
| **设计问题** | 数据库设计层面的缺陷 | 缺少聚集索引的表 |
| **不可预测行为** | 可能导致意外结果的代码 | 隐式类型转换、`TOP` 不带 `ORDER BY` 等 |

### 2.2 规则管理

| 特性 | 说明 |
|------|------|
| **规则级别** | 每个规则可设为 Error / Warning / Info |
| **自动修复** | 部分规则支持一键自动修复 |
| **禁默默认** | 可禁用不符合团队需求的默认规则 |
| **自定义规则** | 支持添加自定义代码分析规则 |
| **团队共享** | 规则配置可导出并在团队间共享 |

### 2.3 分析触发方式

| 触发方式 | 说明 |
|----------|------|
| 实时分析 | 输入代码时自动分析，即时显示问题 |
| 手动触发 | 可对整个脚本或选中代码块手动触发分析 |
| 问题列表 | 集中查看所有检测到的问题 |
| 滚动条标记 | SSMS 2016+ 在滚动条标记问题位置 |

### 2.4 UI 呈现

- 问题代码下方显示**绿色波浪线**（类似拼写检查）
- 问题列表窗口集中展示所有问题（文件/行号/严重级别/规则编号/描述）
- 支持点击问题跳转到代码对应位置

## 三、技术原理推测

### 3.1 静态分析引擎架构

```
┌─────────────────────────────────────────────┐
│              代码分析引擎                      │
├─────────────────────────────────────────────┤
│ 输入：SQL 文本                               │
│   ↓                                         │
│ 1. T-SQL 解析 → 生成完整 AST                  │
│   ↓                                         │
│ 2. AST 遍历 → 对每个节点运行规则检查器          │
│   ↓                                         │
│ 3. 每条规则 = 一个检查函数                     │
│    - 输入：AST 节点                          │
│    - 输出：Option<Issue>                     │
│   ↓                                         │
│ 4. 收集所有 Issue → 按文件/行号排序            │
│   ↓                                         │
│ 5. 输出到问题列表 + 编辑器标记                 │
└─────────────────────────────────────────────┘
```

### 3.2 规则实现示例

```
规则 ST001: "检测旧式 JOIN 语法"
  检查: 遍历 JOIN 节点
  触发: 发现 "*=" 或 "=*" 操作符
  级别: Error
  修复: 改写为 ANSI JOIN 语法
```

### 3.3 自动修复机制

自动修复的实现方式：
1. 每个规则关联一个**修复函数**
2. 修复函数输入：AST 节点 + 问题描述
3. 修复函数输出：修改后的 AST 或文本替换操作
4. 用户触发修复 → 应用修改到编辑器

## 四、用户体验亮点

1. **即时反馈**：编码时实时显示问题，无需等待构建
2. **可视化标记**：绿色波浪线 + 滚动条标记，问题位置一目了然
3. **规则可定制**：团队成员可根据项目需求调整规则级别
4. **一键修复**：减少手动修改的工作量

## 五、可实现的借鉴方案

### 5.1 技术路线

| 步骤 | 内容 | 关键技术 |
|------|------|---------|
| 1 | 实现规则框架 | 定义 `AnalysisRule` 接口（检查 + 修复） |
| 2 | 实现通用规则 | 从最简单明确的规则开始 |
| 3 | 集成编辑器 | 通过 VS Shell 的 Tagging API 实现波浪线标记 |
| 4 | 构建问题列表 UI | 工具窗口展示所有问题 |

### 5.2 规则优先级（从易到难）

| 优先级 | 规则示例 | 复杂度 |
|--------|----------|--------|
| 1 | 缺少分号 | 低（文本检查） |
| 2 | `TOP` 不带 `ORDER BY` | 低（AST 检查） |
| 3 | `SELECT *` 应具体列出列名 | 低（AST 检查） |
| 4 | 旧式 JOIN 语法 | 中（AST + 重写） |
| 5 | 隐式类型转换检测 | 中（类型系统） |
| 6 | SQL 注入风险检测 | 高（数据流分析） |

### 5.3 最小可行实现

```
阶段1（基础规则）：
  - 缺少分号检测
  - SELECT * 检测
  - TOP 不带 ORDER BY 检测
  - 旧式 JOIN 语法检测

阶段2（规则增强）：
  - 性能相关规则
  - 设计相关规则
  - 规则配置和团队共享

阶段3（智能分析）：
  - 上下文感知的安全分析
  - 数据流分析
  - 机器学习辅助的规则建议
```

## 六、优先级建议

| 评估维度 | 评分 | 说明 |
|----------|------|------|
| 实现难度 | **高** (4/5) | 需要完整的 AST + 规则引擎 + 编辑器集成 |

| 实现优先级 | **P2** | 在补全和格式化之后实施，可复用解析器成果 |
