# AI 子项目架构拆分方案

> **日期**：2026-06-02  
> **版本**：v0.2.0  
> **参考项目**：`F:\0.AI-Coding\SSMSBoostPlus`

---

## 1. 变更目标

将原 `SSMSBoostPlus.Core` 中耦合的 AI 辅助编码功能（API 调用、Prompt 构建、响应解析）独立为 `SSMSBoostPlus.AI` 子项目，并新增 `SSMSBoostPlus.Shared` 公共子项目，实现：

- **关注点分离**：Core 不再直接依赖 AI 逻辑，职责边界清晰
- **桥接模式**：引入 `ICodebuddyBridge` 接口，支持 Codebuddy CLI（首选）和 HTTP API（备选）两种 AI 调用方式
- **流式输出**：CLI 桥接原生支持 stream-json 流式响应
- **模板外置**：System Prompt 从硬编码改为 Markdown 嵌入资源文件，便于维护和迭代
- **向后兼容**：通过 `[Obsolete]` 枚举别名确保旧代码不会立即编译报错

## 3. 核心设计

### 3.1 Bridge 桥接模式

```
                    ┌──────────────────┐
                    │  ICodebuddyBridge │  ← 统一接口
                    │──────────────────│
                    │ ExecuteAsync()    │  非流式请求
                    │ ExecuteStreamAsync()│ 流式请求
                    │ IsCliAvailableAsync()│ 可用性检测
                    └────────┬─────────┘
                             │
              ┌──────────────┴──────────────┐
              │                              │
   ┌──────────▼──────────┐     ┌────────────▼──────────┐
   │ CodebuddyCliBridge  │     │  AIApiClientBridge    │
   │ (首选 - 流式支持)    │     │  (备选 - 完整响应回退) │
   └──────────┬──────────┘     └────────────┬──────────┘
              │                              │
   ┌──────────▼──────────┐     ┌────────────▼──────────┐
   │ codebuddy CLI 子进程 │     │  OpenAI 兼容 HTTP API │
   │ Process.Start()      │     │  HttpClient.PostAsync()│
   └─────────────────────┘     └───────────────────────┘
```

**选择策略**（`BridgeFactory.CreateBestAvailableBridgeAsync`）：
1. 先检测 `codebuddy` CLI 是否在 PATH 中可用（`--version` 探测）
2. 可用 → 返回 `CodebuddyCliBridge`（支持流式输出）
3. 不可用 → 回退到 `AIApiClientBridge`（HTTP API，流式为伪实现）

### 3.2 流式输出模型

```csharp
// 流式响应块类型
public enum AIStreamChunkType
{
    Text,        // 普通文本内容
    ToolUse,     // 工具/函数调用指令
    ToolResult,  // 工具调用结果
    Error,      // 错误信息
    Complete    // 流式传输完成标记
}

// 流式响应块
public class AIStreamChunk
{
    public AIStreamChunkType ChunkType { get; set; }
    public string Content { get; set; }
    public bool IsComplete { get; set; }
}
```

**CLI 流式调用**：`codebuddy -p "prompt" --output-format stream-json --append-system-prompt "..."`  
**HTTP API 流式**：不支持原生流式，`ExecuteStreamAsync` 将完整响应包装为单个 Text 块 + Complete 块

### 3.3 Prompt 模板管理

```
Markdown 资源文件（.md）           运行时加载流程
┌─────────────┐                ┌──────────────────────────┐
│ suggest.md  │──── 嵌入 ────→│ PromptTemplateManager    │
│ comment.md  │    资源       │                          │
│ format.md   │               │ 1. 尝试加载嵌入资源        │
│ analyze.md  │               │ 2. 失败 → 降级硬编码 Prompt│
└─────────────┘               └──────────────────────────┘
```

**嵌入资源配置**（csproj）：
```xml
<ItemGroup>
  <EmbeddedResource Include="Prompts\Templates\*.md">
    <LogicalName>PromptTemplates.%(Filename)%(Extension)</LogicalName>
  </EmbeddedResource>
</ItemGroup>
```

**资源命名映射**：
| PromptTemplate 枚举 | 嵌入资源名 |
|---|---|
| `Suggest` | `PromptTemplates.suggest.md` |
| `Comment` | `PromptTemplates.comment.md` |
| `Format` | `PromptTemplates.format.md` |
| `Analyze` | `PromptTemplates.analyze.md` |

## 5. 关键设计决策

### 5.1 CodeAnalysisService 从 Core 迁移到 AI

**问题**：`CodeAnalysisService` 原位于 Core 中，重构后需要调用 AI 子项目的 `ICodebuddyBridge` 接口。如果保持在 Core，会形成 **Core ↔ AI 循环依赖**。

**解决**：将 `CodeAnalysisService` 迁移到 AI 子项目，命名空间保持为 `SSMSBoostPlus.CodeAnalysis`，对上层 SSMS 命令透明。

### 5.2 BridgeFactory 自动选择策略

```
BridgeFactory.CreateBestAvailableBridgeAsync(config)
  │
  ├── 1. 创建 CodebuddyCliBridge 实例
  ├── 2. 调用 IsCliAvailableAsync() 检测 CLI
  │     ├── 可用 → 返回 CliBridge ✅（支持流式）
  │     └── 不可用 → 继续
  └── 3. 创建 AIApiClientBridge(config) 作为回退 ✅
```

### 5.3 HTTP API 流式兼容

`AIApiClientBridge.ExecuteStreamAsync` 并非真正的流式实现：
- 先调用 `ExecuteAsync` 获取完整响应
- 将结果包装为单个 `Text` 块 + `Complete` 块返回
- 调用方可统一使用 `IAsyncEnumerable<AIStreamChunk>` 接口，无需关心底层实现

### 5.4 Prompt 模板降级策略

`PromptTemplateManager.GetSystemPrompt` 三级降级：
1. **缓存命中** → 直接返回
2. **嵌入资源加载** → 从 DLL 嵌入的 `.md` 资源读取
3. **硬编码降级** → 资源加载失败时使用 `FallbackSystemPrompts` 字典中的内置 Prompt
