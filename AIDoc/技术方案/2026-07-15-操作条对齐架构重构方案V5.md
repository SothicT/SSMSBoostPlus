## 一、问题回顾

V1~V4 经过四轮修复，按钮对齐问题始终存在，每轮修复引入新问题：

| 版本 | 修复策略 | 结果 | 失败原因 |
|------|----------|------|----------|
| V1 | 修复字典偏移遗漏 | 功能正常但位置错 | 未解决定位机制本身 |
| V2 | 修复 hunkIndex 碰撞 | 同步后错位 | `_isPositioningButtons` guard 阻止异步重定位 |
| V3 | `PrecomputeBlockYPositions` 替代 `GetCharacterRect` | 全部错位 | 高度假设（18/24px）与实际不匹配 |
| V4 | `LineStackingStrategy=BlockLineHeight` + 恢复 `GetCharacterRect` | 待验证 | 仍依赖 Canvas 绝对定位 + 手动 Y 计算 |

**核心矛盾**：FlowDocument 是流式布局（动态回流），Canvas 是绝对定位（静态坐标）。两者本质不兼容，无论怎么计算 Y 坐标都只是"打补丁"。

## 二、开源项目调研

### DiffPlex（WPF 差异比对控件）

**仓库**：https://github.com/mmanela/diffplex

DiffPlex 的 `SideBySideDiffViewer` 是 .NET 生态最成熟的 WPF 差异比对控件，其架构设计值得借鉴：

#### 布局结构

```
UserControl
└── Grid (2列)
    ├── Column 0: InternalLinesViewer (左面板)
    │   └── Grid (3列: 行号 | 操作符 | 内容)
    │       ├── ScrollViewer → StackPanel (NumberPanel)
    │       ├── ScrollViewer → StackPanel (OperationPanel)
    │       └── ScrollViewer → StackPanel (ValuePanel)
    ├── GridSplitter
    └── Column 1: InternalLinesViewer (右面板)
        └── (同上结构)
```

#### 关键设计决策

| 决策 | DiffPlex 的做法 | 当前项目的做法 |
|------|----------------|---------------|
| **行容器** | `StackPanel` + `TextBlock`（每行一个） | `FlowDocument` + `Paragraph`（RichTextBox） |
| **对齐机制** | 三列 StackPanel 按相同索引添加子元素，布局引擎自动对齐 | Canvas 绝对定位 + 手动 Y 坐标计算 |
| **滚动同步** | `ScrollChanged` 事件互相同步 | 同上（已实现） |
| **行高一致性** | 所有 TextBlock 绑定相同 FontSize/FontFamily，高度天然一致 | 依赖 `LineHeight` + `LineStackingStrategy` |
| **操作按钮** | 无此功能 | Canvas + `Canvas.SetTop()` |

#### 核心洞察

DiffPlex **完全不使用 FlowDocument/RichTextBox**，而是用最简单的 `StackPanel` + `TextBlock`。每行是一个 `TextBlock`，添加到 `StackPanel` 中。对齐由 StackPanel 的顺序布局保证——**不需要任何 Y 坐标计算**。

行内差异高亮通过在 `StackPanel`（水平）中放多个 `TextBlock` 实现，每个片段绑定不同的前景色/背景色。这与 FlowDocument 的 `Run` + `Inline` 机制类似，但更简单可控。

## 三、根因总结

```
问题根因链
─────────────────────────────────────────────────────────────
Canvas 绝对定位 ← 需要手动计算每个按钮的 Y 坐标
    ↓
Y 坐标来源：GetCharacterRect（V2）或 PrecomputeBlockYPositions（V3）
    ↓
GetCharacterRect 在文档修改后返回不可靠值（V2 失败）
PrecomputeBlockYPositions 假设的高度与实际不匹配（V3 失败）
    ↓
LineStackingStrategy 默认值 MaxHeight 导致高度不匹配（V4 发现）
    ↓
即使修复高度匹配，仍需处理：异步布局时序、guard 防重入、滚动偏移同步
    ↓
每修一个边界条件，又引入新的边界条件 → 无限打补丁
```

**结论**：不能在 Canvas 绝对定位这条路上继续修补。需要从架构层面消除"手动 Y 坐标计算"。

## 四、优化方案：用 StackPanel 替代 Canvas

### 核心思路

**把操作条从"Canvas 绝对定位"改为"StackPanel 顺序布局"**。

为右侧文档的每个段落（Paragraph）在操作条 StackPanel 中创建一个对应的"格子"：
- 有按钮的段落 → 格子里放按钮
- 没有按钮的段落 → 格子里放透明占位
- 占位段落（24px）→ 格子高度 24px
- 普通段落（18px）→ 格子高度 18px

StackPanel 自动按顺序堆叠，**累积 Y 位置由 WPF 布局引擎自动计算**，无需任何手动 Y 坐标计算。

### 架构对比

```
❌ 当前架构（V1~V4）
─────────────────────────────────────────────
Grid
├── Column 0: LeftViewer (RichTextBox → FlowDocument → Paragraphs)
├── Column 2: ActionStripScroller (ScrollViewer)
│   └── ActionStripCanvas (Canvas)          ← 绝对定位
│       ├── Button at Canvas.Top = 0        ← 手动计算
│       ├── Button at Canvas.Top = 36       ← 手动计算
│       └── Button at Canvas.Top = 72       ← 手动计算
└── Column 3: RightViewer (RichTextBox → FlowDocument → Paragraphs)

需要：PrecomputeBlockYPositions() + GetCharacterRect() + RepositionAllButtons()
     + PositionActionButtons() + _isPositioningButtons guard
     + Canvas.Height 同步 + ScrollToVerticalOffset 同步


✅ 新架构（V5）
─────────────────────────────────────────────
Grid
├── Column 0: LeftViewer (RichTextBox → FlowDocument → Paragraphs)  ← 不变
├── Column 2: ActionStripScroller (ScrollViewer)                     ← 不变
│   └── ActionStripPanel (StackPanel)         ← 顺序布局
│       ├── [0] Spacer  Height=18             ← 对齐 Paragraph 0
│       ├── [1] Button  Height=18             ← 对齐 Paragraph 1
│       ├── [2] Spacer  Height=18             ← 对齐 Paragraph 2
│       ├── [3] Spacer  Height=24             ← 对齐占位 Paragraph 3
│       └── [4] Button  Height=18             ← 对齐 Paragraph 4
└── Column 3: RightViewer (RichTextBox → FlowDocument → Paragraphs)  ← 不变

需要：仅维护 StackPanel 子元素索引与段落索引的对应关系
删除：PrecomputeBlockYPositions() / GetCharacterRect() / RepositionAllButtons()
     / PositionActionButtons() / _isPositioningButtons / Canvas.SetTop()
```

### 为什么 StackPanel 能彻底解决问题

| 问题 | Canvas（当前） | StackPanel（新方案） |
|------|---------------|---------------------|
| Y 坐标计算 | 手动计算每个按钮 Y | **不需要** — StackPanel 自动堆叠 |
| 高度不匹配 | PrecomputeBlockYPositions 假设高度错误 → 累积漂移 | 每个格子独立设置 Height，与对应段落一致 |
| GetCharacterRect 不可靠 | 文档修改后返回过期值 | **不使用** GetCharacterRect |
| 异步布局时序 | 需 Render/Background 两次异步校正 | **不需要** — StackPanel 布局是同步的 |
| guard 防重入 | `_isPositioningButtons` 阻止重定位 | **不需要** — 没有"重定位"操作 |
| 滚动偏移同步 | 需手动同步 Canvas.Height + ScrollToVerticalOffset | StackPanel 的 ExtentHeight 自动 = 子元素高度之和 |
| 同步/撤销后按钮位置 | 需重新计算所有按钮 Y | 只需在正确索引插入/移除格子，其余格子自动移位 |
| 窗口缩放 | 文本回流 → Y 坐标全变 → 需重新定位 | StackPanel 子元素高度不变 → 自动正确 |

## 五、详细修改方案

### 5.1 XAML 修改

**文件**：`AIDiffDialog.xaml`

```xml
<!-- ❌ 原代码 -->
<ScrollViewer x:Name="ActionStripScroller" Grid.Row="1"
              VerticalScrollBarVisibility="Hidden"
              HorizontalScrollBarVisibility="Disabled"
              Background="#F5F5F5"
              BorderBrush="#E0E0E0"
              BorderThickness="0,0,1,0"
              Focusable="False">
    <Canvas x:Name="ActionStripCanvas" Width="24" />
</ScrollViewer>

<!-- ✅ 新代码 -->
<ScrollViewer x:Name="ActionStripScroller" Grid.Row="1"
              VerticalScrollBarVisibility="Hidden"
              HorizontalScrollBarVisibility="Disabled"
              Background="#F5F5F5"
              BorderBrush="#E0E0E0"
              BorderThickness="0,0,1,0"
              Focusable="False">
    <StackPanel x:Name="ActionStripPanel" Width="24" />
</ScrollPanel>
```

**改动量**：1 行 — `Canvas` 改为 `StackPanel`，`ActionStripCanvas` 改名为 `ActionStripPanel`。

### 5.2 字段修改

**文件**：`AIDiffDialog.xaml.cs`

```csharp
// ❌ 删除
// 无需 _isPositioningButtons（不再有异步重定位）
private bool _isPositioningButtons;

// ✅ _actionButtons 语义不变：blockIndex → Button 控件
// 但不再需要 Canvas.SetTop，按钮的 Y 位置由 StackPanel 自动决定
private readonly Dictionary<int, Button> _actionButtons = new();

// ✅ 新增：操作条格子列表，索引 = 段落索引，值 = StackPanel 中的子元素
// 用于在同步/撤销时按索引插入/移除格子
private readonly List<FrameworkElement> _actionStripSlots = new();
```

### 5.3 `PopulateActionStrip` 重写

**核心变化**：不再计算 Y 坐标，而是为每个段落创建一个等高的格子。

```csharp
private void PopulateActionStrip()
{
    ActionStripPanel.Children.Clear();
    _actionButtons.Clear();
    _actionStripSlots.Clear();

    RightViewer.UpdateLayout();
    LeftViewer.UpdateLayout();

    // 获取所有段落，确定每个段落的高度
    var blockCount = RightViewer.Document.Blocks.OfType<Paragraph>().Count();

    // 第一步：为每个段落创建一个等高格子
    for (int i = 0; i < blockCount; i++)
    {
        double slotHeight = _placeholderBlocks.Contains(i) ? 24.0 : 18.0;
        var slot = CreateActionSlot(slotHeight);
        _actionStripSlots.Add(slot);
        ActionStripPanel.Children.Add(slot);
    }

    // 第二步：在对应格子里放入同步按钮
    for (int h = 0; h < _diffHunks.Count; h++)
    {
        var hunk = _diffHunks[h];
        int blockIndex = hunk.BlockStartIndex;
        if (blockIndex < 0 || blockIndex >= _actionStripSlots.Count) continue;

        var button = CreateSyncButton(h, hunk.HunkChangeType);
        _actionButtons[blockIndex] = button;

        // 将按钮放入对应的格子（替换占位内容）
        var slot = _actionStripSlots[blockIndex];
        if (slot is Grid grid)
        {
            grid.Children.Clear();
            grid.Children.Add(button);
        }
    }

    // 第三步：在对应格子里放入恢复按钮
    foreach (var kvp in _hunkInsertedBlocks)
    {
        int syncId = kvp.Key;
        var syncState = kvp.Value;

        int blockIndex;
        if (syncState.Inserted.Count > 0)
            blockIndex = syncState.Inserted.First();
        else
            blockIndex = syncState.OrigStart;

        if (blockIndex < 0 || blockIndex >= _actionStripSlots.Count) continue;
        if (_actionButtons.ContainsKey(blockIndex)) continue;

        var button = CreateUndoButton(syncId);
        _actionButtons[blockIndex] = button;

        var slot = _actionStripSlots[blockIndex];
        if (slot is Grid grid)
        {
            grid.Children.Clear();
            grid.Children.Add(button);
        }
    }

    // 无需异步重定位！StackPanel 布局是同步的
    // 无需 _isPositioningButtons guard！
    // 无需 PrecomputeBlockYPositions！
    // 无需 RepositionAllButtons！
}

/// <summary>
/// 创建操作条格子：一个固定高度的 Grid，内含居中的内容占位。
/// 格子高度与对应段落高度一致，StackPanel 自动累积定位。
/// </summary>
private Grid CreateActionSlot(double height)
{
    var grid = new Grid
    {
        Height = height,
        Width = 24,
        HorizontalAlignment = HorizontalAlignment.Center,
        VerticalAlignment = VerticalAlignment.Top
    };
    return grid;
}
```

### 5.4 删除的方法（不再需要）

| 方法 | 原因 |
|------|------|
| `PrecomputeBlockYPositions()` | StackPanel 自动累积高度，不需要预计算 Y |
| `RepositionAllButtons()` | 没有"重定位"操作，StackPanel 布局是自动的 |
| `PositionActionButtons()` | 不需要异步重定位 |
| 所有 `Canvas.SetTop()` 调用 | 不再使用 Canvas |
| 所有 `GetCharacterRect()` 调用 | 不再需要获取段落位置 |
| `_isPositioningButtons` guard | 不再有异步重定位的防重入需求 |

### 5.5 滚动同步简化

**当前**（Canvas 模式）：
```csharp
// 需要手动同步 Canvas 高度
ActionStripCanvas.Height = Math.Max(rightSv.ExtentHeight, rightSv.ViewportHeight);
// 需要手动同步滚动偏移
ActionStripScroller.ScrollToVerticalOffset(rightSv.VerticalOffset);
```

**新方案**（StackPanel 模式）：
```csharp
// StackPanel 的 ExtentHeight 自动 = 所有子元素高度之和
// 只需同步滚动偏移（已有代码，保留即可）
ActionStripScroller.ScrollToVerticalOffset(rightSv.VerticalOffset);
// 删除 ActionStripCanvas.Height = ... 这行（StackPanel 无需手动设高度）
```

### 5.6 `SyncHunk` / `UndoHunk` 中的按钮管理

同步/撤销操作会在文档中插入/删除段落，需要同步操作 StackPanel 的子元素。

#### SyncHunk（同步操作）

```csharp
// 在文档中插入新段落后，同步在 StackPanel 中插入对应格子
for (int i = 0; i < insertedCount; i++)
{
    int idx = insertAt + i;

    // ... 插入文档段落的现有代码 ...

    // ★ 新增：在 StackPanel 中插入等高格子（含恢复按钮）
    var slot = CreateActionSlot(18.0); // 同步插入的段落都是 18px
    var undoButton = CreateUndoButton(syncId);
    _actionButtons[idx] = undoButton;
    slot.Children.Add(undoButton);

    // 在 StackPanel 和 _actionStripSlots 中插入
    ActionStripPanel.Children.Insert(idx, slot);
    _actionStripSlots.Insert(idx, slot);

    // 移除原来在该位置的同步按钮（如果有）
    // 注意：ShiftDictionaryKeys 已经处理了 _actionButtons 的索引偏移
    // 被偏移的旧按钮需要从旧格子中移除
}

// ★ 原来的同步按钮需要从格子中移除（该 hunk 已同步，不再需要同步按钮）
// _diffHunks 中该 hunk 已被移除，PopulateActionStrip 会重建
// 或者直接操作：
if (_actionButtons.TryGetValue(hunkBlockStart, out var syncButton))
{
    var slot = _actionStripSlots[hunkBlockStart];
    slot.Children.Clear();
    slot.Children.Add(undoButton);
    _actionButtons[hunkBlockStart] = undoButton;
}
```

#### UndoHunk（撤销操作）

```csharp
// 从文档中删除段落后，同步从 StackPanel 中删除对应格子
for (int i = 0; i < removedCount; i++)
{
    int idx = insertAt; // 总是删除同一位置

    // ... 删除文档段落的现有代码 ...

    // ★ 新增：从 StackPanel 中删除对应格子
    if (idx < _actionStripSlots.Count)
    {
        ActionStripPanel.Children.RemoveAt(idx);
        _actionStripSlots.RemoveAt(idx);
    }
    _actionButtons.Remove(idx);
}

// ★ 在原 hunk 位置重新放入同步按钮
var slot = CreateActionSlot(18.0);
var syncButton = CreateSyncButton(hunkIndex, hunkChangeType);
_actionButtons[hunkBlockStart] = syncButton;
slot.Children.Add(syncButton);
ActionStripPanel.Children.Insert(hunkBlockStart, slot);
_actionStripSlots.Insert(hunkBlockStart, slot);
```

### 5.7 窗口缩放处理

**当前**：`RightViewer.SizeChanged += (s, e) => PositionActionButtons();`

**新方案**：**删除此行**。StackPanel 子元素的 Height 是固定值（18/24px），窗口缩放不会改变格子高度，StackPanel 自动正确布局。

### 5.8 `LineStackingStrategy` 保留

V4 添加的 `LineStackingStrategy = BlockLineHeight` **仍然需要保留**，确保段落实际高度 = 18px/24px，与 StackPanel 格子高度一致。

## 八、为什么这次能根本性解决

| V1~V4 的修补方向 | V5 的方向 |
|------------------|-----------|
| 让 Y 坐标计算更准确 | **不需要计算 Y 坐标** |
| 让 GetCharacterRect 返回可靠值 | **不使用 GetCharacterRect** |
| 让异步重定位不被 guard 阻止 | **不需要异步重定位** |
| 让假设高度与实际高度匹配 | **每个格子独立设置高度，与段落一一对应** |
| 处理窗口缩放后的回流 | **格子高度固定，缩放无影响** |

V5 从架构层面消除了"手动 Y 坐标计算"这一所有问题的根源，改为让 WPF 布局引擎自动处理定位。

## 九、风险与回退

### 风险

| 风险 | 概率 | 缓解 |
|------|------|------|
| StackPanel 性能（大量子元素） | 低 | 差异比对通常 < 200 行，StackPanel 完全可处理 |
| 格子高度与段落高度仍不匹配 | 低 | `LineStackingStrategy=BlockLineHeight`（V4）已确保段落高度 = LineHeight |
| 同步/撤销时索引管理复杂 | 中 | 已有 `ShiftDictionaryKeys` / `UnshiftDictionaryKeys` 机制，StackPanel 的 `Insert`/`RemoveAt` 与之配合 |

### 回退

如果 V5 方案验证失败，可回退到 V4（Git 回滚）。V4 的 `LineStackingStrategy=BlockLineHeight` 修复仍然有效。
