## 问题现象

上一轮修复（`_lineChangeTypes` 偏移 + Canvas 高度同步 + 二次异步校正）后，问题仍然存在：

1. 打开差异比对弹窗，按钮初始位置正确 ✅
2. 点击同步按钮 → 恢复按钮**不在**同步行位置 ❌
3. 点击多个同步按钮 → 每个恢复按钮位置都**不正确** ❌
4. 点击恢复（撤销）→ 同步按钮位置**不变** ❌

## 根因分析

### 🔴 根因 1（主因）：hunkIndex 碰撞导致同步被跳过

**核心问题**：`_hunkInsertedBlocks` 使用 `_diffHunks` 的**列表索引**作为 key，但 `RebuildDiffHunksFromState()` 会完全重建 `_diffHunks`，导致索引重新编号，与已存在的 `_hunkInsertedBlocks` key 碰撞。

#### 详细追踪

**初始状态**（Hunk-Only 模式示例）：

```
_diffHunks = [
  hunk0: blocks 1-3   (Tag=0)
  hunk1: blocks 5-7   (Tag=1)
  hunk2: blocks 9-11  (Tag=2)
]
_hunkInsertedBlocks = {}
```

**用户点击 hunk0 的同步按钮（Tag=0）**：

```
Step 1: SyncHunk(0)
  ├── insertAt = 1, insertedCount = 2
  ├── ShiftDictionaryKeys（所有 >= 1 的 key +2）
  ├── 插入 2 个新段落到 blocks 1, 2
  ├── 标记 blocks 3-5 为 ResolvedBackground
  └── _hunkInsertedBlocks[0] = ([1, 2], 1, 3)  ← key = hunkIndex = 0

Step 2: RebuildDiffHunksFromState()
  ├── blocks 1-2: SyncedBackground → 不是 diff
  ├── blocks 3-5: ResolvedBackground → 不是 diff
  ├── blocks 7-9: ConflictBackground → 是 diff ← 新 hunk0
  └── blocks 11-13: ConflictBackground → 是 diff ← 新 hunk1

  _diffHunks = [
    new_hunk0: blocks 7-9   (原 hunk1，重新编号为 0)
    new_hunk1: blocks 11-13 (原 hunk2，重新编号为 1)
  ]

Step 3: PopulateActionStrip()
  ├── 同步按钮: _diffHunks[0] → Tag=0, blockIndex=7
  ├── 同步按钮: _diffHunks[1] → Tag=1, blockIndex=11
  └── 恢复按钮: _hunkInsertedBlocks[0] → blockIndex=1, Tag=0
```

**碰撞发生**：`_hunkInsertedBlocks` 的 key=0 与 `_diffHunks` 的 index=0 **指向完全不同的 hunk**！

**用户点击 new_hunk0 的同步按钮（Tag=0）**：

```csharp
// SyncHunk(0) — 第 1692 行
if (_hunkInsertedBlocks.ContainsKey(0)) return;  // ← TRUE！直接返回！
```

**同步被跳过！** 用户点击同步按钮但没有任何反应。

#### 影响链

```
SyncHunk(0) 被 _hunkInsertedBlocks.ContainsKey(0) 跳过
    ↓
用户以为同步成功，但实际什么都没发生
    ↓
恢复按钮不出现（因为 SyncHunk 没有执行）
    ↓
用户看到的是旧的恢复按钮（位置可能因布局变化而偏移）
    ↓
表现为"恢复按钮位置不正确"
```

### 🔴 根因 2：SyncAll_Click 中相同的碰撞

**位置**：第 2846 行

```csharp
for (int h = 0; h < _diffHunks.Count; h++)
{
    if (_hunkInsertedBlocks.ContainsKey(h)) continue;  // ← 碰撞！
    // ...
    unsyncedHunks.Add(h);
}
```

如果在"全部同步"之前有过个别同步操作，`_hunkInsertedBlocks` 中已有 key=0，而 `RebuildDiffHunksFromState` 后 `_diffHunks[0]` 是一个新的未同步 hunk，这个 hunk 会被**错误跳过**。

### 🟡 根因 3：恢复按钮初始定位使用过时的布局坐标

`PopulateActionStrip` 在 `SyncHunk` + `RenumberRightParagraphs` 之后立即调用 `GetCharacterRect`。虽然 `UpdateLayout()` 被调用，但 WPF FlowDocument 在大量段落插入 + 文本修改后可能需要多个布局周期才能完全稳定。

异步 `PositionActionButtons` 应该修正，但 `_isPositioningButtons` guard 在 `SizeChanged` 事件触发时序下可能跳过异步校正。

## 修复方案

### 核心思路：引入唯一 syncId，解耦 hunkIndex 与 _hunkInsertedBlocks key

```
当前：  sync按钮 Tag = hunkIndex  →  SyncHunk(hunkIndex)  →  _hunkInsertedBlocks[hunkIndex]
                                        ↑ 碰撞！

修复后：sync按钮 Tag = hunkIndex  →  SyncHunk(hunkIndex)  →  _hunkInsertedBlocks[syncId]
                                        ↑ hunkIndex 仅用于查找 hunk
                                          syncId 是唯一递增计数器，永不碰撞
```

### 修复 1：添加唯一 syncId 计数器

**文件**：`AIDiffDialog.xaml.cs`

在字段声明区域（约第 118 行附近）添加：

```csharp
// 唯一同步 ID 计数器，用于 _hunkInsertedBlocks 的 key
// 避免 hunkIndex 在 RebuildDiffHunksFromState 后重新编号导致的碰撞
private int _nextSyncId = 0;
```

### 修复 2：SyncHunk 使用 syncId 替代 hunkIndex 作为 key

**位置**：`SyncHunk()` 方法

**修改点 A** — 移除 hunkIndex 碰撞检查，改为 block 级别检查（约第 1691-1692 行）：

```csharp
// ❌ 删除：
// 已同步则跳过
if (_hunkInsertedBlocks.ContainsKey(hunkIndex)) return;

// ✅ 替换为：检查 hunk 首行是否已被同步/解决
if (_rightIndicatorBackgrounds.TryGetValue(hunk.BlockStartIndex, out var startBg)
    && (ReferenceEquals(startBg, SyncedBackground) || ReferenceEquals(startBg, ResolvedBackground)))
    return;
```

**修改点 B** — 生成唯一 syncId 并用作 key（约第 1769-1770 行，空 DB 行分支）：

```csharp
// ❌ 删除：
_hunkInsertedBlocks[hunkIndex] = (new List<int>(), hunk.BlockStartIndex, hunk.BlockEndIndex);

// ✅ 替换为：
int syncId = _nextSyncId++;
_hunkInsertedBlocks[syncId] = (new List<int>(), hunk.BlockStartIndex, hunk.BlockEndIndex);
```

**修改点 C** — 生成唯一 syncId 并用作 key（约第 1854-1855 行，正常同步分支）：

```csharp
// ❌ 删除：
_hunkInsertedBlocks[hunkIndex] = (insertedIndices, hunk.BlockStartIndex, hunk.BlockEndIndex);

// ✅ 替换为：
int syncId = _nextSyncId++;
_hunkInsertedBlocks[syncId] = (insertedIndices, hunk.BlockStartIndex, hunk.BlockEndIndex);
```

**修改点 D** — 更新 shift 其他条目时的跳过条件（约第 1870 行）：

```csharp
// ❌ 删除：
if (other.Key == hunkIndex) continue;

// ✅ 替换为：
if (other.Key == syncId) continue;
```

> **注意**：修改点 B 和 C 都需要生成 syncId。由于 B 在 `return` 之前，C 在方法主体中，需要确保两个分支各自生成独立的 syncId。

### 修复 3：UndoHunk 参数语义变更

**位置**：`UndoHunk()` 方法（约第 1921 行）

参数从 `hunkIndex` 变为 `syncId`，但方法签名不变（仍是 `int`），只需更新注释和内部逻辑：

```csharp
// ❌ 原签名注释：
/// 撤销指定 hunk 的同步：移除插入的段落，恢复冲突行指示器。
private void UndoHunk(int hunkIndex)
{
    if (!_hunkInsertedBlocks.TryGetValue(hunkIndex, out var syncState)) return;

// ✅ 新签名注释：
/// 撤销指定同步操作：移除插入的段落，恢复冲突行指示器。
/// 参数 syncId 是 _hunkInsertedBlocks 的 key（由 SyncHunk 生成）。
private void UndoHunk(int syncId)
{
    if (!_hunkInsertedBlocks.TryGetValue(syncId, out var syncState)) return;
```

方法内部所有引用 `hunkIndex` 的地方改为 `syncId`：
- 第 1958 行：`_hunkInsertedBlocks.Remove(hunkIndex)` → `Remove(syncId)`
- 第 2012 行：`_hunkInsertedBlocks.Remove(hunkIndex)` → `Remove(syncId)`

### 修复 4：SyncAll_Click 移除碰撞检查

**位置**：`SyncAll_Click()` 方法（约第 2846 行）

```csharp
// ❌ 删除：
if (_hunkInsertedBlocks.ContainsKey(h)) continue;

// ✅ 替换为：检查 hunk 首行是否已被同步
var hunk = _diffHunks[h];
if (_rightIndicatorBackgrounds.TryGetValue(hunk.BlockStartIndex, out var bg)
    && (ReferenceEquals(bg, SyncedBackground) || ReferenceEquals(bg, ResolvedBackground)))
    continue;
```

注意：原代码在 `ContainsKey` 之后才获取 `hunk`，现在需要先获取 `hunk` 再检查。

### 修复 5：PopulateActionStrip 中恢复按钮 Tag 自动适配

**位置**：`PopulateActionStrip()` 方法（约第 1295-1297 行）

**无需修改**。当前代码已经是：

```csharp
foreach (var kvp in _hunkInsertedBlocks)
{
    int hunkIdx = kvp.Key;  // ← 现在 kvp.Key 是 syncId，自动正确
    var syncState = kvp.Value;
    // ...
    var button = CreateUndoButton(hunkIdx);  // ← Tag = syncId
}
```

`UndoBlock_Click` 将 `Tag`（syncId）传给 `UndoHunk(syncId)`，`UndoHunk` 用 `syncId` 查找 `_hunkInsertedBlocks[syncId]`。整个链条自动正确。

### 修复 6：MergedScript 计算无需修改

**位置**：约第 227-247 行

当前代码遍历 `_hunkInsertedBlocks` 使用 `kvp.Value`，不依赖 key 的语义，无需修改。

## 验证场景

### 场景 2：多个同步

1. 点击第一个同步按钮 → 恢复按钮在正确位置 ✅

3. 点击第三个同步按钮 → 第三个恢复按钮在正确位置 ✅
4. 三个恢复按钮同时存在且位置正确 ✅

### 场景 3：撤销

1. 同步后点击恢复按钮 → 同步按钮重新出现在正确位置 ✅
2. 连续撤销多个 → 每次同步按钮位置正确 ✅

### 场景 4：全部同步

1. 点击"全部同步" → 所有恢复按钮同时出现且位置正确 ✅
2. 逐个撤销 → 每次同步按钮位置正确 ✅

### 场景 5：部分同步 + 全部同步

1. 先同步第一个 hunk
2. 再点击"全部同步" → 其余 hunk 被同步，恢复按钮位置正确 ✅
