## 现象

点击比对窗口的"在编辑器中打开"按钮后，比对窗口自动关闭，SSMS 主编辑器区域正确打开了新的标签页并加载了脚本内容，但 Backspace、Enter 等键盘按键在该新标签页中仍然失效。

## 日志证据

日志文件：`ssmsboostplus-2026072019.log`，两次复现：

```
# 第一次
19:05:23.807 [INF] 历史版本脚本已在编辑器中打开    ← NewFile + ReplaceText 成功
19:05:23.876 [DBG] WindowActivated: Kind=Tool        ← 焦点错误回到 ToolWindow

# 第二次（上一轮修复后）
19:31:25.060 [INF] 历史版本脚本已在编辑器中打开    ← NewFile + ReplaceText 成功
19:31:25.135 [DBG] WindowActivated: Kind=Tool        ← 焦点仍然错误回到 ToolWindow
```

第二轮复现时已部署了 `dte?.MainWindow?.Activate()` 修复，但焦点仍回到 ToolWindow（Kind=Tool），说明 `MainWindow.Activate()` 激活了 SSMS 主窗口框架但并未将键盘焦点置于新创建的文档标签页内的编辑器控件上。

## 根因分析

问题出在两个层面：

### 层面一：dialog 关闭前未激活新文档

`OpenInEditorButton_Click` 的执行流程（`LocalHistoryDiffDialog.xaml.cs` 行 424-465）：

```
NewFile → doc = ActiveDocument → ReplaceText → success=true → DialogResult=true; Close()
```

关键问题：`NewFile` 创建了新文档标签页，但紧接着 `DialogResult=true` 触发 dialog 关闭。此时 WPF 模态机制开始归还焦点——由于 `Owner=null`，焦点被归还到了 ToolWindow（WPF 视角的"上一个活动窗口"），而非 SSMS 中新创建的编辑器标签页。新文档标签页虽然存在且内容正确，但没有键盘焦点。

### 层面二：上一轮修复不够精准

上一轮在 `ShowDialog()` 之后加了 `dte?.MainWindow?.Activate()`。这激活了 SSMS 主窗口的框架（标题栏高亮），但并未将焦点聚焦到内部的文档标签页编辑器中。SSMS 主窗口中有多个子窗口（工具窗口、编辑器标签页等），`MainWindow.Activate()` 只是把主窗口提到前台，不保证编辑器控件获得键盘焦点。

## 修复方案

两处修改：

### 修改一：`LocalHistoryDiffDialog.xaml.cs` — 关闭前激活新文档

在 `OpenInEditorButton_Click` 方法（约行 452）中，`success = true` 之后、`DialogResult` 设置之前，增加 `doc.Activate()`：

```csharp
success = true;
doc.Activate();   // 确保新文档标签页在 dialog 关闭前获得焦点
_logger.Information($"[LocalHistory] 历史版本脚本已在编辑器中打开");
```

这确保在 WPF 模态 dialog 关闭并归还焦点之前，新创建的 SSMS 编辑器标签页已经处于激活状态。

### 修改二：`LocalHistoryToolWindowControl.xaml.cs` — 更精准的焦点恢复

将当前行 796-804 的 `MainWindow?.Activate()` 替换为：

```csharp
try
{
    var dte = Microsoft.VisualStudio.Shell.Package.GetGlobalService(typeof(EnvDTE.DTE)) as EnvDTE.DTE;
    if (diffDialog.DialogResult == true && dte?.ActiveDocument != null)
    {
        // "在编辑器中打开" 路径：激活新创建的文档标签页
        dte.ActiveDocument.Activate();
    }
    else
    {
        // "关闭" 按钮路径：激活主窗口兜底
        dte?.MainWindow?.Activate();
    }
}
catch
{
    // 非致命
}
```

## 边缘情况与异常处理

- DTE 为 null：`?.` 安全导航，不抛异常
- ActiveDocument 为 null（NewFile 失败）：走 else 分支，`MainWindow?.Activate()` 兜底
- "关闭"按钮（非"在编辑器中打开"）：`DialogResult` 未被设置为 true，走 else 分支
- `doc.Activate()` 在 dialog 内调用：该调用发生在 dialog 关闭前，DTE 操作不影响 WPF 模态循环
- COM 异常：catch 静默吞掉

## 结论

`MainWindow.Activate()` 只激活窗口框架，不激活内部的编辑器控件。需要两步修复：(1) 在 dialog 关闭前通过 `doc.Activate()` 确保新文档标签页已激活；(2) `ShowDialog()` 后通过 `ActiveDocument.Activate()` 精准激活文档标签页而非仅激活主窗口框架。
