## 一、改造背景

### 1.1 问题发现

在对比分析 `build-and-deploy` Skill 与 `小H发布部署` Agent 时，发现 3 类 P0 级别问题：

| # | 问题 | 严重度 | 影响 |
|---|------|--------|------|
| 1 | SSMS 22 路径硬编码为 `D:\Program Files\Microsoft SQL Server Management Studio 22\...` | 🔴 P0 | 实际机器路径不一致会导致部署失败 |
| 2 | 编译命令使用 `.sln` + `MSBuild.exe` | 🔴 P0 | `.sln` 被企业加密软件加壳，编译必然失败 |
| 3 | 核心 DLL 清单仅列 2 个（SSMS+Core），遗漏 AI+Shared | 🔴 P0 | 部署后扩展无法加载（缺依赖） |

### 1.2 关键决策

经用户确认采用 **方案 A**（仅修改小H，Skill 保持原样）：

- **小H** 是"动手层"（执行者）
- **Skill** 是"知识层"（SOP 模板，保留通用性）
- 职责分离：动态检测属于运行时行为，归属 Agent 而非 Skill

## 二、改造内容详解

### 2.1 步骤 2.2：编译命令修正

#### 改动前
```powershell
# 使用 .sln + MSBuild.exe
& "D:\Program Files\Microsoft Visual Studio\18\Enterprise\MSBuild\Current\Bin\MSBuild.exe" "SSMSBoostPlus.sln" /p:Configuration=Release /t:Build /m /nologo /v:minimal
```

#### 改动后
```powershell
# 优先 dotnet CLI（.NET 10 SDK 已自带 MSBuild）
dotnet build SSMSBoostPlus.slnx -c Release
```

#### 设计要点

| 层级 | 命令 | 适用场景 |
|------|------|---------|
| 优先 | `dotnet build SSMSBoostPlus.slnx -c Release` | 标准流程 |
| 备选 | `dotnet build SSMSBoostPlus.slnx -c Debug` | 调试模式 |
| 备选 | `dotnet clean ... && dotnet build ...` | 干净重建 |
| 兜底 | `MSBuild.exe "SSMSBoostPlus.slnx" /p:Configuration=Release /t:Build` | dotnet 不可用时 |

**关键变化**：
- 解决方案：`.sln` → `.slnx`（必须，避免企业加密加壳）
- 编译器：`MSBuild.exe` → `dotnet build`（优先，路径自适应）
- DLL 验证：2 个 → 4 个（SSMS+Core+AI+Shared）
- 新增：`SSMSBoostPlus.SSMS.pkgdef` 生成校验（VSSDK 自动管道产物）

### 2.2 步骤 3：新增 SSMS 22 动态路径检测

#### 2.2.1 6 级检测策略

```
┌─────────────────────────────────────────────────────────────┐
│ Tier 1: 用户显式配置（最快、零开销）                           │
│   └─ 读取 %APPDATA%\SSMSBoostPlus\config.json               │
│      → ssms_install_path 字段                                │
├─────────────────────────────────────────────────────────────┤
│ Tier 2: 环境变量（团队约定）                                   │
│   └─ 检查 $env:SSMS22_PATH / $env:SSMS_INSTALL_PATH         │
├─────────────────────────────────────────────────────────────┤
│ Tier 3: vswhere.exe（VS 官方工具，最权威）                    │
│   └─ %ProgramFiles(x86)%\Microsoft Visual Studio\Installer\  │
│      vswhere.exe -prerelease -products * -property           │
│      installationPath → 解析 SSMS 路径                       │
├─────────────────────────────────────────────────────────────┤
│ Tier 4: 注册表查询（Windows 安装元数据）                        │
│   ├─ HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall│
│   ├─ HKLM\SOFTWARE\WOW6432Node\...\Uninstall                 │
│   └─ 筛选 DisplayName 包含 "SQL Server Management Studio 22" │
├─────────────────────────────────────────────────────────────┤
│ Tier 5: 常见路径扫描（兜底）                                    │
│   ├─ D:\Microsoft SQL Server Management Studio 22\Release\   │
│   ├─ C:\Program Files\Microsoft SQL Server Management Studio 22\│
│   └─ E:\ / F:\Microsoft SQL Server Management Studio 22\      │
├─────────────────────────────────────────────────────────────┤
│ Tier 6: 进程探测（最终兜底）                                   │
│   └─ Get-Process SSMS → MainModule.FileName → 向上推导根目录  │
└─────────────────────────────────────────────────────────────┘
```

#### 2.2.2 各 Tier 特性对比

| Tier | 速度 | 准确性 | 覆盖率 | 适用场景 |
|------|------|--------|--------|---------|
| 1 用户配置 | ⚡⚡⚡⚡⚡ | ⭐⭐⭐⭐⭐ | 🟢 个人/团队 | 部署过本扩展的机器 |
| 2 环境变量 | ⚡⚡⚡⚡⚡ | ⭐⭐⭐⭐⭐ | 🟡 团队规范 | 企业统一规范 |
| 3 vswhere | ⚡⚡⚡⚡ | ⭐⭐⭐⭐ | 🟢 VS 用户 | 装了 VS 的开发机 |
| 4 注册表 | ⚡⚡⚡ | ⭐⭐⭐⭐⭐ | 🟢 标准安装 | Windows 标准安装 |
| 5 常见路径 | ⚡⚡ | ⭐⭐⭐ | 🟡 常见布局 | D/E/F 盘用户 |
| 6 进程探测 | ⚡⚡ | ⭐⭐⭐⭐ | 🟡 运行中 | 已启动 SSMS |

#### 2.2.3 持久化机制

检测成功后，结果写入：
```
%APPDATA%\SSMSBoostPlus\config.json
```

文件内容格式：
```json
{
  "ssms_install_path": "D:\\Microsoft SQL Server Management Studio 22\\Release",
  "detection_time": "2026-07-02 14:05:23",
  "detection_source": "registry"
}
```

**复用路径**：小H 现有的 `update_memory` 机制可与该文件联动，作为跨会话记忆。

#### 2.2.4 失败兜底

当 6 级全部失败时：
```
[⚠️ 自动检测失败] 未找到 SSMS 22 安装路径
请选择处理方式：
  1. 手动指定路径（请输入完整根目录，如 D:\Microsoft SQL Server Management Studio 22\Release）
  2. 跳过本次部署
  3. 取消

> 选择 1
> 请输入 SSMS 22 安装根目录: ___
> ✅ 已记录到用户配置，下次自动使用
```

### 2.5 步骤 8：新增部署后强制刷新

#### 新增内容
```powershell
# 【关键】强制刷新 PkgDef 缓存
& "$ssmsInstallPath\Common7\IDE\SSMS.exe" /setup
```

#### 涉及的关键知识

| 项 | 值 |
|---|---|
| **命令** | `SSMS.exe /setup` |
| **作用** | 强制 SSMS 重新扫描合并 pkgdef 到私有注册表 |
| **私有注册表** | `HKU\<SID>\Software\Microsoft\SSMS\22.0_79c71968_Config\` |
| **注意** | 是 `_Config` 后缀，**不是** `_Configuration` |
| **ActivityLog** | `%APPDATA%\Microsoft\Ssms\22.0_79c71968\Configration\ActivityLog.xml` |
| **日志时区** | UTC（本地时间需 +8h） |
