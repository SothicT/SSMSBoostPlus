## 2. 产品概述

### 2.1 业务背景与问题陈述

v1（2026-07-28 PRD）实现了基于 SQL 语句级上下文感知的补全引擎，覆盖 SELECT/INSERT/UPDATE/DELETE/EXEC 五大 DML 的语法节点映射和字段/表名/关键词的上下文分发。用户在 v1 版本的实际使用中发现以下问题：

1. **WHERE 后关键词限制过度**：WHERE/HAVING/ON 条件区只提示 `AND/OR/IN/BETWEEN/LIKE/IS/NOT/NULL` 8 个条件运算符，不提示 `GROUP BY`、`ORDER BY`、`HAVING`、`OFFSET`、`UNION` 等后续合法子句。用户需要补全完整 SQL 时被迫手动输入。

2. **`SELECT TOP 100 *` 的常量被误识别为列别名**：`100` 被 `SelectColumnPattern` 捕获为列名并加入别名列表，导致 `ORDER BY` 时出现错误提示。

3. **空行后补全内容单一**：光标在未完成语句之后的新空行上，系统仅展示未完成语句的上下文关键词，不会同时展示通用 SQL 模板和组合片段（如 `OFFSET...ROWS FETCH...`、`ORDER BY` 等），用户必须手动触发才能看到。

4. **DDL 语法树完全缺失**：当前引擎仅支持 DML（SELECT/INSERT/UPDATE/DELETE/EXEC），`CREATE TABLE`、`ALTER TABLE`、`CREATE INDEX`、`CREATE PROCEDURE`、`CREATE VIEW`、`CREATE FUNCTION`、`CREATE TRIGGER`、`DROP`、`TRUNCATE` 等 DDL 语句无任何语法节点支持，走默认 `ExpressionPosition`。

5. **变量/字段数据类型提示缺失**：`DECLARE @变量 类型`、`CREATE TABLE (列名 类型)` 等场景无数据类型提示，用户需手动输入类型名称。

### 2.2 产品目标

| 目标 | 度量指标 |
|------|---------|
| WHERE 后子句补全覆盖率 | WHERE 后提示列表包含 GROUP BY / ORDER BY / HAVING / OFFSET / UNION 等 ≥ 8 个子句关键词 |
| TOP 常量误识别 | `SELECT TOP n *` 中的数字不会被加入列别名列表 |
| 空行补全内容完整性 | 空行触发时同时展示上下文关键词 + 通用模板 + 组合片段 |
| DDL 语句覆盖率 | CREATE TABLE / ALTER TABLE / CREATE INDEX / CREATE VIEW / CREATE PROCEDURE / CREATE FUNCTION / DROP / TRUNCATE 均有对应的 SyntaxNode 分支 |
| 数据类型补全 | DECLARE、CREATE TABLE 列定义、ALTER TABLE 添加列等场景能提示 SQL Server 全类型列表 |

### 2.3 目标用户画像

| 用户角色 | 场景 | 需求痛点 |
|---------|------|---------|
| DBA / 数据库开发 | 日常编写复杂查询、DDL 脚本 | 子句提示不全、DDL 无补全、类型需记忆 |
| 报表开发 | 编写含多子句的 SELECT 查询 | WHERE 后看不到 GROUP BY/ORDER BY 提示 |
| 应用开发 | 编写存储过程、表定义 | DECLARE 变量时无类型提示 |

## 3. 用户故事与验收条件

### US-01：WHERE 后展示所有合法后续子句

**用户故事**：作为 SQL 开发人员，我希望在 WHERE 条件区输入时，提示列表中包含 `GROUP BY`、`ORDER BY`、`HAVING`、`OFFSET`、`UNION` 等后续子句关键词，以便我快速完成完整 SQL 编写，而不必手动记住每个子句的精确拼写。

**验收条件**：

```
Given 当前光标在 WHERE 条件区内（如 WHERE Col1 = 1 |）
When 输入空格或关键词前缀
Then 提示列表包含：
  - 条件运算符：AND, OR, IN, BETWEEN, LIKE, IS, NOT, NULL
  - 后续子句：GROUP BY, ORDER BY, HAVING, OFFSET, UNION, INTERSECT, EXCEPT
  - 组合片段：ORDER BY, GROUP BY, OFFSET ROWS FETCH NEXT ROWS ONLY
```

```
Given SQL 已有多个子句（WHERE ... GROUP BY ... HAVING ...）
When 光标在 WHERE 条件区（GROUP BY 之前）
Then 提示列表仍包含所有合法后续子句（不受"已有 GROUP BY"影响）
```

**优先级**：P0

---

### US-02：TOP 常量不被误认为列别名

**用户故事**：作为 SQL 开发人员，我希望 `SELECT TOP 100 * FROM [Table] ORDER BY` 中的 `100` 不被当作列别名，以免 ORDER BY 时出现 `100` 的提示项。

**验收条件**：

```
Given SQL 为 "SELECT TOP 100 * FROM [Table] WHERE Col1 = 1 ORDER BY"
When 系统解析 SELECT 列清单
Then 列别名列表不应包含 "100"
```

```
Given SQL 为 "SELECT TOP 50 Col1, Col2 FROM [Table]"
When 系统解析 SELECT 列清单
Then 列别名列表只包含 "Col1", "Col2"，不包含 "50"
```

**优先级**：P0

---

### US-03：空行后补全包含通用模板 + 组合片段

**用户故事**：作为 SQL 开发人员，我在完成 WHERE 条件后换到新行输入时，希望补全列表同时包含 WHERE 上下文的关键词（AND/OR/IN）和通用 SQL 模板/组合片段（ORDER BY / OFFSET...ROWS FETCH...），而不仅仅是上下文关键词。

**验收条件**：

```
Given 光标在 WHERE 条件完成后的新空行上
When 输入关键词前缀（如 OF）
Then 提示列表应包含：
  - 上下文关键词：AND, OR, IN, BETWEEN, LIKE, IS, NOT, NULL（如果仍被识别为 WHERE 上下文）
  - 通用模板：sf→SELECT * FROM, cr→CREATE TABLE 等
  - 组合片段：OFFSET ROWS FETCH NEXT ROWS ONLY, ORDER BY 等
```

**优先级**：P1

```
Then 提示表名位置（TableNamePosition）→ 展示当前库的表名候选

Given 正在编写 ALTER TABLE 语句
When 光标在 "ALTER TABLE" 之后
Then 提示表名位置 → 展示当前库的表名候选

Given 光标在 CREATE TABLE 的列定义括号内（表名列名之后）
When 输入数据类型前缀
Then 提示 SQL Server 数据类型列表

Given 正在编写 CREATE INDEX 语句
When 光标在 "CREATE INDEX" 之后
Then 提示索引名 + 索引选项
When 光标在 "ON" 之后
Then 提示表名位置

Given 正在编写 CREATE VIEW / CREATE PROCEDURE / CREATE FUNCTION
When 光标在 "CREATE VIEW/PROCEDURE/FUNCTION" 之后
Then 提示对象名位置

Given 正在编写 DROP 语句
When 光标在 "DROP TABLE/VIEW/PROCEDURE/INDEX/CONSTRAINT" 之后
Then 提示对应的对象名

Given 正在编写 CREATE TABLE 语句，在列定义之后
When 光标在 "Col1 INT " 之后（数据类型后空格）
Then 提示列级约束：NOT NULL, NULL, PRIMARY KEY, UNIQUE, DEFAULT, CHECK, REFERENCES, IDENTITY

Given 正在编写 CREATE TABLE 语句，在列定义逗号之后的新行
When 光标在 "CREATE TABLE T (Col1 INT, " 之后
Then 提示表级约束：CONSTRAINT, PRIMARY KEY, UNIQUE, FOREIGN KEY, CHECK

Given 正在编写 ALTER TABLE ADD CONSTRAINT 语句
When 光标在 "ALTER TABLE T ADD CONSTRAINT PK_Name " 之后
Then 提示约束类型：PRIMARY KEY, UNIQUE, FOREIGN KEY, CHECK, DEFAULT

Given 正在编写 FOREIGN KEY 约束
When 光标在 "FOREIGN KEY (Col1) REFERENCES " 之后
Then 提示被引用表名
When 光标在 "REFERENCES T (" 之后
Then 提示被引用表的列名
When 光标在 "REFERENCES T (Col1)" 之后
Then 提示 ON DELETE / ON UPDATE 行为选项：CASCADE, SET NULL, SET DEFAULT, NO ACTION
```

**优先级**：P2-建议

## 4. 功能规格说明

### 4.1 WHERE 后子句关键词放开

#### 当前行为

`SyntaxNode.AfterWhereKeyword` / `SearchConditionPosition` / `AfterHavingKeyword` / `AfterJoinOnKeyword` 合并为一个分支，仅返回 8 个条件运算符：

```csharp
return GetFieldCandidates(...)
    .Concat(GetKeywordCandidates(filterText, new[] { "AND", "OR", "IN", "BETWEEN", "LIKE", "IS", "NOT", "NULL" }))
    .ToList();
```

#### 目标行为

1. **WHERE 条件区**（`AfterWhereKeyword` / `SearchConditionPosition`）：返回字段候选 + 全部通用关键词 + 组合片段
2. **HAVING 条件区**（`AfterHavingKeyword`）：同上（HAVING 也是条件区）
3. **ON 条件区**（`AfterJoinOnKeyword`）：返回字段候选 + 全部通用关键词 + 组合片段（ON 后还可以跟 AND/OR 连接多个条件）

#### 交互说明

- 用户输入 `G` → 提示 `GROUP BY`（前缀匹配）
- 用户输入 `O` → 提示 `ORDER`、`OFFSET`、`OFFSET ROWS FETCH NEXT ROWS ONLY`、`ORDER BY` 等
- 用户输入 `H` → 提示 `HAVING`
- 关键词排序优先级：上下文字段 > 上下文关键词 > 通用关键词 > 组合片段

### 4.2 TOP 100 常量误识别修复

#### 当前行为

`GetSelectColumnAliases` 从 `SELECT TOP 100 *` 中提取列清单为 `"100 *"`，解析后得到列名 `"100"`。

#### 目标行为

在提取列名时，跳过纯数字（全部由数字字符组成）的列名。

#### 数据规则

```csharp
// 在 colName 判断中增加
if (!string.IsNullOrEmpty(colName) && colName != "*" && !colName.All(char.IsDigit))
    aliases.Add(colName);
```

### 4.3 空行后补全增强

#### 当前行为

`OnCharTyped` 中，`TryContextAwareCompletion` 返回 true（有候选）时，旧系统的 `ShowCategoryCandidates` 中注册的 `CompoundSqlSnippets` 不展示。

#### 目标行为

`TryContextAwareCompletion` 返回的候选列表与旧系统的通用模板/组合片段**合并展示**：

```
1. 新系统上下文候选（字段、关键词等）— 排前面
2. 旧系统模板 — 排中间
3. 组合片段（CompoundSqlSnippets）— 排后面
```

#### 交互说明

- 优先展示上下文相关候选（字段名、条件运算符等）
- 通用模板和组合片段排在后面，不干扰主要候选
- 空行触发时与空格触发行为一致：展示所有可用候选

### 4.4 DDL 语句语法树

DDL（Data Definition Language）涵盖表结构、索引、视图、存储过程、函数、触发器等对象的创建/修改/删除。为保证补全精度，每类 DDL 语句按**关键词序列**组织语法节点。

---

#### 4.4.1 DDL 语句类型分类

| 语句类型 | 关键词签名 | 说明 |
|---------|-----------|------|
| `CreateTable` | `CREATE TABLE [schema.]表名 (列定义[, 约束]...)` | 创建表 |
| `CreateIndex` | `CREATE [UNIQUE] [CLUSTERED\|NONCLUSTERED] INDEX 索引名 ON [schema.]表 (列[ASC\|DESC],...) [INCLUDE(...)] [WHERE ...]` | 创建索引 |
| `CreateView` | `CREATE VIEW [schema.]视图名 [(列...)] AS SELECT ...` | 创建视图 |
| `CreateProcedure` | `CREATE [OR ALTER] PROCEDURE [schema.]过程名 [@参数 类型 [=默认值] [OUTPUT],...] AS ...` | 创建存储过程 |
| `CreateFunction` | `CREATE [OR ALTER] FUNCTION [schema.]函数名 ([@参数 类型,...]) RETURNS 类型 AS ...` | 创建函数 |
| `CreateTrigger` | `CREATE [OR ALTER] TRIGGER [schema.]触发器名 ON 表\|视图 [AFTER\|INSTEAD OF] [INSERT,UPDATE,DELETE] AS ...` | 创建触发器 |
| `AlterTable` | `ALTER TABLE [schema.]表名 {ADD\|DROP\|ALTER COLUMN\|WITH CHECK\|NOCHECK CONSTRAINT}` | 修改表 |
| `AlterIndex` | `ALTER INDEX 索引名 ON [schema.]表 {REBUILD\|REORGANIZE\|DISABLE} [WITH(...)]` | 修改索引 |
| `AlterView` | `ALTER VIEW [schema.]视图名 [(列...)] AS SELECT ...` | 修改视图 |
| `AlterProcedure` | `ALTER [OR ALTER] PROCEDURE ...` | 修改过程 |
| `AlterFunction` | `ALTER [OR ALTER] FUNCTION ...` | 修改函数 |
| `AlterTrigger` | `ALTER TRIGGER ...` | 修改触发器 |
| `DropTable` | `DROP TABLE [IF EXISTS] [schema.]表名` | 删除表 |
| `DropView` | `DROP VIEW [IF EXISTS] [schema.]视图名` | 删除视图 |
| `DropProcedure` | `DROP PROCEDURE [IF EXISTS] [schema.]过程名` | 删除过程 |
| `DropFunction` | `DROP FUNCTION [IF EXISTS] [schema.]函数名` | 删除函数 |
| `DropIndex` | `DROP INDEX [IF EXISTS] [schema.]表.索引名` 或 `DROP INDEX [IF EXISTS] 索引名 ON [schema.]表` | 删除索引 |
| `DropTrigger` | `DROP TRIGGER [IF EXISTS] [schema.]触发器名` | 删除触发器 |
| `DropConstraint` | `ALTER TABLE [schema.]表名 DROP CONSTRAINT 约束名` | 删除约束 |
| `TruncateTable` | `TRUNCATE TABLE [schema.]表名` | 清空表 |

---

#### 4.4.2 DDL 语法树结构

##### CREATE TABLE 语法树

```
CREATE TABLE [schema.]表名 (
    列定义1  类型  [列级约束] [IDENTITY(seed,inc)],
    列定义2  类型  [列级约束],
    ...,
    [表级约束1,]
    [表级约束2,]
)
                      ↓ 关键词序列
CREATE → TABLE → 表名 → ( → 列名 → 类型 → [列级约束] → [,]
                                ↑                     ↓
                                └── 列名 → 类型 ← 逗号后新列
                                                     ↓
                                              [CONSTRAINT] → 约束名 → 约束类型 → (列...) → )
```

| 光标位置 | 前置关键词条件 | SyntaxNode | 提示内容 |
|---------|---------------|-----------|---------|
| `CREATE` 后 | prev=CREATE | `AfterCreateKeyword` | TABLE, INDEX, VIEW, PROCEDURE, FUNCTION, TRIGGER |
| `CREATE TABLE` 后 | prev=TABLE, prevprev=CREATE | `AfterCreateTableKeyword` | 表名候选（当前 Schema 的可用表名 + 自由文本） |
| `表名 (` 后括号内 | prev=( | `ColumnDefinitionStart` | 列名（自由文本）+ 数据类型 |
| `列名 类型` 后 | prev=类型 | `ColumnConstraintPosition` | NOT NULL, NULL, PRIMARY KEY, UNIQUE, DEFAULT, CHECK, REFERENCES, IDENTITY |
| `,` 后（列定义间） | prev=, | `AfterColumnCommaPosition` | 列名或 CONSTRAINT |
| `CONSTRAINT` 后 | prev=CONSTRAINT | `ConstraintNamePosition` | 约束名（自由文本） |
| `约束名` 后 | prev=约束名(词) | `ConstraintTypePosition` | PRIMARY KEY, UNIQUE, FOREIGN KEY, CHECK, DEFAULT |
| `PRIMARY KEY (` | prev=KEY, prevprev=PRIMARY | `ConstraintColumnsPosition` | 当前表已定义的列名 |
| `UNIQUE (` | prev=UNIQUE | `ConstraintColumnsPosition` | 当前表已定义的列名 |
| `FOREIGN KEY (列)` 后 | prev=KEY, prevprev=FOREIGN | `AfterForeignKeyParenthesis` | 不需要提示（括号内已填列） |
| `REFERENCES` 后 | prev=REFERENCES | `AfterForeignKeyReferences` | 被引用表名候选 |
| `` 后 | prev=表名 | `AfterForeignKeyRefColumns` | 被引用表的列名候选 |
| 外键末尾 | prev=)| `OnDeleteUpdatePosition` | ON DELETE: CASCADE, SET NULL, SET DEFAULT, NO ACTION; 同 ON UPDATE |

##### CREATE INDEX 语法树

```
CREATE [UNIQUE] [CLUSTERED|NONCLUSTERED] INDEX 索引名 ON [schema.]表 (列 [ASC|DESC], ...)
[INCLUDE (列...)] [WHERE 筛选条件] [WITH (填充因子=..., SORT_IN_TEMPDB=ON...)] [ON 文件组]
```

| 光标位置 | SyntaxNode | 提示内容 |
|---------|-----------|---------|
| `CREATE` 后 | `AfterCreateKeyword` | TABLE, INDEX, VIEW, PROCEDURE, FUNCTION, TRIGGER |
| `CREATE INDEX` 后 | `AfterCreateIndexKeyword` | 索引名（自由文本） |
| `CREATE UNIQUE INDEX` 后 | `AfterCreateIndexKeyword` | 索引名 |
| `CREATE CLUSTERED INDEX` 后 | `AfterCreateIndexKeyword` | 索引名 |
| `索引名 ON` 后 | `AfterCreateIndexOnKeyword` | 表名候选 |
| `表名 (列` 括号内 | `IndexColumnPosition` | 当前表列名 + ASC, DESC |
| `)` 后 | `IndexOptionsPosition` | INCLUDE, WHERE, WITH, ON |

##### CREATE VIEW 语法树

```
CREATE VIEW [schema.]视图名 [(列1, 列2...)] AS SELECT ...
```

| 光标位置 | SyntaxNode | 提示内容 |
|---------|-----------|---------|
| `CREATE` 后 | `AfterCreateKeyword` | TABLE, INDEX, VIEW, PROCEDURE, FUNCTION, TRIGGER |
| `CREATE VIEW` 后 | `AfterCreateViewKeyword` | 视图名（自由文本） |
| `视图名 AS` 后 | `AfterViewAsKeyword` | SELECT（从 SELECT 开始构建视图定义） |
| `视图名 (列` 括号内 | `ViewColumnListPosition` | 列名（自由文本） |

##### CREATE PROCEDURE 语法树

```
CREATE [OR ALTER] PROCEDURE [schema.]过程名 [@参数 类型 [=默认值] [OUTPUT],...] AS ...
```

| 光标位置 | SyntaxNode | 提示内容 |
|---------|-----------|---------|
| `CREATE` 后 | `AfterCreateKeyword` | TABLE, INDEX, VIEW, PROCEDURE, FUNCTION, TRIGGER |
| `CREATE PROCEDURE` / `CREATE PROC` 后 | `AfterCreateProcKeyword` | 过程名（自由文本） |
| `过程名 ` 后 | `AfterProcNamePosition` | `@参数名`（自由文本）+ 或 `AS` |
| `@参数名 ` 后 | `AfterProcParamNamePosition` | 数据类型列表 |
| `类型` 后 | `AfterProcParamTypePosition` | `=`（默认值）, `OUTPUT`, `,`（下一参数）, `AS`（过程体） |
| `AS` 后 | `AfterProcAsKeyword` | SELECT, BEGIN + 所有 SQL 起始关键词 |

##### CREATE FUNCTION 语法树

```
CREATE [OR ALTER] FUNCTION [schema.]函数名 ([@参数 类型,...]) RETURNS 类型 [AS] BEGIN ... END
```

| 光标位置 | SyntaxNode | 提示内容 |
|---------|-----------|---------|
| `CREATE` 后 | `AfterCreateKeyword` | TABLE, INDEX, VIEW, PROCEDURE, FUNCTION, TRIGGER |
| `CREATE FUNCTION` 后 | `AfterCreateFuncKeyword` | 函数名（自由文本） |
| `函数名 (` 括号内（逗号分隔参数） | `FuncParamPosition` | `@参数名`（自由文本）|
| `@参数名 ` 后 | `FuncParamTypePositon` | 数据类型列表 |
| `)` 后 / `RETURNS` 后 | `AfterReturnsKeyword` | 数据类型列表（返回值类型） |

##### CREATE TRIGGER 语法树

```
CREATE [OR ALTER] TRIGGER [schema.]触发器名 ON 表|视图 [AFTER|INSTEAD OF] [INSERT,UPDATE,DELETE] AS ...
```

| 光标位置 | SyntaxNode | 提示内容 |
|---------|-----------|---------|
| `CREATE` 后 | `AfterCreateKeyword` | TABLE, INDEX, VIEW, PROCEDURE, FUNCTION, TRIGGER |

#### 4.4.3 语句类型检测（DDL 分支逻辑）

在 `StatementParser` / `SqlBreaker` 的 `DetectStatementType` 中增加 DDL 类型判断：

```csharp
public enum StatementType
{
    Select, Insert, Update, Delete, Merge, Exec,
    CreateTable, CreateIndex, CreateView, CreateProcedure, CreateFunction, CreateTrigger,
    AlterTable, AlterIndex, AlterView, AlterProcedure, AlterFunction, AlterTrigger,
    DropTable, DropView, DropProcedure, DropFunction, DropIndex, DropTrigger,
    TruncateTable,
    Unknown
}

// 根据起始关键词判定
public StatementType DetectStatementType(string statementText)
{
    var match = Regex.Match(statementText.TrimStart(),
        @"^(CREATE|ALTER|DROP|TRUNCATE)\s+(\w+)",
        RegexOptions.IgnoreCase);
    if (!match.Success) return StatementType.Unknown;

    string verb = match.Groups[1].Value.ToUpperInvariant();
    string noun = match.Groups[2].Value.ToUpperInvariant();

    switch (verb)
    {
        case "CREATE":
            return noun switch
            {
                "TABLE" => StatementType.CreateTable,
                "INDEX" => StatementType.CreateIndex,
                "VIEW" => StatementType.CreateView,
                "PROCEDURE" or "PROC" => StatementType.CreateProcedure,
                "FUNCTION" => StatementType.CreateFunction,
                "TRIGGER" => StatementType.CreateTrigger,
                _ => StatementType.CreateTable, // 默认假设建表
            };
        case "ALTER":
            // 同上逻辑
        case "DROP":
            // 同上逻辑
        case "TRUNCATE":
            return StatementType.TruncateTable;
        default:
            return StatementType.Unknown;
    }
}
```

`SyntaxLocator.Locate()` 在原有 DML 逻辑基础上，对于 `StatementType` 为 DDL 的走独立的 DDL 语法定位分支：

```csharp
public SyntaxNode Locate(string statementText, int cursorOffset, StatementType stmtType)
{
    // 原有 DML 逻辑
    if (stmtType is StatementType.Select or StatementType.Insert
        or StatementType.Update or StatementType.Delete or StatementType.Merge
        or StatementType.Exec)
    {
        return LocateDml(statementText, cursorOffset, stmtType);
    }

    // DDL 分支
    return LocateDdl(statementText, cursorOffset, stmtType);
}
```

### 4.5 数据类型提示

#### 数据类型列表（SQL Server 全类型）

按分类组织，显示时在前面标注分类：

|------|------|---------|
| 精确数值 | INT, BIGINT, SMALLINT, TINYINT, DECIMAL(p,s), NUMERIC(p,s), MONEY, SMALLMONEY, BIT | `[数值] INT` |
| 近似数值 | FLOAT(n), REAL | `[数值] FLOAT` |
| 字符串 | VARCHAR(n), NVARCHAR(n), CHAR(n), NCHAR(n), TEXT, NTEXT | `[字符串] VARCHAR` |

| 二进制 | BINARY(n), VARBINARY(n), IMAGE | `[二进制] BINARY` |

#### 数据规则

- 数据类型作为 `CompletionItemType.Keyword` 类型展示
- DisplayText 使用 `[分类] 类型名` 格式方便区分
- InsertText 使用纯类型名（如 `INT`、`VARCHAR(50)`）
- 按使用频率排序：精确数值 > 字符串 > 日期 > 大对象 > 二进制 > 其他
