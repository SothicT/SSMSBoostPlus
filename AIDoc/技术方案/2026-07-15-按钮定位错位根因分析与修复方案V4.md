## 问题现象

V3 修复后：
1. 同步按钮位置**从一开始就显示错位** ❌
2. 点击同步/恢复按钮后，按钮位置**不会变动**（位置稳定但错误） ✅（稳定性改善）
3. 同步/恢复**功能正常** ✅

**关键特征**：位置错位是**确定性**的（不随点击变化），说明 V3 的 `PrecomputeBlockYPositions` 确定性计算生效了，但计算出的 Y 值本身是错的。

## 根因分析

### 🔴 根因（主因）：`LineStackingStrategy` 默认值导致实际段落高度 ≠ 假设高度

#### WPF 行高机制

`Paragraph.LineHeight` 属性设置的是**最小行高**，而非精确行高。实际行高由 `LineStackingStrategy` 决定：

| `LineStackingStrategy` | 行高计算 | 说明 |
|------------------------|----------|------|
| `MaxHeight`（**默认值**） | `max(LineHeight, 自然行高)` | 取两者最大值 |
| `BlockLineHeight` | `LineHeight`（精确） | 强制使用指定值 |

**代码中未设置 `LineStackingStrategy`**（搜索结果为 0 匹配），因此使用默认值 `MaxHeight`。

#### 高度不匹配的推导

```
假设值（PrecomputeBlockYPositions 使用）：
  普通段落 = 18px
  占位段落 = 24px

实际值（MaxHeight 策略下）：
  普通段落 = max(18, Consolas@12px 自然行高)
  占位段落 = max(24, Consolas@10px 自然行高)
```

如果 `Consolas@12px` 的自然行高 > 18px（例如 18.5px 或 19px），则：
- 实际普通段落高度 > 18px
- 每段多出 0.5~1px
- 20 段后累积误差 = 10~20px
- 40 段后累积误差 = 20~40px

**这解释了为什么**：
- 按钮位置从初始加载就是错的（高度假设错误，累积从一开始就存在）
- 点击前后位置不变（`PrecomputeBlockYPositions` 是确定性计算，不依赖运行时状态）
- 所有按钮一致偏移（累积误差随段落数增加而增大，越往下偏移越大）

#### 为什么 V2（使用 `GetCharacterRect`）初始加载是正确的？

V2 在 `PopulateActionStrip` 中使用 `GetCharacterRect` 获取实际 Y 坐标。`GetCharacterRect` 返回的是**文档内容相对坐标**（不含滚动偏移，参见 [MSDN 文档](https://learn.microsoft.com/dotnet/api/system.windows.documents.textpointer.getcharacterrect)），因此初始加载时（布局已完成、未滚动）返回的是精确的实际位置。

**V3 文档的 `GetCharacterRect` 分析有误**：V3 文档声称 `GetCharacterRect` 返回"视口相对坐标"，但根据 MSDN 文档，`GetCharacterRect` 返回的坐标"relative to the content area of the text container"且"does not include any scrolling offsets"——即文档绝对坐标，不是视口相对坐标。

#### V2 同步后错位的真正原因

V2 同步后按钮错位的真正原因不是 `GetCharacterRect` 不可靠，而是 **`_isPositioningButtons` 防重入 guard 阻止了异步 `RepositionAllButtons` 执行**：

```
SyncHunk 插入段落 → SizeChanged 事件 → PositionActionButtons()
→ _isPositioningButtons = true → 异步调度 RepositionAllButtons

RenumberRightParagraphs → 更多 SizeChanged → PositionActionButtons()
→ _isPositioningButtons == true → 跳过（被 guard 阻止）

PopulateActionStrip → PositionActionButtons()
→ _isPositioningButtons == true → 跳过（被 guard 阻止）

结果：RepositionAllButtons 只在第一次 SizeChanged 时调度了一次，
使用的是 SyncHunk 修改过程中的中间布局状态（GetCharacterRect 返回过期值）
```

V3 fix #5（在 `PopulateActionStrip` 中重置 `_isPositioningButtons = false`）已经修复了这个问题。但 V3 同时将 `RepositionAllButtons` 中的 `GetCharacterRect` 替换为 `PrecomputeBlockYPositions`，引入了新的高度不匹配问题。

### 🟡 次因：左右面板标题高度可能不一致

| 面板 | 标题内容 | 潜在问题 |
|------|----------|----------|
| 操作条 | `<TextBlock Text="操 作" FontSize="12"/>` | 纯文本，高度确定 |
| 右侧面板 | `<TextBlock Text="📝" FontSize="12"/> + <TextBlock Text="我的脚本（本地）" FontSize="12"/>` | emoji 📝 可能使用 Segoe UI Emoji 字体渲染，高度略大于纯文本 |

如果右侧面板标题比操作条标题高 1~2px，则文档内容区域起始位置比 Canvas 内容区域低 1~2px，造成**固定偏移**（所有按钮统一上移 1~2px）。

此偏移量小且固定，不是主要问题，但值得一并修复。

## 修复方案

### 核心思路：双管齐下

| 修复 | 目标 | 方法 |
|------|------|------|
| 修复 A | 消除累积漂移 | 设置 `LineStackingStrategy = BlockLineHeight`，强制段落高度 = `LineHeight` |
| 修复 B | 消除固定偏移 | 给标题设置统一 `Height`，确保内容区域起始 Y 一致 |
| 修复 C | 安全兜底 | 在 `RepositionAllButtons` 中恢复 `GetCharacterRect`，用实际测量值校正 |

### 修复 A：设置 `LineStackingStrategy = BlockLineHeight`

**原理**：`BlockLineHeight` 强制行高 = `LineHeight` 属性值，忽略字体自然行高。这样段落高度就是精确的 18px / 24px，`PrecomputeBlockYPositions` 的计算结果与实际渲染一致。

**风险评估**：如果字体自然行高 > `LineHeight`，文本会被裁剪。但 Consolas@12px 的自然行高约 15.6px < 18px，Consolas@10px 的自然行高约 13px < 24px，因此不会裁剪。

### 修复 C：`RepositionAllButtons` 恢复 `GetCharacterRect` 作为安全兜底

**文件**：`AIDiffDialog.xaml.cs`，`RepositionAllButtons` 方法

修复 A 使 `PrecomputeBlockYPositions` 的计算值与实际渲染高度一致，理论上不再需要 `GetCharacterRect`。但作为安全兜底，在异步 `RepositionAllButtons`（`Render`/`Background` 优先级，布局已完全刷新）中用 `GetCharacterRect` 校正一次：

```csharp
// ❌ V3 原代码：
private void RepositionAllButtons()
{
    RightViewer.UpdateLayout();
    LeftViewer.UpdateLayout();

    var rightSv = FindScrollViewer(RightViewer);
    if (rightSv != null)
    {
        ActionStripCanvas.Height = Math.Max(rightSv.ExtentHeight, rightSv.ViewportHeight);
        ActionStripScroller.ScrollToVerticalOffset(rightSv.VerticalOffset);
    }

    // 使用确定性高度计算，不依赖 GetCharacterRect
    var blockYs = PrecomputeBlockYPositions();
    foreach (var kvp in _actionButtons)
    {
        int blockIndex = kvp.Key;
        var button = kvp.Value;
        if (blockYs.TryGetValue(blockIndex, out var y))
        {
            Canvas.SetTop(button, y);
        }
    }
}

// ✅ 新代码：先用 PrecomputeBlockYPositions 快速定位，再用 GetCharacterRect 精确校正
private void RepositionAllButtons()
{
    RightViewer.UpdateLayout();
    LeftViewer.UpdateLayout();

    var rightSv = FindScrollViewer(RightViewer);
    if (rightSv != null)
    {
        ActionStripCanvas.Height = Math.Max(rightSv.ExtentHeight, rightSv.ViewportHeight);
        ActionStripScroller.ScrollToVerticalOffset(rightSv.VerticalOffset);
    }

    // 第一步：用 PrecomputeBlockYPositions 快速定位（确定性，不受布局状态影响）
    var blockYs = PrecomputeBlockYPositions();
    foreach (var kvp in _actionButtons)
    {
        int blockIndex = kvp.Key;
        var button = kvp.Value;
        if (blockYs.TryGetValue(blockIndex, out var y))
        {
            Canvas.SetTop(button, y);
        }
    }

    // 第二步：用 GetCharacterRect 精确校正（此时布局已完全刷新，返回值可靠）
    // GetCharacterRect 返回文档内容相对坐标（不含滚动偏移），与 Canvas 坐标系一致
    var blockSnapshot = RightViewer.Document.Blocks.OfType<Paragraph>().ToList();
    foreach (var kvp in _actionButtons)
    {
        int blockIndex = kvp.Key;
        var button = kvp.Value;
        if (blockIndex >= 0 && blockIndex < blockSnapshot.Count)
        {
            try
            {
                var rect = blockSnapshot[blockIndex].ContentStart.GetCharacterRect(LogicalDirection.Forward);
                double top = rect.Top;
                if (!double.IsNaN(top) && !double.IsInfinity(top) && top > 0)
                {
                    Canvas.SetTop(button, top);
                }
            }
            catch { }
        }
    }
}
```

**关键点**：
- `GetCharacterRect` 在 `Render`/`Background` 优先级执行时，布局已完全刷新，返回值可靠
- 添加 `top > 0` 条件：跳过第一个段落（Y=0），避免 `GetCharacterRect` 返回 0 时覆盖 `PrecomputeBlockYPositions` 的正确值
- 如果 `GetCharacterRect` 因任何原因返回无效值（NaN/Infinity/0），保留 `PrecomputeBlockYPositions` 的值

## 为什么 V3 修复后问题仍然存在

| 版本 | `PopulateActionStrip` | `RepositionAllButtons` | 结果 |
|------|----------------------|----------------------|------|
| V2 | `GetCharacterRect`（同步，布局可能过期） | `GetCharacterRect`（异步，但被 guard 阻止） | 初始正确，同步后错位 |
| V3 | `PrecomputeBlockYPositions`（确定性） | `PrecomputeBlockYPositions`（确定性） | 全部错位（高度假设错误） |
| V4 | `PrecomputeBlockYPositions`（确定性） | `PrecomputeBlockYPositions` + `GetCharacterRect`（精确校正） | 全部正确 |

V3 的问题在于：
1. **错误诊断**：将 `GetCharacterRect` 标记为"返回视口相对坐标"，但实际返回文档绝对坐标
2. **过度修复**：将 `RepositionAllButtons` 中的 `GetCharacterRect` 也替换为 `PrecomputeBlockYPositions`，但后者使用的高度假设（18/24）在 `MaxHeight` 策略下不成立
3. **遗漏根因**：未识别 `LineStackingStrategy` 默认值 `MaxHeight` 是高度不匹配的根源
