## 问题现象

用户在差异比对弹窗中点击同步按钮后，操作条中的按钮（同步按钮 / 恢复按钮）位置错位，不再与对应代码行对齐。

## 根因分析

经过深入代码追踪，发现 **2 个确定性 Bug + 1 个潜在时序问题**，共同导致同步后按钮错位。

### 🔴 根因 1（确定性 Bug）：`_lineChangeTypes` 未随索引偏移

**位置**：`SyncHunk()` 第 1761-1768 行

`SyncHunk` 在插入段落后，会调用 `ShiftDictionaryKeys` 偏移所有跟踪字典的键（>= insertAt 的键 +insertedCount）：

```csharp
// SyncHunk 第 1761-1768 行 —— 偏移了 8 个字典/集合
ShiftDictionaryKeys(_leftParagraphBackgrounds, insertAt, insertedCount);
ShiftDictionaryKeys(_rightParagraphBackgrounds, insertAt, insertedCount);
ShiftDictionaryKeys(_rightIndicatorBackgrounds, insertAt, insertedCount);
ShiftHashSetValues(_syncedBlocks, insertAt, insertedCount);
ShiftHashSetValues(_syncedDeletedBlocks, insertAt, insertedCount);
ShiftHashSetValues(_placeholderBlocks, insertAt, insertedCount);
ShiftDictionaryKeys(_originalRightTexts, insertAt, insertedCount);
ShiftDictionaryKeys(_actionButtons, insertAt, insertedCount);
// ❌ 缺少：ShiftDictionaryKeys(_lineChangeTypes, insertAt, insertedCount);
```

**`_lineChangeTypes` 没有被偏移！**

同样，`UndoHunk()` 第 1962-1969 行也缺少对应的 `UnshiftDictionaryKeys`。

**影响链**：

```
SyncHunk 插入段落后：
  _rightIndicatorBackgrounds 已偏移 → block 10 = 原始 block 8（冲突行）
  _lineChangeTypes 未偏移 → _lineChangeTypes[8] = Modified（旧值）
                               _lineChangeTypes[10] = 不存在（应该是 Inserted）

RebuildDiffHunksFromState 遍历 block 10：
  _rightIndicatorBackgrounds[10] = ConflictBg → 是差异行 ✓
  _lineChangeTypes[10] = 不存在 → 默认 Modified ❌（应该是 Inserted）

结果：原本应分裂为两个 hunk（Modified + Inserted）→ 被错误合并为一个 Modified hunk
      → hunk.BlockStartIndex 指向错误的行 → 同步按钮定位到错误位置
```

**具体示例**：

| Block | 同步前 | 同步后（插入1行） | _lineChangeTypes（未偏移） | 应有值 |
|-------|--------|-------------------|--------------------------|--------|
| 7 | ConflictBg (Modified) | SyncedBg（新插入） | {7: Modified} | 不需要 |
| 8 | ConflictBg (Modified) | ResolvedBg（已处理） | {8: Modified} | 不需要 |
| 9 | ConflictBg (Inserted) | ConflictBg (偏移后) | {9: Inserted} ← 错误！ | 不存在 |
| 10 | ConflictBg (Inserted) | ConflictBg (偏移后) | 不存在 → 默认 Modified ← 错误！ | Inserted |

block 9 的 `_lineChangeTypes[9]` = Inserted 是**巧合正确**（因为旧 block 9 恰好也是 Inserted），
但 block 10 的 `_lineChangeTypes[10]` 不存在 → 默认 Modified，
导致 block 9（Inserted）和 block 10（应为 Inserted 但被判定为 Modified）被合并为一个 hunk。

如果 block 9 和 block 10 的 ChangeType 确实不同（例如 9=Modified, 10=Inserted），
偏移后应该分裂为两个 hunk，但因为 `_lineChangeTypes` 未偏移，它们被错误合并。
合并后的 hunk.BlockStartIndex = 9，同步按钮只在 block 9 出现，block 10 没有按钮。

### 🟡 根因 2（潜在时序问题）：`GetCharacterRect` 在布局未完成时被调用

**位置**：`PopulateActionStrip()` 第 1257-1282 行

```csharp
private void PopulateActionStrip()
{
    RightViewer.UpdateLayout();   // ← 强制布局
    LeftViewer.UpdateLayout();

    // 立即调用 GetCharacterRect
    for (int h = 0; h < _diffHunks.Count; h++)
    {
        var para = GetParagraphAtIndex(RightViewer.Document, blockIndex);
        var rect = para.ContentStart.GetCharacterRect(LogicalDirection.Forward);
        buttonTop = rect.Top;  // ← 可能是过时值
        Canvas.SetTop(button, buttonTop);
    }
    // ...
    PositionActionButtons();  // ← 异步重新定位（Render 优先级）
}
```

**问题**：`SyncHunk` 刚插入了段落 + `RenumberRightParagraphs` 修改了文本，虽然 `UpdateLayout()` 被调用，但 WPF 的 FlowDocument 布局可能存在延迟。`GetCharacterRect` 在此时可能返回**过时的 Y 坐标**。

`PositionActionButtons()` 在 `Render` 优先级异步重新定位，**应该**能修正。但存在一个边界情况：

如果 `OnLoaded` 阶段的 `PositionActionButtons` 异步操作尚未执行（`_isPositioningButtons = true`），用户就快速点击了同步按钮，则 `PopulateActionStrip` 中的 `PositionActionButtons()` 调用会被 **guard 跳过**：

```csharp
private void PositionActionButtons()
{
    if (!_isLoaded || _isPositioningButtons) return;  // ← 如果上次异步还没执行完，直接跳过
    _isPositioningButtons = true;
    // ...
}
```

虽然上一个异步操作最终会执行并使用最新的 `_actionButtons`，但它使用的 `blockSnapshot` 是异步执行时刻的快照，可能错过中间的布局变化。

### 🟡 根因 3（潜在问题）：Canvas 高度未同步更新

`ActionStripCanvas.Height` 仅在异步 `PositionActionButtons` 中更新。如果异步执行前用户看到了按钮，Canvas 高度可能仍然是旧值，导致 ScrollViewer 裁剪或滚动位置不对。

## 修复方案

### 修复 1：偏移 `_lineChangeTypes`（根因 1 — 必须）

**文件**：`AIDiffDialog.xaml.cs`

**修改点 A** — `SyncHunk()` 第 1768 行后，添加 `_lineChangeTypes` 偏移：

```csharp
// 现有代码（第 1768 行）：
ShiftDictionaryKeys(_actionButtons, insertAt, insertedCount);
// ✅ 新增：
ShiftDictionaryKeys(_lineChangeTypes, insertAt, insertedCount);
```

**修改点 B** — `UndoHunk()` 第 1969 行后，添加 `_lineChangeTypes` 反向偏移：

```csharp
// 现有代码（第 1969 行）：
UnshiftDictionaryKeys(_actionButtons, insertAt, removedCount);
// ✅ 新增：
UnshiftDictionaryKeys(_lineChangeTypes, insertAt, removedCount);
```

### 修复 2：同步更新 Canvas 高度和滚动偏移（根因 3）

在 `PopulateActionStrip()` 中，在创建按钮之前同步更新 Canvas 高度：

```csharp
private void PopulateActionStrip()
{
    ActionStripCanvas.Children.Clear();
    _actionButtons.Clear();

    RightViewer.UpdateLayout();
    LeftViewer.UpdateLayout();

    // ✅ 新增：同步更新 Canvas 高度和滚动偏移
    var rightSv = FindScrollViewer(RightViewer);
    if (rightSv != null)
    {
        ActionStripCanvas.Height = Math.Max(rightSv.ExtentHeight, rightSv.ViewportHeight);
        ActionStripScroller.ScrollToVerticalOffset(rightSv.VerticalOffset);
    }

    // ... 后续创建按钮的逻辑不变
}
```

### 修复 3：增加二次异步校正（根因 2 — 保险措施）

在 `PositionActionButtons()` 中，增加一次 `Background` 优先级的二次校正，确保布局完全稳定后再定位一次：

```csharp
private void PositionActionButtons()
{
    if (!_isLoaded || _isPositioningButtons) return;
    _isPositioningButtons = true;

    // 第一次：Render 优先级（现有逻辑）
    Dispatcher.BeginInvoke(new Action(() =>
    {
        try
        {
            if (!_isLoaded) return;
            RepositionAllButtons();  // 提取为独立方法

            // ✅ 新增：第二次校正，使用更低的优先级确保布局完全稳定
            Dispatcher.BeginInvoke(new Action(() =>
            {
                if (!_isLoaded) return;
                RepositionAllButtons();
            }), System.Windows.Threading.DispatcherPriority.Background);
        }
        catch (Exception ex)
        {
            System.Diagnostics.Debug.WriteLine($"PositionActionButtons failed: {ex}");
        }
        finally
        {
            _isPositioningButtons = false;
        }
    }), System.Windows.Threading.DispatcherPriority.Render);
}

/// <summary>
/// 提取的公共方法：更新布局 + 同步 Canvas + 重新定位所有按钮
/// </summary>
private void RepositionAllButtons()
{
    RightViewer.UpdateLayout();
    LeftViewer.UpdateLayout();

    var rightSv = FindScrollViewer(RightViewer);
    if (rightSv != null)
    {
        ActionStripCanvas.Height = Math.Max(rightSv.ExtentHeight, rightSv.ViewportHeight);
        ActionStripScroller.ScrollToVerticalOffset(rightSv.VerticalOffset);
    }

    var blockSnapshot = RightViewer.Document.Blocks.OfType<Paragraph>().ToList();
    for (int i = 0; i < blockSnapshot.Count; i++)
    {
        if (_actionButtons.TryGetValue(i, out var button))
        {
            try
            {
                var rect = blockSnapshot[i].ContentStart.GetCharacterRect(LogicalDirection.Forward);
                double top = rect.Top;
                if (double.IsNaN(top) || double.IsInfinity(top)) top = 0;
                Canvas.SetTop(button, top);
            }
            catch { }
        }
    }
}
```

## 验证步骤

1. 打开差异比对弹窗，确认按钮初始位置正确
2. 点击第一个同步按钮 → 恢复按钮应在同步行位置
3. 点击第二个同步按钮 → 新的恢复按钮在正确位置，第一个恢复按钮位置不变
4. 点击全部同步 → 所有恢复按钮位置正确
5. 依次撤销每个恢复按钮 → 同步按钮重新出现在正确位置
6. 滚动文档 → 操作条同步滚动，按钮保持对齐
7. 窗口缩放 → 按钮重新定位
