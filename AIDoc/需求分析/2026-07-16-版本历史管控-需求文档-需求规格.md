# 版本历史管控功能 需求规格文档

## 一、需求概述

### 1.1 业务背景

SSMSBoostPlus 定位为 SSMS 智能增强工具，服务于数据库开发与运维人员。在制造业 MES 场景中，数据库对象（存储过程、函数、视图、触发器、表）频繁变更，存在以下核心痛点：

1. **变更追溯困难**：多人协作时，难以快速定位"谁在什么时候改了什么"
2. **意外覆盖风险**：用户执行脚本时，可能覆盖他人已提交的变更
3. **版本恢复复杂**：需要手动从备份或源码管理中查找历史版本
4. **审计合规缺失**：缺乏变更记录查询入口，审计需联系 DBA

### 1.2 核心目标

版本历史管控功能基于已有 DDL Trigger 基础设施（`MESBASE.dbo.DBTrigger_Object_Version_Table`），提供以下核心能力：

| 目标 | 说明 |
|------|------|
| 变更记录浏览 | 可视化展示数据库对象的完整变更历史时间线 |
| 差异比对 | 支持历史版本与当前版本、两个历史版本之间的逐行差异对比 |
| 版本回退 | 一键生成恢复到指定版本的 ALTER/CREATE/DROP 脚本 |
| 版本守卫联动 | 与 VersionGuard 协作，外部修改检测后一键跳转查看版本历史 |

### 1.3 适用角色

| 角色 | 使用场景 | 核心需求 |
|------|----------|----------|
| 数据库开发人员 | 查看自己/他人修改过的对象历史 | 变更浏览、差异比对 |
| DBA | 审查变更记录、追溯问题 | 全局对象浏览、版本回退 |
| 代码审查人员 | 审查变更是否符合规范 | 差异比对、变更记录浏览 |
| 运维人员 | 问题排查时查看最近变更 | 最近变更浏览、版本回退 |

### 1.4 关联模块

| 关联模块 | 关联方式 | 说明 |
|----------|----------|------|
| VersionGuard（版本守卫） | 双向联动 | VersionGuard 检测到外部修改 → 一键跳转版本历史；版本历史回退后 → 版本守卫重新校验 |
| DDL Trigger | 数据依赖 | 版本历史依赖 DDL Trigger 自动捕获的变更数据 |
| MESBASE | 数据库依赖 | 版本历史数据存储在 `MESBASE.dbo.DBTrigger_Object_Version_Table` |

### 2.1 功能模块划分

```
版本历史管控
├── 1. 版本历史浏览

│   ├── 1.2 版本时间线展示

├── 2. 版本差异比对
│   ├── 2.1 历史版本 vs 服务器当前版本
│   ├── 2.2 两个历史版本对比
│   ├── 2.3 差异高亮渲染
│   └── 2.4 同步滚动
├── 3. 版本回退
│   ├── 3.1 恢复脚本生成（ALTER/CREATE/DROP 智能转换）
│   ├── 3.2 在编辑器中打开

├── 4. 版本守卫联动
│   ├── 4.1 外部修改检测 → 一键跳转版本历史
│   ├── 4.2 版本历史面板跟随当前窗口
│   └── 4.3 钉住（Pin）模式
└── 5. 权限管控
    ├── 5.1 数据库白名单
    └── 5.2 只读访问
```

### 2.2 与版本守卫的协作关系

```
┌─────────────────────────────────────────────────────────────┐
│                      用户执行 SQL                            │
└────────────────────────┬────────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────────┐
│  VersionChecker.CheckVersionAsync()                          │
│  ├── 解析脚本对象引用                                         │
│  ├── 查询 DB modify_date                                     │
│  └── 检测到过时对象 → 弹出 VersionWarningDialog              │
└────────────────────────┬────────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────────┐
│  VersionWarningDialog                                        │
│  ├── [查看差异] → AIDiffDialog（DB vs 本地脚本）              │
│  ├── [查看版本历史] → LocalHistoryToolWindow（完整变更历史）   │
│  ├── [重新加载脚本] → 从 DB 重新加载                          │
│  └── [继续执行] → 二次校验 → 执行                             │
└────────────────────────┬────────────────────────────────────┘
                         │
                         │ 点击 [查看版本历史]
                         ▼
┌─────────────────────────────────────────────────────────────┐
│  LocalHistoryToolWindow                                      │
│  ├── 自动定位到被修改对象                                     │
│  ├── 显示完整变更时间线                                       │
│  └── 支持差异比对和回退                                       │
└─────────────────────────────────────────────────────────────┘
```

**协作时序**：

1. 版本守卫检测到外部修改 → 弹出 `VersionWarningDialog`
2. 用户点击 [查看版本历史] → 自动打开 `LocalHistoryToolWindow`
3. `LocalHistoryToolWindow` 自动定位到被修改对象，加载其完整变更历史
4. 用户可查看该对象的所有历史版本，理解变更上下文
5. 用户回退版本后，版本守卫在下次执行时重新校验

## 三、详细功能需求

### 3.1 版本历史浏览

#### 3.1.1 对象搜索与选择

| 属性 | 说明 |
|------|------|
| 功能名称 | 对象搜索与选择 |
| 功能描述 | 用户通过搜索框输入关键字或从下拉列表选择数据库对象，快速定位目标对象并加载其版本历史 |
| 触发条件 | 用户打开版本历史面板、手动输入关键字、或从下拉列表选择对象 |
| 前置条件 | 1. 已连接到数据库服务器 2. MESBASE 数据库可访问 3. `DBTrigger_Object_Version_Table` 表存在 |

**核心业务规则**：

1. **初始加载**：打开面板时，自动从当前窗口脚本解析第一个 DDL 定义对象，设为初始对象
   - 解析成功：自动加载该对象的版本历史
   - 解析失败：搜索框显示占位文本"未检测到数据库对象定义语句"
2. **实时搜索**：用户输入关键字时，触发 300ms 防抖后向服务端发起模糊搜索
   - 搜索范围：按当前数据库过滤 + 关键字 LIKE 匹配
   - 结果排序：类型优先级（SP > FN > TBL > VW > TR > TYP > OBJ）→ 名称字母序
   - 下拉列表项格式：`{ObjectName}（{VersionCount} 版本）` + 类型标签（彩色 Badge）
3. **对象列表加载**：初始加载前 200 个对象（可配置 `ObjectListTopLimit`）
   - 超过 200 个时显示截断提示：`已加载 200/523 个对象，输入关键字搜索更多`
4. **对象选择**：用户从下拉列表选中对象后，立即加载其版本历史

**数据校验规则**：

- 对象名不得为空或纯空格
- 搜索关键字最大长度 500 字符
- 对象名格式兼容：`dbo.Proc`、`[dbo].[Proc]`、`Proc`（无 schema）

**异常处理**：

| 异常场景 | 处理方式 |
|----------|----------|
| 搜索超时 | 取消当前搜索，保持上次结果 |
| 服务端查询失败 | 日志记录错误，搜索框保持原值 |
| 搜索无结果 | 下拉列表为空，显示"无匹配对象" |

**已知缺陷**：

| 缺陷编号 | 缺陷描述 | 修复需求 |
|----------|----------|----------|
| BUG-003 | 下拉框加载全量数据导致首次打开慢 | 已实现懒加载分页模式（Top 200 + 服务端搜索），待验证性能 |
| BUG-004 | 下拉框切换到全部数据库时，对象列表加载策略需优化 | 确保全部数据库模式下也使用 Top 限制 |

#### 3.1.2 版本时间线展示

| 属性 | 说明 |
|------|------|
| 功能名称 | 版本时间线展示 |
| 功能描述 | 以 DataGrid 表格形式展示选中对象的完整版本历史，按时间倒序排列 |
| 触发条件 | 1. 用户选中对象 2. 窗口切换自动刷新 3. 手动点击刷新按钮 |
| 前置条件 | 已选中对象、MESBASE 连接正常 |

**核心业务规则**：

1. **列定义**：
   - 数据库名：当前记录的数据库，蓝色加粗
   - `#`：序号倒序（最新版本为最大序号）
   - 时间：`yyyy-MM-dd HH:mm:ss` 格式，Consolas 等宽字体
   - 变更类型：彩色标签，CREATE 绿色 (#27AE60)、ALTER 橙色 (#F39C12)、DROP 红色 (#E74C3C)
   - 操作人：`loginname` 字段
   - 版本号：`Version` 字段，灰色等宽字体
2. **排序规则**：`PostTime DESC, ID DESC`（时间倒序，同时间按 ID 倒序）
3. **默认选中**：加载后自动选中最新版本行（第一行）
4. **加载数量**：默认 100 条（可配置 `MaxVersionsToLoad`）
5. **支持多选**：Ctrl 多选两行用于历史版本间对比

**数据校验规则**：

- `PostTime` 为 NULL 时显示为 "未知时间"
- `LoginName` 为空时显示为 "未知用户"
- `Version` 为 0 或 NULL 时显示为 "-"

**异常处理**：

| 异常场景 | 处理方式 |
|----------|----------|
| 连接失败 | 弹出错误对话框，提示"无法连接到版本历史数据库" |
| 对象无版本记录 | DataGrid 为空，状态栏显示"暂无版本记录" |
| 对象名格式兼容（dbo.XX vs XX） | 同时匹配两种格式 |

**已知缺陷**：

| 缺陷编号 | 缺陷描述 | 修复需求 |
|----------|----------|----------|
| BUG-001 | 刷新按钮点击后 UI 无响应 | 增加加载状态指示、按钮禁用/启用、成功/失败状态提示 |
| BUG-007 | 过时对象页面差异比对关闭后未置顶 | 已在 VersionWarningDialog 中实现 BringSelfToFrontSilently |

#### 3.1.3 数据库过滤

| 属性 | 说明 |
|------|------|
| 功能名称 | 数据库过滤 |
| 功能描述 | 通过数据库下拉框过滤版本历史，只显示指定数据库的对象记录 |
| 触发条件 | 用户从数据库下拉框选择数据库 |
| 前置条件 | 已连接服务器、数据库列表已加载 |

**核心业务规则**：

1. **数据库列表加载**：
   - 查询 `sys.databases WHERE state_desc = 'ONLINE'` 获取在线数据库列表
   - 支持缓存（默认 5 分钟，可配置 `DatabaseListCacheMinutes`）
   - 下拉列表第一项为"(全部数据库)"，表示不过滤
2. **自动识别**：打开面板时，从当前窗口连接信息自动推导数据库名
   - 识别成功：下拉框显示数据库名，黑色字体，状态"已跟随"
   - 识别失败：下拉框显示"未识别"，灰色字体，状态"未识别"
   - 从 SQL USE 语句解析兜底
3. **手动切换**：用户选择其他数据库后，重新加载该库的对象列表和版本历史
4. **状态显示**：
   - 已跟随（绿色）：窗口自动跟随当前编辑器连接
   - 已钉住（橙色）：锁定当前数据库，不跟随窗口切换
   - 未识别（红色）：无法识别当前连接

**异常处理**：

| 异常场景 | 处理方式 |
|----------|----------|
| 数据库列表加载失败 | 下拉框显示"加载失败"，ToolTip 显示错误详情 |
| 网络超时 | 连接超时 10 秒，超时后显示"加载超时" |
| 缓存命中 | 直接使用缓存数据，日志记录"缓存命中" |

**已知缺陷**：

| 缺陷编号 | 缺陷描述 | 修复需求 |
|----------|----------|----------|
| BUG-002 | 窗口切换时数据库下拉框加载策略需优化 | 确保切换时使用缓存，避免重复查询 |
| BUG-006 | 数据库连接状态 Label 悬停不显示 ToolTip | 需要为 ServerLabel 添加 ToolTip 显示完整连接信息（服务器地址、连接用户） |

#### 3.1.4 窗口切换自动跟随

| 属性 | 说明 |
|------|------|
| 功能名称 | 窗口切换自动跟随 |
| 功能描述 | 用户在 SSMS 中切换编辑器标签页时，版本历史面板自动更新为当前窗口的对象 |
| 触发条件 | 用户切换 SSMS 编辑器标签页 |
| 前置条件 | 版本历史面板已打开、未钉住、`AutoFollowEnabled = true` |

**核心业务规则**：

1. **防抖机制**：WindowActivated 事件触发后，等待 300ms（可配置 `DebounceMs`）再执行刷新
2. **连接变更检测**：比较当前窗口连接与面板当前连接
   - 连接变更：全量刷新（重新加载对象列表、数据库列表、搜索框）
   - 连接未变更：仅检查对象切换
3. **钉住模式**：用户点击钉住按钮后，面板不再跟随窗口切换
   - 取消钉住后自动重新跟随当前窗口
4. **SSMS 状态栏同步**：切换时在 SSMS 主窗口状态栏显示"SSMSBoostPlus: 正在切换版本历史..."
5. **连接获取策略**：优先使用 ConnectionServiceFacade（窗口标题解析），兜底 SsmsEditorService

**状态流转**：

```
未识别 → (连接解析成功) → 已跟随
已跟随 → (用户点击钉住) → 已钉住
已钉住 → (用户取消钉住) → 已跟随
已跟随 → (窗口切换，新窗口无连接) → 未识别
```

**异常处理**：

| 异常场景 | 处理方式 |
|----------|----------|
| 获取活动连接失败 | 保持当前状态，不刷新 |
| 新窗口无 DDL 语句 | 搜索框显示"未检测到数据库对象定义语句" |
| 防抖期间多次切换 | 取消上一次防抖，重新计时 |
| 刷新过程中用户再次切换 | `_isLoading` 标志阻止重复刷新 |

### 3.2 版本差异比对

#### 3.2.1 历史版本 vs 服务器当前版本

| 属性 | 说明 |
|------|------|
| 功能名称 | 历史版本 vs 服务器当前版本差异比对 |
| 功能描述 | 选中一条历史版本记录后，弹出差异对比弹窗，左侧显示服务器当前定义，右侧显示选中历史版本 |
| 触发条件 | 单击 DataGrid 中一条版本记录（非加载阶段） |
| 前置条件 | 已选中对象、可获取目标数据库连接 |

**核心业务规则**：

1. **左侧面板（服务器当前定义）**：
   - 通过 `_targetConnectionString`（目标库连接串）实时查询 `sys.sql_modules`
   - 支持对象类型：PROCEDURE、FUNCTION、VIEW、TRIGGER、TABLE
   - TABLE 类型：从系统表拼接 CREATE TABLE 脚本（字段定义 + 主键 + 索引）
   - 加载失败时显示遮罩层 + 重试按钮
2. **右侧面板（历史版本）**：
   - 直接使用选中记录的 `SqlCommand` 字段
   - 标题格式：`V{n} - {时间} ({操作人})`
3. **差异渲染**：
   - 使用 DiffPlex SideBySideDiffBuilder 计算差异
   - 行级着色：删除（浅红 #FFE6E6E6）、新增（浅绿 #E6FFE6）、修改（浅黄 #FFFFDC）
   - 子词级高亮：删除（红色 #E53935）、新增（绿色 #4CAF50）、修改（橙色 #F57F17）
   - 行号显示 + 差异标记（+/-/~）
4. **重试机制**：左侧加载失败时，显示"加载失败"遮罩 + 重试按钮，重试回调重新查询服务器定义

**异常处理**：

| 异常场景 | 处理方式 |
|----------|----------|
| 无法获取目标数据库连接 | 状态栏显示"无法获取目标数据库连接" |
| 服务器定义加载失败 | 左侧显示遮罩层 + 重试按钮 |
| TABLE 类型不支持 | 状态栏显示"不支持的对象类型: TABLE" |
| 对象已被删除 | 左侧显示"(对象不存在)" |
| DiffPlex 计算异常 | 日志记录错误，弹窗仍可打开（显示原始文本） |

**已知缺陷**：

| 缺陷编号 | 缺陷描述 | 修复需求 |
|----------|----------|----------|
| BUG-005 | 重试按钮加载失败后缺少友好提示 | 重试失败后显示具体错误原因，而非仅显示"加载失败" |

### 3.3 版本回退

#### 3.3.1 恢复脚本生成

| 属性 | 说明 |
|------|------|
| 功能名称 | 恢复脚本智能生成 |
| 功能描述 | 根据选中版本的变更类型，智能生成恢复到该版本的 SQL 脚本 |
| 触发条件 | 差异对比弹窗中点击"在编辑器中打开"按钮（目前实现为打开历史版本 SQL，非完整恢复脚本） |
| 前置条件 | 已选中版本记录 |

**核心业务规则**（`GenerateRestoreScriptAsync` 逻辑）：

| 场景 | 变更类型 | 恢复脚本生成逻辑 | RestoreType |
|------|----------|------------------|-------------|
| A | ALTER | 直接返回该版本的 SqlCommand（已是 ALTER 语句） | AlterToHistory |
| B | CREATE | 将 SqlCommand 中的 CREATE 替换为 ALTER（对象已存在） | AlterToHistory |
| C | DROP | 取上一条非 DROP 版本的 SqlCommand，将 ALTER 替换为 CREATE | RecreateDropped |
| D | 未知 | 返回错误信息 | - |

**CREATE/ALTER 转换规则**：

- PROCEDURE：`CREATE PROCEDURE|PROC` ↔ `ALTER PROCEDURE|PROC`
- FUNCTION：`CREATE FUNCTION` ↔ `ALTER FUNCTION`
- VIEW：`CREATE VIEW` ↔ `ALTER VIEW`
- TRIGGER：`CREATE TRIGGER` ↔ `ALTER TRIGGER`
- 使用正则：`^\s*CREATE\s+(TYPE)` → `ALTER $1`（忽略大小写、多行模式）

**DROP 恢复逻辑**：

1. 查询上一条非 DROP 版本的记录（`eventtype NOT LIKE 'DROP_%'`）
2. 如果上一条是 ALTER → 将 ALTER 替换为 CREATE
3. 如果上一条是 CREATE → 直接使用
4. 如果找不到上一条 → 返回错误"未找到 DROP 之前的版本记录"

**对象名解析**（`ParseObjectName`）：

- `Proc` → `("dbo", "Proc")`
- `dbo.Proc` → `("dbo", "Proc")`
- `[dbo].[Proc]` → `("dbo", "Proc")`
- `dbo.MySchema.Proc` → `("dbo", "Proc")`（三级名称，首段为 schema）

**异常处理**：

| 异常场景 | 处理方式 |
|----------|----------|
| 版本记录不存在 | 返回 `CanRestore = false` + "版本记录不存在" |
| 不支持的变更类型 | 返回 `CanRestore = false` + "不支持的变更类型: {type}" |
| DROP 前无历史版本 | 返回 `CanRestore = false` + "未找到 DROP 之前的版本记录" |
| sqlcommand 为空 | 返回 `CanRestore = false` + "版本记录中无 SQL 内容" |

**待实现功能**：

| 功能 | 当前状态 | 需求规格 |

| 完整恢复脚本生成 | 已实现 `GenerateRestoreScriptAsync` | 需在差异对比弹窗中增加"回退到此版本"按钮，调用此方法生成脚本并在编辑器中打开 |

    ON [dbo].[DBTrigger_Object_Version_Table] ([PostTime] DESC)

## 六、非功能需求

### 6.1 性能要求

| 操作 | 目标性能 | 优化措施 |
|------|----------|----------|
| 连接串 + 对象推断 | < 300ms | 连接获取走反射，ScriptDom 解析 < 10ms，两线并行 |
| 加载对象列表 | < 500ms（千级对象） | GROUP BY 查询，建议补充索引 |
| 加载版本时间线 | < 200ms（百级版本） | objectname + PostTime DESC 索引覆盖 |
| 版本间差异对比 | < 100ms | DiffPlex 高性能差异计算 |
| 恢复脚本生成 | < 50ms | 纯文本处理，无额外数据库查询 |
| 搜索框模糊搜索 | < 300ms（含防抖） | 300ms 防抖 + 取消上一次搜索 |
| 差异对比弹窗打开 | < 500ms（含服务器查询） | 异步加载，先显示弹窗框架再渲染内容 |

### 6.2 安全要求

| 要求 | 说明 |
|------|------|
| SQL 注入防护 | 所有查询使用参数化查询（`SqlCommand.Parameters.AddWithValue`），不拼接用户输入 |
| 连接串安全 | 连接串由 SSMS 窗口自动推导，不在配置文件中存储完整连接串 |
| 只读访问 | 对 MESBASE 数据库仅执行 SELECT 查询，不执行写操作 |
| 权限白名单 | 支持通过 `AllowedDatabases` 限制可查看的数据库 |
| 日志脱敏 | 日志中不记录完整连接串（仅记录 Server 和 Database 名） |

### 6.3 日志要求

| 级别 | 场景 | 示例 |
|------|------|------|
| Information | 正常操作流程 | `[LocalHistory] 命令触发`、`[LocalHistory] ✅ 版本历史面板已显示` |
| Debug | 调试信息 | `[LocalHistory] 数据库列表缓存命中`、`[LocalHistory] 连接未变更，仅检查对象切换` |
| Warning | 非致命错误 | `[LocalHistory] 无法获取 DTE 实例`、`[LocalHistory] 加载数据库列表失败` |
| Error | 异常 | `[VersionHistory] SQL 查询失败`、`[LocalHistory] 打开 Diff 对话框失败` |

**日志格式**：`{时间} [{级别}] [{模块}] {消息}`

### 6.4 缓存要求

| 缓存项 | 策略 | TTL | 说明 |
|--------|------|-----|------|
| 数据库列表 | 内存缓存 | 5 分钟（可配置） | 按服务器 + 认证方式缓存 |
| 对象列表 | 不缓存 | - | 每次重新查询，确保数据最新 |
| 版本时间线 | 不缓存 | - | 每次重新查询，确保数据最新 |
| 服务器定义 | 不缓存 | - | 每次实时查询，确保与服务器一致 |

### 6.5 容错要求

| 故障场景 | 容错策略 |
|----------|----------|
| MESBASE 不可连接 | 降级提示用户检查网络，不影响 SSMS 正常使用 |
| 版本表不存在 | 降级提示联系 DBA，不影响其他功能 |
| 对象无版本记录 | 正常显示空状态，不报错 |
| 网络超时 | 连接超时 10 秒，超时后友好提示 |
| 大脚本渲染 | 全量渲染（当前），后续需支持虚拟化 |
| 并发操作 | 只读查询，无并发冲突 |

## 七、研发注意事项与风险提示

### 7.1 易错逻辑

| 编号 | 易错点 | 说明 | 防范措施 |
|------|--------|------|----------|
| 1 | 对象名格式兼容 | 数据库存储可能是 `dbo.Proc` 或 `Proc`，需要同时匹配 | 使用 `ParseObjectName` 统一处理，SQL 查询同时匹配两种格式 |
| 2 | CREATE/ALTER 转换 | 正则替换需要考虑 PROCEDURE/PROC 两种写法 | 使用 `GetObjectTypePattern` 返回正确的正则模式 |
| 3 | DROP 恢复逻辑 | 需要取上一条非 DROP 版本，且需要处理 ALTER→CREATE 转换 | 完整的单元测试覆盖所有场景 |
| 4 | 连接串推导 | 将 InitialCatalog 替换为 MESBASE 时，需保留原始数据库名用于过滤 | 使用 `originalDbName` 参数传递 |
| 5 | 窗口切换防抖 | 快速切换窗口时需取消上一次防抖，避免重复刷新 | 使用 `CancellationTokenSource` 取消机制 |
| 6 | 模态弹窗 + DTE | ShowDialog 弹窗中调用 DTE 创建文档后必须关闭弹窗 | finally 中关闭弹窗，释放模态状态 |
| 7 | 数据库名空值 | 数据库名可能为 null（未识别）或空字符串，需归一化处理 | 统一使用 `string.IsNullOrEmpty` 归一化 |
| 8 | TABLE 类型定义查询 | TABLE 不走 sys.sql_modules，需从系统表拼接 | 已实现 `BuildCreateTableScriptAsync` |

### 7.2 易遗漏场景

| 编号 | 场景 | 说明 |
|------|------|------|
| 1 | 空数据库（无对象） | 搜索框显示空状态，不报错 |
| 2 | 对象已被删除（DROP 后） | 差异对比时服务器定义加载失败，显示遮罩 |
| 3 | 多 Schema 同名对象 | 通过 Schema 区分，对象名含 Schema 前缀 |
| 4 | 极长对象名（>500 字符） | 数据库字段限制 varchar(500)，UI 截断显示 |
| 5 | 超长 SQL 脚本（>1MB） | DiffPlex 可正常处理，但 RichTextBox 渲染可能卡顿 |
| 6 | 特殊字符对象名 | 方括号包裹的对象名需正确解析 |
| 7 | 时区问题 | PostTime 使用服务器时间，不做时区转换 |
| 8 | SSMS 多窗口同服务器不同库 | 通过数据库下拉框切换，不混淆 |

### 7.3 高风险区域

| 编号 | 风险 | 影响 | 缓解措施 |
|------|------|------|----------|
| 1 | DDL Trigger 未安装 | 版本历史功能完全不可用 | 提供 MESBASE 友好提示（待实现） |
| 2 | MESBASE 性能影响 | 大表查询可能影响 MESBASE 性能 | 建议补充索引、使用 TOP 限制 |
| 3 | 恢复脚本执行风险 | 用户执行恢复脚本可能导致数据丢失 | 恢复脚本在编辑器中打开供审阅，不自动执行 |
| 4 | 窗口切换性能 | 频繁切换窗口可能导致 UI 卡顿 | 300ms 防抖 + 取消机制 |
| 5 | 连接串泄露 | 日志中记录连接串存在安全风险 | 日志中仅记录 Server 和 Database 名 |
