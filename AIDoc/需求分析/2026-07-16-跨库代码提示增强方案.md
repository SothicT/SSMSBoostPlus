## 1. 需求概述

### 1.1 当前状态

目前 `DatabaseObjectCacheService` **只缓存当前连接数据库的对象**，按 `"Server.Database"` 为 Key 存储。  
补全弹窗在 FROM/EXEC 等上下文关键词后，**仅显示当前 DB 的表/SP**，无法提示跨库对象（`[OtherDB].[dbo].[Table]`）。

### 1.2 目标行为

| 场景 | 用户输入 | 期望弹窗内容 |
|------|----------|-------------|
| 连接 DB-A，刚输入 FROM | `FROM \|` | 当前 DB-A 的表 + 所有 DB 名称（带 `.` 后缀） |
| 连接 DB-A，输入 DB 名前缀 | `FROM MyOther` | 匹配的 DB 名称（如 `MyOtherDB.`） |
| 已选 DB 名+点 | `FROM MyOtherDB.\|` | 该 DB（MyOtherDB）下的所有表/视图 |
| 无上下文关键词 | `SELECT \|` | 关键词 + 模板 + **DB 名称** |
| EXEC 后 | `EXEC \|` | 当前 DB 的 SP/函数 + **DB 名称** |

### 1.3 核心变化

1. **启动时/切换连接时** → 获取服务器上 **所有数据库列表**，逐一拉取对象缓存
2. **缓存 Key** 保持 `"Server.Database"`，新增 `_allDbNames` 字段（按 Server 分组）
3. **补全分类** 新增 `CompletionCategory.DatabaseNames` 逻辑
4. **GetWordBeforeCaret 感知点号**：识别 `DBName.` 模式，切换候选源

```csharp
// 当前服务器标识（用于跨库查询时区分服务器）

// 标记是否已完成全量数据库拉取（避免重复）
```

### 2.2 新增/修改方法

#### 2.2.1 `GetAllDatabasesOnServerAsync(string connectionString)` ⭐ 新增

```csharp
/// <summary>
/// 查询当前服务器上的所有用户数据库名称。
/// 使用 SELECT name FROM sys.databases WHERE database_id > 4
/// </summary>
private async Task<List<string>> GetAllDatabasesOnServerAsync(string connectionString)
```

- 执行 `SELECT name FROM sys.databases WHERE database_id > 4 ORDER BY name`
- 返回数据库名列表（排除系统库：master, tempdb, model, msdb）
- 使用 `SqlConnection` + `ChangeDatabase` 或直接在 master 上下文中查询

#### 2.2.2 `TryAutoLoadAsync` 修改 ⭐

**当前行为**：只拉取 `ConnectionInfo.DatabaseName` 对应的一个 DB。

**修改后行为**：

```csharp
public async Task TryAutoLoadAsync()
{
    // 1. 获取当前连接信息（Server + 当前 DB + ConnectionString）
    // 2. 设置 _currentServer
    // 3. 后台全量拉取：获取所有 DB 名称 → 逐个 FetchAndCacheAsync
    // 4. 更新 _currentServerDbNames
    // 5. 设置当前 DB 为 _currentCacheKey
}
```

**流程**：
1. `GetConnectionInfoAsync()` → 获取 `ServerInstance`, `DatabaseName`, `ConnectionString`
2. 设置 `_currentServer = server`
3. 调用 `GetAllDatabasesOnServerAsync(connectionString)` → 获取所有 DB 名称
4. 遍历每个 DB 名：
   - 构建 `cacheKey = $"{server}.{dbName}"`
   - 如果 `_cache` 中已有，跳过
   - 否则 `_ = Task.Run(() => FetchAndCacheAsync(..., dbName, ...))` 后台拉取
5. 更新 `_currentServerDbNames = allDbNames`
6. 设置当前 DB 为 `_currentCacheKey = $"{server}.{currentDbName}"`

#### 2.2.3 `RefreshCacheForCurrentConnectionAsync` 修改

- 保持原有的当前 DB 刷新逻辑
- 新增：刷新完成后，**也刷新同服务器的所有 DB 名称列表**
- 如果新增了数据库，也应自动拉取新 DB 的缓存

#### 2.2.4 `GetAllDatabaseNames()` ⭐ 新增

#### 2.2.5 `GetObjectsForDatabase(string dbName, string prefix)` ⭐ 新增

```csharp
/// 当用户输入 "DBName." 后，后续输入在此 DB 中搜索。

public List<CompletionCandidate> GetMatchingObjects(string dbName, string prefix)
{

        return new List<CompletionCandidate>();

}
```

#### 2.2.8 `HasCacheForDatabase(string dbName)` ⭐ 新增

```csharp

/// </summary>
public bool HasCacheForDatabase(string dbName)
{
    if (string.IsNullOrEmpty(_currentServer) || string.IsNullOrEmpty(dbName))
        return false;
    return _cache.ContainsKey($"{_currentServer}.{dbName}");
}
```

### 2.3 持久化影响

- **当前**：`db_object_cache.json` 保存所有 `"Server.DB"` 的缓存
- **不变**：格式兼容，只是内容变多（同一个 Server 下有多个 DB 的缓存）
- **新增字段**：无需新增持久化字段，`_currentServerDbNames` 可从缓存 Key 中动态推导

### 2.4 并发/性能考量

| 问题 | 方案 |
|------|------|
| 全量拉取耗时 | 后台异步拉取，每个 DB 并行独立 Task，不阻塞 UI |
| 多 DB 同时拉取 | 使用 `SemaphoreSlim(3)` 限制并发数，避免服务器过载 |
| 首次启动慢 | 逐个 DB 拉取，完成一个即可显示该 DB 的提示（不是等全部完成） |
| 缓存文件变大 | 每个 DB 平均几百 KB，50 个 DB 约 50MB，可接受 |

## 3. SqlTemplateCompletionService 改动分析

### 3.1 核心改动点

#### 3.1.1 `GetWordBeforeCaret` 改造 — 识别 `DBName.` 模式 ⭐

**当前**：`IsWordChar` 只包含 `char.IsLetterOrDigit(c) || c == '_'`，**点号不是单词字符**。

**改造后**：新增方法识别"光标前是否在 `DBName.` 之后"

```csharp
/// <summary>
/// 检查光标前是否是 "DBName." 模式。
/// 返回 (dbName, objectNameStartPos)，如果不是则返回 (null, -1)
/// </summary>
private (string? dbName, int objectPartStart) DetectCrossDbContext(IWpfTextView textView)
{
    var caret = textView.Caret.Position.BufferPosition;
    var line = caret.GetContainingLine();
    var lineText = line.Extent.GetText();
    var caretColumn = caret.Position - line.Start.Position;

    if (caretColumn <= 0) return (null, -1);

    // 从光标向前扫描，看是否有 "DBName." 模式
    // "DBName." 之后可能跟着对象名前缀
    int pos = caretColumn - 1;

    // 先跳过对象名部分（如果有）
    int objEnd = pos;
    while (pos >= 0 && IsWordChar(lineText[pos])) pos--;
    
    // 检查前一个字符是否是 '.'
    if (pos >= 0 && lineText[pos] == '.')
    {
        int dotPos = pos;
        // 再向前读取 DB 名称
        int dbNameEnd = pos;
        pos--;
        while (pos >= 0 && IsWordChar(lineText[pos])) pos--;
        
        if (pos < dbNameEnd - 1) // 有 DB 名
        {
            var dbName = lineText.Substring(pos + 1, dbNameEnd - pos - 1);
            var objectPrefix = lineText.Substring(dotPos + 1, objEnd - dotPos);
            return (dbName, dotPos + 1);
        }
    }

    return (null, -1);
}
```

#### 3.1.2 `IsWordChar` 修改

```csharp
private static bool IsWordChar(char c)
{
    return char.IsLetterOrDigit(c) || c == '_' || c == '.';
}
```

> ⚠️ **注意**：修改 `IsWordChar` 会影响单词边界判断。需要评估 `GetWordBeforeCaret` 的调用场景：
> - 如果点号作为单词字符，`GetWordBeforeCaret` 在 `FROM DBName.Obj` 中会返回 `"DBName.Obj"` 作为整个单词
> - 需要在上层判断：如果是跨库模式，拆分为 `dbName` + `objPrefix`
> - 或者**不修改 IsWordChar**，单独在 `OnCharTyped` 中检测点号

**推荐方案**：**不修改 `IsWordChar`**，而是在 `OnCharTyped` 中新增分支检测：

```csharp
internal void OnCharTyped()
{
    // ... 现有逻辑 ...

    // ★ 新增：检测跨库上下文
    var (crossDbName, objStart) = DetectCrossDbContext(_activeTextView);
    if (crossDbName != null)
    {
        // 跨库模式：从 objStart 位置读取对象名前缀
        // 只显示该 DB 的对象
        HandleCrossDbCompletion(crossDbName, objectPrefix);
        return;
    }

    // ... 原有 GetWordBeforeCaret 逻辑 ...
}
```

#### 3.1.3 `OnCharTyped` 改造 — DB 名称作为候选 ⭐

在 `KeywordsAndTemplates` 分类下（以及所有分类），**新增 DB 名称候选**：


#### 3.1.4 `OnCharTyped` 改造 — 跨库对象补全 ⭐

```csharp
/// <summary>
/// 处理跨库补全：用户已输入 "DBName."，后续输入在该 DB 中搜索对象。
/// </summary>
private void HandleCrossDbCompletion(string dbName, string objectPrefix)
{
    if (_cacheService == null) return;

    var matches = new List<CompletionCandidate>();

    if (string.IsNullOrEmpty(objectPrefix))
    {
        // 刚输入点号，显示该 DB 的所有对象（按类型分类）
        // 根据 contextKeyword 决定显示表还是 SP
        var contextKeyword = GetSqlContextBeforeWord(_activeTextView, ...);
        var category = GetCompletionCategory(contextKeyword);
        
        if (category == CompletionCategory.TablesAndViews)
        {
            matches = _cacheService.GetAllObjectsForDatabase(dbName, "U", "V");
        }
        else if (category == CompletionCategory.ProceduresAndFunctions)
        {
            matches = _cacheService.GetAllObjectsForDatabase(dbName, "P", "FN", "IF", "TF");
        }
    }
    else
    {
        // 有前缀：在该 DB 中搜索匹配的对象
        matches = _cacheService.GetMatchingObjects(dbName, objectPrefix);
    }

    if (matches.Count > 0)
        ShowOrUpdatePopup(matches, objectPrefix);
    else
        HidePopup();
}
```

#### 3.1.7 排序优先级调整

当前的 `priorityFunc` 只区分 `Template`、`Keyword`、`DatabaseObject`。

需要将 `DatabaseName` 加入排序：

| 分类 | 优先级 |
|------|--------|

| KeywordsAndTemplates | 模板(0) → 关键词(1) → DB名称(2) → DB对象(3) |

## 4. 交互流程图

### 4.1 正常场景：当前 DB 补全

```
用户输入: "FROM "
                    │
                    ▼
          OnSpaceTyped()
                    │
                    ▼
      ShowCategoryCandidates(TablesAndViews)
                    │
                    ▼
      ┌─ 当前 DB 的表/视图
      ├─ 当前 DB 的名称（作为候选）
      └─ DB 名称候选（带 . 后缀）
                    │
                    ▼
              弹窗显示
```

### 4.2 跨库场景：输入 DB 名后补全对象

```
用户输入: "FROM MyOtherDB."
                              │
                              ▼
                    OnCharTyped()
                              │
                              ▼
              DetectCrossDbContext()
              返回 (dbName="MyOtherDB", objStart=...)
                              │
                              ▼
              HandleCrossDbCompletion("MyOtherDB", "")
                              │
                              ▼
              ┌─ 获取该 DB 的所有表/视图
              ├─ (根据 contextKeyword 过滤类型)
              └─ 显示弹窗
                              │
                   用户继续输入 "Or"
                              │
                              ▼
              HandleCrossDbCompletion("MyOtherDB", "Or")
                              │
                              ▼
            在该 DB 中搜索前缀 "Or" 的对象
                              │
                              ▼
              显示匹配结果弹窗
```

### 4.3 输入 DB 名称前缀时

```
用户输入: "FROM MyOth"
                    │
                    ▼
          OnCharTyped()
                    │
                    ▼
      DetectCrossDbContext() → 没有点号，返回 null
                    │
                    ▼
      GetWordBeforeCaret → word="MyOth"
      GetSqlContextBeforeWord → "FROM"
      GetCompletionCategory("FROM") → TablesAndViews
                    │
                    ▼
      ┌─ 关键词匹配（FROM 不匹配 "MyOth"）
      ├─ 模板匹配
      ├─ 当前 DB 表/视图匹配（可能有 "MyOrders" 等）
      └─ DB 名称匹配（"MyOtherDB" 匹配，得分高）
                    │
                    ▼

                    │
                    ▼
```

## 6. 关键风险与注意事项

### 6.1 性能风险

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 服务器有 50+ 个数据库，首次拉取慢 | 用户等待时间长 | 并行拉取但限制并发数（3~5）；优先拉取当前 DB |
| 缓存文件增大 | 启动加载慢 | 按需懒加载（当前仅读当前 DB），全量缓存后台异步构建 |
| `sys.databases` 查询权限 | 某些用户无权限 | 容错处理：查询失败时只使用当前 DB |

### 6.2 SQL 注入风险

- DB 名称来自 `sys.databases`，不来自用户输入，**无 SQL 注入风险**
- 跨库查询时拼接 `USE [DBName]` 或修改连接字符串的 `Initial Catalog`，需用 `SqlConnectionStringBuilder` 安全设置

### 6.3 连接字符串问题

跨库查询需要能够以**同一个凭据**连接到不同数据库。当前 `ConnectionInfo.ConnectionString` 包含 `Initial Catalog=CurrentDB`。跨库时需：

```csharp
var builder = new SqlConnectionStringBuilder(originalConnectionString);
builder.InitialCatalog = targetDbName;
var crossDbConnString = builder.ConnectionString;
```

### 6.4 多服务器场景

如果用户打开了多个连接（不同服务器），`_currentServer` 随当前编辑器窗口切换而变化。

- 每次 `TryAutoLoadAsync` 调用时，如果 `_currentServer` 变化，需要重置 `_currentServerDbNames` 并拉取新服务器的 DB 列表
- 不同服务器的 DB 名称不会混淆（缓存 Key 包含 Server）

### 6.5 Azure SQL / 托管实例

- `sys.databases WHERE database_id > 4` 在 Azure SQL 中同样适用
- Azure SQL 可能无法 `USE` 跨库，需要使用同服务器下的三部分命名 `[DB].[schema].[object]`
- 补全插入格式应保持 `[DBName].[dbo].[TableName]` 格式
