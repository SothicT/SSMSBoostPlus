# 代码提示卡顿分析与优化方案

## 一、问题描述

在 SQL 编辑器中输入代码时（如输入 `EXEC`），**每次按键后代码提示弹窗需要 1~2 秒** 才能弹出/更新，期间编辑器 UI 无响应，体验卡顿。

## 二、核心架构回顾

每次按键触发一次的完整处理链路：

```
用户按键
  → IOleCommandFilter.Exec (TYPECHAR)        [UI 线程]
    → OnCharTyped()                           [UI 线程同步执行]
      1. GetWordBeforeCaret()                 ← 获取光标前单词
      2. GetSqlContextBeforeWord()            ← 获取上下文关键词
      3. _templateService.GetAllTemplates()   ← 获取所有模板列表
      4. foreach (sqlKeyword) + FuzzyMatch    ← 遍历 120+ 关键词
      5. _cacheService.GetMatchingObjects()   ← 遍历所有 DB 对象 + FuzzyMatch
      6. OrderBy().ThenBy().ThenBy() 排序     ← 复杂排序
      7. ShowOrUpdatePopup()                  ← 清空 + 重建 ListBox 全部 UI
```

**关键点**：**全部同步执行在 UI 线程上**，任何一步耗时都会直接阻塞编辑器响应。

## 三、根因定位

### 🔴 瓶颈 1（最严重）：每次按键全量遍历所有数据库对象

**位置**：`DatabaseObjectCacheService.GetMatchingObjects()`（第 325~355 行）

```csharp
var matches = objects  // ← 遍历 _currentObjects 中所有 500+ 个对象
    .Select(o => { var score = CompletionCandidate.FuzzyMatch(prefix, o.Name); ... })
```

- 数据库有 **500+ 个对象**（表、视图、SP、函数）时，每次按键执行 **500+ 次 FuzzyMatch**
- 输入 "E" 时几乎所有对象都匹配（首字母 E 非常常见），产生大量 CompletionCandidate 对象
- **无前缀索引**，每次都是全量 O(n) 线性扫描

### 🔴 瓶颈 2（严重）：每次按键全量遍历 120+ SQL 关键词

**位置**：`SqlTemplateCompletionService.OnCharTyped()`（第 471~486 行）

```csharp
foreach (var keyword in SqlKeywords)  // ← 120+ 关键词
{
    var score = CompletionCandidate.FuzzyMatch(word, keyword);
}
```

- `SqlKeywords` 静态数组有 **120+ 个关键词**
- 每次按键执行 **120+ 次 FuzzyMatch**，每次包含 `ToLowerInvariant()`、`StartsWith`、逐字符循环、`Contains`
- 输入 "E" 时几乎所有关键词都匹配（`EXEC`、`EXISTS`、`END`、`ELSE`...）

### 🔴 瓶颈 3（严重）：每次按键完全重建 WPF ListBox UI

**位置**：`SqlTemplateCompletionService.ShowOrUpdatePopup()`（第 643~713 行）

```csharp
_listBox!.Items.Clear();
foreach (var candidate in matches)
{
    var item = CreateCompletionItem(candidate);  // ← 创建复杂 WPF 元素树
    _listBox.Items.Add(item);
}
```

- `CreateCompletionItem` 创建 `DockPanel` + `StackPanel` + **3 个 TextBlock** + `ListBoxItem` 等复杂 WPF 嵌套元素
- ListBox 已**禁用虚拟化**（`VirtualizingStackPanel.SetIsVirtualizing(_listBox, false)`），所有元素全量渲染
- 匹配项多时（50+ 项），WPF 布局和渲染开销显著

### 🟡 瓶颈 4：复杂排序重复计算

**位置**：`SqlTemplateCompletionService.OnCharTyped()`（第 526~572 行）

- 三层 `OrderByDescending(m => m.MatchScore).ThenBy(m => {...})` 
- lambda 中重复判断 `contextKeyword == "EXEC"` 等条件，每次排序对每个元素重复执行

### 🟡 瓶颈 5：GetAllTemplates() 每次生成新排序列表

**位置**：`SqlTemplateService.GetAllTemplates()`（第 91~94 行）

```csharp
return _templates.OrderBy(t => t.Abbreviation, ...).ToList();  // ← 每次新排序+新分配
```

模板数据运行期间几乎不变，但每次按键创建新列表。

### 🟢 瓶颈 6：FuzzyMatch 字符串分配

**位置**：`CompletionCandidate.FuzzyMatch()`（第 479~534 行）

- 每次调用对 input 和 target 各做一次 `ToLowerInvariant()`（创建新字符串）
- 单次调用影响微小，但**每次按键约 600+ 次调用**（120 关键词 + 500 对象）
- 合计约 1200+ 次字符串分配/按键，GC 压力大

## 四、总耗时估算（输入 "E" 场景）

| 操作 | 单次耗时 | 调用次数 | 小计 |
|------|---------|---------|------|
| FuzzyMatch(关键词) | ~5μs | ~120 次 | ~0.6ms |
| FuzzyMatch(DB对象) | ~5μs | ~500 次 | ~2.5ms |
| 对象分配+排序 | ~0.5ms | 1 次 | ~0.5ms |
| WPF UI 重建 (50+项) | **5~50ms** | 1 次 | **5~50ms** |
| **合计 UI 线程阻塞** | | | **~8~54ms/按键** |

> **实际感受 1~2 秒**的原因：除了上述计算耗时外，SSMS 的命令过滤器链路上还有其他组件同时处理按键，加上高频 GC 触发（每次按键 600+ 临时对象），共同导致实际感知延迟远大于单项耗时累加。

## 五、解决方案

### 方案 A（推荐，低风险高收益）：引入前缀索引

**核心思路**：将全量 O(n) 线性扫描改为 O(1) 前缀索引查找。

#### A1：为数据库对象建立前缀索引

**修改文件**：`src/SSMS/Services/DatabaseObjectCacheService.cs`

```csharp
// 新增：前缀索引
private Dictionary<string, List<DatabaseObjectInfo>> _prefixIndex = new();

// 新增：重建前缀索引（在缓存更新时调用）
private void RebuildPrefixIndex()
{
    _prefixIndex.Clear();
    foreach (var obj in _currentObjects ?? Enumerable.Empty<DatabaseObjectInfo>())
    {
        var lowerName = obj.Name.ToLowerInvariant();
        // 为前 3 个字符的每个前缀建立索引
        for (int len = 1; len <= Math.Min(3, lowerName.Length); len++)
        {
            var prefix = lowerName.Substring(0, len);
            if (!_prefixIndex.ContainsKey(prefix))
                _prefixIndex[prefix] = new List<DatabaseObjectInfo>();
            _prefixIndex[prefix].Add(obj);
        }
    }
}
```

**调用时机**：在 `FetchAndCacheAsync` 更新 `_currentObjects` 后调用 `RebuildPrefixIndex()`。

**查询方法改造**：

```csharp
public List<CompletionCandidate> GetMatchingObjects(string prefix)
{
    if (string.IsNullOrEmpty(prefix)) return new List<CompletionCandidate>();
    var lowerPrefix = prefix.ToLowerInvariant();

    // 从前缀索引 O(1) 定位候选集
    _prefixIndex.TryGetValue(lowerPrefix, out var candidates);
    if (candidates == null || candidates.Count == 0)
        return new List<CompletionCandidate>();

    // 仅在候选集中执行 FuzzyMatch
    return candidates
        .Select(o => (o, score: CompletionCandidate.FuzzyMatch(prefix, o.Name)))
        .Where(x => x.score >= 0)
        .OrderByDescending(x => x.score)
        .ThenBy(x => x.o.Name, StringComparer.OrdinalIgnoreCase)
        .Select(x => new CompletionCandidate { /* 略 */ })
        .ToList();
}
```

**效果**：输入 "E" 时只对以 E 开头的对象执行 FuzzyMatch，从 **500+ 项降到几十项**，速度提升 **10x 以上**。

#### A2：SQL 关键词预构建前缀索引

**修改文件**：`src/SSMS/Services/SqlTemplateCompletionService.cs`

## 八、补充需求分析

### 需求 1：按场景分类，分段提示

**用户需求**：
将候选项分为 **3 大类**，根据当前输入场景只使用对应的分类列表：

| 分类 | 包含内容 | 触发场景 |
|------|---------|---------|
| **关键词&模板** | SQL 关键词 + 用户模板 | 刚开始输入（如 "E"），或非表/SP 上下文 |
| **表&视图** | 表 (U) + 视图 (V) | 在 FROM/JOIN/SELECT/INSERT/UPDATE/DELETE 等之后 |
| **函数&存储过程** | SP (P) + 函数 (FN/IF/TF) | 在 EXEC/EXECUTE/SP_EXECUTESQL 之后 |

**具体行为**：
- 刚开始输入 "E" 或空格后输入首字母 → 只显示**关键词&模板**列表（不查 DB 对象）
- 输入 `EXEC` 后按空格，继续输入 → 只显示**函数&存储过程**列表
- 输入 `FROM` 后按空格，继续输入 → 只显示**表&视图**列表

#### 当前代码分析

**位置**：`SqlTemplateCompletionService.OnCharTyped()`（第 440~517 行）
**现状**：已有 `GetSqlContextBeforeWord()` 获取上下文关键词，并能在排序时做类型优先级调整。但仍存在问题：

1. **当前每次按键仍然搜索了所有来源**（模板 + 关键词 + DB 对象），再通过排序/过滤缩减显示内容。这仍做了大量无效计算。

### 需求 3：空格呼出提示弹窗

**用户需求**：按空格键后，显示代码提示弹窗。

**当前行为分析**：

空格是非单词字符，在命令过滤器中的处理链路：

1. **预处理**（第 1362~1377 行）：非单词字符不拦截，放行给 `Next.Exec`
2. **后处理**（第 1491~1503 行）：非单词字符不触发 `OnCharTyped()`
3. **OnLayoutChanged**（第 385~408 行）：空格改变了文本缓冲区，触发布局变化事件，调用 `OnCharTyped()`
4. **OnCharTyped**：获取光标前单词 → 空格后的单词为空字符串 → 调用 `HidePopup()`

**结果**：按空格后弹窗不会出现，反而如果之前弹窗是打开的则会关闭。

#### 改造方案

##### 3.1 在命令过滤器中拦截空格 TYPECHAR

在预处理的 TYPECHAR 拦截中，针对**空格**特殊处理：

```csharp
// 预处理（第 1362 行附近）
if (nCmdID == CMDID_TYPECHAR)
{
    char ch = GetTypeChar(pvaIn);
    if (char.IsLetterOrDigit(ch) || ch == '_')
    {
        _owner.InsertCharAndRefresh(ch);
        return OLECMDERR_E_CANCELED;
    }
    // ★ 新增：空格键特殊处理
    else if (ch == ' ')
    {
        // 先放行让空格写入缓冲区
        int hr = Next?.Exec(ref pguidCmdGroup, nCmdID, nCmdexecopt, pvaIn, pvaOut) ?? -1;
        if (hr >= 0)
        {
            // 空格写入后，根据上下文关键词触发弹窗
            _owner.OnSpaceTyped();
        }
        return hr;
    }
}
```

##### 3.2 新增 `OnSpaceTyped()` 方法

该方法在空格写入后调用，检查空格前的上下文关键词，决定是否弹窗：

```csharp
/// <summary>
/// 空格键按下后调用。
/// 检查空格前的上下文关键词，决定是否弹出补全提示。
/// </summary>
internal void OnSpaceTyped()
{
    ThreadHelper.ThrowIfNotOnUIThread();
    
    try
    {
        if (_activeTextView == null) return;
        
        // 获取光标前的上下文关键词（即空格前的单词）
        var contextKeyword = GetSqlContextBeforeWord(_activeTextView, _activeTextView.Caret.Position.BufferPosition.Position);
        if (string.IsNullOrEmpty(contextKeyword))
        {
            HidePopup();
            return;
        }
        
        // 根据上下文关键词决定是否弹窗
        var category = GetCompletionCategory(contextKeyword);
        
        // 如果上下文是 EXEC/FROM 等，且该分类有候选对象，则显示弹窗
        if (category == CompletionCategory.TablesAndViews
            || category == CompletionCategory.ProceduresAndFunctions)
        {
            // 显示该分类下的所有对象（无前缀过滤，全部显示）
            // 实际上弹窗不显示匹配列表，而是显示分类下的所有候选
            // 或者显示一个"等待输入"的提示效果
            // 建议：显示弹窗但提示"请输入对象名"
            
            // ★ 更实用的做法：直接显示该分类下的所有对象
            ShowCategoryCandidates(category, contextKeyword);
        }
        else
        {
            // 普通上下文（如 BEGIN/IF 等）— 也可以显示关键词&模板
            ShowCategoryCandidates(CompletionCategory.KeywordsAndTemplates, contextKeyword);
        }
    }
    catch (Exception ex)
    {
        _logger.Error(ex, "[SqlTemplate] OnSpaceTyped 失败");
    }
}
```

##### 3.3 新增 `ShowCategoryCandidates()` 方法

```csharp
/// <summary>
/// 显示指定分类下的所有候选对象（无前缀过滤，用于空格触发）。
/// </summary>
private void ShowCategoryCandidates(CompletionCategory category, string contextKeyword)
{
    var allMatches = new List<CompletionCandidate>();
    
    switch (category)
    {
        case CompletionCategory.KeywordsAndTemplates:
            // 显示所有关键词 + 模板
            foreach (var keyword in SqlKeywords)
                allMatches.Add(new CompletionCandidate { DisplayText = keyword, ... });
            foreach (var t in _templateService.GetAllTemplates())
                allMatches.Add(new CompletionCandidate { DisplayText = t.Abbreviation, ... });
            break;
            
        case CompletionCategory.TablesAndViews:
            // 显示所有表 + 视图
            if (_cacheService != null)
            {
                var dbMatches = _cacheService.GetAllObjectsOfTypes("U", "V");
                allMatches.AddRange(dbMatches);
            }
            break;
            
        case CompletionCategory.ProceduresAndFunctions:
            // 显示所有 SP + 函数
            if (_cacheService != null)
            {
                var dbMatches = _cacheService.GetAllObjectsOfTypes("P", "FN", "IF", "TF");
                allMatches.AddRange(dbMatches);
            }
            break;
    }
    
    if (allMatches.Count > 0)
    {
        ShowOrUpdatePopup(allMatches, "");
    }
    else
    {
        HidePopup();
    }
}
```

##### 3.4 在 `DatabaseObjectCacheService` 中新增类型过滤查询

```csharp
/// <summary>
/// 获取指定类型的所有对象（无前缀过滤，用于空格触发弹窗）。
/// </summary>
public List<CompletionCandidate> GetAllObjectsOfTypes(params string[] typeCodes)
{
    var objects = _currentObjects;
    if (objects == null || objects.Count == 0)
        return new List<CompletionCandidate>();
    
    var filtered = objects.Where(o => typeCodes.Contains(o.TypeCode)).ToList();
    
    return filtered
        .OrderBy(o => o.Name, StringComparer.OrdinalIgnoreCase)
        .Select(o => new CompletionCandidate
        {
            DisplayText = $"{o.Schema}.{o.Name}",
            FilterText = o.Name,
            TypeTag = GetTypeTagName(o.TypeCode),
            TypeCode = o.TypeCode,
            InsertText = $"[{o.Schema}].[{o.Name}]",
            ItemType = CompletionItemType.DatabaseObject,
            Source = o,
            MatchScore = 0,
        })
        .ToList();
}
```

##### 3.5 弹窗交互优化

空格触发弹窗后，用户继续输入字母时的交互流程：

```
用户操作                        | 弹窗行为
--------------------------------|-----------------------------------------------
输入 EXEC → 按空格              | 弹窗显示所有 SP + 函数列表（无前缀过滤）
继续输入 "U"（要找 usp_GetData） | OnCharTyped 被字母 "U" 触发 → 在 SP+函数分类下过滤 → 弹窗更新
继续输入 "s" → "p"              | 逐步模糊匹配 → 候选列表缩小至 usp_XXX
按 TAB/ENTER 选中               | 插入 [dbo].[usp_GetData]
```

**关键**：用户按空格后输入字母时，走的是正常的 `OnCharTyped()` 路径结合分类过滤，而非空格触发的全量显示路径。

这要求 `OnCharTyped()` 也需要感知"最近一次空格触发的分类上下文"，以避免如下问题：

```csharp
// 记录最近一次空格触发的分类
private CompletionCategory _lastSpaceCategory = CompletionCategory.All;
private bool _hasSpaceTrigger;

// OnSpaceTyped 中设置标志
_hasSpaceTrigger = true;
_lastSpaceCategory = category;

// OnCharTyped 中：如果弹窗可见且由空格触发，保持分类过滤
if (_isPopupVisible && _hasSpaceTrigger)
{
    // 根据 _lastSpaceCategory 限定搜索范围
    category = _lastSpaceCategory;
}
else
{
    category = GetCompletionCategory(contextKeyword);
}
```

### 需求与性能优化的一致性分析

以上三条补充需求与性能优化方案是**相辅相成**的：

| 需求 | 与性能优化的关系 | 说明 |
|------|----------------|------|
| 分类分段提示 | **正面叠加收益** | 按场景只搜索对应分类，搜索量进一步缩小至 1/3~1/5 |
| ESC 关闭弹窗 | 已实现，无需修改 | 代码中已有完整处理（第 1402~1404 行） |
| 空格呼出弹窗 | **新增路径，独立优化** | 触发路径独立于 OnCharTyped，建议单独评估实现 |

**综合效果**：前缀索引 + 分类分段 + 增量 UI 更新三管齐下后，每次按键的搜索范围从 **630 项（120 关键词 + 11 模板 + 500 DB 对象）** 降至：
- 一般输入：**仅 131 项**（关键词 + 模板，不查 DB 对象）
- EXEC 后：**仅 ~50 项**（SP+函数子集）
- FROM 后：**仅 ~200 项**（表+视图子集）

加上前缀索引进一步将 FuzzyMatch 范围缩减到前缀匹配项，单次按键实际计算量约 **10~30 次 FuzzyMatch**，性能提升 **20~60 倍**。

## 十、注意事项

1. **前缀索引内存占用**：每个对象平均存储 3 个前缀条目，500 对象约 1500 个引用，内存开销极小（~几 KB）
2. **索引重建时机**：仅在缓存数据变化时重建（自动加载/手动刷新），不影响每次按键的响应速度
3. **ESC 功能已验证**：代码中已有 `CMDID_CANCEL → HidePopup()` 处理，无需修改
4. **空格触发弹窗后的输入流程**：空格触发全量显示后，用户继续输入字母走 `OnCharTyped()` + 分类过滤，两个路径需要协同（`_hasSpaceTrigger` 标志位）
5. **ListBox 虚拟化恢复**：如果之前因标签错位禁用了虚拟化，建议先验证 B2 方案，确认修复后再启用；若仍有问题则保持现状
6. **分类后排序简化**：分类模式下，排序不再需要跨类型优先级调整（因为只包含同类型候选项），可直接按 MatchScore + FilterText 排序
