# 07 - 集成与架构

## 一、功能概述

SQL Prompt 作为 SSMS 的深度集成插件，其架构设计直接决定了功能实现的可能性和性能表现。本章分析 SQL Prompt 如何与 SSMS 集成，以及其元数据缓存、性能优化等核心架构设计。

---

## 二、功能细节

### 2.1 SSMS 集成方式

SQL Prompt 通过 **Visual Studio Shell 扩展性 API** 与 SSMS 集成：

| 集成层面 | 说明 |
|----------|------|
| **编辑器集成** | 通过 VS Shell 的 `ITextBuffer` / `ITextView` 接口操作编辑器内容 |
| **补全窗口** | 通过 `ICompletionBroker` 提供自定义补全实现 |
| **工具栏/菜单** | 通过 MEF（Managed Extensibility Framework）导出菜单项和工具栏 |
| **工具窗口** | 通过 `ToolWindowPane` 创建自定义面板（如代码分析问题列表） |
| **快捷键** | 通过 VS 命令系统注册自定义快捷键 |

### 2.2 元数据缓存架构

SQL Prompt 的缓存是**单进程内存缓存**，是其性能设计的核心：

```
┌─────────────────────────────────────────────────────────┐
│                    元数据缓存层                            │
├─────────────────────────────────────────────────────────┤
│ 连接数据库时：                                            │
│   - 自动加载 schema 到内存（表、视图、SP、函数等）          │
│   - 大型 schema → 显示进度对话框                          │
│   - 查询中引用的其他数据库也自动连接并加载                  │
│   - 同一会话中不卸载已加载的对象                           │
│                                                         │
│ 结构变更时：                                              │
│   - 不自动感知变更（需要手动刷新）                          │
│   - Ctrl+Shift+D → 手动刷新当前数据库                     │
│   - 实验功能：Auto Refresh → 检测变更自动刷新（可能不稳定）  │
│                                                         │
│ 内存管理：                                                │
│   - 多大型数据库 → 可能内存不足 → 弹出警告                  │
│   - Clear Cache → 手动清空所有缓存                        │
│   - Ctrl+Shift+P → 完全卸载（禁用建议）                    │
│   - 排除列表 → 防止不需要的对象加载（支持通配符）            │
└─────────────────────────────────────────────────────────┘
```

### 2.3 缓存加载策略

| 加载时机 | 说明 |
|----------|------|
| **连接时加载** | 连接到数据库时自动加载所有对象 |
| **按需加载** | 查询中引用的数据库才加载 |
| **不卸载** | 同一会话中不会卸载已加载的对象 |
| **排除策略** | 可排除特定服务器/数据库/Schema，支持 `*` 和 `?` 通配符 |

## 三、技术原理推测

### 3.1 SSMS 扩展点利用

SSMS 基于 Visual Studio Shell，SQL Prompt 主要利用以下 VS 扩展点：

```
┌─────────────────────────────────────────────┐
│            SSMS / VS Shell                    │
├─────────────────────────────────────────────┤
│  ┌───────────────┐  ┌──────────────────┐    │
│  │ ICompletion    │  │ ITaggerProvider   │    │
│  │ SourceProvider │  │ (代码分析标记)     │    │
│  └───────┬───────┘  └────────┬─────────┘    │
│  ┌───────┴───────────────────┴─────────┐    │
│  │         SQL Prompt 插件               │    │
│  │  ┌──────────────────────────────┐    │    │
│  │  │  MEF Export Attributes        │    │    │
│  │  │  [Export(typeof(IXxxProvider))]│    │    │
│  │  └──────────────────────────────┘    │    │
│  └──────────────────────────────────────┘    │
└─────────────────────────────────────────────┘
```

### 3.2 插件加载流程

```
SSMS 启动
  ↓
VS Shell 加载所有已注册扩展
  ↓
发现 SQL Prompt .vsix manifest
  ↓
通过 MEF 加载 SQL Prompt 程序集
  ↓
实例化 ICompletionSourceProvider 等扩展点
  ↓
注册命令、菜单、快捷键
  ↓
SQL Prompt 就绪，开始监听编辑器事件
```

### 3.3 性能设计关键点

| 设计要点 | 说明 |
|----------|------|
| **异步加载** | 大型 schema 的加载不阻塞 SSMS UI |
| **进度反馈** | 加载大型数据库时显示进度对话框 |
| **内存控制** | 排除策略 + 手动清除缓存 + 内存不足警告 |
| **增量解析** | 代码补全时增量解析 SQL 文本，不全量重解析 |
| **防抖机制** | 补全触发使用防抖，避免频繁触发查询 |

## 四、用户体验亮点

1. **无缝集成**：所有功能都在 SSMS 编辑器内完成，无需切换工具
2. **智能缓存**：首次连接后补全即时响应，体验流畅
3. **性能可控**：通过排除策略和手动刷新，用户可控制缓存行为
4. **广泛兼容**：覆盖所有主流 SSMS/VS 版本和 SQL Server 平台

## 五、可实现的借鉴方案

### 5.1 SSMS 扩展开发技术栈

VSIX（Visual Studio Extension）开发的核心技术栈：

| 技术 | 用途 |
|------|------|
| **VSIX Manifest** | 定义扩展的元数据、支持的 VS 版本、依赖项 |
| **MEF** | 通过 `[Export]` 属性导出扩展点实现 |
| **Editor API** | `Microsoft.VisualStudio.Text` 命名空间 |
| **Shell API** | `Microsoft.VisualStudio.Shell` 命名空间 |
| **DTE** | SSMS 对象模型自动化（如 Object Explorer 操作） |

### 5.2 关键扩展点实现

| 功能 | 使用的 VS 扩展点 |
|------|-----------------|
| 代码补全 | `ICompletionSourceProvider` → `ICompletionSource` |
| 代码分析标记 | `ITaggerProvider` → `ITagger<ErrorTag>` |
| 格式化 | 命令处理器 + `ITextBuffer` 操作 |
| 工具窗口 | `ToolWindowPane` + `ProvideToolWindow` |
| 菜单/命令 | `IMenuCommandService` + `OleMenuCommand` |

### 5.4 最小可行实现

```
阶段1（基础集成）：
  - 创建 VSIX 项目
  - 实现基本工具栏/菜单
```

## 六、优先级建议

| 评估维度 | 评分 | 说明 |
|----------|------|------|
| 实现难度 | **中** (3/5) | VS Shell 扩展开发有学习曲线但有成熟文档 |
| 业务价值 | **高** (4/5) | 架构设计决定所有功能的质量和性能 |
| 实现优先级 | **P1** | 架构设计先行，为其他功能模块奠定基础 |
