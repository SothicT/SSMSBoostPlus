## 根因分析

点击"在编辑器中打开"按钮后，主编辑器未打开任何新窗口，根因是 `OpenInEditorButton_Click` 中使用了错误的 DTE API 来创建新文档：

```csharp
// src/SSMS/UI/VersionHistory/LocalHistoryDiffDialog.xaml.cs:437
dte.ItemOperations.NewFile("SQL Files\\SQL Query", "VersionScript.sql");
```

`EnvDTE.ItemOperations.NewFile` 依赖 **VS 的项目/项模板系统**：它本质是"向当前选中项目添加一个新项"。但 **SSMS 22 是基于 VS 的隔离外壳（Isolated Shell），没有标准的项目系统**（只有 Misc Files 这类伪项目）。因此 `ItemOperations.NewFile` 找不到合法的宿主项目/模板，直接抛出 `COMException 0x80004005：模板"SQL Files\SQL Query"对选定的项目无效。`

该异常被 `OpenInEditorButton_Click` 的 `try/catch` 捕获，记录错误日志，随后 `finally` 中 `success` 仍为 `false`、`DialogResult` 置为 `null` 并执行 `Close()`——对话框关闭，但**没有任何新编辑器窗口被创建**，与用户描述的"主编辑器未打开新窗口"完全吻合。

### 为什么不是其它分支

代码中还有两处提前返回/告警分支，已在日志中排除：

- `dte == null || string.IsNullOrEmpty(_historicalScript)` 分支（日志应为 `[LocalHistory] 在编辑器中打开失败：DTE 不可用或历史脚本为空`）：日志未出现，且 `_historicalScript` 来自 `rightScript`（右侧历史脚本），差异页能正常渲染说明该脚本非空，DTE 在 SSMS 中始终可用。
- `NewFile 后 ActiveDocument 为 null` 分支（日志应为 `[LocalHistory] 在编辑器中打开失败：NewFile 后 ActiveDocument 为 null`）：日志未出现。

因此确定唯一路径是 `NewFile` 直接抛 `COMException`。

## 修复建议

核心思路：在 SSMS 隔离外壳中，**不要用 `ItemOperations.NewFile`**，改用 SSMS 原生命令 **`dte.ExecuteCommand("Query.NewQuery")`** 来新建查询编辑器窗口（本仓库 `ExecutionInterceptor` 已用同族的 `Query.Execute` 命令，证明该命令族在 SSMS 中可用）。`Query.NewQuery` 会在主编辑器区打开一个空白 SQL 查询窗口并使其成为 `ActiveDocument`，随后再写入历史脚本。

### 方案一（推荐）：把"新建查询+写脚本"移到 ShowDialog 返回之后执行

理由：对话框通过 `ShowDialog()` 以 WPF 模态方式打开，其消息泵由 WPF 嵌套 Dispatcher 驱动。在模态对话框内部直接调用 `dte.ExecuteCommand` 存在命令路由被嵌套泵阻塞/死锁的风险。调用方 `LocalHistoryToolWindowControl` 在 `ShowDialog()` 返回后已有成熟的 `this.Dispatcher.BeginInvoke(... DispatcherPriority.Background)` 模式来安全运行 DTE 代码（见原 799-807 行的 `dte?.ActiveDocument?.Activate()`，已被验证可用）。复用该上下文最稳妥。

改动 1 — `LocalHistoryDiffDialog.xaml.cs`：新增一个对外暴露的属性，并精简按钮处理（只负责"传递意图+关闭对话框"，不再做 DTE 操作）：

```csharp

/// <summary>用户点击"在编辑器中打开"时携带的历史脚本；为 null 表示未请求打开。</summary>
public string? ScriptToOpenInEditor { get; private set; }
```

```csharp
// 修改前（424-465 整体替换为）：
private void OpenInEditorButton_Click(object sender, RoutedEventArgs e)
{
    var dte = Microsoft.VisualStudio.Shell.Package.GetGlobalService(typeof(EnvDTE.DTE)) as EnvDTE.DTE;

    if (dte == null || string.IsNullOrEmpty(_historicalScript))
    {
        _logger.Warning($"[LocalHistory] 在编辑器中打开失败：DTE 不可用或历史脚本为空 (dteNull={dte == null}, scriptEmpty={string.IsNullOrEmpty(_historicalScript)})");
        return;
    }

    bool success = false;
    try
    {
        dte.ItemOperations.NewFile("SQL Files\\SQL Query", "VersionScript.sql");
        var doc = dte.ActiveDocument;
        if (doc == null)
        {
            _logger.Warning("[LocalHistory] 在编辑器中打开失败：NewFile 后 ActiveDocument 为 null");
        }
        else
        {
            var textDoc = (EnvDTE.TextDocument)doc.Object("TextDocument");
            var editPoint = textDoc.CreateEditPoint();
            editPoint.StartOfDocument();
            editPoint.ReplaceText(
                textDoc.EndPoint,
                _historicalScript,
                (int)EnvDTE.vsEPReplaceTextOptions.vsEPReplaceTextAutoformat);
            success = true;
            _logger.Information($"[LocalHistory] 历史版本脚本已在编辑器中打开");
        }
    }
    catch (Exception ex)
    {
        _logger.Error(ex, "[LocalHistory] 在编辑器中打开脚本失败");
    }
    finally
    {
        DialogResult = success ? true : (bool?)null;
        Close();
    }
}
```

### 方案二（备选，单文件最小改动）：在按钮处理内部原地替换 NewFile 为 ExecuteCommand

只改 `LocalHistoryDiffDialog.xaml.cs` 一个文件，将 `dte.ItemOperations.NewFile(...)` 这一行替换为 `dte.ExecuteCommand("Query.NewQuery");` 并相应处理 `ActiveDocument`。优点：改动文件少；缺点：在模态 `ShowDialog` 内部调用 `ExecuteCommand`，存在嵌套消息泵导致的命令阻塞/死锁风险（虽多数情况下可工作，但不如方案一稳妥），故不推荐作为首选。

## 预防措施

- 在 SSMS 隔离外壳环境中，**禁止对"新建文档"使用 `ItemOperations.NewFile` 等依赖项目系统的 API**；统一通过 `dte.ExecuteCommand("Query.NewQuery")` 打开新查询窗口。建议在代码评审清单/注释中加入此约束。
- 对涉及 DTE 的调用，始终对 `dte`、`ActiveDocument`、`TextDocument` 做 null 检查并记录日志，避免异常被静默吞掉导致"无响应"类问题难以排查。
- 对 `ActiveDocument` 为 null 的情况给出明确日志（已在方案中保留），便于后续若 `Query.NewQuery` 后文档未激活时能快速定位。
- （可选）补充知识库条目：`diagnosis/knowledge-base/runtime/ItemOperations.NewFile_SSMS_Shell.md`，记录"SSMS 隔离外壳下 NewFile 抛 0x80004005 模板无效，改用 Query.NewQuery"。
