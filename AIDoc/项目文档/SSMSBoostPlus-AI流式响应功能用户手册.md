# AI 流式响应功能 — 用户手册

## 一、功能概述

SSMSBoost++ 的 AI 功能（智能建议、智能注释、格式化、性能分析）采用**服务端推送事件（SSE）+ 前端零缓冲实时渲染**技术，AI 的每一个输出字符都会**即时**显示在弹窗中，无需等待完整响应。

### 与传统方式的对比

| 特性 | 传统请求 | SSMSBoost++ 流式响应 |
|------|---------|---------------------|
| 响应方式 | 等待完整响应后一次性显示 | 逐 token 实时显示 |
| 等待体验 | 长时间空白 → 突然出现全部内容 | 逐步看到 AI "打字"过程 |
| 首字符延迟 | 等待整个响应完成 | 首个 token 到达即显示 |
| 超时感知 | 等到超时才知道失败 | 连接失败立即提示 |

## 二、使用方法

### 2.1 触发 AI 功能

在 SSMS SQL 编辑器中，选中一段 SQL 代码，右键点击以下菜单项：

| 菜单项 | 功能 | Prompt 示例 |
|--------|------|------------|
| **AI 智能建议** | 优化选中的 SQL 语句 | `@SSMSBOOST 请优化如下语句：` |
| **AI 智能注释** | 为 SQL 添加中文注释 | `@SSMSBOOST 请为如下 SQL 代码添加中文注释：` |
| **AI 格式化** | 按 Microsoft 风格格式化 SQL | `@SSMSBOOST 请格式化如下 SQL 代码（Microsoft 风格）：` |
| **AI 性能分析** | 分析 SQL 性能并提供优化建议 | `@SSMSBOOST 请分析如下 SQL 语句的性能：` |

### 2.2 流式响应弹窗

触发 AI 功能后，弹出流式响应弹窗，界面分三个区域：

```
┌──────────────────────────────────────────┐
│  📘 AI 智能建议                  3.2s    │  ← 标题栏（含计时）
├──────────────────────────────────────────┤
│  正在连接 AI 服务... ▓▓▓▓▓▓▓▓           │  ← 状态栏（进度条）
├──────────────────────────────────────────┤
│  📤 AI 请求内容                          │
│  ┌──────────────────────────────────────┐│
│  │ SELECT * FROM Orders WHERE ...       ││  ← 请求区（原始 SQL）
│  └──────────────────────────────────────┘│
│  ════════════════════════════════════════│  ← 可拖拽分隔条
│  🤖 AI 响应                              │
│  ┌──────────────────────────────────────┐│
│  │ 💭 正在思考...                        ││  ← 思考过程（可折叠）
│  │ 优化这个查询需要考虑...                ││
│  │                                       ││
│  │ ## 优化建议                            ││  ← 正式响应（实时流式）
│  │ 1. 避免 SELECT *，应明确指定列名       ││
│  │ 2. 添加索引建议...                     ││
│  └──────────────────────────────────────┘│
├──────────────────────────────────────────┤
│          [📝 复制代码] [📋 复制响应] [关闭] │  ← 底部操作栏
└──────────────────────────────────────────┘
```

### 2.3 思考过程区域

AI 模型（如 Qwen3）在生成正式回答前会经历一个"思考"阶段。思考过程区域会：

- **思考中**：显示 💭 动画 + "正在思考..." 文字，内容实时滚动
- **思考完成**：自动折叠为可展开的摘要，显示字符数，点击可展开查看

### 2.4 状态指示

| 状态 | 显示 | 说明 |
|------|------|------|
| 连接中 | "正在连接 AI 服务..." + 进度条 | fetch 请求已发出，等待响应头 |
| 流式接收 | "⏳ 响应中" + 计时器 | SSE 数据正在实时流入 |
| 完成 | "✅ 响应完成" | 全部数据接收完毕 |
| 失败 | "❌ 连接失败" | 网络错误或服务不可用 |

### 2.5 操作按钮

| 按钮 | 功能 | 启用时机 |
|------|------|---------|
| 📝 复制代码 | 复制响应中的 SQL 代码块 | 响应包含代码块时 |
| 📋 复制响应 | 复制完整响应文本 | 有响应内容时 |
| 关闭 | 关闭弹窗 | 流式完成或出错后 |

## 三、AI 服务配置

### 3.1 内置默认 API

SSMSBoost++ 内置了一个开箱即用的 AI API，**无需任何配置**即可使用：

| 配置项 | 默认值 |
|--------|--------|
| 端点 | `http://10.32.2.50:7500/feishu/stream/event` |
| 模型 | Qwen3.6-35B-A3B |
| 认证 | 无需 API Key |
| 格式 | SSE 流式 |

### 3.2 自定义 API

如需使用其他 AI 服务，可通过 **工具 → AI 配置** 设置：

| 配置项 | 说明 | 示例 |
|--------|------|------|
| API 端点 | OpenAI 兼容的接口地址 | `https://api.openai.com/v1/chat/completions` |
| API 密钥 | 认证密钥 | `sk-xxxx` |
| 模型名称 | 模型标识 | `gpt-4o` |

> **注意**：自定义 API 使用 OpenAI 协议，响应模式取决于服务端是否支持流式。内置默认 API 始终使用 SSE 流式。

## 四、常见问题

### Q1：为什么有时需要等几秒才开始输出？

AI 模型在生成回答前需要"思考"（特别是推理类模型如 Qwen3）。这段时间思考过程区域会实时显示内容。如果思考过程区也在空白，则是网络延迟或服务端排队。

### Q2：出现"无法连接到 AI 服务器: Failed to fetch"怎么办？

| 原因 | 解决方案 |
|------|---------|
| 默认 API 服务不可用 | 检查 `http://10.32.2.50:7500` 是否可访问 |
| 公司网络限制 | 联系 IT 开放端口或配置自定义 API |
| SSMS 权限不足 | 以管理员身份运行 SSMS |

### Q3：响应内容显示乱码或格式异常？

这是 Markdown 实时渲染的正常现象——在代码块或表格未完整接收时，渲染结果可能暂时不完整。等待流式传输完成后会自动修正。

### Q4：可以中途关闭弹窗吗？

可以。点击"关闭"按钮或按 Esc 键即可中断。已接收的内容会保留在剪贴板（点击"复制响应"）。

### Q5：自定义 API 也支持流式显示吗？

取决于 API 服务端。如果自定义 API 返回 `text/event-stream` 格式，SSMSBoost++ 会自动流式渲染；否则会等待完整响应后一次性显示。
