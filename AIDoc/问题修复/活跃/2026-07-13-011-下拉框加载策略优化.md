# 版本历史下拉框加载策略优化（数据库名列 + 懒加载 + 当前库过滤）

> 合并自 #001（数据库名列下拉框） + #006（下拉框懒加载）
> 合并原因：两者都涉及同一对象下拉框的数据加载逻辑链路改造，分开做会导致第二次重构第一次的代码

## 现象

### 场景 A：缺少数据库名列（原 #001）
版本历史页签页面上缺少数据库名列，用户连接了多个数据库（如 MESFA、MESFB）时无法区分对象所属数据库。下拉框加载了所有库的对象历史记录，导致列表混乱。

### 场景 B：下拉框加载慢（原 #006）
对象下拉框当前一次性加载全量数据，点击展开下拉框时需等待 3-5 秒，数据量大时用户感知明显卡顿。

**期望行为**：新增「数据库名」列放在第一列，下拉框仅显示当前连接库的对象，默认仅加载前 100 个对象，用户输入关键字后触发服务端筛选检索。

## 需求澄清

- **用户场景**：用户连接多个数据库，频繁切换窗口查看不同库的对象版本历史
- **验收标准**：
  1. 新增「数据库名」列，放在第一列，列宽自适应
  2. 下拉框仅加载当前窗口连接的数据库 IP 库名下的对象
  3. 默认仅加载 Top 100 个对象，点击展开无卡顿
  4. 用户输入关键字后触发服务端筛选检索
  5. 切换窗口后自动刷新下拉框和列表
- **范围边界**：仅版本历史页签对象下拉框，不涉及其他下拉框

## 子任务拆分

1. 新增「数据库名」列 UI（第一列，列宽自适应）
2. 下拉框过滤逻辑改为按当前库加载
3. 下拉框改为懒加载分页模式（Top 100 + 关键字搜索）
4. 窗口切换自动刷新联动（与 #010 协同）

## 根因
`GetObjectListAsync` 无条件全量加载对象列表，无分页和关键字过滤支持；DataGrid 缺少数据库名列；下拉框搜索仅做客户端过滤，无法利用服务端索引。

## 影响范围
版本历史页签的对象下拉框和 DataGrid 列表。

## 涉及模块
`src/Core/VersionHistory/IVersionHistoryService.cs`、`VersionHistoryService.cs`、`src/SSMS/UI/VersionHistory/LocalHistoryToolWindowControl.xaml`、`.xaml.cs`

## 诊断记录
- `GetObjectListAsync` SQL 无 TOP 限制，大数据量库全量加载耗时 3-5 秒
- 下拉框搜索仅客户端 `LINQ Where` 过滤，无法利用数据库索引
- `VersionRecord` 已有 `DatabaseName` 字段，但 DataGrid 未展示

## 修复方案
1. 接口新增 `top` 和 `keyword` 可选参数，SQL 支持 `TOP N` + `LIKE` 过滤
2. DataGrid 新增"数据库名"列（第一列，蓝色加粗，`SizeToCells` 自适应宽度）
3. `LoadForObject` 初始加载改为 `top: 100`
4. `OnSearchBoxTextChanged` 改为服务端搜索 + 300ms 防抖 + `CancellationTokenSource` 取消机制
