# 版本差异页显示与性能优化 需求规格（SPEC-SSMSBP-DISPPERF-001）

## 1. 需求概述

- 业务背景：版本历史差异对比页用于对比 SQL 脚本的两个版本，用户反馈长 SQL 单行被截断且无横向滚动、大脚本加载卡顿。
- 核心目标：任意长度 SQL「看得全、看得快」——默认自动换行可看全超长行，可切换不换行 + 横向滚动精确比对；5000 行脚本加载 < 1 秒且 UI 不阻塞。
- 适用角色：DBA、数据库开发、运维（SSMS 用户）。
- 关联模块：LocalHistoryDiffDialog（差异渲染、差异导航、同步滚动、重试加载）。

## 2. 整体功能架构

```
版本差异页显示与性能优化
├── 显示模式切换（工具栏开关）
│   ├── 自动换行（默认）：超长行折行显示
│   └── 不换行 + 横向滚动：水平滑块查看完整行
└── 性能优化（加载链路）
    ├── diff 计算 + 渲染耗时控制（5000 行 < 1 秒）
    └── 超大脚本兜底（不崩溃 / 不长时间无响应）
```

## 3. 详细功能需求

### 3.1 显示模式切换

- 功能名称：自动换行开关
- 功能描述：工具栏新增「自动换行」ToggleButton，控制左右两侧面板的换行/横滚显示模式。
- 触发条件：用户点击开关。
- 前置条件：页面已渲染（Document 已构建完成）。
- 核心业务规则：
  - 默认状态为「自动换行」（按用户决策）。
  - 切换实时应用于左右两侧面板，不重新计算差异、不重新拉取脚本。
  - 切换不影响已采集的差异点导航（计数、高亮、同步滚动）。
- 页面/接口细则：开关置于 Row 1 工具栏（与「同步滚动」开关并列）；两种模式下左右逐行对齐保持。
- 数据校验规则：无。
- 异常处理机制：若切换渲染失败，保留原显示模式并给出提示，不破坏已渲染内容。

### 3.2 性能优化（加载链路）

- 功能名称：大脚本加载优化
- 功能描述：优化打开对比页 / 重试加载时的差异计算与渲染耗时，避免卡顿。
- 触发条件：打开对比页或点击重试。
- 前置条件：存在左右脚本（可为空触发遮罩/重试场景）。
- 核心业务规则：
  - 5000 行 SQL 两端对比，从打开触发到可交互（可滚动、可点导航）< 1 秒。
  - 渲染/计算过程中 UI 线程不被长时间阻塞，页面可响应。
- 数据校验规则：无。
- 异常处理机制：超大脚本（20000+ 行）不崩溃、不长时间无响应，可降级渲染或明确提示。

## 6. 非功能需求

- 性能：5000 行 < 1 秒（打开到可交互）；UI 线程不长时间阻塞。
- 兼容性：net472 / SSMS 22；与现有差异导航、同步滚动、重试逻辑向后兼容。
- 安全：不涉及敏感数据处理变更。
- 日志：保留现有 `ILoggerService` 记录（加载耗时、异常），不新增敏感日志。
- 容错：超大脚本必须有兜底，禁止无响应或崩溃。

## 7. 研发注意事项与风险提示

- 易错逻辑：切换显示模式时**不应重建 FlowDocument**，否则会破坏差异导航已采集的 `Paragraph` 引用与高亮状态（GoToDiff/CollectDiffRows 依赖具体 Paragraph 实例）。
- 易遗漏场景：自动换行模式下，行内逐字符 diff 着色、行号对齐、差异点高亮必须保持正确；切换模式后 BringIntoView 滚动定位仍应准确。
- 显示根因提示（供开发参考，非需求约束）：当前 `BuildDocument` 设置无限列宽禁用了换行；`HorizontalScrollBarVisibility` 设在外层 ScrollViewer 未生效于 RichTextBox 自身。
- 性能选型提示（供 Architect 决策）：当前 FlowDocument 逐行 Paragraph 同步构建、无 UI 虚拟化，是大脚本卡顿主因；性能方案由技术方案阶段确定，本规格仅约束结果指标（AC-004/007）。
- 新旧兼容：需确保现有「在编辑器中打开」、重试遮罩、同步滚动等行为不受影响。
