# 版本比对页面左侧的服务器当前定义脚本内容仍未加载成功

## 现象
版本比对页面左侧的服务器当前定义脚本内容仍未加载成功。

## 根因
`OpenDiffDialogAsync()` 获取左侧服务器当前定义时，依赖 `GetActiveConnectionString()` 从**当前活动窗口**获取连接串，但该调用在多个场景下返回 null/空值，导致静默跳过 DB 定义查询，左侧面板显示为空。同时缺少错误反馈机制，用户无法感知加载失败原因。

## 影响范围
版本历史页签（LocalHistoryToolWindow）→ 单击版本记录打开比对弹窗时，左侧「服务器当前定义」面板内容为空。

## 涉及模块
- `src/SSMS/UI/VersionHistory/LocalHistoryToolWindowControl.xaml.cs:306-366` — OpenDiffDialogAsync() 方法
- `src/Core/VersionHistory/VersionHistoryService.cs:265-296` — GetServerObjectDefinitionAsync() 方法
- `src/SSMS/UI/VersionHistory/LocalHistoryDiffDialog.xaml.cs` — 比对弹窗（显示空内容的受害者）

## 诊断记录
### 代码追踪路径
```
用户单击版本记录 → VersionGrid_SelectionChanged → OpenDiffDialog(record)
  → OpenDiffDialogAsync(serverRecord=选中记录)
    → editorService.GetActiveConnectionString()   ← 关键点：获取当前活动窗口连接串
    → if (!string.IsNullOrEmpty(srcConnStr))      ← 如果为空，直接跳过！无任何提示
        → _historyService.GetServerObjectDefinitionAsync(srcConnStr, schema, name, objectType)
    → leftScript = null (跳过) 或 null (查询失败)
    → new LocalHistoryDiffDialog(leftTitle, leftScript ?? "", ...)  ← 空字符串传入对话框
```

### 发现的问题（按严重度排序）

**P0 — 连接串获取时机错误（核心根因）**
- 位置：`LocalHistoryToolWindowControl.xaml.cs:324-325`
- 问题：每次打开 Diff 弹窗时，通过 `new SsmsEditorService().GetActiveConnectionString()` **实时获取当前活动窗口的连接串**
- 失败场景：
  - 用户点击版本记录后焦点已转移到 LocalHistoryToolWindow 自身（非 SQL 编辑器窗口）
  - 活动窗口不是 SQL 查询编辑器（如对象资源管理器、解决方案资源管理器）
  - SSMS 内部服务无法解析当前连接信息
- 结果：`srcConnStr = null` → 整个 if 块被跳过 → `leftScript = null`

**P1 — 静默失败无用户反馈**
- 位置：同上，326-334 行的 if 块
- 问题：当 `srcConnStr` 为空或 `GetServerObjectDefinitionAsync` 返回 null 时，没有任何日志、提示或 UI 反馈
- 用户看到的是空白左侧面板，完全不知道发生了什么

**P2 — GetServerObjectDefinitionAsync 查询范围受限**
- 位置：`VersionHistoryService.cs:272-277`
- 问题：SQL 查询使用 `sys.sql_modules`，**仅支持存储过程/函数/视图/触发器**
- 对表、索引等非模块对象返回 null，同样静默失败

**P3 — 对象名解析不够健壮**
- 位置：`LocalHistoryToolWindowControl.xaml.cs:328-330`
- 问题：简单按 '.' 分割取 [0] 和 [1]，未处理以下情况：
  - ObjectName 不含 schema 前缀（如 `"MyProcedure"` 而非 `"dbo.MyProcedure"`）
  - ObjectName 包含多个点（如 `[dbo].[sp_name]` 方括号格式）

**P4 — 死代码**
- 位置：`LocalHistoryToolWindowControl.xaml.cs:321-322`
- `connInfo = new ConnectionServiceFacade(...)` 创建后从未使用

## 修复方案

### P0+P1+P4：核心修复

**改动文件**：`src/SSMS/UI/VersionHistory/LocalHistoryToolWindowControl.xaml.cs`

1. **新增 `_targetConnectionString` 字段**（第 35 行）：用于缓存目标库连接串
2. **`LoadForObject` 中推导缓存**（第 85-100 行）：基于 `_connectionString`（MESBASE）+ `_databaseFilter`（目标库名）通过 `SqlConnectionStringBuilder` 替换 `InitialCatalog` 推导出目标库连接串
3. **`OpenDiffDialogAsync` 替换连接串获取方式**（第 326-370 行）：
   - 删除原 `ConnectionServiceFacade` 死代码（2 行）
   - 删除原 `SsmsEditorService.GetActiveConnectionString()` 实时获取（2 行）
   - 改为直接使用缓存的 `_targetConnectionString`
   - 新增 `statusMessage` 变量，在连接串为空或查询失败时显示状态栏提示（"无法获取目标数据库连接" / "服务器定义加载失败"）

### 方案A：窗口切换全量刷新

**改动文件**：同上

**`RefreshForActiveWindowAsync` 方法**（第 420-461 行）：
1. 在方法开头通过 `SsmsEditorService.GetActiveConnectionString()` 获取新窗口连接串
2. 解析比较 `DataSource` + `InitialCatalog` 与当前 `_connectionString` 的 `DataSource` + `_databaseFilter`
3. 若不一致，则将新连接串转换为 MESBASE 连接串，调用 `LoadForObject` 全量重新初始化（含 `_connectionString`、`_targetConnectionString`、对象列表、版本列表）
4. 若一致，保持原有行为（仅刷新对象名和版本列表）

### 未修复（待后续）

- **P2**：`GetServerObjectDefinitionAsync` 仅支持 `sys.sql_modules` 对象（存储过程/函数/视图/触发器），对表等非模块对象返回 null — 属于功能增强，范围超出本次修复
- **P3**：对象名解析不够健壮（未处理方括号格式、无 schema 前缀等） — 属于边缘情况增强，当前场景下 `ObjectName` 格式为 `dbo.XXX`，不影响实际使用
