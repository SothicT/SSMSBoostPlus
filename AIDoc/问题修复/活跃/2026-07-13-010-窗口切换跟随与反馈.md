# 版本历史页签窗口切换跟随与反馈增强

> 合并自 #002（窗口切换跟随） + #005（窗口切换缺反馈）
> 合并原因：共享同一触发事件（编辑器窗口切换），分开修改会导致同一段事件处理代码冲突

## 现象

### 场景 A：窗口切换不跟随（原 #002）
在 SSMS 中打开两个查询窗口分别连接不同数据库，打开版本历史页签，切换到另一个窗口后，版本历史页签显示的数据库名和下拉框内容不会跟随切换，仍停留在上一个窗口的数据库。

### 场景 B：窗口切换无反馈（原 #005）
切换编辑器窗口时，版本历史页签状态栏无任何加载中提示，用户无法感知窗口切换是否触发了数据加载。

**期望行为**：切换窗口后版本历史页签应自动更新为当前窗口连接的数据库 IP 库名，下拉框也刷新为当前库的对象列表，同时状态栏显示「加载中」等状态提示文本。

## 需求澄清

- **用户场景**：用户在 SSMS 中同时打开多个查询窗口连接不同数据库，频繁切换窗口查看各库的版本历史
- **验收标准**：
  1. 切换窗口后版本历史页签自动识别当前连接数据库并刷新
  2. 下拉框内容切换为当前库的对象列表
  3. 状态栏在刷新过程中显示「加载中」提示
  4. 加载完成后状态栏恢复正常
- **范围边界**：所有类型的查询窗口切换均需覆盖，需联动主窗口状态栏（不仅限于版本历史页签内部）

## 根因
`RefreshForActiveWindowAsync` 缺少加载前状态反馈和 SSMS 主窗口状态栏同步，导致用户无法感知切换是否触发。此外 `_isLoading` 未在入口检查，存在并发切换风险。

## 影响范围
所有数据库连接、所有查询窗口切换场景均受影响。

## 涉及模块
`src/SSMS/UI/VersionHistory/LocalHistoryToolWindowControl.xaml.cs`

## 诊断记录
- 窗口切换回调 `OnWindowActivated` 已正确监听 DTE WindowEvents
- `RefreshForActiveWindowAsync` 连接变更检测逻辑正确，但无状态反馈
- 无对象时状态栏被清空为 ""，用户看到空白状态栏
- SSMS 主窗口状态栏未联动，用户在其他窗格时无法感知切换

## 修复方案
1. 入口处添加 `_isLoading` 检查，防止加载中重复触发切换
2. 执行开始时立即显示"切换中..." + 同步 SSMS 状态栏
3. 连接变更时显示"已切换到 xxx/yyy，加载中..." + 同步 SSMS 状态栏
4. 无对象定义时显示"未检测到对象定义"（而非清空）
5. 新增 `UpdateSsmsStatusBar` 方法通过 `DTE.StatusBar.Text` 联动主窗口状态栏
6. 异常时显示"切换失败" + 同步 SSMS 状态栏
