# 历史版本列表加载优化 技术方案（SPEC-SSMSBP-LISTPERF-001）

## 0. 范围与约束（来自使用者确认）

- **本次仅交付诊断 + 方案，不修改代码。**
- **DB 索引无权限**：无法在 `MESBASE.dbo.DBTrigger_Object_Version_Table` 上新建索引，因此诊断报告中的 RC2/F2（覆盖索引）**不纳入本次**。RC2 才是 10S+ 的根因银弹，建议另行向 DBA 申请（见 §6）。
- **加载交互仅做「基础」级**：网格加载遮罩 + 等待光标 + 加载前清空旧数据。不做取消按钮 / 防重叠的「进阶」UI（但 §4 的取消重叠属于性能正确性修复，低成本、建议一并实施，实施时由使用者确认）。
- 全部改动均在应用侧（SSMS 层 + Core 层），不引入新依赖，符合 `Shared→Core→AI→SSMS` 单向依赖。

## 1. 变更概述

针对诊断报告 RC1 / RC3 / RC4 / RC5 的应用侧可解部分，落地三件事：

1. **F1 列表查询剔除 `sqlcommand` 大字段，差异/复制时按 ID 懒加载**（最高确定性收益，纯应用代码）。
2. **F4-basic 加载态交互**：网格加载遮罩 + `Mouse.OverrideCursor = Wait` + 加载开始前清空 `VersionGrid` 旧数据。
3. **F3 取消重叠加载**（建议一并做）：`LoadVersionsAsync` 增加 `CancellationTokenSource`，切换对象/窗口时取消上一次，保证「最后选中的对象」才更新网格，杜绝并发全表扫描。

实施顺序建议：**F1 → F4-basic → F3**。F1 单独即可显著降低每次列表加载的 I/O，是应用侧最大杠杆；F4-basic 直接消除「只能干等」观感；F3 削减因快速切换产生的重复查询浪费。

## 2. F1：列表查询剔除 sqlcommand，按需懒加载

### 2.1 为什么不展示却要查

`VersionGrid` 列仅绑定 `DatabaseName / RowNumber / FormattedTime / ChangeType / LoginName / Version`（LocalHistoryToolWindowControl.xaml:212-263），从不显示 `sqlcommand`。但 `GetObjectHistoryAsync` 的 SELECT 把每行完整脚本正文（可达数百 KB）悉数读回（VersionHistoryService.cs:38-53、689）。差异弹窗与复制功能用的 `sqlcommand` 完全可用已存在的 `GetVersionSqlAsync(conn, Id)`（按主键，极快）替代。

### 2.2 Core 改动（VersionHistoryService.cs）

- `GetObjectHistoryAsync`（:38-53）的 SELECT 列表去掉 `[sqlcommand]`：
  ```sql
  SELECT TOP (@top)
      [ID], [databasename], [eventtype], [objectname], [objecttype],
      [loginname], [hostname], [PostTime], [Version]
  FROM [{_databaseName}].[dbo].[{_tableName}]
  WHERE (...) ORDER BY [PostTime] DESC, [ID] DESC
  ```
- 新增列表专用映射 `MapListRecord(SqlDataReader reader)`（不含 `sqlcommand`），`GetObjectHistoryAsync` 改用它；保留原 `MapRecord`（仍读取 `sqlcommand`）供 `GetRecordByIdAsync`（GenerateRestoreScript 路径）使用，避免误伤恢复功能。
- `GetVersionSqlAsync`（:218）已存在且按 `[ID]` 取单行脚本，无需改动，作为懒加载数据源。

### 2.3 SSMS 改动（LocalHistoryToolWindowControl.xaml.cs）

- `OpenDiffDialogAsync`（:647 起）在使用 `serverRecord.SqlCommand`(:688)、`leftRecord/rightRecord.SqlCommand`(:697/699/729) 之前，判空后补取：
  ```csharp
  if (string.IsNullOrEmpty(record.SqlCommand))
      record.SqlCommand = await _historyService.GetVersionSqlAsync(_connectionString, record.Id, ct)
          .ConfigureAwait(true) ?? "";
  ```
  两个历史版本对比时，older / newer 两条均需补取；恢复路径的 `rightRecord?.SqlCommand` 同样补取。任一返回 null 时降级为空串 + 弹窗提示，不可崩溃。
- `CopySql_Click`（:1101）复制前若 `record.SqlCommand` 为空，先 `GetVersionSqlAsync` 补取再复制。

### 2.4 收益与注意

- 列表查询不再传输 100 条脚本正文，网络与反序列化开销大幅下降；结合 §3 的取消机制，快速切换不再重复搬运大字段。
- 注意：无索引时服务端「全表扫描 + 排序」仍在（RC2 未解），F1 解决的是「把扫描结果的大字段搬回客户端」这部分；真实端到端耗时仍需 RC2 索引兜底，故 §6 单列索引申请。

## 3. F3：取消重叠加载（建议一并实施）

### 3.1 问题

`ObjectSearchBox_SelectionChanged`（:510）、`RefreshForActiveWindow`（:990）以 `_ = LoadVersionsAsync(...)` 触发，且 `LoadVersionsAsync`（:445）无 CTS。快速切换对象 / SSMS 窗口时多个加载并发，各跑一次重查询并竞争 `VersionGrid.ItemsSource`，可能显示旧结果。

### 3.2 改动

- 新增字段 `private CancellationTokenSource? _versionLoadCts;`
- `LoadVersionsAsync` 开头取消并重建 CTS，将 token 透传进 `GetObjectHistoryAsync(... ct: ct)`（该方法已接受 `CancellationToken`，VersionHistoryService.cs:31，无需改签名）：
  ```csharp
  _versionLoadCts?.Cancel();
  _versionLoadCts = new CancellationTokenSource();
  var ct = _versionLoadCts.Token;
  var records = await _historyService.GetObjectHistoryAsync(_connectionString, objectName, _databaseFilter, ct: ct).ConfigureAwait(true);
  if (ct.IsCancellationRequested) return; // 已被更新的选择取代，不覆盖网格
  ```
- `finally` 中复位 `_isLoading` 保持不变；`ct.IsCancellationRequested` 判断确保「仅最后一次选择」更新网格，消除结果错乱与重复扫描。
- 对象选中路径沿用 `_isLoading` 已有语义即可（无需像 DB 下拉那样显式 guard，CTS 合并已足够）。

### 3.3 收益

直接削减由「快速切换」引发的重复重查询，与 F1 叠加后，连续切换对象的体验与耗时显著改善。

## 4. F4-basic：加载态交互（基础级）

### 4.1 XAML 改动（LocalHistoryToolWindowControl.xaml）

在 `VersionGrid`（:164）外层包一个 `Grid`，叠加一个加载遮罩层（默认 `Visibility=Collapsed`）：
```xml
<Grid Grid.Row="1">
    <DataGrid x:Name="VersionGrid" .../>
    <Border x:Name="LoadingOverlay" Visibility="Collapsed"
            Background="#80FFFFFF" HorizontalAlignment="Stretch" VerticalAlignment="Stretch">
        <StackPanel Orientation="Horizontal" HorizontalAlignment="Center" VerticalAlignment="Center">
            <TextBlock Text="⏳ 加载中..." FontSize="12" Foreground="#555" Margin="6,0,0,0"/>
        </StackPanel>
    </Border>
</Grid>
```
> 说明：基础级不含转圈动画 / 取消按钮 / 骨架屏（进阶、完整级才需要）。如需更明显反馈，可后续升级为带 `ProgressBar` 的遮罩。

### 4.2 xaml.cs 改动（LocalHistoryToolWindowControl.xaml.cs）

在 `LoadVersionsAsync`（:445）中：
```csharp
_isLoading = true;
// 1) 加载前清空旧数据，避免残留旧对象行造成歧义
VersionGrid.ItemsSource = null;
// 2) 显示遮罩 + 等待光标
LoadingOverlay.Visibility = Visibility.Visible;
Mouse.OverrideCursor = Cursors.Wait;
UpdateStatus("加载中...");
try { ... }
finally
{
    _isLoading = false;
    LoadingOverlay.Visibility = Visibility.Collapsed;
    Mouse.OverrideCursor = null;   // 必须复位，否则全局光标卡在等待态
}
```
- 遮罩与光标在 `finally` 复位，覆盖正常完成 / 异常 / 取消三种终态，避免光标残留。
- 异常分支（SqlException / 通用）保持现有 `MessageBox` / `UpdateStatus` 逻辑不变，仅在其前已完成遮罩复位。

### 4.3 收益

加载期间网格显示「加载中」遮罩、全局等待光标、且旧数据已清空，用户能明确感知「正在加载、当前为空、完成后才出现」，消除「只能干等且不知进度」的焦虑。

## 5. 接口 / 数据变更

- `GetObjectHistoryAsync`：SELECT 列减少（`sqlcommand` 不再返回），返回模型 `VersionRecord.SqlCommand` 在列表场景为空串，由调用方按需懒加载。方法签名（含 `CancellationToken`）不变。
- `VersionRecord` 模型不变（`SqlCommand` 字段保留，供懒加载回填）。
- 无新增对外接口、无数据库表/字段变更、无新增依赖。

## 6. 未纳入本次但强烈建议（RC2 索引）

`DBTrigger_Object_Version_Table` 缺少 `(objectname, [databasename], PostTime DESC, ID DESC)` 覆盖索引是 10S+ 的服务器侧根因。应用侧优化（F1/F3/F4）只能缓解「搬运大字段 + 重复扫描 + 无反馈」，无法消除「全表扫描 + 排序」本身。建议向 DBA 申请在低峰执行（SQL Server Enterprise 可用 `ONLINE=ON`）：
```sql
CREATE NONCLUSTERED INDEX IX_ObjectVersion_ObjectName_Db_PostTime
  ON dbo.DBTrigger_Object_Version_Table (objectname, databasename, PostTime DESC, ID DESC)
  INCLUDE (eventtype, objecttype, loginname, hostname, Version);
```
该索引 INCLUDE 刻意不含 `sqlcommand`——与 F1 配合后列表查询可做到「索引覆盖 + 不回表 + 不读大字段」，端到端稳定亚秒级。

## 7. 影响评估与风险

| 项 | 说明 | 风险 |
|----|------|------|
| 差异弹窗/复制 | 改为懒加载 `GetVersionSqlAsync`，多一次按 ID 查询（毫秒级、走主键） | 低；需在使用点判空降级 |
| 恢复功能（DROP 重建等） | `GenerateRestoreScriptAsync` 走 `GetRecordByIdAsync`（仍含 sqlcommand），不受影响 | 无 |
| 光标复位 | `finally` 必须 `Mouse.OverrideCursor = null`，否则全局光标卡死 | 低；代码审查重点 |
| 取消时序 | `ct.IsCancellationRequested` 判断要在 `SwitchToMainThreadAsync` 后、`ItemsSource` 赋值前 | 低 |
| 架构合规 | 仅 SSMS/Core 改动，未破坏依赖链，零新依赖 | 无 |

## 8. 验收对照（AC）

| AC | 满足方式 |
|----|----------|
| AC-1 列表查询不再返回 sqlcommand | F1 SELECT 剔除 + 列表专用映射 |
| AC-2 打开差异/复制仍能拿到脚本 | F1 懒加载 GetVersionSqlAsync（判空降级） |
| AC-3 加载中网格有「加载中」遮罩 | F4-basic LoadingOverlay |
| AC-4 加载中全局等待光标，完成后复位 | F4-basic Mouse.OverrideCursor + finally 复位 |
| AC-5 加载开始前清空旧数据 | F4-basic ItemsSource=null |
| AC-6 快速切换对象不叠加重复全表扫描、不显示旧结果 | F3 CTS 取消 + 仅最后一次更新网格 |
| AC-7 异常/取消时遮罩与光标正确复位 | F4-basic finally |

3. `LocalHistoryToolWindowControl.xaml` + `.xaml.cs`：新增 `LoadingOverlay`，`LoadVersionsAsync` 中设/复位遮罩与等待光标、加载前清空 `ItemsSource`。

## 10. 边缘情况与异常处理（实施必覆盖）

- `GetVersionSqlAsync` 返回 null（记录被清理/并发删除）：差异弹窗降级提示，禁止崩溃。
- 取消后再次选中同一对象：CTS 取消后 `_isLoading` 经 `finally` 正确复位。
- 异常路径（SqlException / 通用）也必须走 `finally` 复位遮罩与光标，避免状态卡死。
- 懒加载发生在 UI 线程后续（`SwitchToMainThreadAsync` 之后），注意不要在 UI 线程做同步 DB 调用。
- `async void` 入口（`ObjectSearchBox_SelectionChanged` 等）保持不变以兼容 SSMS 线程模型；取消逻辑收敛在 `LoadVersionsAsync`（可等待）内部。
