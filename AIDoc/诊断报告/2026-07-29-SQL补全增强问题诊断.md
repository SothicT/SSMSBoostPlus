### 问题1：SELECT TOP n 后没有字段提示

**示例**：`SELECT TOP 100 $CURSOR1* FROM [MESDATA].dbo.[API_EDI_LONGSYREQUIRE_COMPONENT] a WITH(NOLOCK)`

**根因定位**：

- `SyntaxLocator.ResolveNode("TOP", ...)` → 返回 `SyntaxNode.AfterTopKeyword`
- `CompletionDispatcher.GetCandidates` **缺少对 `AfterTopKeyword` 的处理**，走 default → `GetKeywordCandidates`（仅关键词）
- 期望行为：在 `SELECT TOP n` 之后提示字段名

**修复方案**：在 `CompletionDispatcher.GetCandidates` switch 中增加 `AfterTopKeyword` case，返回与 `SelectColumnArea` 相同的候选集（字段名 + TOP/DISTINCT/ALL 关键词）。

```csharp
case SyntaxNode.AfterTopKeyword:
    return GetFieldCandidates(currentStatement, filterText, false)
        .Concat(GetKeywordCandidates(filterText, new[] { "TOP", "DISTINCT", "ALL" }))
        .ToList();
```

**影响范围**：仅 `CompletionDispatcher.cs` 一处修改。

### 问题2：ORDER 后没有提示 BY

**示例**：`ORDER $CURSOR2`

**根因定位**：

- `SyntaxLocator.KeywordPattern` 包含多词模式 `ORDER\s+BY`（匹配 `ORDER BY`）
- 当光标在 `ORDER` 之后（`BY` 未输入），仅 `ORDER` 被匹配为关键词
- `SyntaxLocator.ResolveNode` **没有 `"ORDER"` 的 case**（仅有 `"ORDER BY"`），走 default → `ExpressionPosition` → 仅返回通用关键词（无 `BY`）
- 期望行为：在 `ORDER` 之后优先提示 `BY` 关键词

**修复方案**：在 `ResolveNode` 中增加 `case "ORDER"` → 返回 `AfterOrderByKeyword`；同时在 `GetCandidates` 的 `AfterOrderByKeyword` case 中增加 `"BY"` 关键词候选。

```csharp
// SyntaxLocator.ResolveNode
case "ORDER":
    return SyntaxNode.AfterOrderByKeyword;

// CompletionDispatcher.GetCandidates - AfterOrderByKeyword
case SyntaxNode.AfterOrderByKeyword:
    return GetColumnAliasCandidates(currentStatement)
        .Concat(GetFieldCandidates(currentStatement, filterText, false))
        .Concat(GetKeywordCandidates(filterText, new[] { "BY", "ASC", "DESC" }))
        .ToList();
```

**影响范围**：`SyntaxLocator.cs` + `CompletionDispatcher.cs`。

### 问题3：单表别名前缀缺失

**示例**：`WHERE ReqID = '' AND $CURSOR3=''`，表 FROM 中有 `a WITH(NOLOCK)`。

**根因定位**：

- `BuildFieldCandidateList` 中第 492 行：`bool showPrefix = isMultiTable && !isDotTrigger;`
- 当只有 **1 张表**时（`isMultiTable = false`），不显示别名前缀
- 当前设计：单表无歧义，无需前缀；多表才自动加前缀
- **用户需求**：即使单表也想看到带别名的形式

**当前行为**：显示 `TransDateTime`（无前缀）
**期望行为**：显示 `a.TransDateTime`（带前缀）

**修复方案**：当表有显式别名（Alias != PhysicalName）时，即使单表也提供带前缀的版本。最优方案：同时提供两种形式（带前缀和不带前缀），让用户选择。

```csharp
// BuildFieldCandidateList 中逻辑调整：
// 1. 如果 isMultiTable，showPrefix = true（原有逻辑）
// 2. 如果单表但别名与表名不同（用户显式定义了别名），同时显示两种形式
```

### 问题4：新增组合关键词补全

**建议**：将常用的组合关键词作为补全项，如：
- `GROUP BY`
- `ORDER BY`
- `OFFSET n ROWS [FETCH NEXT n ROWS ONLY]`
- `LEFT JOIN`
- `INSERT INTO`
- `WITH(NOLOCK)`

**根因**：当前 `ContextKeywords` 数组仅包含单关键词。组合关键词可作为 **模板（Snippet）** 补全添加到系统中。

**修复方案**：在 `CompletionDispatcher` 中新增一组 `CompoundKeywords`（组合关键词模板），在 `GetKeywordCandidates` 中混入这些组合项。

```csharp
private static readonly (string display, string insert)[] CompoundKeywords =
{
    ("GROUP BY ...", "GROUP BY "),
    ("ORDER BY ...", "ORDER BY "),
    ("LEFT JOIN ... ON ...", "LEFT JOIN "),
    ("RIGHT JOIN ... ON ...", "RIGHT JOIN "),
    ("INNER JOIN ... ON ...", "INNER JOIN "),
    ("INSERT INTO ...", "INSERT INTO "),
    ("WITH(NOLOCK)", "WITH(NOLOCK)"),
    ("OFFSET ... ROWS FETCH NEXT ... ROWS ONLY", "OFFSET "),
};
```

### 问题5：INSERT INTO [dbo].[Acer_AutoBom] 字段未自动展开

**示例**：`INSERT INTO [dbo].[Acer_AutoBom]` 表字段未自动展开

**根因分析**：

代码路径分析：
1. `SyntaxLocator.ResolveNode("INSERT INTO", ...)` → `InsertTableAfterInsertInto` ✓（正确识别）
2. `GetInsertExpandCandidates` → `GetInsertTargetTable` → 正则匹配 `@"^\s*INSERT\s+INTO\s+((?:\[?\w+\]?\s*\.\s*)*)\[?(\w+)\]?"`

**问题**：正则 `[?(\w+)]?` 中的 `\w+` 不含横线 `-`，但 `[Acer_AutoBom]` 中的下划线 `_` 属于 `\w`，所以应该可以匹配。

**可能的原因**：
- 用户输入的是 `INSERT INTO [dbo].[Acer_AutoBom]` 后没有触发补全弹窗（弹窗可能被按键 `]` 关闭后未重新弹出）
- `GetInsertExpandCandidates` 返回的单候选在 UI 层显示问题

**修复方向**：
1. 确认 `InsertTargetPattern` 在 `Acer_AutoBom` 下能正确匹配
2. 检查 `GetInsertExpandCandidates` 的幂等检测正则是否误匹配
3. 考虑在 `InsertTableAfterInsertInto` 位置自动触发弹窗（增加防抖检测）

### 问题6：关键词查询快捷键 Ctrl+Alt+F 无效

**VSCT 定义**：
```xml
<KeyBinding guid="guidSSMSBoostPlusCmdSet" id="cmdidKeywordSearch"
            editor="guidVSStd97" key1="F" mod1="Control Alt"/>
```

**根因**：`Ctrl+Alt+F` 在 SSMS 中可能被其他命令占用（例如默认的"对象资源管理器详细信息"窗口快捷键）。VSCT 定义的 KeyBinding 在冲突时可能不生效。

**修复方案**：更换为 SSMS 中无冲突的快捷键组合，如 `Ctrl+Shift+K`。

```xml
<KeyBinding guid="guidSSMSBoostPlusCmdSet" id="cmdidKeywordSearch"
            editor="guidVSStd97" key1="K" mod1="Control Shift"/>
```
