## 一、V5/V6 失败总结

### V5 (StackPanel)
- **问题**：固定高度格子（18px/24px）与 FlowDocument 实际渲染高度不匹配
- **症状**：顶部对齐、底部对齐、中间错位

### V6 (FlowDocument RichTextBox)
- **问题**：
  1. InlineUIContainer 在只读 RichTextBox 中渲染不可靠
  2. 操作条宽度被压缩（Grid.Column="2" Width="24" 未正确传递）
  3. 两个独立 RichTextBox 的布局时机不同，即使配置相同也无法保证高度一致
- **症状**：按钮不显示、或显示但仍有累积偏移

### 共同根因
所有方案都在尝试**让按钮与段落对齐**，但按钮和段落属于不同的布局容器：
- V5：按钮在 StackPanel，段落在 FlowDocument
- V6：按钮在 FlowDocument A，段落在 FlowDocument B

**只要按钮和段落不在同一个布局容器中，就无法完美对齐。**

## 二、V7 方案：AdornerLayer

### 核心思路

**不再使用中间列，直接在右侧面板的差异段落上附加 Adorner 按钮。**

```
传统方案（V5/V6）:
┌──────────────┬──────────┬──────────────┐
│ 左侧面板      │ 操作条   │ 右侧面板      │
│ FlowDocument │ (按钮)   │ FlowDocument │
└──────────────┴──────────┴──────────────┘
      ↑ 需要跨容器对齐

V7 Adorner 方案:
┌──────────────┬──────────────────────────┐
│ 左侧面板      │ 右侧面板                  │
│ FlowDocument │ FlowDocument + Adorner   │
│              │ (按钮直接附加到段落)      │
└──────────────┴──────────────────────────┘
      ↑ 按钮属于右侧面板，天然对齐
```

### 为什么 Adorner 能彻底解决

| 特性 | 说明 |
|------|------|
| **直接附加** | Adorner 直接附加到目标 UIElement（段落），成为其视觉树的一部分 |
| **自动定位** | WPF 自动计算 Adorner 位置，无需手动 Y 坐标 |
| **跟随滚动** | 段落滚动时，Adorner 自动跟随（同一生存周期） |
| **无高度计算** | 不需要假设高度、不需要同步滚动、不需要计算偏移 |

### AdornerLayer 工作原理

```
Visual Tree:
RichTextBox
└── FlowDocumentScrollViewer
    └── FlowDocument
        └── Paragraph (目标元素)
            └── AdornerLayer (自动创建)
                └── DiffButtonAdorner (自定义 Adorner)
                    └── Button (▶)
```

当段落位置变化（滚动、缩放、字体变化）时，AdornerLayer 自动重新定位 Adorner。

## 三、详细修改方案

### 3.1 XAML 修改

**删除操作条列**（Column 2），将空间分配给右侧面板：

```xml
<!-- 修改前 -->
<Grid.ColumnDefinitions>
    <ColumnDefinition Width="*" MinWidth="200"/>      <!-- 0: Left -->
    <ColumnDefinition Width="6"/>                      <!-- 1: Splitter -->
    <ColumnDefinition Width="24"/>                     <!-- 2: Action Strip (删除) -->
    <ColumnDefinition Width="*" MinWidth="200"/>      <!-- 3: Right -->
    <ColumnDefinition Width="22"/>                     <!-- 4: Minimap -->
</Grid.ColumnDefinitions>

<!-- 修改后 -->
<Grid.ColumnDefinitions>
    <ColumnDefinition Width="*" MinWidth="200"/>      <!-- 0: Left -->
    <ColumnDefinition Width="6"/>                      <!-- 1: Splitter -->
    <ColumnDefinition Width="*" MinWidth="200"/>      <!-- 2: Right (加宽) -->
    <ColumnDefinition Width="22"/>                     <!-- 3: Minimap -->
</Grid.ColumnDefinitions>
```

**删除整个操作条 Grid**：

```xml
<!-- 删除以下整个区域 -->
<Grid Grid.Column="2">
    <Grid.RowDefinitions>
        <RowDefinition Height="Auto"/>
        <RowDefinition Height="*"/>
    </Grid.RowDefinitions>
    <Border Grid.Row="0" ...>操 作</Border>
    <Border Grid.Row="1" ...>
        <RichTextBox x:Name="ActionStripViewer" ... />
    </Border>
</Grid>
```

### 3.2 新增 Adorner 类

创建 `DiffButtonAdorner.cs`：

```csharp
/// <summary>
/// 差异行按钮装饰器：直接附加到 FlowDocument 段落，显示同步/撤销按钮。
/// 使用 AdornerLayer 自动定位，无需手动计算 Y 坐标。
/// </summary>
public class DiffButtonAdorner : Adorner
{
    private readonly Button _button;
    private readonly Paragraph _targetParagraph;

    public DiffButtonAdorner(Paragraph adornedElement, Button button) 
        : base(adornedElement)
    {
        _targetParagraph = adornedElement;
        _button = button;
        
        // 设置按钮样式
        _button.Width = 20;
        _button.Height = 18;
        _button.HorizontalAlignment = HorizontalAlignment.Left;
        _button.VerticalAlignment = VerticalAlignment.Top;
        
        AddVisualChild(_button);
        AddLogicalChild(_button);
    }

    protected override int VisualChildrenCount => 1;

    protected override Visual GetVisualChild(int index)
    {
        if (index != 0) throw new ArgumentOutOfRangeException();
        return _button;
    }

    /// <summary>
    /// 测量按钮大小
    /// </summary>
    protected override Size MeasureOverride(Size constraint)
    {
        _button.Measure(constraint);
        return _button.DesiredSize;
    }

    /// <summary>
    /// 定位按钮：放在段落左侧（行号区域）
    /// </summary>
    protected override Size ArrangeOverride(Size finalSize)
    {
        // 获取段落相对于 RichTextBox 的位置
        var rect = _targetParagraph.ContentStart.GetCharacterRect(LogicalDirection.Forward);
        
        // 按钮放在段落左侧（留出 2px 边距）
        double left = 2;
        double top = rect.Top;
        
        _button.Arrange(new Rect(left, top, _button.DesiredSize.Width, _button.DesiredSize.Height));
        return finalSize;
    }

    /// <summary>
    /// 获取目标段落
    /// </summary>
    public Paragraph TargetParagraph => _targetParagraph;

    /// <summary>
    /// 获取按钮
    /// </summary>
    public Button Button => _button;
}
```

### 3.3 重写 PopulateActionStrip

不再填充操作条，而是为每个差异段落附加 Adorner：

```csharp
/// <summary>
/// 为右侧面板的每个差异段落附加 Adorner 按钮。
/// 使用 AdornerLayer 自动定位，无需手动高度计算。
/// </summary>
private void PopulateDiffButtons()
{
    // 清除现有 Adorner
    ClearDiffButtonAdorners();

    // 获取右侧面板的 AdornerLayer
    var adornerLayer = AdornerLayer.GetAdornerLayer(RightViewer);
    if (adornerLayer == null) return;

    // 为每个 diff hunk 创建按钮并附加到对应段落
    for (int h = 0; h < _diffHunks.Count; h++)
    {
        var hunk = _diffHunks[h];
        int blockIndex = hunk.BlockStartIndex;
        
        var paragraph = GetParagraphAtIndex(RightViewer.Document, blockIndex);
        if (paragraph == null) continue;

        var button = CreateSyncButton(h, hunk.HunkChangeType);
        _actionButtons[blockIndex] = button;

        // 创建 Adorner 并附加到段落
        var adorner = new DiffButtonAdorner(paragraph, button);
        adornerLayer.Add(adorner);
        _diffButtonAdorners.Add(adorner);
    }

    // 为已同步的 hunk 创建恢复按钮
    foreach (var kvp in _hunkInsertedBlocks)
    {
        int syncId = kvp.Key;
        var syncState = kvp.Value;
        
        int blockIndex = syncState.Inserted.Count > 0
            ? syncState.Inserted.First()
            : syncState.OrigStart;

        if (_actionButtons.ContainsKey(blockIndex)) continue;

        var paragraph = GetParagraphAtIndex(RightViewer.Document, blockIndex);
        if (paragraph == null) continue;

        var button = CreateUndoButton(syncId);
        _actionButtons[blockIndex] = button;

        var adorner = new DiffButtonAdorner(paragraph, button);
        adornerLayer.Add(adorner);
        _diffButtonAdorners.Add(adorner);
    }
}

// 存储所有 Adorner 以便清除
private readonly List<DiffButtonAdorner> _diffButtonAdorners = new();

/// <summary>
/// 清除所有差异按钮 Adorner
/// </summary>
private void ClearDiffButtonAdorners()
{
    var adornerLayer = AdornerLayer.GetAdornerLayer(RightViewer);
    if (adornerLayer != null)
    {
        foreach (var adorner in _diffButtonAdorners)
        {
            adornerLayer.Remove(adorner);
        }
    }
    _diffButtonAdorners.Clear();
    _actionButtons.Clear();
}
```

### 3.4 SyncHunk / UndoHunk 修改

同步/撤销后需要重新附加 Adorner（因为段落内容变化）：

```csharp
private void SyncBlock_Click(object sender, RoutedEventArgs e)
{
    if (sender is not Button button || button.Tag is not int hunkIndex) return;

    try
    {
        SyncHunk(hunkIndex);

        _isProgrammaticChange = true;
        try
        {
            RenumberRightParagraphs();
            RebuildDiffHunksFromState();
            // 重新附加 Adorner（段落内容已变化）
            PopulateDiffButtons();
        }
        finally
        {
            _isProgrammaticChange = false;
        }
    }
    catch (Exception ex)
    {
        System.Diagnostics.Debug.WriteLine($"SyncBlock_Click failed: {ex}");
        MessageBox.Show($"同步操作失败: {ex.Message}", "错误",
            MessageBoxButton.OK, MessageBoxImage.Warning);
    }
}
```

## 四、视觉布局调整

由于按钮直接放在右侧面板内，需要调整行号区域宽度，为按钮留出空间：

```csharp
// 在 BuildParagraph 中，为差异行增加行号区域宽度
private Paragraph BuildParagraph(DiffPiece line, bool isLeft, int numWidth, int blockIndex)
{
    var para = new Paragraph
    {
        Margin = new Thickness(0),
        LineHeight = 18,
        LineStackingStrategy = LineStackingStrategy.BlockLineHeight,
        Background = Brushes.White
    };

    // 差异行：增加行号区域宽度，为按钮留出空间
    int effectiveNumWidth = line.Type != ChangeType.Unchanged 
        ? numWidth + 4  // 增加 4 个字符宽度给按钮
        : numWidth;

    // ... 其余代码不变
}
```

或者更简单的方案：**按钮放在行号区域内**，不占用额外空间：

```
修改前行号区域：
"  9 | SET NOCOUNT ON;"

修改后行号区域（差异行）：
"▶ 9 | SET NOCOUNT ON;"
 ^ 按钮放在行号前面，不占用代码区域
```

## 六、优势总结

| 维度 | V5/V6 | V7 (Adorner) |
|------|-------|--------------|
| 对齐机制 | 跨容器手动对齐 | **同容器自动对齐** |
| 高度计算 | 需要假设/计算 | **不需要** |
| 滚动同步 | 需要手动同步 | **自动跟随段落** |
| 布局时机 | 需要等待布局完成 | **WPF 自动处理** |
| 代码复杂度 | 高（~200 行） | 低（~100 行） |
| 可靠性 | 低（多次修复仍有问题） | **高（WPF 原生机制）** |

## 七、风险与注意事项

### 7.1 AdornerLayer 获取时机

`AdornerLayer.GetAdornerLayer` 需要在视觉树构建完成后调用，通常在 `Loaded` 事件后。

### 7.2 段落生命周期

如果段落被移除（UndoHunk），对应的 Adorner 会自动从 AdornerLayer 移除，但需要手动清理 `_diffButtonAdorners` 列表。

### 7.3 性能

Adorner 数量等于差异行数，通常不超过 100 个，性能无问题。

### 7.4 视觉干扰

按钮放在行号区域可能略微遮挡行号数字，需要调整样式确保可读性。
