# 差异块按钮逻辑修复方案

## 问题 1：多冲突时点击一个，其他同步按钮错位

### 现象

- 多个差异块（hunk）时，未点击前所有同步按钮都与差异行对齐 ✅
- 点击其中一个 hunk 的同步按钮后，**其他 hunk 的同步按钮位置发生偏移** ❌

### 根因分析

当前 `PopulateActionStrip` 遍历 `_diffHunks` 创建按钮，使用 `hunk.BlockStartIndex` 作为 `blockIndex` 放入 `_actionButtons` 字典。然后在 `PositionActionButtons` 中通过 `GetCharacterRect` 获取实际 Y 坐标。

**问题**：当一个 hunk 同步后：
1. `SyncHunk` 插入/删除了段落 → 文档结构改变
2. `RebuildDiffHunksFromState` 重建 `_diffHunks` → 其他 hunk 的 `BlockStartIndex` 可能变化
3. `PopulateActionStrip` 使用新的 `BlockStartIndex` 创建按钮
4. 但此时 `PositionActionButtons` 的 `GetCharacterRect` 可能获取到错误的位置

**根本问题**：我们依赖 `blockIndex`（段落索引）来定位按钮，但段落索引在文档修改后会偏移。

### 修复方案

**方案 A（推荐）：使用原始模型行索引定位**

不依赖渲染后的 `blockIndex`，而是使用 `SideBySideDiffModel` 中的原始行索引（`origIdx`）来标识每个 hunk。按钮位置通过查找对应原始行的实际段落位置来确定。

但实现复杂，需要维护原始索引到渲染段落的映射。

**方案 B（当前优化）：同步后强制重新计算所有按钮位置**

在 `PopulateActionStrip` 之后，确保 `PositionActionButtons` 使用最新的文档状态。同时，为每个按钮记录其 hunk 的原始起始位置，在重建时优先使用。

实际上，当前代码已经在 `SyncBlock_Click` 中记录了 `_syncButtonClickedPos` 和 `_syncButtonClickedTop`。问题在于多 hunk 时，其他 hunk 没有记录点击位置。

**方案 C（简化）：每个按钮独立定位**

不再使用 `hunkFirstLines` 字典映射，而是直接在创建按钮时通过 `GetCharacterRect` 定位：

```csharp
// 在 PopulateActionStrip 中
foreach (var hunk in _diffHunks)
{
    var para = GetParagraphAtIndex(RightViewer.Document, hunk.BlockStartIndex);
    if (para != null)
    {
        var rect = para.ContentStart.GetCharacterRect(LogicalDirection.Forward);
        var button = CreateSyncButton(hunkIndex, hunk.HunkChangeType);
        Canvas.SetTop(button, rect.Top);
        Canvas.SetLeft(button, 2);
        ActionStripCanvas.Children.Add(button);
        _actionButtons[hunk.BlockStartIndex] = button;
    }
}
```

这样可以确保每个按钮都基于当前文档状态定位。

## 问题 2：按钮类型逻辑反了

### 当前逻辑（错误）

```
左侧（DB）：PRINT 'a'      右侧（本地）：空
ChangeType：Unchanged     ChangeType：Imaginary
ClassifyDiffLine → Inserted（显示 +）

左侧（DB）：空            右侧（本地）：PRINT 'b'
ChangeType：Imaginary     ChangeType：Inserted
ClassifyDiffLine → Inserted（显示 +）❌ 应该显示 -
```

### 正确逻辑

从**数据库同步到我的脚本**的视角：

| 场景 | 数据库 | 我的脚本 | 同步后效果 | 按钮 |
|------|--------|----------|-----------|------|
| DB有，我没有 | PRINT 'a' | （空） | 我的脚本**新增** 'a' | **+**（新增）|
| DB没有，我有 | （空） | PRINT 'b' | 我的脚本**删除** 'b' | **-**（删除）|
| 双方都有但不同 | PRINT 'x' | PRINT 'y' | 我的脚本**替换**为 'x' | **▶**（替换）|

### 修复方案

修改 `ClassifyDiffLine` 方法，从"同步操作对我的脚本的影响"角度判断：

```csharp
/// <summary>
/// 从数据库同步到我的脚本的视角，判断此行对我的脚本来说是新增/删除/替换。
/// </summary>
private static ChangeType ClassifyDiffLineFromSyncPerspective(ChangeType leftType, ChangeType rightType)
{
    bool leftHasContent = leftType != ChangeType.Imaginary && leftType != ChangeType.Unchanged;
    bool rightHasContent = rightType != ChangeType.Imaginary && rightType != ChangeType.Unchanged;
    
    // DB有，我没有 → 同步后我会新增这行
    if (leftHasContent && !rightHasContent)
        return ChangeType.Inserted; // 显示 +
    
    // DB没有，我有 → 同步后我会删除这行
    if (!leftHasContent && rightHasContent)
        return ChangeType.Deleted; // 显示 -
    
    // 双方都有 → 替换
    return ChangeType.Modified; // 显示 ▶
}
```

| 1 | `AIDiffDialog.xaml.cs` | `ClassifyDiffLine` 方法 | 改为 `ClassifyDiffLineFromSyncPerspective`，反转逻辑 |

## 按钮图标对应表（最终）

| 图标 | 含义 | 场景 |
|------|------|------|
| **+** | 新增 | 数据库有，我的脚本没有 → 同步后会添加到我脚本 |
| **-** | 删除 | 数据库没有，我的脚本有 → 同步后会从我脚本删除 |
| **▶** | 替换 | 双方都有但内容不同 → 同步后替换为我脚本的内容 |

## 测试验证

1. **新增场景**：DB 有代码，本地没有 → 应显示 **+**
2. **删除场景**：DB 没有，本地有代码 → 应显示 **-**
3. **冲突场景**：双方都有但不同 → 应显示 **▶**
4. **多 hunk 错位**：两个以上差异块，同步其中一个，验证其他按钮位置不变
