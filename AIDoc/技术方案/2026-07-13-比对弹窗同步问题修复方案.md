## 问题 5：Cancel 后版本守卫不再触发

### 场景描述

1. 用户编辑脚本后执行（F5）
2. 弹出过时弹窗（VersionWarningDialog）
3. 用户点击"取消"
4. 再次执行脚本 → **不再弹出过时弹窗**，直接执行成功
5. 用户期望：每次执行都应检查版本，Cancel 只是取消本次执行，不应跳过后续检查

### 根因

文件：`src/SSMS/Services/ExecutionInterceptor.cs` 第 430-434 行

```csharp
case VersionWarningResult.Cancel:
    _logger.Information("[ExecInterceptor] User cancelled execution.");
    // 更新脚本打开时间，防止用户修改代码后再次执行时重复弹窗
    // （用户已看过版本警告并选择取消，下次执行不应再次触发同一过时对象的警告）
    SsmsEditorService.UpdateScriptOpenTime(docPath);
    break;
```

Cancel 时调用了 `SsmsEditorService.UpdateScriptOpenTime(docPath)`，将脚本的**打开时间**更新为 `DateTime.Now`。版本守卫的逻辑是：`脚本打开时间 < 数据库对象的 modify_date` 时弹窗。

因为打开时间被更新为"现在"，而 DB modify_date 是更早的时间，所以条件不成立，守卫不再触发。

**设计意图**：用户取消后修改代码再执行，不应重复弹窗。
**用户预期**：取消只是取消本次执行，下次执行仍应检查。

### 修复方案

移除 Cancel 分支中的 `UpdateScriptOpenTime` 调用。脚本打开时间仅在用户实际执行（ContinueExecution / ReloadFromDb）后更新。

```csharp
case VersionWarningResult.Cancel:
    _logger.Information("[ExecInterceptor] User cancelled execution.");
    // ❌ 移除 UpdateScriptOpenTime，保留原始打开时间
    // 下次执行时版本守卫仍会触发（脚本仍过时）
    break;
```

### 修改点

| 文件 | 行号 | 修改前 | 修改后 |
|------|------|--------|--------|
| `ExecutionInterceptor.cs` | 430-434 | `case Cancel: ... UpdateScriptOpenTime ... break;` | `case Cancel: logger.Info("cancel"); break;` |

## 问题 6：同步后恢复按钮与差异行不对齐

### 场景描述

1. 打开比对弹窗
2. 差异行上的同步按钮（▶）与行对齐 ✅
3. 点击同步按钮
4. 同步按钮变为恢复按钮（↺）
5. 恢复按钮**没有**与差异行对齐 ❌（偏上或偏下）

### 根因

恢复按钮的定位由 `PositionActionButtons()` 方法执行（`AIDiffDialog.xaml.cs` 第 1262-1298 行）。该方法：

1. 使用 `Dispatcher.BeginInvoke(DispatcherPriority.Loaded)` 异步执行
2. 通过 `GetCharacterRect(LogicalDirection.Forward)` 获取段落 Y 坐标
3. 使用 `Canvas.SetTop(button, rect.Top)` 设置按钮位置

**根因分析**：

**根因 6.1**：同步操作后，`PopulateActionStrip()` 清空并重建 `ActionStripCanvas.Children` 和 `_actionButtons`，然后调用 `PositionActionButtons()`。但 `PositionActionButtons()` 通过 `Dispatcher.BeginInvoke` 异步执行，其回调执行时可能使用**旧的 `_actionButtons` 引用**（如果多次调度之间存在竞态）。

但更可能的原因是：

**根因 6.2**：同步操作后调用 `RightViewer.UpdateLayout()` 强制布局，但 `GetCharacterRect` 在布局未完全稳定时返回的 Y 坐标可能**不准确**。特别是同步删除了段落（delete-sync）时，段落内容改变（添加了 Strikethrough + Gray Foreground），这可能导致 WPF 的布局引擎重新计算行高。

**最可能的根因 6.3**：`PopulateActionStrip()` 执行结束后立即调用 `PositionActionButtons()`，而 `PositionActionButtons` 使用 `Dispatcher.BeginInvoke` 调度。在调度回调执行之前，**`RightViewer` 的滚动位置可能已发生变化**（因为文档内容改变后 WPF 自动调整滚动）。而 `ActionStripScroller.ScrollToVerticalOffset(rightSv.VerticalOffset)` 获取的是调度时刻的滚动位置，不是回调执行时的滚动位置。

### 修复方案

**修改 `PositionActionButtons()`**：在回调执行时**重新获取**滚动位置，而非使用调度时捕获的旧值：

```csharp
// 在 Dispatcher 回调内部重新获取滚动位置
var rightSv = FindScrollViewer(RightViewer);
if (rightSv != null)
{
    ActionStripCanvas.Height = Math.Max(rightSv.ExtentHeight, rightSv.ViewportHeight);
    ActionStripScroller.ScrollToVerticalOffset(rightSv.VerticalOffset);
}
```

已实现（第 1278-1284 行）。但需要确保：

1. **调度优先级提升**：从 `DispatcherPriority.Loaded` 改为 `DispatcherPriority.Render`，确保在渲染前完成按钮定位，避免按钮先显示在错误位置再跳转
2. **强制完整布局**：在获取段落位置前额外调用一次 `UpdateLayout()` 确保所有新增段落已完成布局

```csharp
// 修改后（第 1262-1298 行）
private void PositionActionButtons()
{
    if (!_isLoaded || _isPositioningButtons) return;

    _isPositioningButtons = true;
    // 使用 Render 优先级，确保在渲染前完成定位
    Dispatcher.BeginInvoke(new Action(() =>
    {
        try
        {
            if (!_isLoaded) return;

            // 强制完成布局
            RightViewer.UpdateLayout();
            LeftViewer.UpdateLayout();

            // 重新获取滚动位置（在回调内部，确保最新）
            var rightSv = FindScrollViewer(RightViewer);
            if (rightSv != null)
            {
                ActionStripCanvas.Height = Math.Max(rightSv.ExtentHeight, rightSv.ViewportHeight);
                ActionStripScroller.ScrollToVerticalOffset(rightSv.VerticalOffset);
            }

            var blockSnapshot = RightViewer.Document.Blocks.OfType<Paragraph>().ToList();

            for (int i = 0; i < blockSnapshot.Count; i++)
            {
                if (_actionButtons.TryGetValue(i, out var button))
                {
                    var rect = blockSnapshot[i].ContentStart.GetCharacterRect(LogicalDirection.Forward);
                    Canvas.SetTop(button, rect.Top);
                }
            }
        }
        catch (Exception ex)
        {
            System.Diagnostics.Debug.WriteLine($"PositionActionButtons failed: {ex}");
        }
        finally
        {
            _isPositioningButtons = false;
        }
    }), System.Windows.Threading.DispatcherPriority.Render);
    // 从 Loaded 改为 Render：确保在渲染前完成按钮定位
}
```

**修改点**：

| 文件 | 行号 | 修改前 | 修改后 |
|------|------|--------|--------|
| `AIDiffDialog.xaml.cs` | 1267 | `DispatcherPriority.Loaded` | `DispatcherPriority.Render` |
| `AIDiffDialog.xaml.cs` | 1275 | `RightViewer.UpdateLayout()` | `RightViewer.UpdateLayout(); LeftViewer.UpdateLayout()` |
