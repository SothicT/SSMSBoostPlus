# Issue Tracker Skill 设计方案

## 概述

系统化的测试问题追踪与修复工作流，以 CodeBuddy Skill（issue-tracker）形式固化。核心思路：人工低摩擦记录 -> Skill 自动拆分/追踪/流转 -> 与 error-diagnosis Skill 协作诊断修复 -> 人工确认后自动归档。

## 文件布局

```
docs/待处理问题箱.md                    <- 收件箱，人工记录，拆分后清空
AIDoc/问题修复/
  ├── YYYY-MM-DD-简短描述.md            <- 独立问题文件
  └── 归档/
      ├── INDEX.md                       <- 归档索引（按时间倒序）
      └── YYYY-MM-DD-简短描述.md         <- 已关闭问题
.codebuddy/skills/issue-tracker/
  ├── SKILL.md
  └── references/
      ├── issue-template.md
      └── inbox-format.md
```

## 状态流转

```
待处理 ->[修复 xxx]-> 修复中 ->[编译通过]-> 待确认 ->[确认]-> 已关闭+归档
```

| 状态 | 含义 | 进入条件 | 离开条件 |
|------|------|----------|----------|
| 待处理 | 已拆分，等待修复 | 收件箱扫描拆分 | 用户触发「修复 xxx」 |
| 修复中 | AI 正在诊断/修复 | 用户触发修复 | 代码编译通过 |
| 待确认 | 修复完成，等人工验证 | 编译通过 | 用户回复「确认」 |
| 已关闭 | 确认完成，归档 | 用户确认 | 移入归档/ |

## 数据格式

### 收件箱：docs/待处理问题箱.md

```markdown
# 待处理问题箱

## 待处理

- [ ] [高] 历史版本检索失败 — 对象标识符带架构限定符导致匹配失败
- [ ] [中] 版本序号时间线错位 — RowNumber 推导依赖未排序结果集
```

格式：`- [ ] [优先级] 简短描述 — 补充说明`。优先级可选：`[阻断] [高] [中](默认) [低]`。

### 独立问题文件：AIDoc/问题修复/YYYY-MM-DD-描述.md

YAML frontmatter（status / priority / resolution / created / updated / closed / tags / affected）+ 结构化正文（现象 / 根因 / 影响范围 / 涉及模块 / 诊断记录 / 修复方案 / 修复记录）。模板见 references/issue-template.md。

### 归档索引：AIDoc/问题修复/归档/INDEX.md

表格：日期 | 问题 | 优先级 | 关闭原因。

## 六大工作流

1. 扫描拆分：读取收件箱 -> 解析条目 -> 去重 -> 生成独立文件 -> 清空收件箱。
2. 问题概览：扫描 AIDoc/问题修复/，按状态+优先级汇总，含归档统计。
3. 开始修复：加载文件 -> 调用 error-diagnosis -> 引导修复 -> 编译验证 -> 状态自动流转至待确认。
4. 确认归档：状态->已关闭，resolution=已修复，移入归档/，更新 INDEX.md。
5. 手动状态（兜底）：跳过修复流程直接关闭归档。
6. 清理归档：批量归档已关闭未归档问题。

## 与 error-diagnosis 协作

修复流程中自动调用，输入取自问题文件「现象」+「涉及模块」，输出写入「诊断记录」区域。

## 设计决策记录

- 方案一（自然语言触发 + Skill 间协作）确定为核心交互方式。
- 收件箱命名为「待处理问题箱.md」，避免与独立问题文件混淆。
- 状态命名采用方案 A：待处理 / 修复中 / 待确认 / 已关闭。
- 纳入三项优化：优先级字段、关闭原因字段、归档索引。
- 用户只需三个主动动作：记录问题、扫描拆分、修复；确认即自动归档。
