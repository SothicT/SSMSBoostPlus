# 跨库提示弹窗类型标签与交互修复方案

## 问题概述

| 序号 | 问题 | 表现 |
|------|------|------|
| 1 | KEYSTOCK 数据库对象缺失类型标签 | 弹窗显示 `[KeyStock].dbo.P_Issue_KDBOM` 等对象名称，但右侧缺少"SP"/"函数"/"表"等类型标签 |
| 2 | ESC/TAB/鼠标点击无效 | 按 ESC 无法关闭弹窗，按 TAB/ENTER/鼠标点击无法选中补全项 |

## 问题一：类型标签缺失

### 现象分析

日志确认 `GetAllObjectsOfTypesForDb('KeyStock', P,FN,IF,TF)` 正确返回 592 项，说明数据查询和过滤正常。但用户观察到弹窗中对象名称右侧无类型标签。

### 根因定位

代码中 `FilterAndFormatObjects()` 和 `SearchInCache()` 均正确调用 `GetTypeTagName(o.TypeCode)` 设置 `TypeTag` 属性，数据映射逻辑无误。

**根因：ListBox 关闭虚拟化 + 大量非虚拟化项导致 WPF 测量/排列异常。**

相关代码（`CreatePopup()`）：

```csharp
// 禁用虚拟化：防止快速滚动时标签错位/消失
VirtualizingStackPanel.SetIsVirtualizing(_listBox, false);
VirtualizingStackPanel.SetVirtualizationMode(_listBox, VirtualizationMode.Standard);
```

当 `_listBox` 包含 **592 项**（KEYSTOCK）且全部非虚拟化时，WPF 的 `DockPanel` 布局引擎在高负载下可能出现测量异常，导致 `LastChildFill` 的子元素错误地占用全部空间，使得 `DockPanel.SetDock(tagText, Dock.Right)` 的标签被挤出可视区域。

**MESDATA（9 项）正常**而 **KEYSTOCK（592 项）异常**的现象与此吻合：项数少时 WPF 布局正常，项数多时布局引擎压力大导致标签偏移。

### 解决方案

#### 方案 A：改用 Grid 固定列宽布局（推荐）

将 `CreateCompletionItem()` 中的 `DockPanel` 替换为 `Grid`，为类型标签预留固定列宽：

```csharp
private ListBoxItem CreateCompletionItem(CompletionCandidate candidate)
{
    var grid = new Grid();
    grid.ColumnDefinitions.Add(new ColumnDefinition { Width = new GridLength(1, GridUnitType.Star) });  // 内容区，填充
    grid.ColumnDefinitions.Add(new ColumnDefinition { Width = GridLength.Auto });                      // 标签区，自适应

    // 主内容（左列，Star）
    var contentPanel = new StackPanel { Orientation = Orientation.Horizontal, VerticalAlignment = VerticalAlignment.Center };
    // ... 构建主文本和预览文本 ...
    Grid.SetColumn(contentPanel, 0);
    grid.Children.Add(contentPanel);

    // 类型标签（右列，Auto）
    var tagText = new TextBlock
    {
        Text = candidate.TypeTag,
        FontSize = 10,
        // ... 其他样式属性 ...
        VerticalAlignment = VerticalAlignment.Center,
        Margin = new Thickness(8, 0, 0, 0),
    };
    Grid.SetColumn(tagText, 1);
    grid.Children.Add(tagText);

    return new ListBoxItem { Content = grid, Tag = candidate, ... };
}
```

**优点**：
- Grid 列宽明确，不受子元素测量顺序影响
- Star + Auto 布局在任何项数下行为一致
- 类型标签永远固定在右侧

#### 方案 B：恢复虚拟化

如果项数多（>200），应考虑恢复虚拟化。之前禁用虚拟化是因为 Grid 的 `Auto/*/Auto` 列布局在虚拟化下导致标签错位。采用方案 A（Grid + 固定列宽）后虚拟化应能正常工作：

```csharp
// 恢复虚拟化（配合 Grid 固定列宽，虚拟化不影响标签位置）
VirtualizingStackPanel.SetIsVirtualizing(_listBox, true);
VirtualizingStackPanel.SetVirtualizationMode(_listBox, VirtualizationMode.Standard);
```

**建议**：方案 A + 方案 B 组合使用。

## 问题二：ESC/TAB/鼠标点击无效

### 现象分析

从日志可以确认：
- 鼠标点击事件被正确接收（日志输出"鼠标单击选中: 展开"）
- `ExpandSelectedTemplate()` 被正确调用
- `MoveSelection()` 正常工作（日志显示方向键导航）

但用户操作后没有效果。

### 根因定位：真正的罪魁祸首

**核心根因：`ExpandSelectedTemplate()` 第 1609~1610 行的 `GetWordBeforeCaret` 返回空字符串，导致方法在第 1610 行静默返回，但 `_lastExpandTime` 计时器已经被污染。**

```csharp
// ExpandSelectedTemplate 第 1586~1615 行（简化版）
internal void ExpandSelectedTemplate()
{
    var now = DateTime.UtcNow;
    if ((now - _lastExpandTime).TotalMilliseconds < ExpandThrottleMs)
    {
        return;  // 节流跳过
    }
    _lastExpandTime = now;  // ← ★ 节流计时器已更新！

    // ↓↓↓ 下面的代码可能静默失败，但上面已经更新了计时器！
    
    var (word, wordStart, _) = GetWordBeforeCaret(_activeTextView);
    if (string.IsNullOrEmpty(word)) return;  // ← ★ 空单词→静默返回！
    // ...
    _logger.Information("✅ ExpandSelectedTemplate 开始执行...");  // 这句话永远打不出来
}
```

这个 bug 发生在**两个关键场景**中：

#### 场景 A：空格触发的弹窗中点击

```
用户输入: EXEC [KeyStock]. ␣（空格）
                      ↑光标在这里

OnSpaceTyped → 弹窗显示 592 个对象
用户点击对象 → ExpandSelectedTemplate()
  → 节流通过 ✅ → _lastExpandTime = 当前时间
  → GetWordBeforeCaret():
      光标前是空格 → IsWordChar(' ') = false
      → wordStart == caretColumn → 返回 ("", 0, 0)
  → if (string.IsNullOrEmpty(word)) return;
    **静默返回！无✅日志！**
  → _lastExpandTime 已被污染！
```

#### 场景 B：DB 名展开后的对象弹窗中点击（更常见）

```
用户输入: EXEC KeyS → 弹窗显示 DB 名称
用户点击 "KeyStock" → ExpandSelectedTemplate
  → word = "KeyS" → ✅ 成功！
  → DoExpand 替换 "KeyS" 为 "[KeyStock]."
  → 文本变成: EXEC [KeyStock].
                         ↑光标在 '.' 后面

ShowCategoryCandidatesForDb → 新弹窗显示 592 个对象

用户点击某个 SP → ExpandSelectedTemplate()
  → 节流通过 ✅ → _lastExpandTime = 当前时间
  → GetWordBeforeCaret():
      光标前是 '.' → IsWordChar('.') = false
      → 返回 ("", 0, 0)
  → if (string.IsNullOrEmpty(word)) return;
    **静默返回！**
  → _lastExpandTime 被污染！
```

**为什么日志中看到大量连续的"节流跳过"？**

因为每次静默返回都更新了 `_lastExpandTime`，后续的点击在 300ms 内进来时，真的被节流挡住了！

```
30.996 ✅ DB名展开成功（word="KeyS"）→ _lastExpandTime = 30.996
31.246 ❌ 节流跳过（SSMS重复事件，250ms内）
31.???  用户点击对象 → 节流通过（过了300ms）
         → GetWordBeforeCaret 返回 "" → 静默返回
         → _lastExpandTime 被更新到 ~31.7
32.015 ❌ 节流跳过（31.7 + 300ms ≈ 32.0，刚好卡住）
```

所以先有"静默失败污染计时器"，后有"节流误杀"——两者叠加造成用户感知的"点了没反应"。

#### 为什么 ESC 看起来也无效？

ESC（CMDID_CANCEL）在命令过滤器中的处理不经过 `ExpandSelectedTemplate`：

```csharp
case CMDID_CANCEL:
    _owner.HidePopup();
    return OLECMDERR_E_CANCELED;
```

这段代码本身没有问题。但 ESC 关闭弹窗后，`OnLayoutChanged` 可能立即触发 `OnCharTyped()`，而 `OnCharTyped()` 中空格触发状态（`_hasSpaceTrigger`）未被重置，导致弹窗**立即重新打开**，让用户感觉 ESC 没起作用。

### 解决方案

#### 修复 1：【核心】空单词时改为光标处插入（替代静默返回）

当 `GetWordBeforeCaret` 返回空单词时，`ExpandSelectedTemplate` 不应静默返回，而应在**光标位置直接插入**选中文本。这适用于空格触发和 DB 名展开后光标在句点后的场景。

修改 `ExpandSelectedTemplate()`：

```csharp
internal void ExpandSelectedTemplate()
{
    // ... 节流检查（不变）...

    try
    {
        if (_listBox == null || _listBox.SelectedItem == null) return;
        if (_activeTextView == null) return;

        var selectedItem = _listBox.SelectedItem as ListBoxItem;
        if (selectedItem == null) return;

        var candidate = selectedItem.Tag as CompletionCandidate;
        if (candidate == null) return;

        // ★ 修复：获取光标前单词，空单词时使用光标位置（插入而非替换）
        string? insertText;
        int startPosition;
        int length;

        var (word, wordStart, wordEnd) = GetWordBeforeCaret(_activeTextView);
        if (string.IsNullOrEmpty(word))
        {
            // ★ 空单词：在光标位置插入
            startPosition = _activeTextView.Caret.Position.BufferPosition.Position;
            length = 0;
        }
        else
        {
            startPosition = wordStart;
            length = word.Length;
        }

        // ★ 构建插入文本（根据候选项类型）
        string? selectedDbName = null;
        HidePopup();

        // ... 判断 ItemType 构建 insertText ...

        if (!string.IsNullOrEmpty(insertText))
        {
            DoExpand(_activeTextView, startPosition, length, insertText);
        }

        // ★ DB 名展开后：重置节流计时器，准备弹新弹窗
        if (selectedDbName != null)
        {
            _lastExpandTime = DateTime.MinValue;  // ← 重置计时器
            _hasSpaceTrigger = true;
            _lastSpaceCategory = _lastCompletionCategory;
            ShowCategoryCandidatesForDb(selectedDbName, _lastCompletionCategory);
        }
    }
    catch (Exception ex)
    {
        _logger.Error(ex, "[SqlTemplate] 选择展开失败");
    }
}
```

**关键改动**：
1. 不再要求 `word` 非空才能继续执行
2. 空单词时 `startPosition = 光标位置`，`length = 0`（插入）
3. 非空单词时 `startPosition = wordStart`，`length = word.Length`（替换）
4. DB 名展开后重置 `_lastExpandTime = DateTime.MinValue`

#### 修复 2：鼠标点击直接 `skipThrottle`

作为双重保险，鼠标点击这种用户明确的选择操作，完全没必要经过节流：

```csharp
// PreviewMouseLeftButtonUp 处理器
_listBox.PreviewMouseLeftButtonUp += (s, e) =>
{
    var lb = (ListBox)s;
    var point = e.GetPosition(lb);
    var hitResult = lb.InputHitTest(point) as DependencyObject;

    while (hitResult != null && !(hitResult is ListBoxItem))
        hitResult = VisualTreeHelper.GetParent(hitResult);

    if (hitResult is ListBoxItem item && item.Tag is CompletionCandidate)
    {
        lb.SelectedItem = item;
        _logger.Debug("[SqlTemplate] 鼠标单击选中: 展开");
        
        // ★ 鼠标点击：不经过节流检查
        _lastExpandTime = DateTime.MinValue;  // 或使用 skipThrottle 参数
        ExpandSelectedTemplate();
        e.Handled = true;
    }
};
```

#### 修复 3：ESC 关闭弹窗后重置 `_hasSpaceTrigger` + 防重开

在 `HidePopup()` 中记录关闭时间，并在 `OnCharTyped()` 中检测是否刚被用户关闭：

```csharp
// 新增字段
private DateTime _lastUserHideTime = DateTime.MinValue;

internal void HidePopup([CallerMemberName] string caller = "")
{
    ThreadHelper.ThrowIfNotOnUIThread();

    if (_popup != null && _isPopupVisible)
    {
        _popup.IsOpen = false;
        _isPopupVisible = false;
        _focusCheckTimer?.Stop();
    }
    
    // ★ 用户主动关闭（非内部 HidePopup）时记录时间 + 重置空格状态
    if (caller != "ExpandSelectedTemplate" && caller != "ShowOrUpdatePopup")
    {
        _lastUserHideTime = DateTime.UtcNow;
        _hasSpaceTrigger = false;
    }
}
```

在 `OnCharTyped()` 中增加检测：

```csharp
if (string.IsNullOrEmpty(word))
{
    if (_isPopupVisible && _hasSpaceTrigger)
        return;
    
    // ★ 用户刚关闭弹窗（200ms 内），不自动重新打开
    if (!_isPopupVisible && 
        (DateTime.UtcNow - _lastUserHideTime).TotalMilliseconds < 200)
        return;
    
    HidePopup();
    return;
}
```

## 问题三：跨库对象补全后插入文本包含重复的 [DBName] 前缀

### 现象

选择 DB 名后展开 `[MESDATA].`，再选择对象时，插入 `[MESDATA].[MESDATA].[dbo].[P_ReceiveMesTableInfo]`，DB 名重复出现。

### 根因

`SearchInCache()` 和 `FilterAndFormatObjects()` 中，跨库模式的 `InsertText` 包含了 `[DBName]` 前缀：

```csharp
// DatabaseObjectCacheService.cs
InsertText = dbName != null ? $"[{dbName}].[{x.o.Schema}].[{x.o.Name}]" : $"[{x.o.Schema}].[{x.o.Name}]"
```

但用户已经通过选择 DB 名在编辑器中插入了 `[DBName].`，导致完整限定名重复。

### 修复

跨库模式下，`InsertText` 不包含 `[DBName].` 前缀，只包含 `[schema].[name]` 部分：

```csharp
// 修复后
InsertText = dbName != null ? $"[{x.o.Schema}].[{x.o.Name}]" : $"[{x.o.Schema}].[{x.o.Name}]"
```

`DisplayText` 保留 DB 前缀（用于展示），`InsertText` 去掉 DB 前缀（用于插入）。

### 修改文件

`src/SSMS/Services/DatabaseObjectCacheService.cs` — 修改 `SearchInCache()` 和 `FilterAndFormatObjects()` 中的 `InsertText` 生成逻辑。
