# 在编辑器中打开历史版本脚本后，主编辑器键盘失效

> 类型: Bug | 优先级: 高 | 标签: 版本历史,脚本比对,在编辑器中打开,模态弹窗,焦点劫持,WPF

## 现象

打开历史版本的脚本内容比对页面（`LocalHistoryDiffDialog`）后，点击「在编辑器中打开」按钮：

- 新文档 `VersionScript.sql` 能在主编辑器中创建并显示在 tab 页
- 弹窗已不再置顶（被遮盖或最小化）
- **但主编辑器界面的键盘失效**：点击编辑器后输入字符无反应 / 光标不动，必须再次手动点击编辑器 tab 才能输入

### 日志证据

`D:\Microsoft SQL Server Management Studio 22\Release\Common7\IDE\Extensions\SSMSBoostPlus\Logs\ssmsboostplus-2026071609.log`：

```text
1620:09:42:32.791 [INF] [LocalHistory] 历史版本脚本已在编辑器中打开     ← 业务成功
1622:09:42:35.410 [DBG] [LocalHistory] WindowActivated: gotFocus.Kind=Tool, lostFocus.Kind=Document   ← 焦点回 ToolWindow
1623:09:42:35.410 [DBG] [LocalHistory] WindowActivated: 非文档窗口 (Kind=Tool)，跳过刷新
1624:09:42:37.297 [DBG] [右键菜单] SQL 文档激活: 'axcnzmii..sql'      ← 用户必须手动重新激活
```

关键证据：
- 第 1620 行：业务成功执行
- 第 1622-1623 行：焦点返回到 `Tool`（弹窗或 ToolWindow）而非 `Document`
- 第 1624 行：用户在 5 秒后被迫手动重新点击 SQL 文档

## 根因分析

### 1. 弹窗未关闭（焦点劫持主因）

`src/SSMS/UI/VersionHistory/LocalHistoryDiffDialog.xaml.cs` 第 308-331 行 `OpenInEditorButton_Click` 方法：

- 调用 `dte.ItemOperations.NewFile(...)` 创建新文档
- 通过 `EditPoint.Insert` 插入历史脚本
- **未调用 `Close()`** —— 弹窗持续占用焦点和消息循环

### 2. 模态 ShowDialog 残留

调用方 `src/SSMS/UI/VersionHistory/LocalHistoryToolWindowControl.xaml.cs` 第 733 行 `diffDialog.ShowDialog()` 模态消息循环未释放，键盘事件被弹窗持续拦截。

### 3. Owner 关系干扰 Z-order

弹窗 Owner = ToolWindow（`diffDialog.Owner = System.Windows.Window.GetWindow(this)`），与 ToolWindow 形成 Z-order 锁定链。

### 4. EditPoint.Insert 性能差

逐字符插入大脚本，O(n) 慢，且影响后续编辑行为（应使用 `ReplaceText`）。

## 修复方案

### 修改文件

| 文件 | 修改类型 | 说明 |
|------|----------|------|
| `src/SSMS/UI/VersionHistory/LocalHistoryDiffDialog.xaml.cs` | 局部重构 | `OpenInEditorButton_Click` 方法体（3 处修改） |

### 修改点

#### 1. 核心修复：finally 中关闭弹窗

```csharp
finally
{
    // 关键修复：无论成功失败都关闭弹窗，释放 ShowDialog 模态状态
    // 让 DTE.ActiveDocument 获得键盘焦点，主编辑器可立即输入
    DialogResult = success ? true : (bool?)null;
    Close();
}
```

#### 2. 性能优化：EditPoint.Insert → EditPoint.ReplaceText

```csharp
// 旧：editPoint.Insert(_historicalScript);  // 逐字符 O(n) 慢
// 新：一次替换 O(1) 快
var editPoint = textDoc.CreateEditPoint();
editPoint.StartOfDocument();
editPoint.ReplaceText(
    textDoc.EndPoint,
    _historicalScript,
    (int)EnvDTE.vsEPReplaceTextOptions.vsEPReplaceTextAutoformat);
```

#### 3. 容错处理

- DTE 为 null / 脚本为空：记录警告，弹窗保持打开（用户可继续看对比）
- NewFile / ReplaceText 抛异常：catch 日志，弹窗仍关闭（避免卡死）
- ActiveDocument 为 null：记录警告，弹窗仍关闭

### 不修改的部分

- **XAML 文件**：UI 不动
- **调用方 `LocalHistoryToolWindowControl.xaml.cs`**：不动
- **单元测试**：因方法依赖全局 DTE 服务（`Package.GetGlobalService`），无法直接单元测试。**作为后续技术债**：抽 `IEditorOpener` 接口后补测试

## 边缘情况与异常处理

| 场景 | 修复前行为 | 修复后行为 |
|------|------------|------------|
| 正常点击 | 新文档创建+插入+**弹窗残留** | 新文档创建+ReplaceText+**弹窗关闭** |
| `_historicalScript` 为空 | 跳过 DTE，弹窗残留 | 跳过 DTE + 记录警告 + 弹窗保持打开 |
| DTE 为 null | 弹窗残留 + 静默 | 记录警告 + 弹窗保持打开 |
| NewFile 抛异常 | catch 日志 + 弹窗残留 | catch 日志 + 弹窗仍关闭 |
| ReplaceText 抛异常 | catch 日志 + 弹窗残留 | catch 日志 + 弹窗仍关闭 |
| ActiveDocument 为 null | 弹窗残留 | 记录警告 + 弹窗仍关闭 |
| 调用方收到 DialogResult | 无（始终 false） | true=成功 / null=失败 / false=未点击 |

## 踩坑经验

### EnvDTE 枚举拼写

`vsEPReplaceTextOptions` 枚举的正确成员名是 **`vsEPReplaceTextAutoformat`**（注意：f 小写，**不是** `vsEPReplaceTextAutoFormat`）。值是 **8**（不是 1）。

参考：
- [vsEPReplaceTextOptions Enum (EnvDTE) | Microsoft Learn](https://learn.microsoft.com/zh-cn/dotnet/api/envdte.vsepreplacetextoptions?view=visualstudiosdk-2022)
- 项目内既有 `SsmsEditorService.cs` 第 85 行的注释 `vsEPReplaceTextAutoformat = 1` 是错误的，实际值是 8

### WPF 模态弹窗 + DTE 调用

**模式**：在 `Window.ShowDialog()` 显示的模态弹窗中，调用 DTE 创建新文档后，**必须** 主动 `Close()` 弹窗，否则：
- 模态消息循环不释放
- 新文档虽然创建但焦点被弹窗劫持
- 用户在主编辑器中输入无响应

这是 WPF 模态 + DTE COM 交互的一个隐性陷阱，不在文档中明示。
