# 版本差异页显示与性能优化 产品需求文档（PRD）

## 1. 文档信息

- 版本：v1.0
- 创建日期：2026-07-16
- 作者：PM-Product-Manager（Agent 代行，因 Agent 当前 enabled:false 由主 Agent 按角色定义代行）
- 需求类型：功能迭代优化（现有差异对比页的显示与性能增强）
- 关联页面：`LocalHistoryDiffDialog`（版本历史差异对比页）

## 2. 产品概述

### 2.1 业务背景与问题陈述

版本历史差异对比页用于对比「服务器当前定义」与「历史版本」、或两个历史版本的 SQL 脚本差异。用户反馈两类痛点：

1. 显示不全：长 SQL 单行（如 `DECLARE @var VARCHAR(200)='...长串...'`）被截断，既无自动换行也无左右滚动条，部分内容不可见。
2. 加载慢：脚本内容过大（如存储过程数千行）时，打开对比页面明显变慢、卡顿，影响使用效率。

### 2.2 产品目标与成功标准（可量化）

- 目标：让任意长度的 SQL 在差异页中「看得全、看得快」。
- 成功标准：
  - 显示：超长行完整可见——默认自动换行；可按需切换为不换行 + 横向滚动。
  - 性能：5000 行 SQL 两端对比，从打开触发到可交互（可滚动、可点导航）< 1 秒（含 diff 计算与渲染）。

### 2.3 目标用户画像（Persona）

- 角色：DBA、数据库开发、运维工程师（日常使用 SSMS 管理 SQL Server 对象）。
- 痛点：审查对象定义变更、回滚前比对、定位历史修改时，常遇到超长行与大体量脚本。

### 2.4 核心使用场景

- 场景 A：查看含超长 DECLARE / 长字符串的存储过程差异，需要看全每一行内容。
- 场景 B：对比数千行的大对象，需要快速打开、流畅滚动不卡顿。
- 场景 C：精确比对某超长行的字符级差异，需要不换行 + 横向滚动以对齐字符位置。

## 3. 用户故事与验收条件

**US-1（P0）**：作为 DBA，我希望长 SQL 行默认自动换行，以便无需横向滚动即可看全内容。
- Given 打开差异对比页，When 脚本含超长行，Then 该行在面板宽度内折行显示、内容完整无截断。

**US-2（P0）**：作为 DBA，我希望可切换到「不换行 + 横向滚动」模式，以便精确比对超长行字符差异。
- Given 已切换为不换行模式，When 存在超长行，Then 显示水平滚动条且可左右拖动查看完整内容；左右逐行对齐保持正确。

**US-3（P0）**：作为 DBA，我希望提供「换行/不换行」切换开关，以便按场景选择显示方式。
- Given 页面已渲染，When 点击切换开关，Then 实时切换显示模式，无需重新计算差异或重新加载。

**US-4（P0）**：作为 DBA，我希望 5000 行脚本加载 < 1 秒，以便快速查看不卡顿。
- Given 脚本约 5000 行，When 打开对比页，Then 从触发到可交互耗时 < 1 秒，UI 线程不长时间阻塞。

**US-5（P1）**：作为 DBA，我希望切换显示模式不影响差异导航，以便随时跳转差异点。
- Given 处于某显示模式且已有 N 个差异点，When 切换模式，Then 差异计数、上一个/下一个、高亮、同步滚动均保持正确。

**US-6（P2）**：作为 DBA，我希望超大脚本不崩溃，以便极端情况有兜底。
- Given 脚本 20000+ 行，When 打开对比，Then 不崩溃、不长时间无响应（可降级渲染或明确提示）。

## 4. 功能规格说明

### 4.1 显示模式切换（核心功能）

- 触发条件：工具栏新增「自动换行」开关（ToggleButton）。
- 正常流程：用户点击开关 → 两侧面板实时切换 → 自动换行 / 不换行 + 横向滚动。
- 默认状态：自动换行（根据用户决策）。
- 异常流程：切换过程若失败，保留原模式并提示，不破坏已渲染内容。
- 边界条件：切换不触发 diff 重算、不重新拉取脚本；与同步滚动、差异高亮共存。

### 4.2 性能优化（核心功能）

- 触发条件：打开对比页 / 重试加载。
- 目标：5000 行 < 1 秒、UI 线程不阻塞（加载中与渲染过程可响应）。
- 正常流程：计算差异 + 渲染在可接受耗时内完成，页面可交互。
- 边界条件：极大脚本（20000+ 行）需有降级或提示，避免无响应。

## 5. 数据埋点与指标

- 关键事件：差异页打开耗时（ms）、脚本行数、显示模式选择次数。
- 核心指标：P95 打开耗时、超 1 秒占比、自动换行使用率。
- 看板需求：发布后观察打开耗时分布与模式使用率。

## 6. 非功能需求

- 性能要求：5000 行 < 1 秒；UI 线程不被长时间阻塞。
- 兼容性要求：net472 / SSMS 22；与现有差异导航、同步滚动、重试逻辑向后兼容。
- 安全与合规：不涉及敏感数据处理变更。

## 7. 验收标准

- 核心功能：AC-1 默认换行完整可见；AC-2 切换横滚可查看；AC-3 开关实时生效；AC-4 5000 行 < 1 秒；AC-5 导航不受影响。
- 异常场景：AC-6 空脚本 / 加载失败遮罩 / 重试逻辑保持原有行为。
- 性能指标：AC-4（5000 行 < 1 秒）、AC-7（20000+ 行不崩溃）。

## 8. 上线计划建议

- 灰度策略：随 SSMSBoostPlus 常规版本发布，发布说明标注「差异页显示与性能优化」。
- 回滚条件：该功能为增量增强，可通过构建版本回退。
- 上线后观察：打开耗时分布、显示模式使用率、崩溃/卡顿反馈。

## 9. 范围边界与风险

- 不在范围：差异算法（DiffPlex）本身、在编辑器中打开功能、行内逐字符 diff 着色（均保持现状）。
- 产品风险：性能目标（5000 行 < 1 秒）的达成依赖技术实现选型（是否引入支持虚拟化的轻量渲染控件），需 Architect 评估；优先约束为不引入重型第三方依赖、控制包体积与 net472 兼容性。
- 技术探索方向（供 Architect 决策，非 PM 结论）：
  - 自动换行：移除禁用换行的无限列宽约束，按面板实际宽度约束文档宽度。
  - 横向滚动：在 RichTextBox（TextBoxBase）自身启用水平滚动条，纠正当前设在外层 ScrollViewer 未生效的问题。
  - 性能：FlowDocument 无 UI 虚拟化，探索 ListView/VirtualizingStackPanel 替代、异步构建、首屏限量 + 增量加载，或评估轻量编辑器控件（如 AvalonEdit）的可行性与依赖成本。
