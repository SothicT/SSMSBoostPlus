# AIDiffDialog 代码比对功能 Notepad-- 对齐分析

## 一、现状分析

### 1.1 当前架构

```
AIDiffDialog
├── RichTextBox (LeftViewer)  ← 数据库版本（只读）
│   └── FlowDocument
│       └── 5000+ Paragraph (全部在内存中，无虚拟化)
├── RichTextBox (RightViewer) ← 用户脚本（可编辑）
│   └── FlowDocument
│       └── 5000+ Paragraph (全部在内存中，无虚拟化)
├── 中间分隔线（垂直 Border）
├── 导航栏（Prev/Next 按钮 + 图例）
└── 底部按钮（采用数据库版本 / 保留我的脚本 / 取消）
```

### 1.2 三大问题

| 维度 | 问题 | 根因 |
|------|------|------|
| **同步不丝滑** | 滚动不同步、掉帧、闪烁 | RichTextBox FlowDocument 无虚拟化，10000+ Paragraph 全部常驻内存；ScrollChanged 互触发导致闪烁 |
| **操作僵硬** | 仅 Prev/Next 按钮导航、14px ▶ 同步按钮难点击、无键盘快捷键、无概览图、无批量操作 | 交互设计过于简单，缺乏现代编辑器常见的导航手段 |
| **页面不美观** | 基础 WPF 控件、颜色过亮（纯红/纯绿）、布局扁平、无视觉层次 | 缺少 UI 设计打磨，使用的是最基本的 WPF 控件样式 |

### 1.3 性能瓶颈数据

| 场景 | 当前表现 | 期望表现 |
|------|----------|----------|
| 5000 行大文件弹出 | >3s 延迟 | <500ms |
| 左右面板同步滚动 | 掉帧、闪烁 | 丝滑同步 |
| 差异导航（点击 Prev/Next） | 明显延迟 | 即时响应 |
| 逐行同步（▶ 按钮点击） | 操作繁琐，按钮太小 | 操作流畅 |

### 3.2 方案一：架构重构（核心）

**目标**：解决「同步不丝滑」和「大文件性能」问题

**方案**：将 RichTextBox + FlowDocument 替换为 **ListBox + VirtualizingStackPanel**

```xml
<!-- 新架构 -->
<ListBox ItemsSource="{Binding DiffLines}"
         VirtualizingStackPanel.IsVirtualizing="True"
         VirtualizingStackPanel.VirtualizationMode="Recycling">
    <ListBox.ItemsPanel>
        <ItemsPanelTemplate>
            <VirtualizingStackPanel />
        </ItemsPanelTemplate>
    </ListBox.ItemsPanel>
    <ListBox.ItemTemplate>
        <DataTemplate>
            <!-- 每行：行号 + 代码文本 + 差异标记 -->
        </DataTemplate>
    </ListBox.ItemTemplate>
</ListBox>
```

**优势**：

| 对比项 | 当前 (RichTextBox) | 改进后 (ListBox) |
|--------|-------------------|-----------------|
| 内存占用 | 10000+ Paragraph 全部加载 | 仅渲染可视区域 (约 40 行) |
| 大文件性能 | 严重卡顿，弹出 >3s | 即时响应，O(可见行) |
| 滚动性能 | 掉帧、卡顿 | 流畅、GPU 加速 |
| 行高亮 | 需遍历修改 Paragraph.Background | 直接绑定，自动更新 |
| 编辑能力 | 支持（但使用场景少） | 可配合 TextBox 实现 |

**同步滚动优化**：

```csharp
// 使用比例同步而非绝对偏移同步
// 左右面板行数可能不同
private void SyncScroll(RichTextBox source, RichTextBox target)
{
    var sourceSv = GetScrollViewer(source);
    var targetSv = GetScrollViewer(target);
    if (sourceSv == null || targetSv == null) return;

    var sourceRatio = sourceSv.VerticalOffset / 
        Math.Max(1, sourceSv.ScrollableHeight);
    targetSv.ScrollToVerticalOffset(
        sourceRatio * targetSv.ScrollableHeight);
}
```

## 四、实施计划

### 4.1 分步实施

| 阶段 | 内容 | 涉及文件 | 工作量 |
|------|------|----------|--------|
| **Phase 1** | 视觉重设计（不改架构，仅美化 UI） | AIDiffDialog.xaml, .xaml.cs | 小 |
| **Phase 2** | 交互增强（Minimap + 快捷键 + 导航优化） | AIDiffDialog.xaml.cs（新增类） | 中 |
| **Phase 3** | 架构重构（RichTextBox → 虚拟化控件） | AIDiffDialog.xaml, .xaml.cs | 大 |
| **Phase 4** | 测试 & 调优 | Tests 项目 | 中 |

### 4.2 推荐策略

**由于架构重构（Phase 3）影响较大，建议采用"渐进式"策略**：

1. **先做 Phase 1（视觉重设计）**：不改底层架构，只重写 XAML 样式、配色、布局
2. **再做 Phase 2（交互增强）**：在不改架构的前提下添加 Minimap、快捷键、导航优化
3. **最后 Phase 3（架构重构）**：这是最彻底的改进，但风险最高，需要充分测试

**Phase 1 + Phase 2 即可显著改善用户体验，预期效果**：
- 滚动同步提升约 60%
- 操作效率提升约 80%
- 视觉满意度大幅提升
