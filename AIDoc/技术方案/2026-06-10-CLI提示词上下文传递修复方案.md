# CLI 提示词缺少 Schema/执行计划修复方案

## 1. 问题描述

### 症状
通过 `CodebuddyCliBridge` 调用 CLI 时，传递给 AI 的 Prompt 中**缺少 Schema 信息和执行计划**，导致性能分析功能不完整。

### 影响范围
- `CodebuddyCliBridge` 路径下的所有 AI 调用（SQL 建议、注释、格式化、性能分析）
- 其中 **Analyze 模板**受的影响最大（需要 Schema、执行计划、索引信息）

### 不受影响路径
- `AIApiClientBridge` — 有独立的 `GetUserPromptForTemplate()` 实现，直接读取 `request.SchemaInfo/IndexInfo/ExecutionPlan`

---

## 2. 根因分析

### 数据流追踪

```
AIPerformanceCommand.ExecuteAsync()
    ✅ 正确获取 executionPlanXml、schemaInfo、indexInfo
    ↓
CodeAnalysisService.AnalyzePerformanceAsync()
    ✅ 正确设置到 AIRequest 对象
    ↓
CodebuddyCliBridge.ExecuteAsync()  ← 🔴 断裂点！
    ❌ var prompt = _promptManager.BuildPrompt(request.Template, request.Code);
    ❌ 第3参数 AIContext? context 默认为 null！
    ↓
PromptTemplateManager.BuildAnalyzePrompt()
    ❌ if (context == null) 跳过所有上下文追加
```

### 核心问题

`BuildPrompt` 方法签名：
```csharp
public string BuildPrompt(string template, string code, AIContext? context = null)
```

`CodebuddyCliBridge` 调用时：
```csharp
// ❌ 错误：未传 context
var prompt = _promptManager.BuildPrompt(request.Template, request.Code);
```

`BuildAnalyzePrompt` 中的跳过逻辑：
```csharp
if (context == null)  // ← 始终为 true，因为没人传
{
    userPrompt.AppendLine("SQL:");
    userPrompt.AppendLine(code);
    return userPrompt.ToString();  // ← 直接返回，不追加 Schema/执行计划
}
```

---

## 3. 修复方案

### 3.1 核心修复：CodebuddyCliBridge.cs

**新增辅助方法**：
```csharp
/// <summary>
/// 将 AIRequest 中的上下文字段映射为 AIContext 对象，
/// 以便传入 PromptTemplateManager.BuildPrompt() 构建完整的 Prompt。
/// </summary>
private static AIContext BuildContextFromRequest(AIRequest request)
{
    return new AIContext
    {
        SchemaInfo = request.SchemaInfo,
        IndexInfo = request.IndexInfo,
        ExecutionPlan = request.ExecutionPlan,
        FormatStyle = request.FormatStyle,
        DatabaseName = request.DatabaseName
    };
}
```

**修复 `ExecuteAsync` 方法**：
```csharp
// 修复前：
var prompt = _promptManager.BuildPrompt(request.Template, request.Code);

// 修复后：
var context = BuildContextFromRequest(request);
var prompt = _promptManager.BuildPrompt(request.Template, request.Code, context);
```

**修复 `ExecuteStreamAsync` 方法**：同上。

### 3.2 补充字段：AIRequest.cs

为保持与 `AIContext` 字段对齐，新增 `DatabaseName` 属性：

```csharp
/// <summary>数据库名称上下文（所有模板均可用）</summary>
public string? DatabaseName { get; set; }
```

### 3.3 AIRequest → AIContext 字段映射表

| AIRequest 字段 | AIContext 字段 | 来源 | 说明 |
|---|---|---|---|
| `request.SchemaInfo` | `context.SchemaInfo` | AIPerformanceCommand | 数据库 Schema 信息 |
| `request.IndexInfo` | `context.IndexInfo` | AIPerformanceCommand | 索引信息 |
| `request.ExecutionPlan` | `context.ExecutionPlan` | AIPerformanceCommand | 执行计划 XML |
| `request.FormatStyle` | `context.FormatStyle` | 调用方 | 格式化风格 |
| `request.DatabaseName` | `context.DatabaseName` | 新增 | 数据库名称 |

---

## 4. 边缘情况与异常处理

| 场景 | 处理方式 | 说明 |
|---|---|---|
| 所有上下文字段均为 null | `BuildContextFromRequest` 映射全为 null，`BuildAnalyzePrompt` 跳过空字段，Prompt 仅含 SQL 代码 | 正常降级 |
| 执行计划超长（>8000 字符） | `BuildAnalyzePrompt` 已有 `Truncate(8000)` 截断，`BuildContextFromRequest` 无需重复处理 | 设计已考虑 |
| 非 Analyze 模板（Suggest/Comment/Format） | `BuildContextFromRequest` 只映射通用字段，对应 Prompt 构建方法不读取 SchemaInfo | 无副作用 |
| AIApiClientBridge 路径 | 不受影响，路径独立 | 无需修改 |
