## 问题现象

V2 修复（hunkIndex 碰撞）后，同步功能已正常（段落正确插入、恢复按钮正确创建），但按钮位置仍然错位：

1. 打开差异比对弹窗，按钮初始位置正确 ✅
2. 点击同步按钮 → 恢复按钮**不在**同步行位置 ❌
3. 点击多个同步按钮 → 每个恢复按钮位置都**不正确** ❌
4. 点击恢复（撤销）→ 同步按钮位置**不变** ❌

**关键特征**：偏移量一致（所有按钮向上偏移相同行数），非随机错位。

## 根因分析

### 🔴 根因（主因）：`GetCharacterRect` 在文档修改后返回不可靠坐标

#### 初始加载 vs 同步后的关键差异

| 场景 | `PopulateActionStrip` 调用方式 | `GetCharacterRect` 可靠性 |
|------|-------------------------------|--------------------------|
| 初始加载 | `Dispatcher.BeginInvoke(Render)` — **延迟到布局完成后** | ✅ 可靠（文档从零构建，布局完整） |
| 同步后 | **同步调用** — 紧跟在 `SyncHunk` + `RenumberRightParagraphs` 之后 | ❌ 不可靠（文档刚被修改，布局缓存可能过期） |

**代码证据**：

```csharp
// 初始加载（第 458 行）— 延迟到 Render 优先级，布局已完成
Dispatcher.BeginInvoke(new Action(() =>
{
    PopulateActionStrip();
}), DispatcherPriority.Render);

// 同步后（第 1670 行）— 同步调用，布局可能未完全更新
RenumberRightParagraphs();
RebuildDiffHunksFromState();
PopulateActionStrip();  // ← 立即执行，GetCharacterRect 可能返回过期值
```

#### `GetCharacterRect` 不可靠的两个机制

**机制 1：视口相对坐标**

WPF 的 `TextPointer.GetCharacterRect()` 在某些情况下返回**视口相对坐标**（相对于可见区域顶部），而非文档相对坐标（相对于文档内容顶部）。

```
文档相对坐标：     rect.Top = Y（段落在文档中的绝对位置）
视口相对坐标：     rect.Top = Y - VerticalOffset（段落在可见区域中的位置）
```

当 `VerticalOffset = 0`（未滚动）时，两种坐标相同，按钮位置正确。
当 `VerticalOffset > 0`（用户滚动到差异区域）时，两种坐标不同，按钮偏移量 = `VerticalOffset`。

**偏移量计算**：

```
Canvas 坐标系：       0 → ExtentHeight（文档相对）
GetCharacterRect：     Y - VerticalOffset（视口相对，假设机制 1 生效）
Canvas 滚动偏移：      VerticalOffset

按钮在 Canvas 上的位置：Canvas.SetTop = Y - VerticalOffset
按钮在视口中的位置：    (Y - VerticalOffset) - VerticalOffset = Y - 2×VerticalOffset
段落在视口中的位置：    Y - VerticalOffset
偏移量：               VerticalOffset（按钮在段落上方 VerticalOffset 像素处）
```

**这解释了为什么所有按钮一致偏移** — 偏移量 = `VerticalOffset`，对所有按钮相同。

**机制 2：布局缓存过期**

`SyncHunk` 插入段落后，`RenumberRightParagraphs` 修改所有段落的行号文本。即使调用 `UpdateLayout()`，FlowDocument 的内部布局缓存可能未完全失效。`GetCharacterRect` 使用此缓存，返回的 Y 坐标可能反映**修改前**的段落位置。

**异步 `PositionActionButtons` 为什么没有修复？**

`PositionActionButtons` 在 `Render` 和 `Background` 优先级各执行一次 `RepositionAllButtons`。但：
1. 如果机制 1（视口相对坐标）生效，异步回调中的 `GetCharacterRect` 仍然返回视口相对坐标
2. 如果机制 2（布局缓存过期）生效，`Background` 优先级可能仍不足以让缓存完全刷新
3. `_isPositioningButtons` 防重入 guard 可能在 `SizeChanged`（由段落插入触发）时阻止新的定位请求

### 🟡 次因：占位段落高度差异累积

占位段落（"— N 行未变更 —"）的 `LineHeight = 24`，普通段落 `LineHeight = 18`。如果 `GetCharacterRect` 在某些占位段落上返回不准确的值，累积误差会导致后续所有按钮偏移。

## 修复方案

### 核心思路：用确定性高度计算替代 `GetCharacterRect`

不依赖 WPF 布局系统，直接根据段落索引和已知高度计算 Y 坐标：

```
Y(blockIndex) = Σ(前 blockIndex 个段落的高度)
              = Σ(placeholder ? 24 : 18)
```

**优势**：
- **确定性**：不依赖 WPF 布局缓存，修改前后结果一致
- **无视口依赖**：不关心 `VerticalOffset`，直接计算文档绝对坐标
- **O(N) 预计算**：一次遍历预计算所有位置，O(1) 查找

**前提条件**（均已满足）：
- 每个段落只有一行文本（无换行）
- `Margin = 0`，无额外间距
- `LineHeight` 显式设置（18 或 24），非 `NaN`（auto）

### 修复 1：添加 `PrecomputeBlockYPositions` 方法

**文件**：`AIDiffDialog.xaml.cs`

在 `RepositionAllButtons` 方法之前添加：

```csharp
/// <summary>
/// 预计算所有段落的 Y 坐标（基于已知高度，不依赖 GetCharacterRect）。
/// 占位段落高度 24px，普通段落高度 18px。
/// </summary>
private Dictionary<int, double> PrecomputeBlockYPositions()
{
    var positions = new Dictionary<int, double>();
    double y = 0;
    int blockCount = RightViewer.Document.Blocks.OfType<Paragraph>().Count();
    for (int i = 0; i < blockCount; i++)
    {
        positions[i] = y;
        y += _placeholderBlocks.Contains(i) ? 24.0 : 18.0;
    }
    return positions;
}
```

### 修复 2：`PopulateActionStrip` — 用计算值替代 `GetCharacterRect`

**位置**：`PopulateActionStrip()` 方法

**修改点 A** — 同步按钮定位（约第 1273-1295 行）：

### 修复 3：`RepositionAllButtons` — 用计算值替代 `GetCharacterRect`

**位置**：`RepositionAllButtons()` 方法（约第 1379-1408 行）

```csharp
// ❌ 原代码：
private void RepositionAllButtons()
{
    RightViewer.UpdateLayout();
    LeftViewer.UpdateLayout();

    var rightSv = FindScrollViewer(RightViewer);
    if (rightSv != null)
    {
        ActionStripCanvas.Height = Math.Max(rightSv.ExtentHeight, rightSv.ViewportHeight);
        ActionStripScroller.ScrollToVerticalOffset(rightSv.VerticalOffset);
    }

    var blockSnapshot = RightViewer.Document.Blocks.OfType<Paragraph>().ToList();
    for (int i = 0; i < blockSnapshot.Count; i++)
    {
        if (_actionButtons.TryGetValue(i, out var button))
        {
            try
            {
                var rect = blockSnapshot[i].ContentStart.GetCharacterRect(LogicalDirection.Forward);
                double top = rect.Top;
                if (double.IsNaN(top) || double.IsInfinity(top)) top = 0;
                Canvas.SetTop(button, top);
            }
            catch { }
        }
    }
}

// ✅ 新代码：
private void RepositionAllButtons()
{
    RightViewer.UpdateLayout();
    LeftViewer.UpdateLayout();

    var rightSv = FindScrollViewer(RightViewer);
    if (rightSv != null)
    {
        ActionStripCanvas.Height = Math.Max(rightSv.ExtentHeight, rightSv.ViewportHeight);
        ActionStripScroller.ScrollToVerticalOffset(rightSv.VerticalOffset);
    }

    // 使用确定性高度计算，不依赖 GetCharacterRect
    var blockYs = PrecomputeBlockYPositions();
    foreach (var kvp in _actionButtons)
    {
        int blockIndex = kvp.Key;
        var button = kvp.Value;
        if (blockYs.TryGetValue(blockIndex, out var y))
        {
            Canvas.SetTop(button, y);
        }
    }
}
```

### 修复 4（可选保险）：`PositionActionButtons` — 移除 `_isPositioningButtons` 对 `PopulateActionStrip` 后调用的阻止

**问题**：`SyncBlock_Click` → `PopulateActionStrip` → `PositionActionButtons` 设置 `_isPositioningButtons = true`。如果在异步回调执行前，`SizeChanged` 事件触发（因段落插入导致布局变化），新的 `PositionActionButtons` 调用会被跳过。

**修复**：在 `PopulateActionStrip` 中调用 `PositionActionButtons` 前强制重置标志：

```csharp
// 在 PopulateActionStrip 末尾：
_isPositioningButtons = false;  // 强制重置，确保后续 PositionActionButtons 能执行
PositionActionButtons();
```

## 修改清单

| # | 修改位置 | 修改内容 | 根因 |
|---|---------|---------|------|
| 1 | 新增 `PrecomputeBlockYPositions()` | 基于已知高度预计算所有段落 Y 坐标 | 基础设施 |
| 2 | `PopulateActionStrip()` 同步按钮 | 用 `blockYs[blockIndex]` 替代 `GetCharacterRect` | 根因 1 |
| 3 | `PopulateActionStrip()` 恢复按钮 | 用 `blockYs[blockIndex]` 替代 `GetCharacterRect` | 根因 1 |
| 4 | `RepositionAllButtons()` | 用 `blockYs` 遍历替代 `GetCharacterRect` | 根因 1 |
| 5 | `PopulateActionStrip()` 末尾 | 强制重置 `_isPositioningButtons` | 次因 |

## 为什么初始加载正确

初始加载时 `PopulateActionStrip` 通过 `Dispatcher.BeginInvoke(Render)` 延迟执行：

1. **文档从零构建**：所有段落一次性添加，无增量修改，布局缓存是新鲜的
2. **延迟到 Render 优先级**：WPF 已完成所有布局测量和排列
3. **VerticalOffset = 0**：用户尚未滚动，视口相对 = 文档相对

因此 `GetCharacterRect` 返回正确值。同步操作后，这三个条件都不满足。
