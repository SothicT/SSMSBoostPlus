# SSMSBoostPlus 周报生成 Skill

基于 `AIDoc/周报/周报模板.md` 模板，自动收集 Git 提交历史数据，生成结构化项目周报。

## 使用方式

| 触发词 | 日期范围 | 示例 |
|--------|----------|------|
| `写周报` / `生成周报` | 智能推算（默认） | 自动从上次周报截止日+1 到 今天 |
| `写周报 06-02 06-09` | 手动指定 | 从 2026-06-02 到 2026-06-09 |
| `写周报 06-02` | 指定起始日 | 从指定日到 今天 |

## 工作流（7 步）

### Step 1: 确定日期范围

**默认智能推算**：

1. 扫描 `AIDoc/周报/` 目录下所有 `周报-*至*.md` 文件
2. 解析文件名中截止日期（如 `周报-2026-06-02至2026-06-09.md` → 截止日 `2026-06-09`）
3. 取最新一份的截止日 + 1 天作为起始日，今天作为截止日
4. 自动计算工作日名称（周一/周二等）

**手动覆盖**：用户输入 `写周报 MM-DD MM-DD` 时，直接使用指定范围（假定当前年份）

**首次无历史周报**：回退为「上周一 → 今天」

### Step 2: 收集 Git 数据

执行以下命令收集数据：

```powershell
# 提交记录表
git log --oneline --since="{{start}}" --until="{{end}}+1 day" --format="| %ad | `%h` | %s |" --date=short

# 文件变更统计
git diff --stat $(git log --oneline --since="{{start}}" --until="{{end}}+1 day" --format="%H" | Select-Object -Last 1)^..$(git log --oneline --since="{{start}}" --until="{{end}}+1 day" --format="%H" | Select-Object -First 1)

# 当前分支
git branch --show-current

# 更简单的 diff 统计方式（如果上面复杂命令失败）
git diff --stat {{start}}..{{end}}
```

**简化统计命令**（推荐）：

```powershell
# 提交数
git log --oneline --since="{{start}}" --until="{{end}}+1 day" | Measure-Object -Line

# 新增/修改文件数
git diff --name-status {{start}}..{{end}} | ForEach-Object { $_ -split '\t' } | Where-Object { $_ -match '^(A|M|R)' }

# 净增代码行（插入-删除）
git diff --shortstat {{start}}..{{end}}
```

注意：`--until` 不包含当天，需要 `--until="{{end}}+1 day"` 才能包含结束日期。

### Step 3: 读取 Memory 工作记录

读取 `.workbuddy/memory/` 目录下日期范围内的 `YYYY-MM-DD.md` 文件，解析结构化工作记录。

#### 3.1 确定文件列表

- 日期范围已由 Step 1 确定（start ~ end）
- 遍历范围内每一天，检查 `.workbuddy/memory/YYYY-MM-DD.md` 是否存在
- 使用 `read_file` 工具读取存在的文件

#### 3.2 解析内容结构

Memory 文件的典型层级结构：

```
# YYYY-MM-DD 工作记录          → 日期标识

## 模块名（如"AI对话面板"）      → 模块分类
### 子任务（如"新增功能"）       → 具体任务
- **文件**：路径               → 文件引用
- **修复**：方案               → 修改要点

## 验证结果                     → 状态报告
- 编译：✅ 0 错误

## Git 提交与推送               → Commit 汇总参考
| # | 类型 | 说明 |

## 待后续完善                    → 待办事项来源

## 已知风险                     → 已知风险来源
```

#### 3.3 提取结构化数据

| 提取内容 | 识别模式 | 提取方式 |
| --- | --- | --- |
| 模块摘要 | `## 标题` 行 | 遍历所有二级标题，提取标题文本和后续摘要 |
| 任务详情 | `### 标题` + 后续列表 | 提取三级标题+后续有序/无序列表项 |
| 待办事项 | 含"待续""TODO""待完善"的小节 | 提取该小节下的所有列表项 |
| 已知风险 | `## 已知风险` 小节 | 提取该小节下的所有列表项 |
| Commit 统计 | `\| # \| 类型 \| 说明 \|` 表格 | 提取表格行，按类型字段计数 |
| 文件信息 | `**文件**：` 行 | 提取冒号后面的路径 |

#### 3.4 降级策略

- **无文件**：范围内无任何 Memory 文件 → Step 5 回退到原始用户补充流程，告知用户
- **部分缺失**：某天无文件则跳过该天，不影响其他天的数据提取
- **文件为空**：只有标题无内容 → 跳过，不提取数据

### Step 4: 读取模板

读取 `AIDoc/周报/周报模板.md`，识别所有 `{{占位符}}`：

| 占位符 | 填充方式 | 来源 | Memory 增强 |
|--------|----------|------|-------------|
| `{{周期开始}}` / `{{周期结束}}` | 自动 | Step 1 日期范围 | — |
| `{{开始星期}}` / `{{结束星期}}` | 自动 | 日期 → 工作日换算 | — |
| `{{分支名称}}` | 自动 | `git branch --show-current` | — |
| `{{报告人}}` | 待补充 | 默认 "AI Agent"，用户可覆盖 | — |
| `{{提交次数}}` | 自动 | `git log --oneline` 行数 | — |
| `{{新增文件数}}` / `{{修改文件数}}` | 自动 | `git diff --name-status` 统计 | — |
| `{{净增代码行}}` | 自动 | `git diff --shortstat` | — |
| `{{解决Bug数}}` / `{{新增功能数}}` / `{{文档产出数}}` | 自动 | **Memory Commit 表推断** + Git 兜底 | 按 commit 类型字段(fix/feat/docs)计数 |
| `{{本期主线概述}}` | **自动生成 + 用户校对** | **Memory 模块标题汇总** | 从 `##` 模块标题生成 1-3 句话 |
| `{{本周事项摘要}}` | **自动生成 + 用户校对** | **Memory 模块摘要** | 格式：`[MM-DD] 模块名：简要描述` |
| `{{完成事项详述}}` | **自动生成 + 用户校对** | **Memory 任务详情** | 含模块、文件路径、修改要点 |
| `{{待办事项}}` | **自动提取 + 用户补充** | **Memory 待办小节** | 从"待续/TODO/待完善"小节提取 |
| `{{已知风险}}` | **自动提取 + 用户补充** | **Memory 风险小节** | 从"已知风险"小节提取 |
| `{{下周计划}}` | 待补充 | 需用户提供 | Memory 中通常无此信息 |
| `{{提交记录表}}` | 自动 | `git log` 输出 | — |

### Step 5: 分步填充

按填充优先级分两轮：

**Round 1：自动填充（增强版，融合 Memory + Git）**

| 占位符 | 原填充方式 | 新填充方式 | 填充策略 |
|--------|-----------|-----------|---------|
| `{{本期主线概述}}` | 用户提供 | **自动生成 + 用户校对** | 从所有 Memory 的 `##` 模块汇总，生成 1-3 句话主线概述 |
| `{{本周事项摘要}}` | 用户提供 | **自动生成 + 用户校对** | 按日期+模块提取，格式：`[06-14] 模块名：简要描述` |
| `{{完成事项详述}}` | 用户提供 | **自动生成 + 用户校对** | 按日期组织，含模块、文件路径、修改要点 |
| `{{待办事项}}` | 用户提供 | **自动提取 + 用户补充** | 从 Memory 的"待续/TODO"小节提取，无数据则留空提示用户 |
| `{{已知风险}}` | 用户提供 | **自动提取 + 用户补充** | 从 Memory 的"风险"小节提取，无数据则留空提示用户 |
| `{{解决Bug数}}` | 推断/用户提供 | **从 Commit 表推断** | 统计 Memory 中 commit 表类型=fix 的行数 |
| `{{新增功能数}}` | 推断/用户提供 | **从 Commit 表+模块标题推断** | 统计 commit 表类型=feat 的行数，或模块标题含"新增" |
| `{{文档产出数}}` | 推断/用户提供 | **从 Commit 表推断** | 统计 commit 表类型=docs 的行数 |
| 元信息/其他 | 自动 | 不变 | 日期、分支、Git 指标等仍从原来源获取 |

**Round 2：用户校对（精简版）**

- 展示 Round 1 的自动填充结果给用户校对
- 用户可确认/修改/补充自动填充内容
- 必须用户提供：`{{下周计划}}`
- 可选补充：主线概述/事项摘要/详述/待办/风险的微调
- 每项支持"跳过"（保留占位符以便手动编辑）

### Step 6: 最终组装

将所有填充后的内容按模板顺序拼接，输出到文件：
`AIDoc/周报/周报-{{开始日期}}-至-{{结束日期}}.md`

文件名格式：`周报-YYYY-MM-DD-至-YYYY-MM-DD.md`

### Step 7: 验证

- 检查所有占位符已填充（未被跳过的除外）
- 检查日期格式一致
- 检查 Git 提交记录与日期范围匹配
- 确认文件已写入目标路径

## 注意事项

- PowerShell 环境下 Git 命令的 `--since`/`--until` 参数需用双引号包裹日期
- `git log --until` 不包含当天，使用 `--until="{{end}}+1 day"` 确保覆盖截止日
- 首尾提交的 diff 统计：`git diff --stat <first-commit>^..<last-commit>`
- 文件名中的日期格式为 `YYYY-MM-DD`，与 ISO 8601 一致
- 生成的周报统一存放于 `AIDoc/周报/` 目录
