## 2. 产品概述

### 2.1 业务背景与问题陈述

SQL 补全增强 v2 上线后，用户在 **172.16.50.154 的 PUB 数据库**（缓存对象 **3757 个**）实测发现严重卡顿：

1. **输入单字符卡顿**：在 `SELECT TOP 100 * FROM $CURSOR WITH(NOLOCK)` 的 `$CURSOR`（表名位置）输入 `a`，卡顿约 **1 秒**。
2. **删除单字符卡顿**：删除 `a` 后（前缀变为空），再次卡顿约 **1 秒**。
3. **多字符不卡顿（对照）**：继续输入 `bd` 再删除完全无卡顿，因 `b`/`bd` 前缀命中对象极少。

4. **TAB/ENTER 按键交互异常**：弹窗弹出后按 TAB 键会**默认提交首个提示项**（`ExpandSelectedTemplate` 对 `ListBox.SelectedItem` 展开），连续按 TAB 会反复插入首个候选内容，用户无法使用 TAB 做正常缩进。

根因（代码定位）：

| 卡顿场景 | 触发路径 | 根因 |
|---------|---------|------|
| 输入 `a` | `GetMatchingObjects("a")` → `SearchInCache` | 前缀 `a` 命中**几百个**对象，每个对象执行完整 `FuzzyMatch`（2 次 ToLowerInvariant 字符串分配 + 子序列扫描 + Contains），再全量排序 |
| 删除 `a` | `GetTableCandidates("", db)` → `GetAllObjectsOfTypes("U","V")` | **全量遍历** 3757 个对象按类型过滤 + 全量 OrderBy + **创建几千个 CompletionCandidate 对象** |

用户对卡顿的感知阈值：**单次补全计算超过 100ms 即有明显卡顿**，当前 1 秒远超可接受范围。

### 2.2 产品目标

| 目标 | 度量指标 | 当前基线 | 目标值 |
|------|---------|---------|--------|
| 输入单字符补全无卡顿 | SearchInCache 计算耗时 | ~1000ms（前缀命中几百个） | **< 50ms** |
| 删除到空前缀补全无卡顿 | GetAllObjectsOfTypes 计算耗时 | ~1000ms（3757 全量） | **< 50ms** |
| 连续输入删除无卡顿 | 键盘连续输入期间 UI 无阻塞 | 输入 `bd` 不卡，输入/删除 `a` 卡 | **所有输入均无感知卡顿** |
| 功能零回归 | 补全候选结果质量不劣化 | v2 测试 220 通过 / 3 预存失败 | **不新增失败，候选排序合理性不下降** |

### 2.3 目标用户画像

| 用户角色 | 场景 | 需求痛点 |
|---------|------|---------|
| DBA / 数据库开发 | 在大型生产库（3000+ 对象）编写查询 | 输入几个字符就卡顿 1 秒，严重打断思路 |
| 报表开发 | 频繁在 FROM 后输入/删除表名试探 | 删除字符触发全量候选，界面冻结 |

### 2.4 核心使用场景

**场景 A：大型库输入单字符**
用户在 PUB（3757 对象）输入 `SELECT * FROM a` → 期望即时弹出以 `a` 开头的对象列表，无卡顿。

**场景 B：删除到空前缀**
用户在 `FROM a` 删除 `a` → 期望空前缀提示列表快速出现（或快速关闭），无卡顿。

**场景 C：连续输入试探**
用户快速输入 `bd` 再逐个删除 → 期望全程无卡顿，补全列表随输入即时刷新。

## 3. 用户故事与验收条件

### US-01：空前缀全量返回限量（P0）

**用户故事**：作为 SQL 开发人员，我希望在 FROM 后删除所有输入字符时，补全计算不因数据库对象多而卡顿，以便我快速修正输入。

**验收条件**：

```
Given 当前库对象数为 3757（PUB）
When 在表名位置删除输入至空前缀（filter = ""）
Then SearchInCache 空前缀分支 / GetAllObjectsOfTypes 仅返回前 250 个候选
And 计算耗时 < 50ms
```

```
Given 对象数为 3757
When 空前缀查询返回
Then 候选结果按名称字典序排序，且不超过 250 条
```

**优先级**：P0

---

### US-02：类型索引 O(1) 定位（P0）

**用户故事**：作为 SQL 开发人员，我希望按类型取对象（如只取表 U 和视图 V）时不必全量遍历所有对象，以便删除字符后补全即时响应。

**验收条件**：

```
Given 缓存已构建（含 typeIndex 类型索引）
When 调用 GetAllObjectsOfTypes("U", "V")
Then 直接从 typeIndex 定位，不遍历全量 3757 个对象
And 返回结果与旧逻辑全量过滤结果一致（同集合、同排序）
```

**优先级**：P0

---

### US-03：预排序 + 惰性链优化（P0）

**用户故事**：作为 SQL 开发人员，我希望全量/空前缀返回时不做重复的排序和对象创建，以便大库下补全列表快速呈现。

**验收条件**：

```
Given 缓存构建时已按 Name 字典序排序 Objects
When 空前缀查询
Then 跳过 OrderBy，直接 Take(250) + Select
And 惰性链确保只创建最终返回的 250 个 CompletionCandidate，而非全量创建
```

**优先级**：P0

---

### US-04：前缀命中直接算分（P1）

**用户故事**：作为 SQL 开发人员，我希望输入单字符时，对已确定前缀命中的对象不再走完整 FuzzyMatch 算法，以便输入响应更快。

**验收条件**：

```
Given 输入 prefix = "a"，前缀索引命中 300 个对象
When SearchInCache 计算分数
Then 前缀命中对象直接套公式 score = 500 - (Name.Length - prefix.Length)
And 不调用 CompletionCandidate.FuzzyMatch（无 ToLowerInvariant 字符串分配）
```

```
Given 前缀命中数量 >= 候选上限（250）
When SearchInCache 执行
Then 跳过子序列补充匹配（候选已满，补充无意义）
And 直接 Take(250) + 公式算分 + 排序返回
```

**优先级**：P1

---

### US-05：NameLower 预计算（P1）

**用户故事**：作为 SQL 开发人员，我希望子序列匹配和 FuzzyMatch 不再反复做大小写转换，以便大规模对象扫描时减少计算开销。

**验收条件**：

```
Given DatabaseObjectInfo 构建时已填充 NameLower 字段
When IsSubsequence / FuzzyMatch 执行
Then 直接比较 NameLower，不调用 char.ToLowerInvariant / string.ToLowerInvariant
And 匹配结果与旧逻辑一致（大小写不敏感语义不变）
```

**优先级**：P1

---

### US-06：输入防抖（P2）

**用户故事**：作为 SQL 开发人员，我希望连续输入时补全计算不逐键触发，以便快速连打不会卡顿。

**验收条件**：

```
Given 用户在 120ms 内连续输入多个字符（如 "ab"）
When 每次按键触发补全
Then 仅最后一次输入触发实际补全计算（防抖窗口 120ms）
And 最终补全结果与不防抖时一致
```

**优先级**：P2

---

### US-07：结果 LRU 缓存（P3）

**用户故事**：作为 SQL 开发人员，我希望反复输入/删除相同字符时，补全结果直接复用，以便高频编辑操作零重复计算。

**验收条件**：

```
Given 已查询过 prefix = "a" 的结果
When 再次查询相同 prefix = "a"
Then 直接命中 LRU 缓存返回，不重新执行匹配 + 排序 + 对象创建
And 缓存容量上限 100 条，超出后按最少最近使用淘汰
```

**优先级**：P3

---

### US-08：TAB 不自动触发弹窗，已弹窗时 TAB 可提交补全（P0）

**用户故事**：作为 SQL 开发人员，我希望按 TAB 键**不会自动触发**补全弹窗（TAB 不是弹窗触发器，缩进时不被弹窗打扰），但当补全弹窗**已经弹出**时，按 TAB 键能正常**提交选中项完成补全**；同时 TAB 提交后弹窗不应自动重新弹出，以免连续按 TAB 反复带出首个提示项。

**验收条件**：

```
Given 补全弹窗不可见
When 用户按 TAB 键（缩进场景，光标前无模板缩写）
Then 不弹出补全弹窗
And TAB 事件放行给 SSMS 原生处理（正常缩进）
```

```
Given 补全弹窗不可见，光标前是模板缩写（如 sel）
When 用户按 TAB 键
Then 仅展开模板（TryExpandExactMatch 保留），不弹出补全弹窗
```

```
Given 补全弹窗已弹出（如输入 "FROM a" 后弹窗可见，选中首个候选）
When 用户按 TAB 键
Then 提交选中项完成补全（ExpandSelectedTemplate 正常执行）
And 提交后弹窗关闭且**不自动重新弹出**
```

```
Given 补全弹窗可见
When 用户按 ENTER 键
Then 不插入补全候选文本
And 弹窗关闭
And ENTER 事件放行给 SSMS 原生处理（插入换行）
```

**核心修复点**：`ExpandSelectedTemplate` 提交后调用 `HidePopup` 时**未设置防重开时间戳**（`HidePopup` caller 机制在 2573 行：`caller != "ExpandSelectedTemplate"` 时不重置 `_lastUserHideTime`）→ 提交插入的文本触发 `OnCharTyped` → 弹窗自动重开 → 连续 TAB 反复提交。修复：**TAB/提交路径需设置防重开时间戳**，使提交后弹窗不因提交引起的文本变化自动重开（需重新输入字符才弹出）。

**设计决策（已定稿，v1.4 修正）**：

| 场景 | 定稿方案 |
|------|---------|
| 弹窗不可见 + TAB | **不触发弹窗**（TAB 非弹窗触发器；模板缩写展开保留） |
| 弹窗可见 + TAB | **提交选中项完成补全**（`ExpandSelectedTemplate` 保留） |
| TAB 提交后 | **弹窗不自动重开**（设置防重开时间戳，修复连续 TAB 反复提交） |
| ENTER（弹窗可见） | 关闭弹窗 + 放行换行（现状已符合） |

**兼容性说明（v1.3 已确认，继续有效）**：`ExpandSelectedTemplate` 内含 SP/函数参数自动补全（F8 特性）与跨库前缀剥离逻辑，TAB 提交时**照常执行**；鼠标双击候选（2157 行）为另一保留触发路径。

**优先级**：P0

## 4. 功能规格说明

### 4.1 模块一：SearchInCache 优化

**位置**：`DatabaseObjectCacheService.SearchInCache`

**4.1.1 空前缀分支限量**（US-01）

```csharp
if (string.IsNullOrEmpty(prefix))
{
    // 预排序后免 OrderBy（US-03），限量 250（US-01），惰性创建候选（US-03）
    return objects
        .Take(MaxCandidates)
        .Select(o => CreateObjectCandidate(o, prefix, dbName))
        .ToList();
}
```

- 触发条件：filter 为空字符串
- 数据规则：返回对象数 ≤ 250；排序依赖构建期预排序
- 常量：`MaxCandidates = 250`

**4.1.2 前缀命中直接算分 + 候选已满跳过补充**（US-04）

```csharp
var prefixHits = GetPrefixHits(objects, prefixIndex, lowerPrefix);

// 前缀命中已 ≥ 上限：免子序列补充 + 免 FuzzyMatch
if (prefixHits != null && prefixHits.Count >= MaxCandidates)
{
    return prefixHits
        .Take(MaxCandidates)
        .Select(o => (o, score: 500 - (o.Name.Length - prefix.Length)))
        .OrderByDescending(x => x.score)
        .ThenBy(x => x.o.Name, StringComparer.OrdinalIgnoreCase)
        .Select(x => CreateObjectCandidate(x.o, prefix, dbName))
        .ToList();
}

// 前缀命中不足：子序列补充（补到上限即停）+ 混合算分
//   前缀命中 → 公式直算；子序列补充 → FuzzyMatch
```

- 触发条件：前缀索引命中 ≥ 250
- 边界条件：前缀命中为 null 或空 → 正常走子序列补充路径
- 分数规则：前缀命中 `500 - (Name.Length - prefix.Length)`；补充命中走 `FuzzyMatch`

**4.1.3 NameLower 匹配**（US-05）

- `IsSubsequence(lowerPrefix, obj.NameLower)` 替代逐字符 `char.ToLowerInvariant`
- FuzzyMatch 增加传入 `inputLower` / 使用 `targetLower` 的重载，避免内部重复 ToLowerInvariant

### 4.2 模块二：GetAllObjectsOfTypes 优化

**位置**：`DatabaseObjectCacheService.GetAllObjectsOfTypes`

**4.2.1 类型索引定位**（US-02）

```csharp
public List<CompletionCandidate> GetAllObjectsOfTypes(params string[] typeCodes)
{
    var set = new HashSet<string>(typeCodes, StringComparer.OrdinalIgnoreCase);
    // 从 typeIndex 直接取（构建期已按类型分桶）
    var filtered = typeIndex
        .Where(kv => set.Contains(kv.Key))
        .SelectMany(kv => kv.Value)
        .ToList();
    // 预排序 + 限量 250 + 惰性创建
    return filtered
        .Take(MaxCandidates)
        .Select(o => CreateObjectCandidate(o, "", dbName))
        .ToList();
}
```

- 触发条件：任何调用 GetAllObjectsOfTypes 的场景（FROM/INSERT/UPDATE/DELETE 空 filter）
- 数据规则：typeIndex key 为类型码（U/V/P/FN/IF/TF/...），构建缓存时生成
- 边界条件：typeIndex 未构建（旧缓存文件）→ 回退旧逻辑全量过滤，并触发缓存重建

**4.2.2 预排序 + 惰性链**（US-03）

- 构建缓存时 Objects 按 Name 字典序排序（一次），查询期免 OrderBy
- 链式：`Take(250).Select(...).ToList()`，仅创建返回的 250 个候选

### 4.3 模块三：缓存数据结构扩展

**位置**：`DatabaseObjectCacheService` 缓存构建逻辑 + `DatabaseObjectInfo`

| 新增/调整 | 类型 | 说明 | 兼容性 |
|-----------|------|------|--------|
| `typeIndex` | `Dictionary<string, List<DatabaseObjectInfo>>` | 类型码 → 对象列表 | 新增字段，缓存文件需升级版本号 |
| `NameLower` | `string` 属性（DatabaseObjectInfo） | 构建期填充小写名 | 新增字段，序列化需兼容 |
| Objects 预排序 | `List<DatabaseObjectInfo>` | 构建期按 Name 排序 | 缓存文件升级 |

- **缓存文件兼容策略**：对象缓存 JSON 增加版本号（如 v2）；读取 v1 旧文件时检测到缺字段 → 触发重建，保证 NameLower / typeIndex / 预排序就绪
- 触发条件：缓存加载时校验版本

### 4.4 模块四：CompletionDispatcher 输入防抖（US-06）

**位置**：`CompletionDispatcher` 补全请求入口（UI 触发侧）

- 防抖窗口：**120ms**
- 行为：窗口内新输入重置计时器，仅最后一次触发实际计算
- 边界：防抖不得影响"回车确认补全""候选窗口关闭"等交互；防抖仅作用于候选计算，不延迟文本插入

### 4.5 模块五：结果 LRU 缓存（US-07）

**位置**：`SearchInCache` 外层（GetMatchingObjects / GetMatchingObjectsForDb）

- 容量：**100 条**
- Key：`prefix`（当前库）或 `dbName + prefix`（跨库）
- 淘汰：LRU（最少最近使用）
- 失效：缓存切换（DetectServerSwitch）/ 缓存重建时清空
- 注意：结果缓存仅缓存 `List<CompletionCandidate>`，不缓存内部对象引用生命周期问题（候选含 Source 引用，缓存清理后由 GC 回收）

### 4.6 模块六：TAB/ENTER 按键交互优化（US-08）

**位置**：`SqlTemplateCompletionService.CompletionCommandFilter.Exec`（VSStd2K 命令组，CMDID_TAB=4 / CMDID_RETURN=3）

**4.6.1 弹窗可见时 TAB：提交补全（保留），提交后防弹窗重开**

现状（保留提交逻辑，需补充防重开）：

```csharp
case CMDID_TAB:
    _owner.ExpandSelectedTemplate();   // ✅ 保留：提交选中项完成补全
    return OLECMDERR_E_CANCELED;
```

**核心修复点**：`ExpandSelectedTemplate` 内部调用 `HidePopup` 时未设置防重开时间戳（2573 行 caller 机制：`caller != "ExpandSelectedTemplate"` 时不重置 `_lastUserHideTime`）→ 提交插入的文本触发 `OnCharTyped` → **弹窗自动重开** → 连续 TAB 反复提交。

目标行为：

```csharp
case CMDID_TAB:
    _owner.ExpandSelectedTemplate();   // 提交选中项
    _owner.MarkPopupDismissed();       // ✅ 新增：设置防重开时间戳（类似 _lastUserHideTime）
    return OLECMDERR_E_CANCELED;
```

- 触发条件：`_isPopupVisible == true` 且按 TAB
- 数据规则：`ExpandSelectedTemplate()` 照常执行（含跨库前缀剥离、SP 参数补全 F8、选区删除）；提交后设置防重开时间戳，使 `OnCharTyped` 在防重开窗口（建议 200ms）内不重新弹出弹窗
- **跨库前缀剥离**：TAB **需要经过**——`ExpandSelectedTemplate` 内部工序（跨库前缀剥离、SP 参数补全）在 TAB 提交时照常执行
- 异常流程：`_lastExpandTime` 节流逻辑保留；防重开时间戳复用 `_lastUserHideTime` 机制（200ms 窗口）或独立字段，不得影响后续正常输入触发弹窗

**4.6.2 弹窗可见时 ENTER 保持现状**

现状已符合（无需修改）：

```csharp
case CMDID_RETURN:
    _owner.HidePopup();                // ✅ 关闭弹窗
    break;                             // ✅ 放行给 Next.Exec（插入换行）
```

- 验证项：确认 ENTER 后弹窗不会因文本变化（换行）被 `OnCharTyped` 重新触发

**4.6.3 弹窗不可见时 TAB：不触发弹窗**

现状（已符合，无需修改）：

```csharp
if (nCmdID == CMDID_TAB)
{
    if (节流...) return OLECMDERR_E_CANCELED;
    if (_owner.TryExpandExactMatch())   // 光标前词精确匹配用户模板 → 展开
        return OLECMDERR_E_CANCELED;
}
```

- **定稿方案**：保留 `TryExpandExactMatch` —— 用户显式输入模板缩写（如 `sel`）后按 TAB 展开是有意行为；光标前无词时该方法直接返回 false → TAB 放行缩进，**不弹出补全弹窗**
- **验证项**：确认弹窗不可见时按 TAB 不会因放行后的缩进文本变化触发 `OnCharTyped` 弹出弹窗（`OnLayoutChanged` 492 行 `if (!_isPopupVisible) return;` 已保证，需回归验证）

**4.6.4 兼容性影响（v1.4 已确认）**

| 影响面 | 说明 |
|--------|------|
| TAB 提交功能 | 弹窗可见时 TAB 照常提交选中项（`ExpandSelectedTemplate` 保留） |
| 模板展开功能 | 弹窗不可见时 `TryExpandExactMatch` 保留，TAB 不触发弹窗 |
| SP 参数展开 | `ExpandSelectedTemplate` 内含 SP/函数参数自动补全（F8 特性），TAB 提交时照常执行；鼠标双击候选（2157 行）为另一保留触发路径 |
| 跨库前缀处理 | `ExpandSelectedTemplate` 内含跨库 `[DB].Schema.` 前缀剥离逻辑，TAB 提交时照常执行 |
| 弹窗重开 | TAB 提交后设置防重开时间戳，弹窗不因提交引起的文本变化自动重开；重新输入字符后正常触发 |

## 8. 上线计划建议

### 8.1 实施顺序（按优先级）

| 阶段 | 内容 | 对应 US | 预期收益 |
|------|------|---------|---------|
| 阶段一（P0） | 限量 Take(250) + typeIndex + 预排序惰性链 | US-01/02/03 | 空前缀 1s → <50ms，主卡顿解决 |
| 阶段一（P0） | TAB/ENTER 按键交互优化 | US-08 | 连续 TAB 不再带出首个提示项 |
| 阶段二（P1） | 前缀命中直算分 + NameLower | US-04/05 | 输入单字符 1s → <50ms |
| 阶段三（P2） | 输入防抖 | US-06 | 连续输入体验根治 |
| 阶段四（P3） | LRU 结果缓存 | US-07 | 高频重复查询零计算 |

### 8.2 灰度与回滚

- **灰度策略**：缓存文件版本升级后，首次加载触发重建（一次性成本），建议在测试库验证后全量生效
- **回滚条件**：任一验收项不达标（性能 > 50ms 或候选结果集合劣化）→ 回退至上一版本
- **上线后观察**：补全耗时日志（`completion.search.duration`）、用户卡顿反馈
