# 版本差异页显示与性能优化 技术方案（SPEC-SSMSBP-DISPPERF-001）

## 1. 变更概述

- 变更范围：`LocalHistoryDiffDialog` 的差异渲染层与显示控制（XAML + .xaml.cs），仅涉及 SSMS 层 UI，不引入跨层依赖，符合 `Shared→Core→AI→SSMS` 单向依赖约束。
- 影响模块：差异渲染（RenderDiff/BuildDocument）、差异导航（CollectDiffRows/GoToDiff）、同步滚动（OnScrollChanged）、重试加载、在编辑器中打开。
- 技术目标：默认自动换行看全超长行、可切不换行 + 横向滚动；5000 行加载 < 1 秒、UI 不阻塞；超大脚本不崩溃。

## 2. 显示方案设计（确定）

### 2.1 切换开关

- 工具栏（Row 1）新增 `ToggleButton x:Name="WordWrapButton"`，复用既有 `ToolbarToggleButton` 样式，`Content="自动换行"`，`IsChecked="True"`（默认自动换行），绑定 `Checked`/`Unchecked` 事件处理显示模式切换。
- 语义：`IsChecked=True` → 自动换行；`False` → 不换行 + 横向滚动。

### 2.2 自动换行 / 横滚控制（不重建 Document）

- `BuildDocument` 移除 `ColumnWidth = double.PositiveInfinity`（该设置禁用了换行，是"无自动换行"的根因）。
- 自动换行模式：`doc.ColumnWidth = viewer.ActualWidth`（文档列宽约束为面板可视宽度，文本在面板内折行）；窗口 `SizeChanged` 时同步更新 `ColumnWidth` 以适配缩放。
- 不换行模式：`doc.ColumnWidth = double.PositiveInfinity`，并启用横向滚动。
- 横向滚动修正（关键）：当前外层 `ScrollViewer` 包 `RichTextBox` 的结构下，`HorizontalScrollBarVisibility` 设在外层未生效于 RichTextBox 自身（RichTextBox 内部嵌套 ScrollViewer 优先处理内容宽度，外层检测不到溢出）。修正为：在 `RichTextBox` 上直接设置 `HorizontalScrollBarVisibility`（TextBoxBase 依赖属性）——自动换行模式设为 `Hidden`（靠折行，无需横滚），不换行模式设为 `Auto`（出现水平滚动条）。
- 结构清理：移除冗余外层 `ScrollViewer`，让 `RichTextBox` 直接占位并利用其自带 ScrollViewer（垂直 + 水平）；同步滚动逻辑改为通过 `GetScrollViewer(Visual)` 递归查找 RichTextBox 内部 ScrollViewer 并订阅其 `ScrollChanged`（替代原监听 `LeftScroller`/`RightScroller`）。
- 切换仅修改 `ColumnWidth` 与 `HorizontalScrollBarVisibility`，**不重建 FlowDocument**，因此不破坏差异导航已采集的 `Paragraph` 引用与高亮状态（满足 AC-003、AC-005）。

## 3. 性能方案设计（双方案对比，待 G3 决策）

当前瓶颈根因：`FlowDocument` 逐行 `Paragraph` 同步构建且**无 UI 虚拟化**，5000 行时全量布局开销大、阻塞 UI 线程。

### 路线 2（推荐·ListView 虚拟化，零新依赖）

- 新增行模型 `DiffLineItem`：`{ int? LineNumber; Brush LineNumberBg; ChangeType Type; IList<SubPiece>? SubPieces; string Text; Brush RowBg; bool IsDiff }`。
- `RenderDiff` 改为构建 `List<DiffLineItem>` 并赋值 `ListView.ItemsSource`（数据构建 O(n)，UI 仅布局可见行）。
- `ListView` 默认 `VirtualizingStackPanel` 虚拟化：5000 行仅布局可见约 50 行，渲染毫秒级，根本解决虚拟化缺失。
- 行内逐字符 diff 着色：ItemTemplate 用 `TextBlock` + `Run` 集合（按 `SubPieces` 着色）；行号列同理。
- 自动换行/横滚：`ListView` 内部 `ScrollViewer.HorizontalScrollBarVisibility` 绑定显示模式；`TextBlock.TextWrapping` 绑定（Wrap=自动换行，NoWrap=不换行 + 横滚）。
- 差异导航适配：`_diffLineIndexes` 记录差异行索引；`GoToDiff(idx)` 经 `ItemContainerGenerator.ContainerFromIndex(i)` 取容器设背景 + `BringIntoView`；同步滚动监听 ListView 内部 ScrollViewer。
- 优势：稳定满足 5000 行 < 1 秒；原生虚拟化；零新依赖；符合架构约束。
- 劣势：渲染层重构范围较大（RichTextBox→ListView，重写 RenderDiff/CollectDiffRows/GoToDiff/OnScrollChanged）；OpenInEditor 不受影响（仍用 `_historicalScript`），重试遮罩/失败逻辑保持。

### 路线 1（备选·保留 FlowDocument 优化，低风险渐进）

- 异步差异计算：`Task.Run` 执行 `SideBySideDiffBuilder.Diff`（纯数据，释放 UI 线程计算阶段），UI 线程构建 Document。
- 渲染优化：`TextOptions.TextFormattingMode=Display` 加速文字；固定 `LineHeight=18`；自动换行（移除 Infinity）降低单行宽度，布局更快。
- 可选首屏限量 + 滚动补全：先渲染前 N 行，滚动到底补建后续；但因破坏"全部 Paragraph 引用"的导航假设，复杂度高、慎选。
- 优势：改动小、风险低，可与显示优化一并快速交付。
- 劣势：FlowDocument 本质无虚拟化，5000 行可能仍接近 1 秒边界，**不保证达标**，需实测；若不达标需降级到路线 2。

### 选型建议

- 若以"稳定达标 + 长期健康"为目标：选**路线 2**（推荐）。
- 若以"最小改动先交付显示优化 + 部分性能"为目标、且可接受性能实测验证：选**路线 1**，但须以 AC-004（5000 行 < 1 秒）实测为门禁，不达标即降级路线 2。

## 4. 接口 / 数据变更

- 无新增对外接口；无数据库表/字段变更（与需求规格一致）。
- 内部新增 `DiffLineItem` 仅为 UI 绑定模型（路线 2 时），不持久化。

## 5. 影响评估（兼容性）

- 差异导航（计数/上/下/高亮/同步滚动）：路线 2 需适配为行索引导航；路线 1 保持不变（仅改 ColumnWidth/横滚）。
- 同步滚动：结构清理后改监听内部 ScrollViewer，逻辑等价。
- 重试加载 / 失败遮罩：保持不变（仅替换渲染数据源）。
- 在编辑器中打开：不受影响（仍基于 `_historicalScript`）。
- 行内逐字符 diff 着色、行号对齐：两种路线均保留。

## 6. 风险提示

- 路线 2 重构范围：替换渲染控件需重写多处逻辑，回归测试覆盖差异导航全路径（风险中，缓解：保留单元测试 + 手动验收 7 条 AC）。
- 路线 1 性能不确定：FlowDocument 无虚拟化，可能不达 1 秒（风险中，缓解：实测门禁 + 降级路线 2）。
- 自动换行下 BringIntoView 精度：折行后单逻辑行占多视觉行，滚动定位应落在逻辑行首（风险低，缓解：导航测试）。
- 架构合规：若路线中考虑引入 AvalonEdit 等第三方控件，须仅由 SSMS 层引用、不破坏依赖链；本方案主推零新依赖，不引入 AvalonEdit（风险低）。

## 7. 验收对照

| AC | 满足方式 |
|----|----------|
| AC-001 默认换行可见超长行 | 默认自动换行（ColumnWidth=面板宽），超长行折行 |
| AC-002 切换横滚看全+对齐 | 不换行模式 + RichTextBox.HorizontalScrollBarVisibility=Auto，左右逐行对齐保持 |
| AC-003 开关实时生效 | 仅改 ColumnWidth/横滚，不重建 Document |
| AC-004 5000 行 < 1 秒 | 路线 2 虚拟化（推荐）/ 路线 1 异步+优化（实测） |
| AC-005 切换不影响导航 | 切换不重建 Document（路线1）或导航基于行索引重载（路线2） |
| AC-006 空脚本/失败遮罩/重试 | 保持原有逻辑 |
| AC-007 超大不崩溃 | 虚拟化天然支撑大文件（路线2）；路线1 实测兜底 |

## 8. 待 G3 决策项

- **性能路线选择**：路线 2（推荐，ListView 虚拟化，重构较大但稳定达标）vs 路线 1（保留 FlowDocument 优化，低风险但性能需实测）。
- 其余显示为确定设计，无需决策。
