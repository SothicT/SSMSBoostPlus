## 一、问题现象

用户运行 `deploy-to-ssms.bat` 后，**PS1 脚本正确执行**并输出：
```
[Tier 1] ? 找到: D:\Microsoft SQL Server Management Studio 22\Release
[持久化] 已写入: C:\Users\100019624\AppData\Roaming\SSMSBoostPlus\config.json
D:\Microsoft SQL Server Management Studio 22\Release
```

**但 bat 仍报错**：
```
[ERROR] SSMS 22 path detection failed!
Please specify install dir manually
```

**症状矛盾点**：
- PS1 正常输出 + 持久化成功 = 检测 100% 成功
- bat 报"检测失败" = `SSMS_ROOT` 变量未正确接收

## 1.1 二次 Bug（修复过程中暴露）

**时间线**：
1. 第一次 Bug：`set SSMS_ROOT=` 预定义 → `if not defined` 失效 → 已修复（删除该行）
2. **第二次 Bug**：删除预定义后，for /F 内 set 仍赋值失败 → 重新走手动输入

**第一次修复后的 bat 跟踪**：
```cmd
F:\...>(if not defined SSMS_ROOT set "SSMS_ROOT=D:\Microsoft SQL Server Management Studio 22\Release" )
F:\...>if not defined SSMS_ROOT (
echo.
 echo [ERROR] SSMS 22 path detection failed!
```

**矛盾点**：第 1 行 set 明明赋值成功（bat 跟踪显示了完整命令），第 2 行 `if not defined` 却为真。

**根因**：`for /F do (...)` 块内的 `set` 属于**子 shell 上下文**，其修改对父 shell 不可见。

**最终修复**：删除 for 循环，改用 `set /p SSMS_ROOT=<"%TMP_FILE%"` 直接读取文件（set /p 在父 shell 执行，变量立即可见）。

详见第四节"修复方案 2.0"。

## 二、根本原因

### 2.1 关键代码（修复前）

`deploy-to-ssms.bat` 第 66-75 行：

```bat
::: Call PowerShell script to detect SSMS 22 path
set SSMS_ROOT=                                          ← 🐛 元凶
set "TMP_FILE=%TEMP%\SSMS22_Root_%RANDOM%.txt"
powershell -NoProfile -ExecutionPolicy Bypass -File "%FIND_SCRIPT%" -Quiet -OutputFile "%TMP_FILE%" 1>nul 2>nul
if exist "%TMP_FILE%" (
    for /f "usebackq delims=" %%P in ("%TMP_FILE%") do (
        if not defined SSMS_ROOT set "SSMS_ROOT=%%P"   ← 永远不执行
    )
    del "%TMP_FILE%" >nul 2>&1
)
```

### 2.2 底层机制

**Windows 批处理中 `set VAR=` 与"未定义"的区别**：

| 语句 | 变量状态 | `if defined VAR` | `if not defined VAR` |
|------|---------|------------------|---------------------|
| 首次引用前 | ❌ 未定义 | false | **true** |
| `set VAR=` 后 | ⚠️ **已定义-空字符串** | **true** | **false** |
| `set VAR=hello` 后 | ✅ 已定义-有值 | true | false |

### 2.3 推导出的失败链路

```
1. set SSMS_ROOT=
   └─ SSMS_ROOT 状态: 已定义 + 空字符串

2. for /f 读到临时文件内容 "D:\...\Release"
   └─ %%P = "D:\...\Release"

3. if not defined SSMS_ROOT
   └─ SSMS_ROOT 已定义(空)，条件永远为 false
   └─ set "SSMS_ROOT=%%P" 永不执行
   └─ SSMS_ROOT 保持空字符串

4. if not defined SSMS_ROOT (第 77 行)
   └─ SSMS_ROOT 状态: 已定义 + 空字符串
   └─ 条件 false → 走"误判"分支

5. echo [ERROR] SSMS 22 path detection failed!
   └─ 用户被引导进入手动输入流程
```

**关键事实**：PS1 完美运行，但 bat 的变量传递环节出错 → 用户毫无感知。

## 五、技术教训

### 5.1 bat 中"已定义-空" vs "未定义" 的陷阱

**核心规则**：
- **首次引用前** = 未定义（`if defined` false / `if not defined` true）
- **`set VAR=`** = 已定义-空字符串（`if defined` true / `if not defined` false）
- **`set VAR=value`** = 已定义-有值（`if defined` true / `if not defined` false）

**黄金准则**：
> 需要"未定义"状态时，**不写 set 语句**。
> 需要"清空"且配合 `if defined` 检测时，才用 `set VAR=`。

### 5.2 本次 Bug 的反模式

```bat
::: ❌ 错误：预初始化导致 if not defined 永远为假
set VAR=
... (后续赋值) ...
if not defined VAR set "VAR=%%P"

::: ✅ 正确：保持未定义直到真正赋值
... (后续赋值) ...
if not defined VAR set "VAR=%%P"
```

### 5.3 类似陷阱排查清单

排查脚本中是否存在以下反模式：

| 位置 | 语句 | 风险 |
|------|------|------|
| 函数入口 | `set RESULT=` | `if not defined RESULT` 永远为假 |
| 循环初始化 | `set FOUND_FLAG=` | `if not defined FOUND_FLAG` 永远为假 |
| 默认值占位 | `set PARAM=` | 参数覆盖检查失效 |
| 错误状态 | `set ERR_MSG=` | 错误判断逻辑被绕过 |

### 5.4 推荐工具检测

可使用 `set VAR & if defined VAR (echo DEFINED) else (echo UNDEFINED)` 做现场验证：
- `set VAR=` → DEFINED
- 不写 set → UNDEFINED
