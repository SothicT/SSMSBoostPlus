## 1. 插件简介

### 1.1 什么是 SSMSBoost++

SSMSBoost++ 是一款集成在 SQL Server Management Studio（SSMS）中的增强插件，通过 AI 辅助、版本守护、本地历史、SQL 工具等核心功能，帮助开发人员和 DBA 提升 SQL 编写效率、减少因数据库对象变更导致的脚本失效问题。

### 1.2 主要功能一览

| 功能分类 | 功能名称 | 快捷键 | 说明 |
|---------|---------|--------|------|
| **AI 代码助手** | 智能建议 | Ctrl+Shift+A | 分析 SQL 代码，提供优化建议和语法修复 |
| | AI 智能注释 | Ctrl+Shift+C | 自动为 SQL 代码添加中文注释 |
| | 自动格式化 | Ctrl+Shift+F | 按风格自动格式化 SQL |
| | 性能分析 | Ctrl+Shift+P | 分析 SQL 性能瓶颈，提供优化建议 |
| | AI 对话面板 | Ctrl+Shift+K | 可停靠的多轮对话面板 |
| **版本守护** | 启用/禁用版本守护 | — | 快速开关版本守护功能 |
| | 检查脚本版本 | Ctrl+Shift+V | 检测脚本引用的对象是否已过时 |
| | F5 自动拦截检查 | F5 | 执行 SQL 前自动检查版本，防止覆盖 |
| | 特殊标记跳过 | — | 支持 `#nosynccheck` / `#checklater` |
| **SQL 工具** | 关键词查询 | — | 选中关键词，搜索数据库对象中匹配项 |
| | 打开脚本 | — | 选中对象名，从数据库获取完整定义 |
| | 刷新对象缓存 | — | 刷新代码补全使用的数据库对象缓存 |
| **本地版本历史** | 版本历史面板 | — | 记录每次执行的 SQL 历史，支持对比恢复 |
| **SQL 模板** | 模板设置 | — | 管理自定义 SQL 代码片段缩写 |
| **功能开关** | 启用代码补全 | — | 控制输入时是否弹出智能补全提示 |

| **系统** | 检查更新 | — | 手动检查插件版本更新 |

## 2. 安装与部署

### 2.1 系统要求

- **操作系统**：Windows 10 / Windows 11
- **.NET 运行时**：.NET Framework 4.7.2 及以上
- **SSMS 版本**：SQL Server Management Studio 22（20.5.x）及以上
- **网络要求**：使用 AI 功能需要访问 AI API（支持 OpenAI 兼容接口或 Codebuddy CLI）

### 2.2 部署步骤

> **注意**：`SSMSBoostPlus.sln` 已被企业加密软件加壳，`dotnet` 无法解析。请改用 **`SSMSBoostPlus.slnx`**。

#### 步骤 1：编译项目

```powershell
双击InstallSSMSBoostPlus.exe程序以安装
```

> **注意**：`/setup` 需要管理员权限。

### 2.3 首次启动验证

1. 启动 SSMS 22
2. 观察主菜单栏是否出现 **SSMSBoost++** 顶级菜单
3. 点击 **SSMSBoost++ → AI 代码助手 → 智能建议**，如果弹出"AI 尚未配置"提示框，说明插件已正常加载

## 4. AI 代码助手

使用 AI 能力辅助 SQL 开发。所有 AI 功能均需要先完成 [AI 配置](#101-ai-配置)。

> **提示**：如果未配置 AI，第一次使用时会自动弹出配置对话框。

### 4.1 智能建议（Ctrl+Shift+A）

分析当前 SQL 代码（选中文本或整篇文档），提供语法修正、代码简化和性能优化建议。

**适用场景**：
- 不确定 SQL 写法是否规范
- 希望了解是否有更优的实现方式
- 想要发现潜在的语法错误或逻辑问题

**操作步骤**：

1. 打开或编写 SQL 脚本
2. （可选）选中需要分析的代码片段
3. 按 `Ctrl+Shift+A` 或通过 **SSMSBoost++ → AI 代码助手 → 智能建议**
4. 等待 AI 分析（状态栏显示"正在使用 AI 分析 SQL 代码..."）
5. 查看 Diff 对比窗口，确认改动后点击 **接受右侧（AI 建议）** 或 **取消**

> **注意**：如果已选中文本，仅替换选中区域；如果未选中文本，则替换整篇文档。

### 4.2 AI 智能注释（Ctrl+Shift+C）

自动为 SQL 代码添加结构化中文注释，包括：表结构说明、字段注释、JOIN 关系说明、存储过程参数说明等。

**适用场景**：
- 接手他人遗留的 SQL 脚本，需要快速理解代码逻辑
- 希望生成规范化的代码文档

**操作步骤**：

1. 编写或打开 SQL 脚本
2. （可选）选中需要添加注释的代码片段
3. 按 `Ctrl+Shift+C` 或通过菜单 **SSMSBoost++ → AI 代码助手 → AI 智能注释**
4. 等待 AI 生成注释
5. 在 Diff 窗口中预览，点击接受

### 4.3 AI 自动格式化（Ctrl+Shift+F）

按配置的格式化风格（Microsoft 或 Google）自动美化 SQL 代码，包括：关键字大小写统一、缩进规范化、换行整理等。

**格式化风格说明**：

| 风格 | 关键字大小写 | 示例 |
|------|------------|------|
| **Microsoft**（默认） | 小写 | `select * from users` |
| **Google** | 大写 | `SELECT * FROM users` |

**操作步骤**：

1. 编写或打开 SQL 脚本
2. 按 `Ctrl+Shift+F` 或通过菜单 **SSMSBoost++ → AI 代码助手 → AI 自动格式化**
3. 在 Diff 窗口中预览格式化效果，点击接受

### 4.4 AI 性能分析（Ctrl+Shift+P）

深度分析 SQL 代码的性能问题，提供执行计划解读和优化建议。功能包含两部分：

- **分析报告**：返回自然语言描述的性能问题
- **优化代码**：如果 AI 生成了优化后的代码，提供 Diff 替换功能

**适用场景**：
- SQL 执行缓慢，怀疑有性能问题
- 想要了解执行计划中的 Cost 分布
- 希望获得具体的索引建议或查询改写方案

**操作步骤**：

1. 编写或打开 SQL 脚本
2. 按 `Ctrl+Shift+P` 或通过菜单 **SSMSBoost++ → AI 代码助手 → AI 性能分析**
3. 如果 AI 生成了优化代码，会显示 Diff 窗口
4. 查看分析结果后，点击接受（如果提供了优化代码）

> **注意**：性能分析会尝试获取当前查询的执行计划 XML，以提供更精确的分析结果。获取失败时会以无执行计划模式分析，不影响基本功能。

### 4.5 流式响应弹窗

性能分析、以及 4.6 节 AI 对话面板的输出均采用 **SSE（Server-Sent Events）+ 零缓冲实时渲染**：AI 的每一个 token 一旦到达就立即显示在弹窗中，无需等待完整响应。

**弹窗三区布局**：

```
┌──────────────────────────────────────────┐
│  📘 AI 智能建议                  3.2s    │  ← 标题栏（含计时）
├──────────────────────────────────────────┤
│  正在连接 AI 服务... ▓▓▓▓▓▓▓▓           │  ← 状态栏（进度条）
├──────────────────────────────────────────┤
│  📤 AI 请求内容                          │
│  ┌──────────────────────────────────────┐│
│  │ SELECT * FROM Orders WHERE ...       ││  ← 请求区（原始 SQL）
│  └──────────────────────────────────────┘│
│  ════════════════════════════════════════│  ← 可拖拽分隔条
│  🤖 AI 响应                              │
│  ┌──────────────────────────────────────┐│
│  │ 💭 正在思考...                        ││  ← 思考过程（可折叠）
│  │ 优化这个查询需要考虑...                ││
│  │                                       ││
│  │ ## 优化建议                            ││  ← 正式响应（实时流式）
│  │ 1. 避免 SELECT *，应明确指定列名       ││
│  └──────────────────────────────────────┘│
├──────────────────────────────────────────┤
│          [📝 复制代码] [📋 复制响应] [关闭] │  ← 底部操作栏
└──────────────────────────────────────────┘
```

**思考过程区域**：AI 模型（如 Qwen3）生成正式回答前会经历"思考"阶段，区域会：

- **思考中**：显示 💭 动画 + "正在思考..." 文字，内容实时滚动
- **思考完成**：自动折叠为可展开的摘要，显示字符数，点击可展开查看

**状态指示**：

| 状态 | 显示 | 说明 |
|------|------|------|
| 连接中 | "正在连接 AI 服务..." + 进度条 | fetch 请求已发出，等待响应头 |
| 流式接收 | "⏳ 响应中" + 计时器 | SSE 数据正在实时流入 |
| 完成 | "✅ 响应完成" | 全部数据接收完毕 |
| 失败 | "❌ 连接失败" | 网络错误或服务不可用 |

**操作按钮**：

| 按钮 | 功能 | 启用时机 |
|------|------|---------|
| 📝 复制代码 | 复制响应中的 SQL 代码块 | 响应包含代码块时 |
| 📋 复制响应 | 复制完整响应文本 | 有响应内容时 |
| 关闭 | 关闭弹窗（Esc 也可） | 流式完成或出错后 |

### 4.6 Diff 对比窗口

AI 代码助手统一使用左右分栏 Diff 对比窗口：

| 区域 | 内容 |
|------|------|
| **左侧（原始）** | 编辑器中当前的 SQL 代码 |
| **右侧（AI 结果）** | AI 返回的建议代码 |

| 按钮 | 行为 |
|------|------|
| **接受右侧（AI 建议）** | 将 AI 建议代码替换到编辑器中 |
| **取消** | 放弃更改，保留原始代码 |

Diff 窗口支持滚动同步，方便对比差异位置。

### 4.8 AI 桥接优先级

AI 功能支持三种通信方式，按以下优先级自动选择：

| 优先级 | 通信方式 | 配置项 | 适用场景 |
|--------|---------|--------|---------|
| 🥇 第一优先 | **CodeBuddy CLI**（本地命令行） | `CodebuddyCliPath` | 本地执行，无需网络，支持流式输出 |
| 🥈 第二优先 | **HTTP API**（用户自定义） | `ApiEndpoint` + `ApiKey` | 使用自有 OpenAI 兼容 API（如 DeepSeek / Claude） |
| 🥉 第三优先（兜底） | **内置默认 API** | 零配置 | 初次使用，无需任何配置即可体验 |

选择过程自动执行，可在日志中查看：

| 日志信息 | 含义 |
|---------|------|
| `✅ 使用用户配置的 CodeBuddy CLI` | 本地 CLI 生效 |
| `⚠️ 用户配置的 CLI 路径不可用，回退到 HTTP API` | CLI 不可用，自动降级 |
| `使用用户配置的 HTTP API` | 用户自定义 API 生效 |
| `使用内置默认 AI API` | 零配置兜底模式 |

## 5. 版本守护

版本守护（Version Guard）用于检测当前脚本引用的数据库对象（如表、视图、存储过程等）是否在数据库中被修改过，帮助你避免使用过时定义执行脚本导致错误。

### 5.1 功能概述

当你打开一个 SQL 脚本后，版本守护会记录脚本的"打开时间"。后续执行版本检查时，会对比脚本中引用的每个数据库对象在数据库中的最后修改时间（`modify_date`），如果有任何对象的修改时间晚于脚本打开时间，说明该对象已被更新，脚本中使用的是旧定义。

### 5.2 启用/禁用

快速开关版本守护功能。禁用后，所有版本检查操作将被跳过。

**操作**：菜单 **SSMSBoost++ → 🔒 启用版本守护**（可勾选）

> 菜单文本会根据当前状态动态变化：启用时显示"禁用版本守护"，禁用时显示"启用版本守护"。

### 5.3 检查当前脚本版本（Ctrl+Shift+V）

手动触发版本检查，分析当前脚本并与数据库对象进行比对。

**操作步骤**：

1. 确保已连接到数据库服务器
2. 打开或编写 SQL 脚本
3. 按 `Ctrl+Shift+V` 或通过菜单 **SSMSBoost++ → 检查当前脚本版本**
4. 等待分析完成（状态栏显示进度）
5. 根据结果选择操作

**比对结果说明**：

| 情形 | 含义 | 操作建议 |
|------|------|---------|
| 无过时对象 | 所有引用的数据库对象自脚本打开以来未被修改 | 可以正常执行脚本 |
| 检测到过时对象 | 至少一个对象已被修改 | 建议从数据库重新加载最新定义 |

### 5.4 F5 自动拦截检查（v2.0 新增）

**这是版本守护最实用的功能之一。**

当你按 `F5`（Query.Execute）执行 SQL 时，版本守护会自动拦截执行请求，先执行版本检查：

1. **未检测到过时对象** → 自动放行，正常执行 SQL
2. **检测到过时对象** → 弹出警告对话框，提示哪些对象已过时，让您决定：
   - **继续执行**（跳过警告）
   - **取消执行**（先确认修改后再执行）
   - **从数据库重新加载**（一键替换为最新定义）

**支持拦截的命令**：

| 命令 | 快捷键 | 说明 |
|------|--------|------|
| Query.Execute | F5 | 执行当前查询 |
| Query.ExecuteWithResultsToGrid | Ctrl+F5 | 执行到结果网格 |
| Query.ExecuteCurrentStatement | Alt+F5 | 执行当前语句 |

> **注意**：版本守护功能必须处于 **启用** 状态，F5 拦截才会生效。

### 5.5 配置项说明

通过 **版本守护设置** 对话框（菜单 **SSMSBoost++ → ⚙ 版本守护设置...**）可配置：

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| 启用版本守护 | 是 | 总开关 |
| 默认操作 | 询问用户 | 发现过时对象时的默认行为 |
| 排除的数据库 | `tempdb, master, model, msdb` | 这些数据库中的对象不参与检查 |
| 排除的对象 | （空） | 支持 Glob 模式，如 `sp_*` |
| 询问令牌 | `#checklater` | 脚本中包含此令牌时弹出询问窗口 |
| 跳过令牌 | `#nosynccheck` | 脚本中包含此令牌时跳过检查 |
| 令牌大小写敏感 | 是 | 令牌匹配是否区分大小写 |
| 不匹配时自动刷新 | 否 | 是否自动从数据库拉取最新定义 |

### 5.6 特殊标记

在 SQL 脚本中插入特殊注释，控制版本守护的行为：

| 标记 | 效果 |
|------|------|
| `-- #nosynccheck` | 完全跳过本次版本检查（包括 F5 拦截） |
| `-- #checklater` | 发现过时对象时弹出确认窗口 |

> **提示**：这些标记支持大小写敏感配置，默认区分大小写。

## 6. SQL 工具（右键菜单）

SQL 工具位于 **SQL 编辑器右键菜单 → SQL 工具** 子菜单中，提供三个实用的数据库对象检索功能。

### 6.1 关键词查询

在数据库对象内容中搜索关键词。支持搜索存储过程、函数、视图、触发器的脚本定义内容，以及表的列名。

**适用场景**：
- 想找到所有引用某个表名或列名的存储过程
- 不确定某个关键词在哪些数据库对象中出现过

**操作步骤**：

1. 在 SQL 编辑器中**选中**要搜索的关键词（如：表名、列名、SQL 关键字）
2. 右键 → **SQL 工具 → 🔍 关键词查询**
3. 后台自动生成搜索 SQL 并执行到当前连接
4. 结果直接显示在 SSMS 结果网格中，编辑器保持干净

> **提示**：搜索完成后编辑器中的临时 SQL 会被自动清除，搜索结果保留在结果网格中供查看。

### 6.2 打开脚本

从数据库获取选中对象的完整定义脚本。

**适用场景**：
- 想查看某个存储过程、函数、视图或触发器的完整代码
- 需要复制对象的当前定义

**操作步骤**：

1. 在 SQL 编辑器中**选中**对象名称（支持 1段名、2段名 或 3段名 格式）
2. 右键 → **SQL 工具 → 📄 打开脚本**
3. 自动从数据库获取该对象的完整定义脚本
4. 在新 SQL 编辑器中打开，方便查看或修改

**支持的对象类型**：存储过程（SP）、标量函数、表值函数、视图、触发器

> **提示**：如果选中的是 `ALTER` 或 `CREATE` 开头的完整脚本，会自动添加 `--` 注释前缀，保护原始对象不被意外覆盖。

### 6.3 刷新对象缓存

刷新代码补全功能使用的数据库对象缓存。

**适用场景**：
- 数据库中新增了表或存储过程，但代码补全没显示
- 想要手动触发一次缓存重建

**操作步骤**：

1. 打开 SQL 编辑器（连接到目标数据库）
2. 右键 → **SQL 工具 → 🔄 刷新对象缓存**，或顶部菜单 **SSMSBoost++ → 🔄 刷新对象缓存**
3. 状态栏显示刷新进度
4. 完成后缓存即更新

> **提示**：缓存文件保存在插件部署目录下，重启 SSMS 后自动加载。通常无需手动刷新，此功能用于数据库结构频繁变更的场景。

| `sp` | `CREATE PROCEDURE $cursor` |
| `vi` | `CREATE VIEW $cursor` |
| `if` | `IF EXISTS ($cursor)` |

| `jo` | `JOIN $cursor ON` |

## 11. 插件版本检查与自动更新

> ⚠️ **注意区分**：本章讲的是 **插件自身** 的版本更新（不是第 5 章的「SQL 脚本版本守护」）。第 5 章防止过时脚本覆盖数据库新对象；本章保证你的插件始终是最新功能与最新 bug 修复。

### 11.1 什么是自动更新

SSMSBoost++ 在以下时机自动检查更新：

- **SSMS 启动后 30 秒**：延迟检查，避免影响 SSMS 启动速度
- **运行时每小时轮询**：后台轮询，最小化对用户干扰
- **距上次手动检查 ≥ 7 天 且 ≥ 12:00**：每日定时检查，避开工作时段高峰

**数据源**：内网 Git 仓库 `Release` 分支。

**机制简述**：

```
git ls-remote → 取最新 commit hash
  → 与本地 version_info.json 的 localHash 比对
  → 不一致 → 弹出版本更新对话框
  → 用户确认 → git clone --depth 1 --branch Release 到临时目录
  → 执行 InstallSSMSBoostPlus.exe (verb=runas)
  → Environment.Exit(0) 关闭 SSMS
  → 用户重新打开 SSMS 即生效
```

### 11.2 手动检查更新

**触发方式**：
- 菜单 **SSMSBoost++ → 🔄 检查更新**
- 右键菜单 **版本守护 → 检查更新**

**两种结果**：

| 状态 | 弹窗 | 用户操作 |
|------|------|---------|
| 已是最新 | 提示「当前已是最新版本」 | 直接关闭 |
| 有新版本 | 显示版本号 + commit 信息 + 「更新」/「稍后」按钮 | 「更新」进入下载流程；「稍后」关闭窗口 |
| 手动查看 | 显示详细 commit log | 阅读后关闭 |

### 11.3 自动更新流程（7 天自动检查触发）

1. **检测阶段**（启动 30s 后 / 每小时 / 7 天定时）：
   - `git ls-remote <repo> Release` 拿远端 commit hash
   - 与 `version_info.json` 的 `localHash` 比对
2. **发现新版本**：
   - 自动弹出更新对话框（非阻塞，可关闭）
   - 用户点击「更新」进入下载
3. **下载阶段**：
   - `git clone --depth 1 --branch Release <url> %TEMP%\sbp_install`
   - 显示进度条（克隆阶段：约 5-30s 视网络情况）
4. **安装阶段**：
   - 调用 `InstallSSMSBoostPlus.exe --download` 参数
   - Installer 自动检测 SSMS 路径 → 复制产物 → 注册 PkgDef → 写新 `version_info.json`
5. **SSMS 重启**：
   - 自动关闭 SSMS
   - 桌面弹出提示「更新完成，请重新打开 SSMS」

### 11.4 离线更新（双击安装器）

若自动更新失败（如网络隔离、Git 凭据过期），可手动离线更新：

1. 从内网 Git 仓库 `Release` 分支下载最新 `InstallSSMSBoostPlus.exe`
2. **双击** `InstallSSMSBoostPlus.exe`
3. Installer 自动检测 SSMS 22 安装路径（注册表 + 默认值回退）
4. 复制文件 + 注册 PkgDef + 写 `version_info.json`
5. 关闭所有 SSMS 窗口，重新打开即生效

**支持的 SSMS 版本**（自动检测顺序）：22.0 → 20.0 → 19.0 → 18.0 → 17.0

### 11.5 关闭自动检查

可通过编辑 `version_info.json` 临时禁用：

```json
{
  "localHash": "abc123def456",
  "lastCheckUtc": "2026-07-02T08:00:00Z",
  "autoCheckEnabled": false  // 改为 false 即可禁用
}
```

### 11.6 常见问题

**Q1：自动检查会泄露我的 SQL 代码吗？**

不会。检查更新仅传输 commit hash（40 字节 SHA-1），不涉及任何业务数据。

**Q2：更新会中断当前编辑吗？**

会。更新流程需要关闭 SSMS。建议在保存脚本后触发更新。

**Q3：能回滚到旧版本吗？**

可以。`InstallSSMSBoostPlus.exe --install <path>` 支持从任意历史 commit 安装。也可从 Git 仓库 checkout 旧 tag 后重新构建。

## 12. 常见问题

### Q1：AI 功能提示"AI 尚未配置"怎么处理？

首次使用任何 AI 代码助手功能时，如果未配置 AI，会自动弹出配置对话框。也可以手动打开：菜单 **SSMSBoost++ → ⚙ AI 配置...**。

### Q2：没有数据库连接时，版本守护会有什么行为？

如果没有活动的数据库连接，版本检查会弹出提示，说明需要先连接数据库。请确保：
1. 已连接到 SQL Server
2. 查询窗口已关联连接
3. 重新打开查询窗口后重试

### Q3：如何查看插件的运行日志？

日志文件默认保存在扩展安装目录下的 `Logs` 子目录，按日期滚动，单文件最大 10MB，保留 30 天。

日志路径：`D:\Microsoft SQL Server Management Studio 22\Release\Common7\IDE\Extensions\SSMSBoostPlus\Logs\`

> **注意**：日志功能默认**不启用**。需要先在菜单 **SSMSBoost++ → 📝 启用日志** 中勾选才会写入日志文件。

### Q4：Diff 窗口中没有看到"接受"按钮？

请确保 Diff 窗口已完全展开，某些按钮可能被最小化的窗口遮挡。尝试最大化 Diff 窗口后重试。

### Q5：提示"无法获取执行计划"？

性能分析尝试获取当前查询的执行计划 XML 时，如果查询无法执行（如语法错误或无连接），会显示此提示。分析仍会以无执行计划模式继续，不影响基础分析功能。

### Q6：AI 使用哪种通信方式？如何查看当前使用的桥接？

AI 按以下优先级自动选择通信方式：
1. **CodeBuddy CLI**（本地命令行，优先）
2. **HTTP API**（用户自定义）
3. **内置默认 API**（零配置兜底）

可在日志中查看选择结果，搜索 `[BridgeFactory]` 关键字。

### Q7：什么是 CodeBuddy CLI？在哪里下载？

CodeBuddy CLI 是本插件配套的本地命令行工具，提供流式 AI 交互能力。可在 AI 配置对话框中配置其路径。

### Q8：配置了 CLI 路径后，还能回退到 HTTP API 吗？

可以。如果配置的 CLI 路径不可用（文件不存在或执行失败），系统会自动降级到 HTTP API（用户自定义或内置默认），并在日志中记录降级原因。

### Q9：AI 对话面板中的 Markdown 渲染支持哪些格式？

| 格式 | 渲染效果 |
|------|---------|
| ```sql ... ``` 围栏代码块 | 等宽字体 + 灰底边框 |
| `行内代码` | 灰底等宽字体 |
| # 标题（1-4 级） | 不同字号加粗 |
| **粗体** / *斜体* | 正常渲染 |
| - 无序列表 / 1. 有序列表 | 缩进排列 |
| > 引用块 | 蓝色左边框 |
| [链接](url) | 可点击蓝色链接 |
| \| 表格 \| | 完整表格渲染 |
| --- 分隔线 | 水平线 |

### Q10：代码补全不显示数据库对象怎么办？

代码补全需要先加载数据库对象缓存。请尝试：
1. 确保 **SSMSBoost++ → 🔧 启用代码补全** 已勾选
2. 在 SQL 编辑器中确保已连接到目标数据库
3. 执行 **SSMSBoost++ → 🔄 刷新对象缓存** 手动更新缓存

### Q11：右键菜单中没有"SQL 工具"子菜单？

"SQL 工具"子菜单仅在 SQL 编辑器窗口中可见。请确保：
1. 当前打开的是 `.sql` 文件
2. 在 SQL 编辑器中点击右键
3. 查看 **SQL 工具** 子菜单（可能位于右键菜单靠下位置）

### Q12：如何添加或修改 SQL 模板？

通过 **SSMSBoost++ → 📋 SQL 模板设置...** 打开模板管理对话框，可自由新增、修改或删除模板。

也可以直接编辑 `部署目录/sql_templates.json` 文件，修改后重启 SSMS 生效。
